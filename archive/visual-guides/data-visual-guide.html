机器人数据：从一条数据说起

在你训练出第一个策略之前，先看清楚数据长什么样。

想象这样一个场景：你用遥操作手柄控制一台机械臂，花了 8 秒把桌上的红色方块放进篮子里。这 8 秒的操作，被传感器记录下来，变成了硬盘上的一段数据。

这段数据就叫做一条 episode（回合）。它是机器人学习的基本单位——模型从成百上千条这样的 episode 中学习"看到什么就做什么"。

但问题是：这段数据到底长什么样？里面有什么字段？一个"时间步"包含哪些信息？

本页用一条真实的数据记录，带你从最小的单位——一个 step（时间步）——开始，一层一层看清机器人数据的结构。

一个时间步（Step）里有什么

机器人以固定频率运行（比如每秒 50 次），每次"滴答"就是一个 step。一个 step 记录了那一瞬间机器人看到了什么、做了什么。

下面是一条真实的 step 数据。每个字段都标注了含义：

Step #37 / Episode #12
index: 1237 // 在整个数据集中的全局编号
episode_index: 12 // 属于第 12 条示教
frame_index: 37 // 这条示教中的第 37 帧
timestamp: 0.740 // 距 episode 开始 0.74 秒（50Hz → 每帧 0.02s）
observation.state: [0.12, -0.45, 0.78, 1.23, -0.56, 0.34, 0.8]
  // 7 个数：6 个关节角度（弧度）+ 1 个夹爪开度（0=闭, 1=开）
observation.images.front: [480 x 640 x 3] uint8 RGB
  // 正前方相机拍到的图像
observation.images.wrist: [480 x 640 x 3] uint8 RGB
  // 腕部相机拍到的图像（近距离看抓取）
action: [0.003, -0.012, 0.008, 0.001, -0.005, 0.002, 0.0]
  // 7 个数：6 个关节目标增量 + 1 个夹爪命令（此刻夹爪不动）
task: "pick up the red block and place it in the basket"
done: false // 任务还没结束
success: false // 还没成功（成功只在最后一帧标记）
读懂这条数据

这一帧的含义是：在第 12 次示教的第 0.74 秒，机械臂的 6 个关节处于某个角度、夹爪张开到 80%，两个相机各拍了一张图。操作员在这一刻发出的动作指令是"各关节微微调整"——因为方块还在桌上，臂正在慢慢靠近。

你可能注意到了：observation（观测）是机器人此刻"看到"的世界，action（动作）是此刻"要做"的事。训练模型时，目标就是从 observation 预测 action。

观测（Observation）：机器人的眼睛和感觉

观测是策略模型的输入。一个机器人通常有多种"感官"：

一个 step 的观测由多种模态组成：图像、机器人状态、语言指令

常见的观测模态包括：

模态典型字段名内容数据格式
图像observation.images.front外部相机的 RGB 图像[H, W, 3] uint8
腕部图像observation.images.wrist机械臂末端相机[H, W, 3] uint8
深度图observation.depth.front像素级距离信息[H, W] float32 (米)
关节状态observation.state关节角度 + 夹爪开度[n_joints + 1] float32
末端位姿observation.end_effector末端在空间中的位置和朝向[7] float32 (xyz + quat)
力/力矩observation.force_torque末端受力[6] float32
语言指令task自然语言描述的任务字符串
初学者最常踩的坑：时间对齐

图像和关节状态可能来自不同传感器，采样频率不同（相机 30Hz，关节 500Hz）。如果没有正确对齐时间戳，模型学到的是"看到上一帧图像，做出当前动作"——在真机上就变成反应慢半拍。

动作（Action）：机器人被告知做什么

action 是操作员在那一刻发出的控制指令。但"控制指令"有很多种写法，不同的写法叫做不同的动作空间（action space）：

三种常见动作空间对比。同一个"往右移 1 厘米"的动作，在不同空间里写法完全不同
选哪种动作空间？

新手建议：先用关节位置（joint position），因为和 observation.state 直接对应，调试最简单。末端位姿更直观但需要逆运动学，增量动作更平滑但对控制频率敏感。

从 Step 到 Episode 到 Dataset

理解了一个 step 之后，让我们把视角拉远，看一条完整的 episode，以及整个数据集的结构：

数据集的三层结构：Dataset → Episode → Step。每条 episode 是一次完整的任务尝试
关键概念

Episode = 一次完整的任务执行，从 reset 到结束。有成功的，也有失败的。
Step/Frame = episode 中的一个时间步，包含那一刻的观测和动作。
Dataset = 很多条 episode 的集合，可能包含多个任务、多个操作员的数据。

数据怎么存：从文件夹结构说起

收集完数据后，要存到硬盘上。目前机器人学习社区最常用的格式是 LeRobot v2（Hugging Face 维护），文件夹结构长这样：

dataset/
├── meta/
│   ├── info.json          ← 数据集级别的元信息
│   ├── stats.json         ← 每个字段的均值、标准差（用于归一化）
│   ├── episodes.jsonl     ← 每条 episode 的起止位置和标签
│   └── tasks.jsonl        ← 任务列表
├── data/
│   ├── chunk-000/
│   │   └── episode_000000.parquet  ← 状态、动作等数值数据
│   │   └── episode_000001.parquet
│   │   └── ...
├── videos/
│   ├── chunk-000/
│   │   ├── observation.images.front/
│   │   │   ├── episode_000000.mp4  ← 图像压缩成视频
│   │   │   └── episode_000001.mp4
│   │   └── observation.images.wrist/
│   │       ├── episode_000000.mp4
│   │       └── ...

为什么这样设计？

设计决策原因
数值数据用 Parquet列式存储，读取特定字段极快，支持高效压缩
图像压缩成 MP4 视频1000 帧 JPEG ≈ 200MB，MP4 ≈ 5MB。省 40 倍空间
按 episode 分文件加载单条 episode 不用读整个数据集
chunk 分组单目录文件过多时文件系统变慢，分 chunk 避免
stats.json 预计算训练时归一化不用重新扫全集
注意 stats.json

如果你修改了数据（增删 episode、改了动作空间），必须重新生成 stats.json。过时的归一化统计量是训练失败的常见隐性原因——模型看到的数值范围和它认为的不一致。

数据从哪里来：采集流水线

一条 episode 的诞生过程，从操作员的手开始：

数据采集流水线：人 → 遥操 → 执行 → 录制 → 质检

采集数据不只是"录一段视频"。需要同时记录图像、关节状态、动作指令，并确保它们在时间上对齐。一次质量合格的采集通常需要：

1. 采集前

确定任务定义、动作空间、相机位置。写清楚"什么算成功"。用几条试录验证硬件。

2. 采集中

操作员按协议执行任务，每条 episode 独立标记成功/失败。保持一致性。

3. 采集后

回放录像检查质量，删除明显失败的 episode。生成 stats.json、拆分训练/验证集。

4. 格式化

转换为 LeRobot v2 格式。上传到 Hugging Face Hub 或本地存储。填写 dataset card。

常见数据格式一览

不同的机器人学习项目用了不同的数据格式。核心差异在于"数值数据怎么存"和"图像怎么存"：

格式数值存储图像存储代表项目特点
LeRobot v2 Parquet MP4 视频 Hugging Face LeRobot 当前社区主流，空间效率高
HDF5 HDF5 dataset HDF5 中的数组 robomimic, ACT 单文件包含一切，读取灵活
RLDS/TFDS TFRecord TFRecord 中的字节 Open X-Embodiment Google 生态，适合大规模
Zarr Zarr arrays Zarr 中的数组 Diffusion Policy 按 chunk 分块，适合流式访问
原始文件 CSV / JSON PNG / JPEG 序列 早期项目 最容易理解，但效率最低
选哪个？

如果你刚开始学，用 LeRobot。它有完善的工具链（录制、可视化、训练、上传），社区支持最活跃。只有在对接已有项目时才需要其他格式——到时候可以用 Any4LeRobot 工具做转换。

一条完整 Episode 的故事

让我们用一条实际的 episode 把所有概念串起来。这是一条 "抓起红色方块" 的示教：

Episode #12 完整时间线
t=0.00s 机械臂在初始位置，夹爪张开。方块在桌面左侧。 t=0.20s 臂开始向左移动，靠近方块。action 主要是 x/y 方向的位移。 t=0.74s ← 就是上面那个 step #37。臂已经很靠近方块了。 t=1.10s 末端降低到方块高度，开始对准抓取姿态。 t=1.30s 夹爪闭合！action[-1] 从 0.0 变成 1.0（闭爪指令）。 t=1.50s 确认抓住，开始抬起。action 的 z 分量变正。 t=2.00s 移向篮子上方。 t=2.20s 夹爪松开，方块落入篮子。 t=2.40s Episode 结束。 done=true, success=true。共 120 帧。

这 120 帧数据，就是模型要学习的"教材"。模型的目标：对于任何一帧，给定当时的图像和关节状态，预测操作员在那一刻的动作。学会了，就能自己执行"抓红色方块"。

带走这几件事

总结
  1. 一条 step = 那一瞬间的观测 + 动作 + 标记。是训练的最小单位。
  2. 一条 episode = 一次完整的任务尝试。有成功有失败，每条独立。
  3. 观测不只是图像——还有关节状态、力觉、语言指令等多种模态。
  4. 动作空间有多种选择——关节位置、末端位姿、增量速度，选择影响学习难度。
  5. 数据质量 > 数据数量——100 条高质量示教 > 1000 条对齐混乱的数据。
  6. 时间对齐是命门——观测和动作错开一帧，模型在真机上就会反应迟钝。
