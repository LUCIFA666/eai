04 感知 > 可视化概念指南

感知系统：看图学概念

相机、点云、检测分割、手眼标定——一步步看懂机器人的"眼睛"。

你让朋友帮你拿桌上的红色杯子。朋友会怎么做？先"看到"杯子在哪里，再判断怎么伸手过去。机器人也一样——但它的"看到"背后，藏着一条从像素到 3D 坐标的完整链路。这条链路上任何一环出错，最终都会表现为"抓不准"或"抓错了"。

这一页用图来解释这条链路上的核心概念。不需要你有计算机视觉的基础——只需要知道图片是由像素组成的就够了。

1. 小孔成像：从 3D 世界到 2D 像素

相机最基本的数学模型叫针孔模型（Pinhole Model）。它描述了一个简单的事实：3D 世界中的一个点，通过镜头，会落在图像传感器上的某个像素位置。

针孔相机模型：3D 点通过镜头投射到 2D 传感器平面

这里面有 4 个关键数字，合称相机内参：

fx, fy（焦距）

以像素为单位的焦距。它决定了"看到的范围有多宽"——焦距大，视野窄但远处更清楚；焦距小，视野宽但放大倍率低。

cx, cy（主点）

图像中心的像素坐标。理想中是正中央，但真实镜头总是有点偏。如果主点标错了，所有 3D 点都会向一个方向系统性偏移。

类比
想象你用手机拍一张桌面照片。焦距决定了你"站多远"才能把整个桌面拍全；主点决定了照片有没有"歪"。内参就是手机镜头出厂时固有的参数——换了手机，参数就变了。

反过来：从像素到 3D

机器人不是要拍照——它需要知道杯子在真实世界中的位置。所以要反过来算：

X = (u - c_x) × Z / f_x
Y = (v - c_y) × Z / f_y
Z = depth(u, v)          ← 来自深度相机

注意：没有深度值 Z，像素只能告诉你方向，无法告诉你距离。这就是为什么机器人通常需要 RGB-D 相机（同时拍颜色和深度）。

2. 从 RGB-D 图像到点云

RGB-D 相机每一帧输出两张图：一张彩色图（RGB），一张深度图（Depth）。把每个像素用上面的公式反投影，就得到了点云——一堆 3D 点，每个点有位置和颜色。

RGB + Depth + 内参 → 相机坐标系点云 → 经外参变换 → 机器人坐标系点云

新手最常犯的错
深度单位搞错了。很多相机输出深度单位是毫米（mm），但你的代码假设是米（m）——结果所有点云都被放大了 1000 倍。永远检查 depth_scale！

点云不是拍完就能用

原始点云通常有几十万个点，里面包含大量无用信息（桌面、背景墙、噪声）。在送给规划器之前，需要一系列清洗步骤：

去掉无效深度 → 体素降采样 → 工作空间裁剪 → 去桌面平面 → 去离群噪声点
步骤做什么为什么
去无效深度过滤 depth = 0、NaN、太近或太远的像素深度相机对反光、透明物体经常丢失深度
体素降采样把空间分成小立方体（如 5mm），每个格子只保留一个点减少点数，降低计算量，同时平滑噪声
工作空间裁剪只保留机器人能到达的区域内的点远处的背景对抓取没有意义
去桌面平面用 RANSAC 检测并移除最大平面桌面点太多，会淹没物体的点
去离群噪声删除周围邻居太少的孤立点它们通常是传感器噪声，不是真实物体

3. 检测 vs 分割：找到物体的不同方式

有了点云，下一个问题是：哪些点属于"我要拿的那个杯子"？这就要靠检测和分割来回答。

四种视觉识别方式的输出对比

机器人抓取为什么需要实例分割？
想象桌面上有三个杯子。语义分割会把它们全标成"杯子类"，你分不清哪些像素属于哪个杯子。但实例分割能区分"杯子 #1""杯子 #2""杯子 #3"——用这个 mask 去裁剪点云，就能得到单独一个杯子的 3D 形状，这才是抓取规划需要的输入。

4. 完整感知管线：从拍照到告诉机器人"在哪抓"

把前面的步骤串起来，就是一条完整的感知管线。让我们以"抓桌上的红色杯子"为例，走一遍全流程：

从一帧 RGB-D 图像到"杯子在哪里"的完整管线

一条真实的感知输出长什么样？

管线最终会输出一份结构化数据，交给下游的规划器或抓取策略使用：

感知输出 — "红色杯子" (object_id: cup_03)
frame robot_base ← 坐标系必须写清楚，否则规划器不知道数字是什么含义
timestamp 2026-05-25T14:32:01.123Z ← 拍摄时刻，判断数据是否过期
position [0.42, -0.15, 0.03] m ← 杯子中心在 base frame 下的 XYZ
orientation [0.0, 0.0, 0.38, 0.92] (quaternion) ← 杯口朝哪个方向
confidence 0.87 ← 检测置信度，低于阈值时应该拒绝动作
symmetry axial_z ← 杯子绕 Z 轴旋转对称，yaw 角不可信
mask_coverage 0.72 ← mask 覆盖了多少有效深度，太低说明遮挡严重
failure_code none ← 可能的值：depth_hole, occlusion, low_confidence, calibration_stale
为什么需要 failure_code？
机器人不能像人一样"感觉不确定就多看一眼"。如果感知输出看起来正常但其实不靠谱（比如反光导致深度全是空洞），机器人会自信地抓向一个不存在的位置。failure_code 让系统可以提前拒绝不可靠的结果，而不是等到抓空了才发现问题。

5. 手眼标定：让相机和机器人说同一种"话"

假设相机看到杯子在图像右下角，深度 0.5 米。经过反投影，你得到了杯子在相机坐标系下的位置——但机器人不认识"相机坐标系"，它只懂自己的基座坐标系。

手眼标定就是找到这两个坐标系之间的"翻译关系"（一个 4×4 变换矩阵）。

两种手眼标定设置——区别在于相机装在哪里

Eye-in-Hand

相机跟着手动。相机装在手腕/末端上，随机器人一起移动。适合近距离精细操作，但视野随姿态变化。

要标定的是：相机 → 夹爪 的变换

Eye-to-Hand

相机从外面看。相机固定在三脚架或桌面上，不随机器人移动。视野稳定，但当手遮挡物体时就看不到了。

要标定的是：相机 → 机器人基座 的变换

最容易搞反的地方
T_camera_gripper 和 T_gripper_camera 是互逆的。用错了方向，所有 3D 点都会出现在镜像的位置。如果发现机器人总是朝反方向动作——大概率是变换矩阵用反了。

标定质量怎么判断？

只看重投影误差（reprojection error）不够。真正的检验方法很直接：

检查方式怎么做通过标准
重投影误差 把 3D 标定点投回图像，看偏了多少 < 0.5 像素
3D 一致性 机器人移到不同位姿，同一个桌角的 base frame 坐标应该不变 偏差 < 3mm
抓取验证 让机器人根据视觉结果去碰一个已知位置的物体 到位偏差 < 5mm
重启稳定性 关机重启后重测上面三项 结果不变

6. 深度相机的"坑"：为什么有些东西看不到

初学者经常把深度相机想象成完美的 3D 扫描仪——实际上它在很多情况下会"失明"：

不同材质对深度相机的影响——并不是所有东西都能被"看到"

这就是为什么感知输出需要 failure_code 和 mask_coverage：当深度空洞覆盖了目标物体的大部分面积时，系统应该主动拒绝这次观测，而不是用残缺的点云去估计一个不靠谱的位姿。

7. 坐标系链路：为什么所有东西都必须写 frame

一个机器人系统里同时存在很多坐标系。这个概念在 机器人基础 里有详细图解，这里我们只看感知相关的部分：

Eye-in-Hand 设置下的坐标系链路——每个箭头都是一个变换矩阵

坐标系的"黄金规则"
任何 3D 数据，不写 frame 就是废数据。一个点 (0.3, -0.1, 0.5) 在 camera frame 和 base frame 下指向完全不同的物理位置。把 camera frame 的数字当 base frame 用，机器人会撞到桌子。

总结：感知链路的核心检查清单

无论你的项目用什么硬件和模型，在把感知结果交给下游之前，检查这几件事：

#检查项常见失败原因
1内参是否正确且匹配当前分辨率缩放图像后忘了同步缩放内参
2深度单位是否正确（m vs mm）点云比真实世界大 1000 倍
3点云坐标系是否是 base frame相机坐标系的数据被当成 base frame 使用
4手眼标定是否有效相机支架动了、线缆拉扯了但没有重新标定
5mask 和 depth 是否对齐RGB 裁剪了但 depth 没有，或两者分辨率不同
6深度空洞是否被标记反光/透明物体的空洞被当成有效深度
7位姿的 frame 方向是否写清楚T_camera_object 和 T_object_camera 用反了
8时间戳是否在容忍范围内相机延迟大，图像和机器人状态不同步
一句话总结
机器人感知 = 相机内参（像素 ↔ 射线）+ 深度（射线 → 3D 点）+ 分割（哪些点是目标）+ 外参标定（3D 点在哪个坐标系）+ 质量检查（结果可不可信）。任何一环缺失或出错，下游都会失败。
