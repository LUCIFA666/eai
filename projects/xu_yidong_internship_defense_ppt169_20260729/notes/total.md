# 02-outcome

我的实习产出可以分成四层：先建立世界模型的知识地图，再完成 DINO-WM、LeWM、Δ-IRIS 和 TD-MPC2 的复现链路，然后用成功率、回报、训练进度、MAE 和 PSNR 记录结果与边界，最后把提交版本、环境、脚本、日志、哈希和报告整理成证据交付。这里最重要的是，每个结论都能回到具体的运行口径和落盘结果，而不是只保留一次成功截图。我的自动化专业背景、专业第一的课程基础，以及对具身智能、VLA 和机器人系统的兴趣，为后续研究迁移提供了基础。

# 03-routes

这四条路线的差异可以用两个问题统一：预测什么，以及如何把预测接入决策。Dreamer 类方法预测像素或潜变量并进行想象式策略学习，DINO-WM 和 LeWM 直接预测视觉特征并做目标匹配，IRIS 类方法预测离散 token 的随机动态，TD-MPC2 则学习面向 reward 和 value 的控制潜变量。我的统一验收问题是：这个预测表示是否保留了对控制真正有用的信息；这也解释了为什么世界模型不一定需要重建逼真的像素。

---

# 04-dino-wm

DINO-WM 的结果说明，预训练视觉特征可以直接成为规划空间。在固定版本、固定随机种子和有界评估口径下，PointMaze 成功率为一点零，PushT 五十次成功四十三次，成功率百分之八十六，Wall 五十次成功四十七次，成功率百分之九十四；页面底部同时给出了完整曲线和 Wilson 置信区间。我完成了版本固定、MuJoCo EGL 兼容修复、运行与统计脚本封装，并用五轮上限构造可重复的五十次评估。我的理解是，只要特征空间保留了适合目标匹配的几何结构，就可以直接定义规划代价，而不必先恢复每一个像素。

---

# 05-lewm

LeWM 使用更紧凑的 JEPA 目标：预测损失负责下一嵌入的可预测性，SIGReg 用于避免表示坍塌，规划时直接比较预测终点嵌入与目标嵌入的距离。使用官方权重完成五十个 Push-T episode 的 MPC 评估后，成功四十八次，成功率百分之九十六，耗时三百六十三点六二秒。我进一步验证了权重哈希与严格加载、编码器和动作接口、损失可反传、两套数据加载接口、MPC 候选代价，以及短训练后的 checkpoint 回载。这个结果证明的是整条推理和训练接口可用；它没有把官方权重的性能误写成我从头训练得到的性能。

---

# 07-delta-understanding

这页区分两个容易混淆的实验。上方 tokenizer 条件重建的 MAE 为零点零零零四三七八六，PSNR 为五十七点五八九二分贝，但编码器看到了真实下一帧，所以它验证的是压缩和重建质量，不是未来预测。下方 world model 单步想象的 MAE 为零点零零三五八七四三，PSNR 为三十点四六五四分贝，生成时不再输入真实下一帧，因此才是条件预测证据。我的理解是，随机实体位置的误差应该通过条件分布来解释，同一历史和动作可能采样出不同的 Δ-token；报告时应展示典型误差与分布，而不是只挑最好看的一张图。

---

# 08-tdmpc2

TD-MPC2 展示了另一种更直接的控制观点：世界模型只需预测对控制有用的信息。策略先验和 MPPI 或 CEM 采样动作序列，模型在潜空间累积短期 reward，并用 terminal Q 补足有限 horizon 之外的价值，最后只执行优化序列的第一步并滚动重规划。官方 dog-run checkpoint 的单 episode 回报为七百六十二点二；我自己的训练在十五万四千步时回报为一百三十四，十五万一千步附近最高为一百五十七点三。十万步量级仍然只能证明训练链可用，正式复现应接近七百万步并报告多随机种子；我认为规模化难点还包括潜表示稳定性、reward 与 value 尺度、Q 过估计和多任务接口。

---

# 09-judgments

跨四条路线，我形成了三条可以迁移的判断。第一，表征不等于重建，DINO-WM 和 LeWM 说明特征几何可以直接支持目标匹配；第二，预测不等于一张图，Δ-IRIS 提醒我们应报告随机未来的分布和边界；第三，规划不等于无限延长 rollout，TD-MPC2 用短期模型、terminal Q 和策略先验形成了可扩展闭环。因此，好的世界模型应同时具备任务相关表示、可校准的不确定性和实际闭环决策价值，最终仍要回到成功率、回报、稳定 rollout 和泛化能力。

---

# 10-engineering

为了让复现从一次运行变成可追溯证据，我形成了七步流程：固定代码提交、隔离环境、执行 CUDA 和 EGL 探针、运行最小 smoke、严格加载 checkpoint、进行有界或正式评估，最后交付脚本、日志、哈希和图表。版本漂移通过固定提交和依赖清单处理，无显示器服务器问题通过 MuJoCo EGL 探针处理，评估语义混淆则通过明确区分 smoke、官方权重和从头训练来处理。这个方法的验收标准是，每个结论都能指向命令、日志、指标或落盘产物，使其他人可以复核。
