# 项目选型模板

本页给项目报告写仿真平台选择理由的模板。选型不能只写“Genesis 新、快、支持多物理”，而要从任务需求倒推。

## 本节目标

本节围绕下面几个问题展开：

1. 项目选型理由应该包含哪些维度？
2. 如何说明任务为什么需要 Genesis？
3. 如何承认版本、复现、性能和调试成本？
4. 如何把 Genesis、MuJoCo、Isaac Sim / Isaac Lab 的选择写得有依据？

## 基础模板

项目报告可以用下面这段作为选型说明：

```text
本项目选择 _______，因为任务主要需要 _______。
本项目不选择 _______，是因为当前任务暂时不需要 _______。
本项目第一阶段最需要验证的是 _______。
项目将保存 _______ 作为运行证据。
如果后续扩展到 _______，可能会重新考虑 _______。
```

## Genesis 项目示例

```text
本项目选择 Genesis，因为任务主要需要比较刚体和布料对象交互。
本项目不选择 MuJoCo，是因为当前任务需要非刚体形变，而不仅是刚体接触。
本项目不选择 Isaac Sim，是因为第一阶段暂时不需要 RTX 级传感器和 ROS 2 集成。
本项目第一阶段最需要验证的是布料接触是否稳定、参数是否可复现。
项目将保存运行日志、summary.json、预览图、动态素材视频和 solver/material 参数作为运行证据。
如果后续扩展到高保真合成数据，可能会重新考虑 Isaac Sim。
```

## 证据要求

选型说明最好引用真实运行证据：

| 证据 | 示例 |
|---|---|
| 官方示例 | `physics_09_pbd_cloth`、`physics_12_cloth_on_rigid` |
| 本地运行目录 | `runs/<genesis-showcase-run>/`，或随书发布的稳定证据目录 |
| 状态说明 | `STATUS.md` 中的 adapter、proxy、短帧数或 GUI 依赖 |
| 风险记录 | adapter、依赖、失败日志、参数敏感点 |
| 第一阶段验收 | 先跑单对象，再跑耦合，再加机器人 |

这样写出来的选型理由会更像工程判断，而不是平台宣传。

## 选型审查清单

写完模板后，用下面的清单自查。只要有两项以上答不上来，说明选型理由还不够扎实：

| 问题 | 应该能给出的证据 |
|---|---|
| 任务为什么需要这个平台？ | 具体物理对象、传感器、训练接口或工程生态 |
| 第一阶段最小验收是什么？ | 一个可运行脚本、一份 `summary.json`、一张预览图；动态过程再加一个视频 |
| 哪些风险已经暴露？ | 依赖、版本、adapter、GUI 限制、性能瓶颈 |
| 替代平台为什么暂时不选？ | MuJoCo、Genesis、Isaac Sim / Isaac Lab 的对比理由 |
| 后续何时重新选型？ | 需要高保真传感器、ROS 2、标准 RL 框架或更成熟 benchmark 时 |

## 更完整的填写示例

```text
任务：机械臂拨动颗粒堆，并观察末端轨迹和颗粒响应。
首选平台：Genesis。
理由：任务涉及刚体机械臂和颗粒介质耦合；`physics_05_sand_wheel`
和 `physics_13_rigid_mpm_attachment` 只能证明颗粒 / MPM 与刚体耦合现象可作为入口。
第一阶段验收：先跑单独 MPM / sand 示例，再另存简化机械臂脚本的 summary、log、控制参数和颗粒响应，不开 Nyx，不开并行训练。
证据：保存 `logs/`、`summaries/`、`previews/`、`videos/` 和 solver/material 参数。
风险：MPM 参数、时间步、GPU 显存和可视化角度可能影响结果。
暂不选 MuJoCo：任务核心不只是刚体接触；若第一阶段只做机械臂和刚体物体基线，应先保留 MuJoCo 对照。
暂不选 Isaac Sim：第一阶段不需要 ROS 2、USD 场景和 RTX 级合成数据。
重新评估条件：如果后续要生成高保真视觉数据集，再评估 Isaac Sim。
```

如果阶段素材本身是静态渲染图，例如某些 Nyx 材质或灯光示例，就不要强行要求 `videos/`。这类条目更应该检查 `previews/`、`summaries/`、`logs/` 和原始输出是否齐全。

## 最低证据要求

项目报告可以按下面四项检查，不需要复杂打分，但每一项都应该有证据：

| 维度 | 合格表现 |
|---|---|
| 任务需求 | 能说清楚需要刚体、多物理、传感器、并行环境还是任务框架 |
| 平台对比 | 至少解释 Genesis、MuJoCo、Isaac Sim / Isaac Lab 中两个平台的取舍 |
| 运行证据 | 有 `logs/`、`summaries/`、`STATUS.md`、预览图；动态素材有视频，不只是一张截图 |
| 风险说明 | 写出版本、依赖、adapter、GUI、性能或参数敏感点中的至少一类 |

如果一个项目选择 Genesis，却没有引用任何 Genesis 本地运行目录或官方 showcase 条目，这份选型说明还不够。反过来，如果项目能把 `physics_05_sand_wheel`、`sim_06_lidar`、`render_03_nyx_attached_camera` 这类素材和任务风险对应起来，就说明它真的在用运行证据做判断。

## 读完应能回答

1. 一份 Genesis 选型说明至少要写清哪几类任务需求？
2. 为什么“Genesis 支持多物理”不能单独作为选型理由？
3. 如果项目暂不选择 MuJoCo 或 Isaac Sim / Isaac Lab，应该引用什么证据说明取舍？

## 小结

- 选型模板要同时写任务需求、替代平台取舍、第一阶段验收和风险说明。
- “选择 Genesis”必须能落到具体素材、具体 `runs/` 目录和具体证据文件。
- 静态渲染条目不必强行要求视频，但必须保留 preview、summary、log 和原始输出。
