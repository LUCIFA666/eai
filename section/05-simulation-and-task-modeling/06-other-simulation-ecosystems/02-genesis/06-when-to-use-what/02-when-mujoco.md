# 什么时候继续用 MuJoCo

本页讲为什么很多刚体控制、接触调试、RL 原型和可复现实验仍然适合继续用 MuJoCo。

## 本节目标

本节围绕下面几个问题展开：

1. MuJoCo 在刚体机器人动力学上有哪些稳定优势？
2. 什么任务不需要 Genesis 的多物理能力？
3. 为什么基础部分仍然应该保留 MuJoCo？
4. 如何避免把“新平台”误当成“总是更好”？

## 继续用 MuJoCo 的情况

如果任务主要是刚体动力学和控制，MuJoCo 仍然是很稳的选择：

| 任务 | 为什么 MuJoCo 合适 |
|---|---|
| 关节、actuator、contact 入门 | 概念成熟，反馈直接 |
| 简单机械臂抓取 | 资产和调参路径清晰 |
| RL 原型 | Gymnasium、dm_control、MJX 等生态成熟 |
| CI / 自动化测试 | 轻量、可复现、依赖少 |

Genesis 的多物理能力很宽，尤其适合 MPM / SPH / FEM、多材料耦合和复杂非刚体探索。但如果任务的核心仍是刚体控制，或者小规模布料 / 软体基准已经能被 MuJoCo 的 deformable / flex 能力覆盖，Genesis 的宽能力也可能变成额外排错面。

## 继续用 MuJoCo 的信号

如果项目说明里写不出“为什么必须要 Genesis 的哪一类物理对象”，就先不要急着换。下面这些信号通常说明 MuJoCo 更合适：

| 信号 | 解释 |
|---|---|
| 任务对象都是刚体 | 多物理能力不会带来核心收益 |
| 主要问题是 actuator、friction、contact 调参 | MuJoCo 的模型和调试路径更直接 |
| 需要长期稳定的脚本 | 依赖少、启动快、CI 更容易 |
| 需要和已有 Gymnasium / dm_control 代码衔接 | 现成生态成本低 |
| 论文基线已经在 MuJoCo | 不必为了平台新鲜感增加变量 |

这不是否定 Genesis，而是让工具承担正确的任务。稳妥的学习路线应该先在 MuJoCo 里建立刚体接触和控制直觉；当任务确实需要更宽的多物理对象、多 solver 耦合或批量仿真 API 时，再解释 Genesis 为什么值得引入。

## 从 Genesis 回退到 MuJoCo

项目推进中如果发现以下情况，可以主动回退到 MuJoCo 做最小对照：

1. Genesis 场景失败，但还不确定是机器人资产、控制器还是多物理对象的问题；
2. 训练结果不稳定，无法判断是算法问题还是仿真平台问题；
3. 只需要一个刚体基准来对比多物理扩展前后的差异。

回退不是倒退，而是建立基线。没有基线，就很难证明 Genesis 带来的复杂度是值得的。

## 用证据做反向决策

选 MuJoCo 不是因为 Genesis 不行，而是因为某些证据会说明“当前还不需要更复杂的平台”。可以按下面这样反向判断：

| 手头证据 | 更合理的动作 |
|---|---|
| 只需要 `Plane + robot + cube`，没有多材料耦合或复杂非刚体交互 | 先用 MuJoCo 建刚体基线 |
| 主要问题是关节控制、摩擦、接触参数 | 先在 MuJoCo 里把动力学和控制调清楚 |
| Genesis showcase 里能引用的只有刚体条目 | 不要把平台切换当成研究贡献 |
| 项目报告里写不出 Physics 03-17 哪类多物理能力有用 | 暂时不必引入多物理复杂度 |
| 需要 CI、共享机器、低依赖安装 | MuJoCo 的轻量性通常更合适 |

反过来，如果能明确引用 `physics_05_sand_wheel`、`physics_09_pbd_cloth`、`physics_12_cloth_on_rigid` 或 `physics_15_water_wheel` 这类素材，并说明任务为什么需要颗粒、布料、刚柔耦合或流体，再考虑 Genesis 就更有根据。

## 读完应能回答

1. 一个抓方块任务在什么情况下仍然应该先用 MuJoCo？
2. 一个抓布料任务在什么情况下可以先核对 MuJoCo deformable / flex，又在什么情况下更适合转向 Genesis？
3. 如果选择 Genesis，但项目证据里没有任何多物理条目，这个选型理由哪里薄弱？

## 基准工具仍然重要

本章保留 MuJoCo，不是因为它更新潮，而是因为它适合建立基础直觉。先在 MuJoCo 理解关节、接触、控制和可复现，再去看 Genesis 的多物理扩展，会更稳。

## 小结

- MuJoCo 仍然适合刚体动力学、接触调参、控制和轻量可复现原型。
- 如果项目证据里没有多物理、复杂传感器或批量环境需求，不必急着切到 Genesis。
- 回退到 MuJoCo 建基线，是判断 Genesis 复杂度是否值得的工程动作。
