# 非刚体实验为什么难验收

本页讲软体、布料、颗粒和流体实验的验收困难。非刚体对象不能只看“动起来了”，还要检查形变、稳定性、参数、图像和状态记录。

## 本节目标

本节围绕下面几个问题展开：

1. 非刚体对象的状态为什么比刚体更难记录？
2. 图像看起来合理是否足够？
3. 参数、时间步和分辨率变化会怎样影响结果？
4. 项目报告中怎样写非刚体实验的验收标准？

## 为什么刚体好验收

刚体对象通常可以用少量状态描述：位置、姿态、线速度、角速度，机器人再加关节位置和速度。验收时可以问：

- 物体是否落到合理高度；
- 机器人关节是否达到目标；
- 接触是否稳定；
- 相机是否看到目标。

非刚体不一样。布料是一片网格或粒子集合，流体是一团不断变化的粒子，软体可能有内部形变状态。很难用一个 `pos` 概括它。

## 非刚体要多看几层

非刚体验收至少要分四层：

| 层 | 要看什么 |
|---|---|
| 运行层 | 脚本是否完成、是否有 exception、是否需要可选依赖 |
| 数值层 | 是否 NaN、粒子是否飞散、形变是否爆炸 |
| 物理层 | 现象是否符合材料直觉，例如布不会像刚板一样 |
| 记录层 | 是否保存参数、图像、视频、状态摘要和日志 |

官方 showcase 中的 `physics_11_ipc_cloth_teleop` 是一个很好的警示案例：如果只看最后视频，就会错过运行过程中的依赖和 material adapter。非刚体示例的“成功”不只是生成画面，还包括依赖、材料、求解器和参数都被记录下来。

本页只挑四类最容易被误判的运行证据，作为非刚体验收的提醒：

| 示例 | 运行现象 | 证据解释 |
|---|---|---|
| `physics_10_smoke` | 75 帧通过，但 summary 标明 slice output resized and centered | 可作为烟雾素材，但要说明它经过裁切、缩放和居中处理 |
| `physics_16_flush_cubes` | 捕获 100 帧 | 耦合现象重点看过程是否稳定，捕获帧数随示例步数变化，不必和其他示例对齐 |
| `physics_17_sap_franka_grasp_rigid_cube` | 捕获 65 帧 | 高级接触 / 抓取示例更适合当能力索引，重点看接触和抓取是否真的发生 |
| `physics_11_ipc_cloth_teleop` | 75 帧通过，但使用 plane material adapter | “通过”要和 adapter 说明一起读 |

这说明多物理素材的验收不是把所有示例压成同一种格式。证据目录要保留差异：有的是可用短片，有的是能力索引，有的是带 adapter 的运行。判断这些差异时，先看 `STATUS.md` 和 summary，再决定它应该进入正文、脚注、实验报告，还是只作为排错记录保留。

## 一张非刚体验收清单

做项目报告时，可以把下面这张表直接放进实验记录：

| 检查项 | 记录方式 |
|---|---|
| Genesis / 插件版本 | `summary.json` 或 `STATUS.md` |
| solver family | `Rigid / FEM / MPM / SPH / PBD / IPC / SAP` |
| 材料参数 | density、stiffness、friction、coupling notes |
| 时间步 | `dt`、`substeps`、总 step 数 |
| 分辨率 / 粒子数 | 网格尺寸、粒子数量或采样密度 |
| 初始条件 | 对象位置、尺寸、边界约束 |
| 输出证据 | 预览图、视频、日志、摘要 |
| 失败说明 | exception、adapter、依赖缺失或不稳定现象 |

不要只写“实验成功”。写清楚“在什么参数下成功”，才是可复现。

## 证据判读

读一份非刚体运行记录时，可以用下面几题检查是否真的看懂了：

| 看到的证据 | 不能直接得出的结论 | 还要补什么 |
|---|---|---|
| 有一张好看的布料截图 | 物理一定可信 | 参数、时间步、日志、是否穿透 |
| `result: passed` | 原脚本无条件通过 | 是否有 adapter、proxy、额外依赖 |
| `captured_frames: 4` | 示例失败 | 先看 `STATUS.md`，它可能只是短帧数能力索引 |
| `error: null` | 没有任何风险 | warning、材料边界、求解器参数仍要读 |
| contact sheet 中一格清晰 | 可以直接训练策略 | 还要看原始状态、传感器输出和任务接口 |

这组判读的核心是：非刚体素材的证据必须多源交叉。截图、summary、日志、参数和 `STATUS.md` 少了任意一项，结论都要保守一些。

## 图像合理不等于物理可信

渲染图像有时会让问题看起来比实际更稳定。比如：

- 粒子数量太少，但远景图看不出来；
- 布料有轻微穿透，但相机角度遮住了；
- 流体边界不合理，但画面仍然像水；
- 后处理图很清楚，但原始传感器数据并不是这个格式。

因此，图像是证据之一，不是全部证据。尤其在多物理里，最好同时保存状态摘要和参数。官方 showcase 的 contact sheet 适合做视觉索引，但真正排错要回到 `logs/` 和 `summaries/`。

## 参数变化要小步做

非刚体实验的排错策略是一次只改一个变量：

1. 先跑官方示例，不改对象和参数；
2. 再改相机或记录方式，不改物理；
3. 再改材料参数，不改时间步；
4. 再改时间步或分辨率；
5. 最后再加机器人控制、传感器或并行环境。

如果同时改材料、时间步、相机、机器人和后端，失败时几乎无法定位。多物理实验最需要耐心，不是蛮力。

## 读完应能回答

1. 非刚体为什么不能只用一张好看的截图验收？
2. `result: passed`、adapter 和短帧数之间应该怎样一起解释？
3. 修改材料、时间步、相机和机器人控制时，为什么要一次只改一个变量？

## 小结

- 非刚体对象不能用一个位姿概括，验收要看形变、粒子、约束和稳定性。
- 图像是证据之一，但必须结合日志、摘要、参数和原始状态。
- `STATUS.md` 里记录 adapter 和失败原因，是多物理证据的一部分。
- 做项目报告时，非刚体验收清单比一段展示视频更有价值。
