# Depth Anything 与单目深度模型

> 难度：[中级] | 预计用时：75 分钟
> 先修：[DINO 与 DINOv2](02-dino-and-dinov2.md)
> 阅读提示：本页重点是“单张 RGB 如何补几何”，和 [RGB-D 与点云](../01-geometric-perception-foundations/03-rgbd-pointcloud.md) 配合阅读效果最好。

目标：讲清 Depth Anything 这一类单目深度基础模型能提供什么、不能提供什么，以及为什么深度图只有经过校验和坐标变换后，才真正变成机器人可用的几何信息。

## 先建立直觉

如果只看一张 RGB 图像，系统很容易知道“杯子在图像左侧”，却很难直接知道：

- 它离相机 20 cm 还是 80 cm
- 它是不是比旁边的碗更近
- 它的顶部是不是适合当前抓取高度

因此，深度基础模型解决的核心问题是：

**给二维图像补上距离这一维。**

## 什么是单目深度，并立刻接例子

单目深度指的是：

**只看一张 RGB 图像，就估计每个像素离相机有多远。**

立刻看例子：

- 同一张桌面图像里，模型可能判断杯子前缘比桌后墙面更近
- 也可能给出杯口、桌面、背景三者的距离层次

这类能力的价值在于：  
即使没有真实 RGB-D 相机，也能先补出一份几何先验。

## 相对深度是什么，并立刻接例子

相对深度更擅长回答：

**谁更近，谁更远。**

例如：

- 模型判断“杯子比墙更近”
- 模型判断“把手比抽屉内壁更靠前”

但它未必能可靠回答：

- 杯子距离相机究竟是 `0.32 m` 还是 `0.41 m`

因此，相对深度适合做粗排序、场景层次理解和几何先验，不适合直接拿去当执行真值。

## 度量深度是什么，并立刻接例子

度量深度尝试直接输出接近米制尺度的深度值。

例子如下：

- 对桌面场景输出一张深度图，其中杯口附近约为 `0.48 m`
- 桌面平面约为 `0.52 m`

这比相对深度更接近机器人需要的量，但仍然不能盲信。  
换场景、换材质、换相机后，尺度仍然可能漂移。

## Depth Anything 这一类模型在做什么

Depth Anything 这一类模型的核心价值，是把大规模单目深度先验做得更通用、更稳定。  
从本章角度，只需要抓住三点：

- 它输入的是单张 RGB 图像
- 输出的是一张深度图或接近深度的几何先验
- 它特别适合在没有真实深度传感器时补一份距离信息

把术语和例子接起来看：

- 没有 RGB-D 相机时，可以先用它判断场景前后关系
- 有检测或分割结果后，可以把目标区域和深度图结合，恢复对象级几何候选

## 为什么 RGB 本身不够，并立刻接公式

RGB 图像里只有像素位置，没有绝对距离。  
如果已知：

- 像素坐标 `(u, v)`
- 深度值 `z`
- 相机内参 `fx, fy, cx, cy`

就能把像素反投影到相机坐标系：

```text
x = (u - cx) * z / fx
y = (v - cy) * z / fy
z = depth(u, v)
```

术语刚出现后立刻接结论：

- 深度图只是几何原料
- 反投影之后才得到可进入 3D 系统的点

## 深度图和点云不是一回事

深度图：

- 以像素网格为组织方式
- 每个像素存一个深度值

点云：

- 以 3D 点集合为组织方式
- 每个点至少有 `(x, y, z)`

立刻接一个例子：

- 一张 `640 x 480` 的深度图可以反投影出许多 3D 点
- 但在点云里，这些点已经不再按原像素网格组织，而是按几何坐标存在

这就是为什么机器人系统里真正进入 3D 几何处理的，常常是点云而不是原始深度图。

## `rgbd_to_pointcloud.py` 里最值得看的是什么

运行：

```bash
python labs/04-perception/rgbd_to_pointcloud.py
```

这份脚本的重点不在保存 `PLY` 文件，而在下面这段最小逻辑：

```python
x = (u - CX) * z / FX
y = (v - CY) * z / FY
xyz = np.stack([x, y, z], axis=1)
```

这就是从“图像里的深度”走向“几何系统里的点”的关键一步。

## 为什么单目深度不能直接当执行真值

这部分必须讲透，因为初学者最容易在这里过度乐观。

| 场景 | 可能表现 | 风险 |
|---|---|---|
| 判断哪个物体更近 | 通常还不错 | 适合粗排序 |
| 精确抓取高度 | 常有系统偏差 | 高度会整体偏高或偏低 |
| 透明、反光表面 | 容易失真 | 几何结果不可靠 |
| 跨场景切换 | 尺度可能漂移 | 历史阈值失效 |

因此更稳妥的说法是：

**深度模型给出的是几何候选，而不是自动可执行真值。**

## 机器人真正关心哪些质量检查

单目深度要进入机器人链路，至少要补几类检查：

- `valid_depth_ratio`：目标区域里有多少像素真的有有效深度
- `scale_check`：深度尺度和已知物理量是否一致
- `frame_id`：结果处在哪个坐标系
- `staleness_ms`：这份结果是不是已经过时
- `failure_code`：失败是来自空洞、漂移还是尺度异常

也就是说，真正可交给下游的不是“一张看起来很平滑的深度图”，而是一份带质量说明的几何 observation。

## 一份更合理的对象级记录

```yaml
object_3d_observation:
  object_id: mug_01
  depth_source: monocular_depth_anything
  frame_id: panda_link0
  centroid_xyz_m: [0.43, -0.11, 0.08]
  valid_depth_ratio: 0.81
  scale_check: review_required
  failure_code: null
```

这份记录强调的不是“模型名字”，而是：

- 深度来自哪里
- 几何量是否已经能进入机器人坐标系
- 当前质量是否足以继续下游处理

## 常见误解

| 误解 | 为什么错 |
|---|---|
| “有深度图就等于有点云” | 深度图还需要反投影 |
| “能出米制深度就可以直接抓” | 还需要尺度校验、坐标变换和目标裁剪 |
| “单目深度能替代标定” | 标定决定反投影与坐标关系 |
| “深度模型解决了语义问题” | 深度模型补的是距离，不是对象语义 |
