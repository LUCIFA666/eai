# Point Foundation Model

> 难度：[中级] | 预计用时：70 分钟
> 先修：[Depth Anything 与单目深度模型](03-depth-foundation-models.md)
> 阅读提示：本页重点是“点云特征不是坐标”，以及 3D 表征如何服务于机器人任务。

目标：讲清 point foundation model 这类 3D 预训练模型究竟在点云上学什么、它们和深度模型有什么分工，以及为什么 point feature 不应被误当成可直接执行的几何量。

## 先建立直觉

单目深度模型主要回答的是：

- 每个像素离相机多远

但机器人操作往往还会继续追问：

- 哪些点属于同一个对象
- 哪些局部表面结构最重要
- 哪些点在 3D 语义上彼此相似
- 哪一片局部区域更可能成为接触候选

这时系统需要的不再只是深度值，而是：

**对点云本身的通用 3D 表征能力。**

## point foundation model 在做什么

可以把这类模型理解成：

**在大量点云数据上预训练，学习可迁移的 3D 特征表示。**

它们关注的不是单个像素，而是：

- 点与点之间的空间关系
- 局部邻域的几何结构
- 物体表面的三维模式
- 对象级和场景级的 3D 语义

从机器人角度看，这类模型的价值在于：  
即使没有为某个具体任务从头训练，也能先提供一套可迁移的 3D 特征基础。

## 什么是 point feature，并立刻接例子

`point feature` 指的是：

**模型为点云中的每个点，或每片局部区域，生成的特征表示。**

立刻接例子：

- 杯口边缘附近的一簇点会有自己的 3D feature
- 杯身侧壁的一簇点也会有另一组 feature
- 如果两片局部结构在 3D 形状上相似，它们的 feature 往往也更接近

这和 2D 图像里的 patch feature 很像，但工作对象已经从像素块换成了点云局部邻域。

## 什么是局部邻域，并立刻接例子

点云处理里经常会提到“局部邻域”，意思是：

**围绕某个点，取它附近的一小片空间结构来一起分析。**

例子如下：

- 观察杯口边缘时，单独看一个点不够
- 把这个点周围一圈边缘结构一起看，模型才能更稳定地判断它属于“杯口这一类局部形状”

所以点云模型并不是孤立地看单点，而是看“点及其邻域”的几何关系。

## 先把“坐标”和“特征”分开

一个点云点通常至少有两类信息：

- 物理坐标：`(x, y, z)`，表示它在空间中的位置
- 特征表示：`feature embedding`，表示模型对这点或这一小片区域的 3D 理解

刚定义完就立刻接例子：

- 坐标告诉系统“这点在桌面上方 8 cm”
- 特征告诉系统“这一小片局部结构像杯口边缘，而不是桌面平面”

所以必须牢牢记住：

**point feature 不是物理坐标，也不是动作指令。**

## 这类模型常见于哪些任务

### 1. 3D 分割与前景提取

点云里哪些点属于目标对象，哪些点属于桌面或背景，往往需要强 3D 表征来辅助判断。

### 2. 3D 对应与检索

如果任务是“在多个局部点云片段中找和演示对象最像的一块结构”，point feature 能提供很强的 3D 匹配证据。

### 3. 对象级 3D observation

机器人并不总是消费整幅场景点云，更常消费对象级记录。  
point foundation model 可以帮助把对象局部结构编码成更稳定的 3D 特征。

## 这类模型和深度模型的分工是什么

两者虽然都和三维有关，但职责不同：

| 模型族 | 更主要回答什么 |
|---|---|
| 单目深度模型 | 像素离相机多远 |
| point foundation model | 点云局部结构在 3D 上像什么、是否重要 |

立刻接一个完整例子：

1. 单目深度模型先从 RGB 图像补出距离信息
2. 反投影后得到对象点云
3. point foundation model 再对对象点云做 3D 特征编码
4. 后续模块根据这些 3D feature 做分割、匹配、检索或接触候选分析

所以深度模型更像“补几何”，point 模型更像“理解几何结构”。

## 为什么“有点云”还不等于“有对象级 3D observation”

整幅场景点云往往太粗，还不能直接交给下游。  
对象级 observation 通常还需要：

- 目标裁剪
- 坐标系变换
- 几何汇总
- 特征记录
- 质量检查

例如更合理的对象级结果应该接近：

```yaml
object_3d_observation:
  object_id: mug_01
  frame_id: panda_link0
  pointcloud_ref: runs/04-perception/clouds/mug_01.pcd
  point_feature_ref: runs/04-perception/features/mug_01_point.npy
  centroid_xyz_m: [0.43, -0.11, 0.08]
  aabb_extent_m: [0.08, 0.08, 0.11]
  confidence: 0.74
  failure_code: null
```

这里必须同时记录：

- 几何量
- 特征来源
- 坐标系
- 质量状态

## 这类模型不能直接替代什么

point foundation model 很强，但默认仍然不直接替代：

- 相机标定
- 坐标系变换
- 位姿求解
- 接触与控制约束

尤其要避免把“3D feature 很强”误写成“已经知道机械臂该怎么动”。

## 用几个模型名字建立背景，但不把重点放在名词上

本页说的不是某一个单独模型，而是一整类 3D 预训练路线。  
常见代表会包括：

- 以点云局部结构建模为核心的 point transformer 类方法
- 以掩码重建、离散 token 或自监督预训练为核心的 Point-BERT、Point-MAE 一类方法

这些名字有助于后续阅读论文，但对本章最重要的仍然是职责判断：

- 它们的共同点是处理点云和 3D 表征
- 它们的区别不影响本页要建立的核心边界

## 常见误解

| 误解 | 为什么错 |
|---|---|
| “point feature 就是 3D 坐标” | 特征是表征，坐标是物理位置 |
| “有了点云预训练模型，就不需要深度或反投影” | 点云本身仍然要先得到 |
| “point model 输出强，所以可以跳过 pose” | 特征匹配不等于刚体位姿恢复 |
| “整幅场景点云可以直接喂给控制器” | 下游通常需要对象级、带质量说明的 observation |
