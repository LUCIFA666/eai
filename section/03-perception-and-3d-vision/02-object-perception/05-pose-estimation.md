# 位姿估计

> 难度：[中级] | 预计用时：60 分钟
> 先修：[检测与分割](01-detection-segmentation.md)
> 建议：先理解本页的任务边界，再进入 [PnP 与 ICP](06-pnp-icp.md)。

目标：把二维或三维观测结果变成机器人可执行的 6D 位姿，并学会判断这个位姿什么时候可信、什么时候必须拒收。

## 先建立直觉

到这一节为止，我们已经知道“目标是哪一个”和“它在图像中的哪些像素属于自己”。但这还不够。机械臂真正需要的是：

- 这个物体在三维空间里的位置。
- 它朝向哪里。
- 这个姿态是在哪个坐标系里定义的。
- 这个姿态能否支持抓取、放置、插入、避障等动作。

位姿估计做的事情，就是把“图像里的对象”进一步压缩成“空间中的刚体状态”。

一句更直白的话：检测与分割让机器人知道“看见了谁”，位姿估计让机器人知道“它到底在哪、朝哪”。

## 为什么具身智能里的位姿估计比看起来更重要

如果只是做图像理解，知道“图里有个杯子”往往已经够了。  
但在具身智能里，动作系统真正依赖的是空间关系，而不是类别本身。

比如机械臂在决定抓不抓的时候，真正关心的是：

- 杯子离我多远。
- 杯口朝哪边。
- 杯子和桌面的关系是什么。
- 从当前姿态接近会不会碰撞。

这说明位姿估计之所以重要，不是因为它听起来更高级，而是因为它是“识别结果”真正进入“动作空间”的那一步。

## 先把 6D pose 讲清楚

**6D pose** 里的 “6D” 不是六维向量这么简单，而是“刚体在三维空间里的 6 个自由度”：

- 3 个平移自由度：`x, y, z`
- 3 个旋转自由度：绕三个轴的朝向变化

常见表示方式有三种：

| 表示方式 | 例子 | 优点 | 常见问题 |
|---|---|---|---|
| 欧拉角 | `roll, pitch, yaw` | 直观 | 可能有万向锁，不适合做稳定插值 |
| 四元数 | `qx, qy, qz, qw` | 数值稳定、常用于工程接口 | 对新手不直观 |
| 旋转矩阵 | `3x3` 矩阵 | 计算方便、几何意义明确 | 存储冗余，需要保持正交 |

机器人系统里常见的最终输出形式是：

```yaml
pose:
  frame_id: panda_link0
  xyz_m: [0.43, -0.12, 0.08]
  quat_xyzw: [0.0, 0.0, 0.71, 0.70]
```

注意，这个结构里最容易被忽视、但实际最重要的字段往往不是 `quat_xyzw`，而是 `frame_id`。没有坐标系说明的 pose，基本不能安全交给下游。

## 位姿估计到底在回答什么

位姿估计最常见的三类问题是：

| 问题类型 | 已知条件 | 目标输出 |
|---|---|---|
| object pose estimation | 已知目标对象，拿到图像/深度/点云 | 求 `T_camera_object` 或 `T_base_object` |
| camera pose estimation | 已知世界中的标记点或场景 | 求相机相对场景的姿态 |
| grasp pose estimation | 不一定关心完整物体位姿 | 直接求可执行的抓取姿态 |

本章重点是第一类，也就是机器人操作里最常见的“物体位姿估计”。

## 物体 pose 不等于抓取 pose

这一点非常容易混淆，值得单独拿出来讲。

物体 pose 回答的是：

- 这个物体整体在空间中的位置和朝向是什么。

抓取 pose 回答的是：

- 夹爪应该以什么姿态、从什么方向去接近并闭合。

二者有关系，但不是同一个东西。

举个例子：

- 你知道杯子的 6D pose，只说明你知道杯子整体在空间中的状态。
- 但夹爪怎么抓，还要看杯把位置、桌面高度、夹爪宽度、接近方向、碰撞空间等约束。

所以很多系统会先估计物体 pose，再从 pose 推导候选抓取姿态；而不是把二者混成同一件事。

## 为什么这一层很容易被误解

新手常把 pose 理解成“模型输出的另一个字段”，但工程上它其实是高度脆弱的一层，因为它同时依赖多种上游条件：

- 相机内参是否正确。
- 检测或 mask 是否准确。
- 深度是否可靠。
- 坐标变换是否正确。
- 目标物体是否具有足够的几何特征。

只要上面有一项出错，pose 往往就会漂，而且漂得很“像是真的”。这也是为什么位姿估计比分类更需要验收指标和失败码。

## 常见方法按输入分类

| 方法 | 主要输入 | 输出 | 适合场景 |
|---|---|---|---|
| PnP | 3D 模型点 + 2D 图像点 + 内参 | 位姿 | 已知 CAD 或关键点的物体 |
| ICP | 两份点云或点云 + 模型 | 刚体变换 | 深度/点云较可靠时 |
| keypoint pose | 图像关键点或 3D 关键点 | 位姿或抓取框架 | 几何特征稳定的对象 |
| pose tracking | 上一帧 pose + 当前观测 | 当前 pose | 视频流、连续操作 |
| foundation pose 类方法 | RGB、mask、depth、CAD 等 | 位姿 + 跟踪状态 | 复杂对象和开放场景 |

我们可以把这些方法粗略分成两条路线：

- 从 2D 对应关系恢复 3D 姿态，例如 PnP。
- 从 3D 几何对齐恢复刚体变换，例如 ICP。

后面的小节会详细比较这两条路线。

## 从相机坐标到机器人坐标，这一步不能默认正确

很多读者一开始会觉得，既然 pose 已经算出来了，为什么还要反复强调 `frame_id`？

原因是：  
大多数视觉方法最先恢复出来的 pose，往往是在相机坐标系里。

但真正执行动作时，下游常常需要的是：

- `T_base_object`
- 或者 `T_world_object`

所以中间至少还要经过一步坐标变换：

```text
T_base_object = T_base_camera * T_camera_object
```

如果这一层搞错了，就会出现一种特别危险的情况：

- pose 数值本身看起来很合理；
- 但机械臂却会朝完全错误的位置伸过去。

这也是为什么手眼标定、外参和 `frame_id` 会在本章里反复出现。它们不是补充细节，而是位姿结果真正可执行的前提。

## 一张表先记住 pose 的最小验收字段

| 字段 | 为什么必须有 |
|---|---|
| `frame_id` | 不然下游不知道这个 pose 在哪个坐标系里 |
| `timestamp` | 不然无法判断数据是否过时 |
| `pose` 本体 | 位置和朝向是执行的核心输入 |
| `confidence` 或质量分数 | 不然上层无法做风险控制 |
| `failure_code` | 不然失败只能靠猜 |
| `symmetry` 或等价说明 | 对称物体的角度误差不能按普通物体解释 |

如果只给出一个 `xyz + quat`，而没有这些上下文，通常还不足以称为机器人级输出。

## 对称物体为什么是位姿估计的重点难点

很多日常物体并不是“每个角度都能区分”的。例如：

- 圆柱杯身绕轴旋转后看起来几乎一样。
- 盘子从正上方看几乎没有方向信息。
- 碗、瓶盖、球体都存在不同程度的对称性。

这会带来一个非常重要的工程问题：一个 pose 数值上“错了”，不一定意味着动作上也“错了”；反过来，一个 pose 数值上“看起来差不多”，也可能因为接触面方向错了而完全不可执行。

因此对称物体常常需要额外记录：

```yaml
pose_quality:
  symmetry: axial_z
  translation_confidence: 0.92
  rotation_confidence: 0.61
```

这样评测和下游策略才不会把“不可区分角度”误当成普通错误。

## 最小代码：PnP 的输入输出是什么样

下面这段代码来自仓库里的示例 [labs/04-perception/pnp_pose.py](../../../labs/04-perception/pnp_pose.py)：

```python
ok, rvec, tvec = cv2.solvePnP(
    object_points,
    image_points,
    camera_matrix,
    distortion,
)
```

这里最值得你先记住的不是函数名，而是它背后的语义：

- `object_points`：物体自身坐标系里的 3D 点。
- `image_points`：这些点在图像里的 2D 位置。
- `camera_matrix`：相机内参。
- `rvec, tvec`：求出来的相机与物体之间的位姿关系。

可以先用一句话概括 PnP：

“已知同一组点在 3D 里长什么样，也知道它们投影到图像后落在哪，反过来求相机和物体之间的姿态。”

## 位姿结果什么时候不能交给规划器

下面几种情况，哪怕 pose 有数值输出，也建议阻塞执行：

| 情况 | 为什么危险 |
|---|---|
| 连续帧 pose 大幅抖动 | 说明观测不稳定，执行目标会跳 |
| 对称物体角度不确定却被当成确定值 | 评测和控制会被误导 |
| mask 或点云明显不完整 | 几何基础已经坏了 |
| 位姿在 camera frame，下游却默认 base frame | 会直接造成执行错误 |
| 置信度低但系统没有降级逻辑 | 等于把风险静默传给下游 |

## 当位姿不稳定时，系统不一定要硬算，也可以先重看

在具身任务里，如果当前 pose 很不稳定，最自然的反应不一定是“换一个更强的 pose 模型”，而可能是“先换个视角再看一次”。

例如：

- 当前目标只有一半露出来。
- 当前深度空洞很多。
- 当前视角正好落在对称物体最难区分的方向上。

这时更好的系统动作可能是：

- 把手腕相机再靠近一点。
- 换一个更侧面的视角。
- 等待目标与遮挡物分开。
- 重新采一帧再估计 pose。

也就是说，位姿估计在具身智能里往往是“感知-动作循环”的一部分，而不是单次离线求解。
