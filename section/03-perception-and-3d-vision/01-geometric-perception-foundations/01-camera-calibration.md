# 相机标定

> 难度：[基础] | 预计用时：55 分钟
> 先修：[感知与三维视觉](../README.md)
> 建议：先运行 `python labs/04-perception/camera_calibration_synthetic.py`，再读本页。

目标：理解相机内参、主点、畸变和分辨率之间的关系，知道为什么标定是像素进入机器人几何链的第一道门槛。

相机标定不是”先做一次就忘掉”的准备工作，而是像素进入机器人几何世界的门槛。我们可以把相机想成一支固定在机器人上的激光笔：`fx, fy` 决定这支笔向外张开的角度，`cx, cy` 决定它是不是正对传感器中心，畸变参数决定边缘光线是不是被镜头掰弯了。只要这些量有系统误差，后面的点云、PnP、抓取位姿和避障距离都会一起偏。对具身系统来说，标定的任务不是”把一张表填满”，而是确保从像素到 3D 射线的映射在工作空间里足够可信。

## 本页目标

这一页读完后，我们希望能一起把下面几件事说明白：

- 解释 `fx, fy, cx, cy` 与畸变参数分别如何影响像素到 3D 射线的几何关系。
- 判断一份标定结果是否足以支持抓取、放置和避障，而不只盯着平均重投影误差。
- 复现 `labs/04-perception/camera_calibration_synthetic.py` 中的合成标定实验，并读懂输出里的误差含义。
- 在图像缩放、裁剪、自动对焦变化后，正确更新或重新验证相机内参。

## 先弄懂几个前置概念

正式开始前，先把几个后面反复出现的概念说清楚。标定涉及到”像素坐标”、”相机坐标系”、”3D射线”之间的变换，如果这些概念不熟悉，后面的公式会越看越晕。

**像素坐标系**：(u, v)，以图像左上角为原点，u向右，v向下。单位是”像素”。这是相机直接输出的坐标。

**相机坐标系**：以相机光心为原点，X轴向右，Y轴向下，Z轴向前（镜头方向）。这个坐标系是三维的，用来描述空间中点的位置。

**3D射线**：从相机光心出发，穿过像素(u,v)的一条直线。像素只是2D信息，深度信息缺失时，我们只知道点在这条射线上，但不知道具体在哪。

**内参矩阵K**：把相机坐标系下的3D点投影到像素坐标的3x3矩阵：

```
| u |   | fx  0 cx |   | X |
| v | = |  0 fy cy | * | Y |
| 1 |   |  0  0  1 |   | Z |
```

其中：
- `fx, fy`：焦距，单位是像素。决定射线张角——fx越大，同样的像素偏移对应的角度越小。
- `cx, cy`：主点坐标。图像中心实际落在传感器上的位置，帮助把射线方向和像素位置对应起来。
- 最后一行的(0,0,1)是齐次坐标，用于做平移变换。

## 一张表先记住最关键的量

| 概念 | 它控制什么 | 典型故障现象 | 可以怎么检查 |
|---|---|---|---|
| `fx, fy` | 像素到射线的张角 | 同一物体的 3D 尺寸整体偏大或偏小 | 用已知尺寸物体测尺度 |
| `cx, cy` | 光轴落在传感器的哪个像素位置 | 左右/上下位置出现系统偏移 | 看中心与边缘都是否一致 |
| distortion | 径向/切向畸变 | 边缘点比中心点误差大很多 | 单独看边缘误差分布 |
| reprojection error | 标定点投影回图像后的像素误差 | 平均值很好看，但局部失败被掩盖 | 同时看均值、最大值和单张分布 |
| image size | 标定时使用的像素网格 | 运行时换分辨率后 3D 全部偏 | 核对运行分辨率是否一致 |

## 从数据出发：一份标定输出应该长什么样

本仓库已经给了一个合成实验：`labs/04-perception/camera_calibration_synthetic.py` 渲染一个 9x6 的棋盘格，地面真值内参如下：

```python
# 合成相机真值：1280x720 图像上的 pinhole intrinsics
K_GT = np.array([
    [950.0,   0.0, 644.0],
    [  0.0, 950.0, 357.0],
    [  0.0,   0.0,   1.0],
])
DIST_GT = np.array([-0.10, 0.04, 0.0, 0.0, 0.0])

# 预期输出:
# calibrateCamera 恢复出的 K 与 DIST 接近真值；
# 加入 0.25 px 噪声后，RMS reprojection error 约为 0.34 px。
```

运行脚本时，会看到一段类似下面的输出。先看最有教学价值的部分：

| 噪声标准差 | 使用视角数 | RMS 重投影误差 | `fx` 相对误差 | `cx` 相对误差 | 读法 |
|---|---:|---:|---:|---:|---|
| `0.00 px` | 36 | `0.0000 px` | `0.000%` | `0.000%` | 无噪声时几乎恢复真值 |
| `0.25 px` | 36 | `0.3448 px` | `0.010%` | `0.353%` | 轻微角点噪声先伤到主点估计 |
| `0.50 px` | 36 | `0.6897 px` | `0.020%` | `0.700%` | 误差继续增大，边缘定位更脆弱 |

这张表说明两个很实用的判断：

1. 平均误差在 `0.3 px` 左右，不代表所有参数都同样稳定。这里 `fx, fy` 还很准，但 `cx, cy` 已经开始飘。
2. 角点检测噪声上来以后，畸变参数可能会“吸收”一部分系统误差，所以只看畸变系数数值是否漂亮没有意义，关键是看它投影回去后的整体效果。

## 标定流程：不是拍够张数，而是覆盖误差模式

下面这张流程图比“至少采 20 张图”更重要，因为很多失败不是张数不够，而是视角太单一。

```text
固定成像条件
  |
  |-- 分辨率固定
  |-- 曝光/增益固定
  |-- 对焦/变焦固定
  v
采集标定板图像
  |
  |-- 中心 + 四角
  |-- 近距离 + 远距离
  |-- 正视 + 倾斜 + 旋转
  v
求解 intrinsics + distortion
  |
  |-- 平均 RMS
  |-- 单张误差
  |-- 边缘误差
  v
独立验证
  |
  |-- 已知尺寸物体
  |-- 桌面平面
  |-- 运行分辨率一致
  v
写入部署记录
```

推荐流程如下：

1. 固定相机分辨率、曝光、对焦和图像裁剪策略。
2. 使用棋盘格、Charuco 或 AprilTag 标定板采集多角度图像。
3. 让标定板覆盖画面中心、四角、近距离、远距离和倾斜视角。
4. 求解内参和畸变参数。
5. 检查平均误差之外的单张误差、最大误差和边缘区域误差。
6. 用独立验证图像或已知尺寸物体复核，而不是只看参与求解的那批图。

这里的 trade-off 很明确：采更多图像通常更稳，但如果相机在采集过程中自动对焦漂移，更多图只是在把两个不同成像模型揉在一起，结果会更糟。

## 一个最小可运行示例：缩放和裁剪后怎么更新内参

真实项目里，最常见的坑不是求解器坏了，而是部署时改了图像尺寸。下面这个例子展示如何在“先缩放、再裁剪”后更新内参。

```python
# 把 1280x720 标定结果缩放到 640x360，再向右裁 40 px、向下裁 20 px
import numpy as np

K = np.array([
    [950.0,   0.0, 644.0],
    [  0.0, 950.0, 357.0],
    [  0.0,   0.0,   1.0],
], dtype=float)

sx, sy = 640 / 1280, 360 / 720
crop_x, crop_y = 40, 20

K_new = K.copy()
K_new[0, 0] *= sx
K_new[1, 1] *= sy
K_new[0, 2] *= sx
K_new[1, 2] *= sy
K_new[0, 2] -= crop_x
K_new[1, 2] -= crop_y

print(K_new)
# 预期输出:
# [[475.    0.  282. ]
#  [  0.  475.  158.5]
#  [  0.    0.    1. ]]
```

这个更新规则背后的逻辑非常朴素：

- 缩放图像，相当于每个像素变大了，所以焦距和主点都要按比例缩放。
- 裁剪图像，相当于像素原点平移了，所以主点要减去裁剪偏移。
- 如果运行时做了非线性畸变校正、数码变焦或 ISP 裁切，而你拿不到真实几何变换链路，最稳妥的做法通常是重新标定。

## 机器人场景里的验收，不只看一个 RMS 数字

抓取系统真正关心的是“工作空间中的误差长什么样”，而不是“标定日志是否好看”。下面这个验收表可以直接拿去用。

| 检查项 | 为什么要看 | 通过标准示例 | 失败时常见原因 |
|---|---|---|---|
| 平面重建 | 桌面应接近平面，不能被镜头畸变拉弯 | 桌面点云拟合残差稳定、无明显弧形 | 畸变未校正、深度尺度漂移 |
| 尺度一致性 | 抓取宽度和放置间隙依赖真实尺寸 | 已知长度物体测量误差在任务容忍范围内 | `fx, fy` 错、深度尺度错 |
| 边缘稳定性 | 机器人常在画面边缘观察目标 | 边缘点误差不显著高于中心 | 标定板只拍了中心区域 |
| 配置稳定性 | 重启后仍应是同一套参数 | 分辨率、对焦、裁剪配置完全一致 | 驱动自动改配置 |
| RGB/Depth 对齐 | 2D mask 投到 3D 时必须同 frame | 训练与部署的 alignment 设置一致 | 软件栈默认值不同 |

一个经验判断是：如果任务需要亚厘米级放置，而相机离工作台只有 40 到 60 cm，那么 `0.5 px` 以内的误差通常只是起点，不是终点。还需要把它换算成桌面上的毫米误差，并看误差是否集中在真正抓取的区域。

## 常见错误：每一条都会直接伤到下游任务

| 错误 | 直接后果 | 会在哪个任务里暴露 |
|---|---|---|
| 用一个分辨率标定，运行时换分辨率但没缩放内参 | 3D 尺度整体偏 | 抓取张角不准、避障距离错 |
| 裁剪图像后没更新主点 | 全局位置偏移 | 放置点始终偏一边 |
| 自动对焦或变焦开启 | 同一相机的内参随时间漂移 | 同一目标今天能抓明天不能抓 |
| 标定板只覆盖中心 | 边缘畸变估计差 | 画面边缘抓取更容易失败 |
| RGB 与 Depth 对齐开关不一致 | mask 和点云错位 | 目标分割正确但 3D 位置错误 |

## 自检问题

1. 如果一份标定结果的平均重投影误差只有 `0.25 px`，但机器人在画面边缘抓取时明显更容易失败，会优先检查什么，为什么？
2. 为什么“缩放图像后把 `fx, fy` 按比例缩放”还不够？在什么情况下 `cx, cy` 一定也要改？
3. 如果 RGB 图像和 Depth 图像各自都看起来正常，但把 2D mask 投到 3D 点云上总是偏，会先排查标定、对齐配置还是分割模型？给出顺序和依据。

## 练习

### [观察] 运行合成标定脚本，判断噪声先伤到哪类参数

运行：

```bash
python labs/04-perception/camera_calibration_synthetic.py
```

观察：

- `views used` 是否为 `36`。
- `0.25 px` 噪声下的 `RMS reprojection error` 是否约为 `0.3448 px`。
- `fx/fy` 与 `cx/cy` 哪一组相对误差先明显变大。

完成后，可以先用下面几条检查这一部分是否已经到位：
- 能指出“主点 `cx, cy` 比焦距 `fx, fy` 更早明显漂移”这一现象。
- 能用脚本输出解释为什么平均 RMS 不能替代对单个参数稳定性的判断。

### [复现] 写一份最小标定验收报告

要求：

1. 参考本页模板，运行 `python labs/04-perception/camera_calibration_synthetic.py`。
2. 从终端输出中提取图像尺寸、棋盘格规格、噪声条件、RMS 误差、`fx/fy/cx/cy` 相对误差。
3. 用 5 到 8 句话写一段验收结论，回答“这份标定是否足以支持桌面抓取，风险在哪”。

完成后，可以先用下面几条检查这一部分是否已经到位：
- 报告同时包含“数值结论”和“工程风险”，不是只抄结果。
- 能明确写出：如果运行时改成别的分辨率，内参必须同步更新或重新标定。

### [修改] 模拟缩放或裁剪，手算新的内参

要求：

1. 以本页示例中的 `1280x720` 内参为起点。
2. 任选一种变换：
   - 缩放到 `960x540`
   - 缩放到 `640x360` 后再裁掉左边 `40 px`
3. 写出新的 `fx, fy, cx, cy`，并解释每一步更新为什么成立。

完成后，可以先用下面几条检查这一部分是否已经到位：
- 结果满足“焦距按比例缩放，主点先缩放再减裁剪偏移”。
- 能说清楚为什么只改 `fx, fy` 而不改 `cx, cy` 会让 3D 重建产生系统偏移。
