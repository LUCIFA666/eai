# 点云配准

> 难度：[中级] | 预计用时：40 分钟
> 先修：[RGB-D 与点云](03-rgbd-pointcloud.md)
> 建议：先运行 `python labs/04-perception/icp_demo.py`。

目标：理解为什么多份点云需要配准，知道 `ICP`、`RANSAC`、局部特征匹配各自在解决什么问题，并学会判断一份配准结果能不能进入下游几何或位姿系统。

## 先建立直觉

本页要解决的核心问题是：

**如果两份点云描述的是同一个物体或同一个场景，但它们处在不同坐标表达下，怎样把它们对齐？**

典型场景包括：

- 多相机观测同一桌面场景；
- 当前观测点云和 CAD 模型点云对齐；
- 连续帧之间的物体点云跟踪；
- 多次扫描的场景融合。

点云配准最终想得到的，不是“看起来差不多重合了”，而是：

```text
T_target_source
```

也就是一份明确的刚体变换，把源点云变到目标点云所在的坐标系。

## 先把刚体变换再说准一次

点云配准的输出本质上是一份刚体变换：

- 旋转 `R`
- 平移 `t`

满足：

```text
P_target = R * P_source + t
```

这里最重要的仍然是**方向感**：

- `T_target_source` 和 `T_source_target` 不是一回事。
- 变换方向写反，后面的配准、位姿和碰撞都会一起错。

## 为什么需要配准

把配准的用途分成四类最容易理解：

| 用途 | 在对齐什么 |
|---|---|
| 多视角融合 | 两台相机或两个视角看到的同一场景 |
| 模型匹配 | CAD / mesh 点云与观测点云 |
| 视频跟踪 | 上一帧点云与当前帧点云 |
| 离线重建 | 多次扫描的场景片段 |

换句话说，配准是一种“让不同来源的 3D 证据说同一种空间语言”的方法。

## 两层方法：粗配准和精配准

### 粗配准

粗配准负责解决：

> 两份点云一开始差得比较远，我先大概找一个初始对应关系。

常见方法包括：

- 局部特征匹配
- `FPFH`
- `RANSAC`

### 精配准

精配准负责解决：

> 已经有了一个还不错的初值，现在继续把误差压小。

最典型的方法就是 `ICP`。

所以我们可以把完整流程记成：

```text
粗配准给初值
  -> ICP 做精修
```

## `FPFH` 和 `RANSAC` 到底是什么

### `FPFH`

`FPFH` 是一种局部几何特征描述子。它会为每个点编码附近表面的局部结构，让不同视角下相似几何位置更容易被匹配到。

你不需要一开始深入它的数学细节，但要知道它在做什么：

**给点云里的每个局部区域做“几何指纹”。**

### `RANSAC`

`RANSAC` 是随机采样一致性算法。它的直觉是：

- 随机选少量对应点；
- 求出一个候选变换；
- 看这个变换能解释多少其它点；
- 重复很多次，保留支持最多的那一个。

它的价值在于：

**哪怕有很多错误匹配，也有机会从中找出那部分真正一致的对应关系。**

## `ICP` 在解决什么

`ICP` 的直觉可以理解成：

> 我已经大概知道这两团点云位置接近了，现在反复做“找最近点 -> 重新估计变换”，直到误差不再明显下降。

它很常见，也很实用，但一定要先记住它的边界：

**ICP 不是全局搜索，它是局部优化。**

这意味着：

- 如果初值已经比较接近，它通常很有效。
- 如果初值差太远，它可能收敛到错误的局部极小。

## 跑一次最小 ICP 实验

运行：

```bash
python labs/04-perception/icp_demo.py
```

这个脚本会：

- 生成一份合成源点云；
- 用已知真值刚体变换生成目标点云；
- 再用纯 numpy ICP 尝试把它恢复回来；
- 输出每轮迭代的 RMSE。

可以重点看：

- `estimated T`
- `residual rotation error`
- `residual translation err`
- `ICP RMSE per iteration`

最有教学价值的观察是：

**配准结果不能只看最后一个姿态矩阵，还要看误差是否随着迭代稳定下降。**

## 初值为什么决定了 ICP 能不能工作

这是点云配准最值得建立的工程直觉之一。

如果初值很差，ICP 会出现几种常见问题：

- 对错局部表面；
- 在对称结构上“看起来也很像”；
- 很快停住，但停在错误姿态；
- RMSE 不高，却没有对到真正语义上对应的物体。

所以很多系统不会直接“裸跑 ICP”，而会先用：

- 手眼外参
- 上一帧 pose
- 粗配准
- 检测或 mask 裁剪

来提供更合理的起点。

## 一张表理解常见配准方法

| 方法 | 最擅长什么 | 最大风险 |
|---|---|---|
| 特征匹配 + RANSAC | 初值差很大时找粗对应 | 特征不稳定时会误匹配 |
| Point-to-point ICP | 几何结构明显时精修 | 对初值和遮挡敏感 |
| Point-to-plane ICP | 局部平面丰富时收敛更快 | 依赖法向量质量 |
| Colored ICP | 几何弱但颜色强时有帮助 | 颜色受光照影响较大 |

## 配准结果最少要记录什么

```yaml
registration_result:
  source_frame: object_crop_t0
  target_frame: object_crop_t1
  method: icp_point_to_point
  init_transform: from_previous_pose
  fitness: 0.91
  inlier_rmse: 0.0032
  converged: true
  failure_code: null
```

这些字段的意义在于：

- 明确变换方向；
- 明确初值来源；
- 明确误差和是否收敛；
- 给下游一个明确的“能不能信”依据。

## 常见失败模式

| 失败模式 | 现象 | 应对思路 |
|---|---|---|
| 初值太差 | ICP 很快停在错误姿态 | 先做粗配准或给更好初值 |
| 对称结构歧义 | 多个姿态都看起来能对上 | 加语义、关键点或历史状态 |
| 点云重叠太少 | `fitness` 低 | 增大视角覆盖或多帧融合 |
| 法向量质量差 | point-to-plane 抖动 | 重新估计法向 |
| 动态物体 | 连续帧无法稳定对齐 | 加时间同步和对象级裁剪 |

## 什么时候配准结果不能继续往下传

下面几种情况，即使算法给出了一个变换，也建议阻塞下游：

- `fitness` 很低；
- `RMSE` 不降或异常大；
- 对称歧义没有被标出来；
- 变换方向不清楚；
- 源点云和目标点云根本不是同一对象。

很多“位姿估计不稳定”的问题，根本原因其实出在这一步的配准没有过质量门。

## 练习

### [观察] 读懂一次 ICP 误差历史

运行：

```bash
python labs/04-perception/icp_demo.py
```

然后回答：

- RMSE 是否持续下降？
- 最后的平移误差和旋转误差各在什么量级？
- 如果 RMSE 降了，但对象其实对错了，可能是什么原因？

完成后，可以先用下面几条检查这一部分是否已经到位：
- 能解释 ICP 为什么是局部优化。
- 能指出至少一种“低 RMSE 但语义仍然错”的情况。

### [复现] 写一份配准结果记录

为一次“当前帧点云对齐上一帧点云”的过程写一份最小记录，至少包含：

- `source_frame`
- `target_frame`
- `method`
- `init_transform`
- `fitness`
- `inlier_rmse`
- `failure_code`

完成后，可以先用下面几条检查这一部分是否已经到位：
- 记录足以让别人复盘这次配准是否可信。
- 能说明为什么只保存最终矩阵还不够。
