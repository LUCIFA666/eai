# 抓取位姿生成

目标：理解抓取位姿不是“拍脑袋选一个 6D pose”，而是从对象几何、接触候选、碰撞约束和可达性中筛选出来的一组可执行候选。

## 先建立直觉

知道一个接触点还不等于已经知道“怎样抓”。对抓取任务来说，下游真正需要的是一份可执行的 grasp candidate，它通常至少要包含：

- 末端执行器的位姿。
- 接近方向。
- 夹爪开口宽度。
- 抓取质量分数。
- 碰撞和可达性检查结果。

所以抓取位姿生成解决的是这样一个问题：

**怎样把“哪里值得碰”变成“机械臂现在真的能去抓、而且大概率抓得住”的候选动作？**

## 抓取位姿和接触点是什么关系

可以把它们理解成两层约束：

- `contact point` 更像局部接触建议。
- `grasp pose` 更像完整执行候选。

同一个接触区域，往往可以导出多种抓取姿态：

- 从左侧夹。
- 从右侧夹。
- 从上方抓。
- 略微旋转夹爪，避开障碍物。

因此 grasp generation 的核心不只是“生成”，还包括“排序与筛选”。

## 一条典型的数据流

```text
object mask / point cloud / pose
  -> affordance region or contact seed
  -> sample grasp candidates
  -> score candidates
  -> collision check
  -> IK / reachability check
  -> top-k executable grasps
```

这条链路里，后面三步经常和视觉本身一样重要。因为一个视觉上很合理的抓取姿态，可能：

- 夹爪张不开。
- 会撞桌面。
- 超出机械臂可达范围。
- 到得了但闭合后会打滑。

## 常见方法可以粗分成两类

| 路线 | 代表思路 | 优点 | 风险 |
|---|---|---|---|
| 几何采样 | 从表面法向、边缘、对称轴生成候选 | 可解释、易排错 | 对噪声敏感 |
| 学习生成 | 用 GraspNet、Contact-GraspNet 一类模型直接预测 | 在复杂物体上更灵活 | 依赖训练分布和数据质量 |

教学上最好先理解它们共同遵守的约束，再去看具体模型。

## 一份抓取候选至少要包含什么

```yaml
grasp_candidate:
  object_id: mug_01
  frame_id: panda_link0
  pose:
    xyz_m: [0.43, -0.10, 0.12]
    quat_xyzw: [0.0, 0.71, 0.0, 0.70]
  approach_vector_xyz: [0.0, 0.0, -1.0]
  gripper_width_m: 0.062
  score: 0.79
  collision_free: true
  ik_feasible: true
  source: contact_graspnet
  failure_code: null
```

这份结构和普通 `pose` 最大的区别在于：  
它不仅要说“到哪里”，还要说“能不能抓、为什么认为它更好”。

## 为什么排序比“生成很多候选”更重要

很多初学者会误以为抓取位姿生成的难点在于“想办法多生成一些姿态”。实际工程里更难的是：

- 候选多了，谁先试。
- 分数高的姿态是不是会撞桌面。
- 相似分数的姿态，哪个更稳、哪个更省动作。

因此排序常常会综合几类信号：

- 几何匹配质量。
- 夹爪闭合稳定性。
- 与障碍物的安全余量。
- 末端接近路径是否顺滑。
- 机械臂可达性与关节余量。

## 三个常见过滤器

| 过滤器 | 它在排掉什么 |
|---|---|
| collision check | 会撞桌面、会撞环境、会穿模的候选 |
| IK / reachability | 目标姿态到不了或姿态太别扭的候选 |
| force / closure heuristic | 看起来夹得住，实际上闭合不稳的候选 |

如果这三关都不做，视觉上“像样”的抓取姿态很容易在真机上失败。

## 为什么这一页放在触觉之前

抓取位姿生成仍然属于“接触前”的感知与规划接口层，它回答的是：

- 先试哪个抓法。
- 怎样接近更安全。
- 目标物体的几何和局部接触如何转成执行候选。

接触观测则负责回答：

- 试了以后到底抓没抓住。
- 抓住后有没有滑。
- 受力有没有超限。

所以二者是前后衔接关系，不是替代关系。

## 常见失败模式

| 失败 | 现象 | 常见原因 |
|---|---|---|
| top-1 抓不住 | 分数最高的抓取在真机上失败 | 训练分布和真实摩擦差异大 |
| 会撞桌面 | 目标姿态看似合理，但接近时碰撞 | 缺少桌面约束或碰撞检查 |
| 到不了 | grasp pose 很好，但机械臂做不到 | 没做 IK 或 reachability check |
| 候选过密但都相似 | 生成很多姿态，实际没有多样性 | 采样策略单一 |
| 抓得住但不稳定 | 抬起时滑移 | 只看几何，没考虑闭合稳定性 |
