# 触觉、力觉与接触观测

> 难度：[中级] | 预计用时：55 分钟
> 先修：[可供性与交互区域](01-affordance-grounding.md)
> 建议：本节先回答“有哪些接触观测可用”，下一节再回答“怎样把这些观测变成事件判断”。

目标：理解触觉、力觉和各类接触观测分别测量什么、适合回答什么问题，以及它们如何和视觉一起构成交互阶段的观测基础。

## 先建立直觉

如果说视觉负责“接触前的世界理解”，那么接触观测负责“接触发生后的状态确认”。

视觉可以告诉你：

- 物体大概在哪里。
- 应该从哪个方向接近。
- 抓取目标在几何上是否看起来合理。

但一旦机械臂真的碰到物体，很多关键事实只有接触相关观测才能告诉你：

- 夹爪到底有没有真正碰到目标。
- 接触发生在指尖、腕部还是环境其他位置。
- 当前受力是在正常加载，还是已经过载、卡滞或侧撞。
- 接触面的局部压力分布、纹理压痕和剪切变化怎样演化。

因此这一页先不讨论事件检测逻辑，而是先把“传感器本身在看什么”讲清楚。只有先分清观测来源，后面谈接触事件、滑移和失败诊断才不会混乱。

## 本页目标

本页聚焦四件事：

- 区分触觉、六维力/力矩、关节力矩、电机电流和夹爪开口这些观测各自测量什么。
- 理解它们的安装位置、观测粒度和典型盲区。
- 建立“连续接触观测”与“离散接触事件”之间的职责边界。
- 写出一份最小 `contact_observation`，为后续事件检测和力控证据链做准备。

## 为什么视觉无法完全替代它们

即使视觉模型再强，也仍然存在几个天然盲区：

- 被手爪遮挡后，看不到接触点真实状态。
- 透明、反光、柔性物体的几何不稳定。
- 滑移通常是细微接触变化，不容易从 RGB 中稳定判断。
- 插入、按压、拧紧这类任务的最后几毫米，往往更依赖受力反馈而不是视觉。

所以一个成熟的具身系统，通常会形成这样的协作方式：

- 视觉负责“去哪、从哪接近”。
- 接触观测负责“碰到了什么、碰得是否正确、受力是否安全”。

## 先把几类接触观测分开

| 观测类型 | 典型安装位置 | 主要输出 | 更擅长回答什么 |
|---|---|---|---|
| 指尖触觉阵列 / 视触觉 | 指尖、夹爪接触面 | taxel 压力、触觉图像、局部形变 | 接触面形状、局部压力、剪切、微滑 |
| 六维力/力矩传感器 | 腕部或末端法兰 | `Fx, Fy, Fz, Tx, Ty, Tz` | 整体载荷、碰撞冲击、接触方向 |
| 关节力矩估计 | 各关节 | joint torque | 整条运动链上的异常阻力、环境阻抗 |
| 电机电流 / 夹爪电流 | 执行器内部 | current | 闭手时是否顶到物体、阻力是否突增 |
| 夹爪开口 / 编码器 | 夹爪或关节 | width / position | 闭合过程是否达到预期、是否出现空抓或卡滞 |

它们都和“接触”有关，但空间粒度、频率和可解释性差别很大，不能混成同一种信号。

## 触觉和力觉的差别到底在哪里

最容易混淆的是“触觉”和“力觉”。

- **触觉**更偏局部接触面本身，关注哪里在压、压成什么形状、局部是否在剪切或滑动。
- **力觉**更偏整体载荷，关注末端或机构整体受了多大力、沿什么方向、是否出现异常力矩。

例如两指抓杯子时：

- 六维 F/T 传感器更容易告诉你“整体是不是撞上了桌沿”。
- 指尖触觉更容易告诉你“左指接触面积是不是太小”。
- 夹爪电流和开口更容易告诉你“夹爪是不是已经闭死但仍没形成稳定夹持”。

这也是为什么高质量系统通常不是只装一种传感器，而是让不同粒度的观测互相补证。

## 各类接触观测最常见的盲区

| 观测类型 | 典型优势 | 典型盲区 |
|---|---|---|
| 指尖触觉阵列 / 视触觉 | 分辨率高，能看局部接触几何和微滑 | 视野只覆盖接触面，成本和处理复杂度较高 |
| 六维力/力矩传感器 | 对碰撞、过载和整体接触方向很敏感 | 难以精确定位具体是哪一小块接触面出了问题 |
| 关节力矩估计 | 无额外硬件也常能拿到，能反映整机阻抗变化 | 容易受摩擦、动力学模型误差和控制器影响 |
| 电机电流 | 成本低，常见于夹爪闭手检测 | 信号粗糙，不足以单独解释复杂接触状态 |
| 夹爪开口 | 对空抓、过闭合和几何约束很直观 | 只能反映机构位置，不能直接说明局部受力质量 |

这张表的重点不是比较“谁更高级”，而是明确它们回答的问题层级不同。

## 机器人里常见的三种接触观测组合

### 1. 低成本组合：开口 + 电流 + 关节力矩

适合：

- 教学平台
- 低成本夹爪
- 首先需要判断“有没有夹到东西”

代价是：

- 对局部接触分布几乎没有观测能力。
- 很难解释“碰到了哪里、为什么会滑”。

### 2. 操作常用组合：腕部 F/T + 开口 + 电流

适合：

- 插入
- 桌面抓取
- 需要区分正常受力与异常碰撞的任务

它的优点是：

- 能较稳定地做接触检测、过载检测和安全停机。
- 对接触阶段切换很有价值。

但它仍然不擅长：

- 重建局部接触几何。
- 精细区分左右指是否对称接触。

### 3. 高分辨率组合：指尖触觉 / GelSight + F/T + 视觉

适合：

- 精细装配
- 软物体抓取
- 滑移预警
- 需要局部接触对齐的操作

它的价值是：

- 既能看整体受力，又能看接触面细节。
- 后续更容易做视触融合和高质量失败复盘。

## 连续观测和离散事件的边界

这一页讲的是连续接触观测，例如：

- 当前腕部力是多少；
- 当前夹爪开口是多少；
- 当前触觉图像长什么样；
- 当前关节力矩是否异常。

下一页讲的是离散事件，例如：

- `contact_onset`
- `stable_grasp`
- `slip_detected`
- `collision`

这个边界必须清楚，因为：

- 观测负责保留原始证据；
- 事件负责给上层模块提供阶段性判断。

## 一份最小接触观测应该长什么样

```yaml
contact_observation:
  timestamp: 2026-06-03T14:20:00.000Z
  frame_id: gripper_tcp
  grasp_phase: close
  signals:
    gripper_width_m: 0.034
    gripper_current_a: 0.41
    wrist_wrench_n_nm: [0.1, -0.2, 5.8, 0.01, 0.03, -0.02]
    tactile_available: true
    tactile_ref: runs/04-perception/tactile/frame_0231.png
  confidence: 0.86
  failure_code: null
```

这份记录还不是事件结论，而是更原始的接触观测切片。  
后面的 [接触事件与滑移检测](06-contact-slip.md) 会在此基础上继续判断：

- 是否已经接触。
- 是否形成稳定抓取。
- 是否出现滑移、空抓、过抓或碰撞。

## 为什么这一层和安全、评测强相关

很多感知错误最多会让系统“看错”；但接触观测相关错误常常会直接让系统“碰坏”。

因此这层天然和两件事紧密相关：

- **安全**：何时停、何时退、何时减力、何时触发保护。
- **评测**：失败到底发生在接触前、接触瞬间还是接触后阶段。

这也是为什么高质量教程不能只写“模型抓失败了”，而要继续追问：  
失败到底是没接触到、接触位置不对、法向力不够，还是局部已经滑移。

## 练习

### [观察] 为任务选择接触观测组合

分别判断下面任务更需要哪类接触观测，并说明原因：

- 普通桌面粗抓取
- 插接或卡扣装配
- 软物体抓取与防滑

完成后，可以先用下面几条检查这一部分是否已经到位：
- 能区分“整体载荷信息”和“局部接触几何信息”各自由谁提供。
- 能指出哪些任务需要高分辨率触觉，而哪些任务用 F/T 和开口就足够。

### [复现] 设计一份最小 `contact_observation`

至少包含：

- `timestamp`
- `frame_id`
- `grasp_phase`
- 一组连续接触信号
- `confidence`
- `failure_code`

完成后，可以先用下面几条检查这一部分是否已经到位：
- 输出仍然是“观测”，而不是已经混入了事件结论。
- 下游可以基于它继续做接触检测、滑移检测或力控复盘。
