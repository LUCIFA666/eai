# 视触融合

> 难度：[进阶] | 预计用时：45 分钟
> 先修：[触觉、力觉与接触观测](05-tactile-force-sensing.md) → [接触事件与滑移检测](06-contact-slip.md)
> 建议：把本页理解成“接触后阶段的多模态状态估计”，而不是简单把两路传感器拼起来。

目标：理解视觉与触觉为什么互补，知道视触融合在抓取验证、姿态精修、滑移预测中的典型用法，并能把它写成机器人可消费的融合 observation。

## 先建立直觉

视觉和触觉各自都很强，但它们各自都有稳定盲区：

- 视觉擅长远距离观察、对象识别和全局布局。
- 触觉擅长近距离接触、局部几何、滑移和受力变化。

很多关键失败恰好出现在两者交界处：

- 视觉上看似已经夹住，实际上接触面很浅。
- 触觉知道已经接触，但不知道接触的是目标还是遮挡物。
- 视觉能看见大体姿态，但精细接触偏移要靠触觉补。

所以视触融合解决的不是“把两个模态都用上更高级”，而是：

**让系统在接触前、接触中、接触后都能维持对同一交互状态的更完整判断。**

## 本页目标

这一页读完后，应该能回答下面几件事：

- 解释为什么视觉和触觉在机器人系统里是强互补关系。
- 区分视触融合在抓取验证、姿态精修、滑移预测中的三类典型作用。
- 说明 GelSight 一类传感器为什么采用视觉式读出，却仍然属于触觉感知。
- 写出一份最小 `visuotactile_observation`，并知道什么时候融合结果也必须拒收。

## 视觉和触觉分别擅长什么

| 模态 | 更擅长回答什么 | 典型盲区 |
|---|---|---|
| 外部视觉 | 目标是谁、在哪里、全局关系怎样 | 被夹爪遮挡、接触后细节看不清 |
| 触觉 / 力觉 | 是否接触、哪里在滑、局部接触几何怎样 | 看不到全局目标与周围环境 |

所以在执行链里，两者最常见的配合关系是：

- 视觉决定去哪里接近。
- 触觉决定接近后是不是已经正确接触。
- 视觉继续提供全局上下文，触觉提供局部闭环证据。

## 先把 GelSight 讲清楚

GelSight 不是普通相机，也不是传统力传感器。  
它本质上是**一种基于相机的触觉传感器**：把物体压在一层柔软凝胶表面上，再用内部相机去“看”这层凝胶发生了什么形变。

如果只记一句话，可以记成：

**GelSight = 用视觉读出接触形变的触觉传感器。**

### 它的结构大致是什么

一个典型的 GelSight 传感器通常包含几层：

- 最外层是一块柔软的 elastomer / gel，负责和物体直接接触。
- 凝胶表面往往带有可观测的纹理或反射层，方便后端恢复形状。
- 传感器内部有 LED 光源，从不同方向打光。
- 传感器内部还有一枚小相机，持续拍摄凝胶表面的受压图像。

当物体压上来时，凝胶会发生局部形变。  
相机看到的不是“物体原来的外观”，而是**接触区域在凝胶表面留下的压痕、阴影、反射变化和纹理位移**。

因此它输出虽然还是图像，但图像表达的语义已经变了：

- 普通视觉图像描述的是物体外观。
- GelSight 图像描述的是接触几何、局部纹理、剪切形变和滑移迹象。

### 它到底能测到什么

根据具体设计和算法，GelSight 一类传感器通常可以恢复或估计：

- 接触区域的位置和形状。
- 局部表面法向和高分辨率几何。
- 纹理压痕和细小边缘。
- 接触过程中的剪切、滚动和微滑。
- 某些任务中还可以进一步推断硬度、摩擦状态或物体在指尖内的相对位姿。

可以把它理解成：  
外部相机负责看“整个场景里发生了什么”，GelSight 负责看“接触面这一小块地方到底发生了什么”。

### 它和普通视觉、力觉有什么区别

| 传感器 | 主要看什么 | 更像在回答什么问题 |
|---|---|---|
| 外部 RGB / 深度相机 | 场景外观、目标位置、全局关系 | “目标在哪、姿态大概怎样、周围还有什么” |
| 六维力 / 力矩传感器 | 整体受力与力矩变化 | “机械臂或夹爪现在受了多大力” |
| GelSight | 接触面局部形变、压痕、剪切和微滑 | “指尖这一小块接触区域到底压成了什么样” |

这三者并不是替代关系，而是观测粒度不同：

- 外部视觉提供全局上下文。
- 力觉提供整体载荷变化。
- GelSight 提供高分辨率局部接触证据。

### 为什么它会出现在“视触融合”里

GelSight 很容易让人困惑的一点是：  
它内部明明也有相机，为什么不把它直接归到视觉里？

关键不在于传感器里有没有 camera，而在于**它测量的是不是接触事件**。

- 外部 RGB / 深度相机主要在非接触或弱接触阶段提供全局观察。
- GelSight 只有在接触发生后才真正提供高价值信息。
- 它输出的核心不是颜色语义，而是接触诱发的局部形变。

所以在机器人系统里，GelSight 通常被视为**高分辨率触觉**，只是它碰巧采用了视觉式读出方式。

也正因为如此，它天然适合和外部视觉融合：

- 两边的数据形式都像图像，容易接入现成的 computer vision 编码器。
- 外部视觉负责全局定位，GelSight 负责局部接触校正。
- 当夹爪遮挡严重时，GelSight 还能继续提供手内状态估计。

### 一个最小工作流程

```text
object touches gel
  -> gel deforms
  -> internal lights make the deformation visually observable
  -> internal camera captures the contact image
  -> algorithm reconstructs contact geometry / slip / shear
```

这也是 GelSight 在机器人里最有价值的地方：  
它把原本很难直接读出的接触状态，变成了可以被图像算法消费的观测。

## 为什么 GelSight 这类传感器很有代表性

GelSight 一类传感器在视触融合里很有代表性，因为它正好站在“视觉表示”和“触觉语义”的交界处：

- 表示形式像图像。
- 信息来源却是接触。
- 输出既能用于几何重建，也能用于滑移和姿态估计。

因此它很适合承担三类工作：

- 接触是否发生的验证。
- 局部姿态或接触面对齐的精修。
- 滑移先兆预测。

## 三类最典型的融合任务

### 1. 抓取验证

视觉可能告诉你夹爪大概包住了目标，但真正要判断“是不是抓稳了”，常要加入触觉或力觉：

- 接触是否对称。
- 接触面是否真的压实。
- 是否出现一侧先脱开或微滑。

### 2. 姿态精修

物体已经大体定位，但真正插接或精细放置前，触觉能提供更细的局部误差信号：

- 当前接触面法向是否偏了。
- 局部边缘是否已对齐。
- 接触图案是否和预期一致。

### 3. 滑移预测

视觉能看到“已经掉了”，但很难在掉之前就稳定判断。  
触觉往往能更早看到：

- 法向压力变化。
- 切向微动。
- 接触图案的连续漂移。

因此视触融合的价值不只是复盘，更在于提前预测失败。

## 融合时最容易犯的错

很多系统把“多模态融合”做成简单拼接：

```text
vision feature + tactile feature -> MLP
```

这样当然可能工作，但工程上真正要先解决的是三件事：

- 时间同步：两路信号是不是来自同一阶段。
- 坐标语义：视觉看到的是哪个对象区域，触觉对应的是哪个接触面。
- 失败边界：如果其中一路明显失效，系统是否知道该降级而不是盲融。

所以融合前比融合模型本身更重要的问题通常是：

- `timestamp` 是否一致。
- `frame_id` 和接触参考系是否说清。
- 是否有每一路自己的质量分和失败码。

## 一个最小视触融合 observation

```yaml
visuotactile_observation:
  timestamp: 2026-06-03T14:20:00.000Z
  object_id: mug_01
  camera_frame: wrist_color_optical_frame
  tactile_frame: gripper_left_pad
  visual_confidence: 0.81
  tactile_confidence: 0.88
  fused_state:
    contact_established: true
    slip_risk: 0.18
    local_alignment: good
  confidence: 0.84
  failure_code: null
```

这份结构说明了一件事：  
融合结果不是只剩一个总分，而是仍应保留各模态自己的状态与质量。

## 什么时候融合结果也不能继续用

即使做了融合，下面这些情况通常仍然要拒收：

| 情况 | 风险 |
|---|---|
| 两路时间戳明显错位 | 融合的是不同阶段状态 |
| 视觉对象身份不确定 | 触觉再稳定，也未必接触的是目标 |
| 触觉接触面明显饱和或丢失 | 局部证据已不可信 |
| 两路结论持续冲突 | 需要进入重观察或人工规则仲裁 |

所以多模态融合不是“消灭失败”，而是让失败边界表达得更清楚。

## 常见误区

| 误区 | 为什么错 |
|---|---|
| “视触融合就是把 feature 拼起来” | 真正难点常在同步、语义对齐和失败边界 |
| “有了触觉就不需要视觉” | 触觉看不到对象全局关系和环境上下文 |
| “视觉能看见成功，就不需要触觉验证” | 接触稳定性和微滑往往视觉不敏感 |
| “融合后就不需要分别记录各模态质量” | 下游仍需要知道是谁坏了 |
