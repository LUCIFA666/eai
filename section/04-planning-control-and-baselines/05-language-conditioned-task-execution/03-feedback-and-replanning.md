# 反馈纠错与重新规划

目标：说明语言条件任务执行不能只生成一次计划，而要根据感知、执行和安全反馈持续纠错。

本页需要覆盖：

- 反馈来源：控制器状态、导航结果、抓取成功/失败、感知置信度、接触/力觉事件、超时、安全触发和人工反馈。
- 失败码设计：目标不可达、对象丢失、碰撞风险、抓取滑移、定位漂移、语义不确定、技能超时、用户取消。
- 纠错动作：重观察、重新定位、换视角、换 grasp、换导航目标、降级到人工确认、终止任务。
- 重新规划触发条件：前置条件失效、执行失败超过阈值、地图更新、目标状态变化、风险升高、用户改指令。
- 计划更新方式：保留已完成子任务，更新未完成子任务，记录失败历史，避免无限重试同一动作。
- 日志与复盘：每次 replanning 要记录原因、输入状态、旧计划、新计划、执行结果和证据路径。
- 常见失败：把模型幻觉当事实、无限重试、失败码太粗、感知低置信度仍继续执行、重新规划破坏安全约束。

本页只保留写作框架，后续详细写作时应配一个“抓取失败后重观察再重试”的最小闭环例子。
