# 长程任务状态维护

目标：说明长程具身任务为什么需要显式状态记录，以及这些状态如何影响下一步技能选择和重新规划。

本页需要覆盖：

- 状态内容：任务阶段、已完成子目标、未完成子目标、已访问区域、已尝试对象、失败历史、当前地图版本、对象状态。
- 记忆粒度：短期执行状态、episode 内任务状态、跨 episode 的环境记忆和用户偏好要分开管理。
- 地图与任务状态：语义地图、拓扑图、对象列表和导航历史如何支持长程任务进度判断。
- 与世界模型的区别：本页维护可审计任务状态，不负责学习环境动力学或生成未来视频。
- 与第 8 章评测的连接：长程任务要记录中间成功率、子目标完成率、重规划次数、失败位置和最终任务成功。
- 存储格式：建议记录 `task_state.json`、`execution_trace.jsonl`、`map_version`、`skill_history` 和 `failure_summary`。
- 常见失败：状态和真实环境不一致、对象状态过期、遗忘已失败路径、不同模块各记一套状态、日志无法复盘。

本页只保留写作框架，后续详细写作时应给出一个“找物体-导航-抓取-放置”的任务状态更新示例。
