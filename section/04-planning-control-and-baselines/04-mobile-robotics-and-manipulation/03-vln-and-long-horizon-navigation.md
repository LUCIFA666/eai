# 视觉语言导航与长程任务

目标：说明语言条件导航和长程具身任务如何接入规划控制链路，重点是“语言目标如何落成可执行导航子目标”，而不是单独做 VLN 论文综述。

本页需要覆盖：

- VLN / ObjectNav / RoomNav / EQA / 长程任务的区别：语言指令、目标对象、目标房间、问答式探索和多阶段任务分别需要什么状态。
- 语言目标 grounding：把“走到沙发旁边”“找到杯子”“去厨房再拿水果”转成地图区域、对象候选、导航 waypoint 或子任务序列。
- 子目标选择：前沿探索、对象候选排序、房间级拓扑节点、历史轨迹、失败位置和置信度如何影响下一步导航目标。
- 长程任务状态维护：记录已访问区域、已尝试对象、失败动作、当前任务阶段、剩余约束和重新规划条件。
- 与导航栈的接口：VLM/VLN 模型输出不应直接控制底盘速度，通常应输出 subgoal、waypoint、object id、room id 或 exploration command，再交给 Nav2 / 局部控制器执行。
- 与移动操作的接口：导航到位不是任务完成，还要考虑 base placement、机械臂可达性、视角是否能看到目标、是否需要二次观察。
- 与第 8 章评测的连接：OmniNavBench、Habitat Challenge、AI2-THOR、RoboTHOR 等 benchmark 细节放评测章节，本页只说明它们对应哪类导航能力。
- 常见失败：语言歧义、目标 grounding 错误、地图缺失、探索陷入循环、到达位置不可操作、长程状态遗忘、成功判定和真实任务目标不一致。

本页只保留写作框架，后续详细写作时应优先围绕可运行环境、输入输出接口和失败日志组织，而不是堆论文列表。
