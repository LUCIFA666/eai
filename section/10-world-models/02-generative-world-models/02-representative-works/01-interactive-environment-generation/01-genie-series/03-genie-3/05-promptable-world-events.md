# Promptable World Events

## 本页目标

导航动作只能决定智能体如何在世界中移动。

Promptable World Events 允许外部文本在交互过程中改变世界本身。

本页重点解释：

```text
导航动作和世界事件有何区别？
文本如何改变天气、对象和角色？
为什么世界事件适合构造反事实场景？
世界事件是否等于智能体动作？
如何评价事件后的环境一致性？
```

## 导航动作与世界事件

导航动作包括：

```text
向前
向后
转向
改变相机
```

它们主要改变智能体的位置和观察方向。

Promptable World Events 可以：

```text
改变天气
加入对象
加入角色
改变局部世界状态
触发新的环境现象
```

可以概括为：

```text
导航动作：
智能体在世界中移动

世界事件：
外部条件改变世界本身
```

## 为什么需要世界事件

真实环境不会一直保持不变。

智能体可能遇到：

```text
突然降雨
道路出现障碍
新的角色进入场景
目标发生移动
光照和能见度变化
```

如果生成环境只支持移动和转向，就难以构造这些异常情况。

## 对象事件

<video src="./assets/genie3-event-object.mp4" controls width="100%"></video>

该视频来自 Google DeepMind 官方演示，展示向当前世界加入新对象或障碍。应观察对象的位置、透视、遮挡和后续持续性。对象成功出现不代表其具备精确碰撞体、物理参数或标准化任务状态。

## 角色事件

世界事件还可以引入新角色。

这会增加：

```text
角色外观保持
自主运动
遮挡关系
多个主体之间的互动
角色与环境的空间关系
```

官方也将复杂多智能体互动列为当前开放问题。

## 反事实环境

相同基础世界可以产生：

```text
正常天气轨迹
暴雨天气轨迹
道路出现障碍的轨迹
新角色加入的轨迹
```

这些反事实场景可以用于：

```text
策略鲁棒性
异常情况处理
重新规划
失败恢复
风险识别
```

## 为什么需要相同起点

反事实比较需要尽量保持：

```text
初始环境
角色状态
任务目标
```

只改变一个事件。

如果两个场景从一开始完全不同，就无法判断策略差异来自事件还是地图差异。

## 世界事件不等于智能体动作

文本触发暴雨，并不表示智能体学会了“制造暴雨”。

应区分：

```text
Agent Action：
智能体通过控制接口执行

World Intervention：
外部系统通过文本改变环境
```

官方也说明，世界事件不一定由 Agent 自身执行。

## 事件后的状态保持

事件发生后，模型还需要记住结果。

例如：

```text
道路出现障碍
-> 用户离开
-> 一段时间后返回
```

障碍是否仍然存在，是世界事件和环境记忆共同决定的问题。

## Project Genie 的功能范围

Promptable World Events 属于 Genie 3 研究展示能力。

Project Genie 的具体版本是否向用户开放该能力，应与底层模型研究能力分开理解。

本页只介绍 Genie 3 研究展示，不把该能力写成所有 Project Genie 用户都已拥有的固定功能。

## 如何评价世界事件

| 维度 | 核心问题 |
| --- | --- |
| 指令遵循 | 事件是否按文字要求出现 |
| 环境保持 | 原有场景是否保持连续 |
| 时间连续性 | 变化是否自然发生 |
| 对象持续性 | 新对象是否继续存在 |
| 可交互性 | 事件是否影响后续行动 |
| 局部控制 | 是否只改变指定因素 |
| 任务有效性 | 事件后任务是否仍能完成 |

## 能力边界

当前演示不能证明：

```text
任意事件都能执行
复杂多角色互动完全稳定
事件具有精确物理意义
事件结果能够永久保存
事件会自动生成奖励函数
```

## 本页小结

Promptable World Events 将 Genie 3 从可导航世界扩展为可由文本干预的动态世界。

天气、对象和角色能够在交互中加入，为智能体构造反事实和异常场景。但世界事件是外部干预，不等于 Agent 自己拥有对应动作。
