
# 实时可交互世界生成

## 本页目标

本页独立介绍 Genie 3 的实时生成过程，重点回答：

```text
世界描述如何成为可探索环境？
文本和图像分别起什么作用？
用户动作如何持续影响未来？
实时世界与普通视频续写有什么区别？
帧率、分辨率和延迟如何共同影响交互？
```

## 世界不是一次生成完成的

普通视频生成通常是：

```text
文本或图像
-> 一次生成完整视频
```

Genie 3 的世界则随着动作逐步展开：

```text
世界描述
-> 初始观察
-> 输入动作
-> 生成下一观察
-> 再输入动作
-> 继续生成新区域
```

用户转向此前没有观察的道路时，模型需要生成道路后方的新建筑、地形和对象。

## 文本描述世界

Genie 3 首发演示主要从文本 Prompt 生成世界。

一个完整世界描述可以包括：

```text
环境类型
地形和道路
天气与光照
视觉风格
第一人称或第三人称视角
受控主体
主体的移动方式
环境中的动态现象
```

例如，火山机器人场景同时描述：

```text
第一人称轮式机器人
黑色火山岩
需要避开的熔岩池
远处烟雾和岩浆
崎岖可通行地形
蓝色天空
```

这些信息不仅影响初始画面，也为后续运动和环境变化提供约束。

## 图像作为世界入口

Project Genie 允许使用生成图或上传图像创建 World Sketch。

图像决定：

```text
初始角色
局部环境
观察视角
视觉风格
初始地形
```

但单张图像不包含完整地图。

当用户离开初始视野后，模型仍需生成：

```text
建筑背面
道路延伸
遮挡区域
转弯后的空间
新的物体和植被
```

因此，图像是世界入口，而不是已经完成的三维环境文件。

## 闭环生成

在不假设具体网络结构的情况下，可以将交互抽象为：

```text
世界描述
+ 历史观察
+ 当前动作
-> 下一观察
```

历史信息使模型能够知道：

```text
用户从哪里来
之前看到过什么
某个对象是否已经离开视野
用户是否改变了环境状态
```

## 动作不只是移动整张画面

用户向前移动时，模型需要同时处理：

```text
近处物体快速靠近
远处物体变化较慢
遮挡关系更新
道路继续延伸
角色或载具动画变化
水、树木和烟雾继续运动
```

用户转动视角时，模型还需要生成此前不可见的区域。

## 第一人称和第三人称

第一人称中：

```text
相机代表智能体位置
转向改变大部分画面
前进改变物体相对尺度
```

第三人称中：

```text
角色需要稳定出现在画面
相机需要跟随角色
角色动画要与输入方向匹配
环境相对角色和相机同时变化
```

不同视角需要不同的动作解释和场景生成规律。

## 帧率与控制延迟

20–24 FPS 表示画面更新频率，但完整体验还受到：

```text
输入延迟
网络延迟
生成延迟
界面渲染延迟
角色控制稳定性
```

影响。

即使画面达到 24 FPS，动作很久后才生效，用户仍会感到明显迟滞。

## 720p 与感知细节

720p 可以提供更清晰的：

```text
道路边缘
远处目标
小型障碍
建筑入口
角色轮廓
局部纹理
```

这些细节对视觉智能体很重要，但也增加每帧计算成本。

## 轨迹分叉

同一个世界起点可以产生：

```text
向左探索的轨迹
向右进入另一条道路的轨迹
停留观察环境的轨迹
转身返回旧区域的轨迹
```

不同动作序列决定不同未来，这是交互世界与固定视频的根本区别。

## 随机性的双重影响

生成随机性带来：

优点：

```text
环境更丰富
可以获得不同经验
适合探索反事实
```

问题：

```text
实验难以完全复现
任务难度可能变化
目标位置可能不稳定
不同 Agent 难以公平比较
```

用于正式 benchmark 时，需要额外控制随机性和任务条件。

## 本页小结

Genie 3 使用文本或图像定义世界起点，再根据动作实时生成下一观察。

真正的挑战不是单独达到 20–24 FPS，而是让动作、相机、空间、角色和动态环境在闭环控制中共同保持稳定。720p 提升了感知信息，也使实时生成更困难。
