
# 长时一致性与环境记忆

## 本页目标

实时生成世界如果只能稳定几秒，就难以支持长程导航和复杂任务。

本页重点解释：

```text
为什么自回归世界容易累积误差？
数分钟一致性具体包括什么？
一分钟视觉记忆应如何理解？
环境外观记忆和动作结果记忆有何不同？
```

## 自回归误差

Genie 3 根据生成历史继续预测：

```text
历史观察
+ 当前动作
-> 下一观察
```

如果某一帧中房屋位置出现轻微偏差，该偏差会进入后续历史。

误差可能形成：

```text
第一次偏差
-> 下一帧继续使用偏差状态
-> 场景结构逐步变化
-> 回访时环境与原来不同
```

## 一致性的不同层次

| 类型 | 需要保持的内容 |
| --- | --- |
| 角色一致性 | 角色外观、尺寸和运动方式 |
| 对象一致性 | 建筑、树木和道路不会随意改变 |
| 空间一致性 | 不同区域保持合理位置关系 |
| 状态一致性 | 用户造成的变化能够持续 |
| 动态一致性 | 水、天气和其他角色变化连续 |
| 视角一致性 | 转身和回访时环境与之前匹配 |

官方表示 Genie 3 能够在数分钟交互中保持较高一致性。

## 一分钟视觉记忆

官方介绍指出，部分视觉内容可以追溯到约一分钟前。

这不意味着模型逐像素保存完整画面，而是：

```text
对象重新进入视野时，
模型能够恢复其主要外观和位置关系。
```

## 对象持续性

当房屋、树木或道路离开相机视野时，模型仍需要记住其存在。

否则，回访会出现：

```text
房屋颜色改变
树木数量变化
门的位置变化
道路方向改变
建筑被重新生成
```

## 动作结果记忆

记住用户造成的变化比记住静态房屋更加困难。

模型需要区分：

```text
世界的初始状态
用户已经执行的动作
动作造成的新状态
```

例如，粉刷墙面、加入对象或改变天气后，结果应继续影响未来。

## 跨区域一致性

传送门或多区域案例要求模型维护：

```text
入口外部环境
入口内部可见区域
进入后的新环境
返回时原环境
```

这比在单一道路上持续前进更困难，因为模型需要维持多个区域之间的连接关系。

## 一致性为什么被称为涌现能力

Genie 3 没有公开传统引擎式的：

```text
地图文件
对象数据库
精确物体坐标
三维网格
可查询状态表
```

环境结构主要通过世界描述、历史和动作维持。

因此，长时一致性是一种生成能力，而不是显式状态系统提供的确定性保证。

## 与三维重建的差别

NeRF 或 Gaussian Splatting 通常根据真实场景的多视角数据建立稳定表示。

Genie 3 可以从文本创建不存在的动态世界，但其几何和对象状态不具有同样明确的显式保证。

## 当前边界

数分钟一致性不意味着：

```text
可以连续运行数小时
所有对象都永久保存
每次回访完全一致
拥有精确可查询地图
所有动作结果都不会丢失
```

仍可能出现小物体消失、建筑变化、道路漂移和角色外观改变。

## 对长程智能体任务的意义

环境记忆使智能体有机会：

```text
绕过建筑后返回
寻找之前见过的目标
在多个区域之间导航
执行多步探索
保留部分操作结果
```

但智能体自身仍需要任务记忆、规划和位置估计。

## 如何评价环境记忆

可以关注：

| 指标 | 含义 |
| --- | --- |
| 回访一致性 | 返回旧位置后主要对象是否仍存在 |
| 对象持续率 | 离开视野的对象能否重新出现 |
| 状态保持 | 用户造成的变化是否持续 |
| 空间闭环 | 绕行后能否回到合理区域 |
| 角色稳定性 | 长轨迹中角色是否变化 |
| 任务持续性 | 长程目标是否仍可完成 |

## 本页小结

Genie 3 可以在数分钟交互中保持较高环境一致性，并恢复约一分钟前出现的部分视觉内容。

房屋粉刷等案例体现了动作结果记忆，但这种记忆仍是隐式生成能力，不等于显式地图、永久存储或确定性的游戏引擎状态。
