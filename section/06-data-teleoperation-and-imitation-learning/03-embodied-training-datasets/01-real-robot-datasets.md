# 大规模真机数据集

目标：建立阅读大规模真机或真机相关数据集的统一检查框架，能从本体、任务、模态、格式、许可和采集流程判断数据是否适合自己的项目。

大规模真机数据集可以看成不同实验室、机器人平台和任务场景积累下来的“机器人经验库”。它们不是普通视频集，也不只是动作日志，而是把视觉、机器人状态、动作、语言、任务边界、采集流程、硬件平台和许可约束放在一起。读这类数据时，别只问“有多少条轨迹”，还要追问：这些轨迹来自什么机器人，做了什么任务，每一步动作是什么意思，有没有语言指令，是否包含人类隐私，能不能公开训练或再分发。

这里展示了 9 个具有代表性的大规模真机或真机相关数据源。比较它们时，不要只按规模排序；更要看它们各自的数据建设思路：跨机器人混合、工业化采集、多模态统一、远程操控、双臂协作、人机交互隐私，以及复杂接触条件。

## 读数据集时先看六件事

### 1. 看机器人本体

机器人本体决定了动作空间、状态空间和安全边界。机械臂、双臂机器人、移动操作机器人、人形机器人即使都在执行“拿起物体”，其动作表示也可能完全不同。

读数据集时至少要问：

```text
robot_type 是什么？
末端执行器是什么，是夹爪、灵巧手还是吸盘？
action 是关节空间、末端空间，还是底盘 + 手臂联合空间？
不同机器人之间是否共享同一种 action convention？
```

如果一个数据集覆盖多种机器人，就要格外注意它是否提供 `robot_type`、动作维度说明、状态字段说明和控制频率。否则，即使数据很多，也不一定能直接用于你的训练目标。

### 2. 看任务集合

任务集合决定数据是否覆盖目标技能。任务数量多不一定代表对你有用，关键是任务类型是否接近你的研究问题。

可以把任务粗略分成几类：

```text
基础物体操作：抓取、放置、移动、推拉
工具和容器操作：开门、开抽屉、倒入、取出
长程组合任务：多个动作阶段串联完成
双臂协作任务：左右臂同时或交替配合
人机交互任务：人类参与、语音或手势辅助
导航和移动操作：底盘移动与操作结合
```

如果你研究的是桌面抓取，DROID、BridgeData V2、RoboMIND 可能更直接；如果你研究跨机器人泛化，Open X-Embodiment 更合适；如果你研究多模态接触，RH20T、FUSE 或 ARIO 更值得看。

### 3. 看数据模态

机器人数据不只是图像。典型模态包括：

```text
视觉：RGB、深度、腕部相机、外部相机、多视角视频
状态：关节角、关节速度、末端位姿、夹爪状态
动作：控制指令、末端增量、关节目标、底盘速度
语言：任务指令、片段描述、自动标注或人工标注
触觉：接触传感器、力/力矩、触觉图像
声音：环境声音、交互声音、操作声音
元信息：任务 id、场景 id、机器人 id、数据来源、成功标签
```

模态越多，不代表越容易用。多模态数据的难点在于时间对齐、缺失模态处理、采样频率不同和训练接口复杂。比如一个模型如果只接收 RGB 图像和动作，那么触觉和声音最好先作为 metadata 或分析字段处理，而不是强行塞进训练。

### 4. 看数据格式

数据格式决定你能不能顺利读取、转换和训练。前面已经讲过 HDF5、RLDS、LeRobot 等格式，这里要把它们和具体数据集联系起来。

常见情况包括：

```text
RLDS / TFDS：常见于 Open X-Embodiment、DROID、BridgeData V2 等生态，适合按 episode/step 读取。
HDF5：常见于不少机器人演示数据，集中存储轨迹、图像、状态和动作。
LeRobot 风格：适合把数据整理成 meta/data/videos 结构，便于可视化、训练和共享。
原始文件结构：有些数据会保留视频、图片、pkl、json、状态文件等，需要先做 schema 审计。
```

格式不是最核心的问题，字段语义才是。一个数据集即使用了 RLDS，也不代表 action 已经统一；一个数据集即使用了 HDF5，也不代表它不可用。要检查的是字段名、shape、dtype、单位、时间戳、episode 边界和 metadata。

### 5. 看许可与隐私

真机数据集往往可能包含真实实验室、真实人类、真实语音、真实场景。使用前要确认：

```text
是否允许商用？
是否允许再分发？
是否允许公开展示视频帧？
是否包含人脸、语音或个人行为？
是否需要脱敏？
是否区分商业子集和非商业子集？
```

RH20T 这类人机交互数据尤其要先看隐私和许可。即使你的研究只是训练模型，也要确认模型发布、样例展示、数据再分发是否被许可允许。

### 6. 看采集流程

采集流程决定数据质量是否可追踪。一个高质量机器人数据集通常不只是“有人采了很多数据”，而是有明确的采集协议、标注规则、失败处理和质检流程。

重点看：

```text
数据是统一采集还是多来源汇聚？
由人类遥操作、脚本策略还是自动策略产生？
是否保留失败轨迹？
是否有人类质检？
是否有任务分段和关键帧？
是否公开硬件和采集代码？
是否有 raw data 和标准化格式两个版本？
```

DROID 这类数据集公开硬件和训练代码，适合从采集系统一路读到训练管线。AgiBot World 更适合学习工业化数据生产线。Open X-Embodiment 则更适合研究多来源数据如何汇聚和混合。

## 九个数据集分别适合什么

### Open X-Embodiment：看跨本体数据混合

Open X-Embodiment 适合用来理解“多机器人数据混合”这件事。它不是一个实验室用同一种机器人采出来的数据，而是把多个已有机器人数据集整理到统一训练接口中。它的核心价值是规模和覆盖面，尤其适合研究通用机器人策略、跨本体迁移和数据混合配方。

使用 Open X 时，先别只问“能不能加载”，而要问“加载出来的数据能不能放在一起训练”。不同子数据集之间的机器人、相机、任务文本和 action convention 都可能不同。如果只是训练某个单一机器人任务，直接使用 Open X 全量数据未必合适；如果研究 robot foundation model 或 VLA 的数据配方，它才更有代表性。

官方页：https://robotics-transformer-x.github.io/

### AgiBot World Datasets：看工业化数据生产线

AgiBot World Datasets 更像工业化采集体系下的数据产品。它强调同构或较统一的机器人平台、规模化轨迹、多级质检和人工在环。和 Open X 这种多来源汇聚不同，AgiBot 的重点在于采集流程、任务分层、质量控制和数据封口。

它适合用来学习真实机器人数据是怎样批量生产出来的：任务如何拆分，轨迹如何质检，失败如何处理，人工如何参与闭环。使用时要注意，它的数据一致性较强，但跨本体泛化不能默认成立。如果目标机器人和 AgiBot 使用的平台差异较大，仍然需要检查 action 和 state 的可迁移性。

官方页：https://agibot-world.com/

### RoboMIND：看多任务真实演示和物体分布

RoboMIND 适合观察真实多任务演示如何组织。它覆盖多种协作臂、多类物体和大量任务，重点不是某一个任务做得特别深，而是提供较宽的任务类别和物体类别覆盖。

读 RoboMIND 时要特别关注任务 taxonomy 和物体 taxonomy。很多机器人学习问题并不是缺少轨迹，而是缺少足够丰富的任务和物体变化。RoboMIND 的价值就在于可以分析任务类别、物体类别和演示质量之间的关系。使用时，不同机械臂的数据是否能混训，需要看状态和动作语义是否被明确映射。

官方页：https://x-humanoid-robomind.github.io/

### ARIO：看多模态统一

ARIO 的重点是多模态统一。它不应该只被当成普通图像 + action 数据，而要从 2D、3D、文本、触觉、声音等模态共同理解。它还涉及操作、导航、真实和仿真数据的统一视角。

读 ARIO 时要重点看时间戳和模态对齐。多模态数据最容易出现的问题是：图像、触觉、声音和状态采样频率不同，某些 episode 缺少部分模态，不同来源的数据 schema 不完全一致。如果模型并不使用触觉或声音，就不应该在文档里夸大这些模态的训练价值，而应该说明它们在当前任务中是训练输入、辅助标签还是 metadata。

官方页：https://imaei.github.io/project_pages/ario/

### FUSE Dataset：看遮挡、远程操控和多传感器融合

FUSE Dataset 适合研究复杂视觉条件下的远程操控和多传感器融合。它的特点不是轨迹数量特别大，而是任务环境里包含遮挡、语言指令、触觉、声音等对感知有挑战的条件。

如果一个模型只在干净桌面、无遮挡、单一相机条件下训练，它在真实世界中很容易失败。FUSE 的价值就在于把遮挡和多模态信号放到数据里，让研究者可以分析模型在困难感知条件下是否仍能完成任务。使用时要分清遮挡样本是训练增强、常规训练数据，还是专门评测难例。

官方页：https://fuse-model.github.io/

### BiPlay Dataset：看双臂操作和语言片段

BiPlay Dataset 适合观察双臂轨迹如何和语言描述结合。它和单臂操作数据不同，关键在于左右臂动作的同步、协调和片段边界。它还包含从长 episode 中切出的 clips，因此不能简单把每个 clip 当成完整 episode。

读 BiPlay 时要特别注意：视频片段边界是否等于动作起止边界，语言描述是对应整个片段还是片段中的某个子动作，双臂 action 是同步记录还是分臂记录。对于双臂策略训练来说，左右臂之间的时间关系和动作分工，比单个动作维度本身更重要。

官方页：https://dit-policy.github.io/

### DROID：看真实大规模分布式采集

DROID 是典型的真实大规模机器人操作数据源。它的价值不只是轨迹数量和采集小时数，还在于硬件平台、场景、任务、代码和数据格式一起公开，方便研究者从采集系统一路理解到训练数据。

DROID 适合研究真实场景泛化：同一个机器人在不同房间、不同桌面、不同物体和不同操作者下采集数据。这种数据最大的风险是 split 泄漏。如果训练集和测试集只按 frame 或随机 trajectory 切分，很可能出现相似场景、相似任务或相同操作者泄漏。更合理的做法是按场景、任务、操作者或物体分布进行验证。

官方页：https://droid-dataset.github.io/

### BridgeData V2：看多环境、多技能和条件输入

BridgeData V2 适合用来理解多环境、多技能数据如何连接到条件输入。它同时包含目标图像和语言指令，也混合了远程操控和脚本策略数据，因此很适合研究“给定目标图像或语言，机器人如何完成对应技能”。

使用 BridgeData V2 时，要区分不同数据来源。teleoperation demonstration 和 scripted rollout 的数据分布不同，质量、偏差和动作风格也不同。训练时可能需要 source weighting 或 source filtering。它还适合做跨环境验证：同一技能在不同环境中能不能泛化，比单个环境内的成功率更能说明问题。

官方页：https://rail-berkeley.github.io/bridgedata/

### RH20T：看人机交互和接触丰富操作

RH20T 的重点是人机交互和接触丰富操作。它包含多模态记录，可能涉及 RGB、Depth、红外、力/力矩、音频、触觉等信息，因此适合研究接触、交互和多模态感知。

RH20T 也是这一页里最需要强调隐私和合规的数据集之一。含有人脸、语音或人类行为的视频不能只当作普通训练样本。使用前要确认许可范围、是否可商用、是否能公开展示样例、是否需要脱敏，以及是否只保留低维派生特征。技术问题之前，先解决使用边界问题。

官方页：https://rh20t.github.io/

## 如何选择适合自己的数据集

下面给出一个粗略选择思路。

如果你的目标是研究通用机器人策略或 VLA 数据混合，优先看 Open X-Embodiment、DROID、BridgeData V2。

如果你的目标是学习真实数据采集工程，优先看 AgiBot World Datasets 和 DROID。前者更像工业化生产线，后者更像开放硬件和分布式真实采集系统。

如果你的目标是多模态融合，优先看 ARIO、FUSE 和 RH20T。ARIO 强调统一多模态结构，FUSE 强调遮挡、触觉和声音，RH20T 强调人机交互和接触丰富操作。

如果你的目标是双臂协作，优先看 BiPlay Dataset，并关注左右臂同步、语言片段和 clip 边界。

如果你的目标是单一机器人、单一任务的快速模仿学习，不一定需要优先选择最大的数据集。更重要的是数据和目标机器人、目标任务、目标动作空间足够接近。
