# 任务到动作的执行链路

## 本章概述

对于初次接触具身智能的读者而言，一个最容易产生的问题是："当我向机器人发送一条任务指令之后，它究竟是如何一步一步完成动作的？"

例如，当用户输入一句简单的自然语言指令：

**"抓取桌面上的红色杯子。"**

对于人类来说，这句话表达的是一个十分明确的任务目标；但对于机器人而言，这条指令必须经过环境感知、策略推理、动作生成、控制执行以及状态反馈等多个环节，最终才能转化为机械臂运动、电机旋转和夹爪闭合等真实物理动作。

现代具身智能系统通常采用分层的软件架构，高层负责理解任务和生成动作，底层负责执行控制和状态反馈。各个模块之间通过统一的数据接口进行通信，共同构成了一条完整的机器人执行链路（Execution Pipeline）。理解这条链路，有助于理解后续的策略训练、数据采集、仿真部署以及真实机器人控制等内容。

本章将围绕一条典型的机器人执行流程展开，介绍任务如何逐步转换为机器人动作，并说明各个模块之间传递的数据类型及职责。同时重点区分 Observation 与 Robot State 的不同作用，解释为什么策略模型输出不能直接驱动机器人硬件，以及控制器与硬件反馈在整个闭环系统中的作用。

## 从任务到动作的整体执行流程

无论是固定机械臂、移动机器人、移动操作机器人还是人形机器人，大多数具身智能系统都可以概括为如下执行流程：

```text
Task Instruction
        │
        ▼
Observation
        │
        ▼
Policy
        │
        ▼
Action
        │
        ▼
Adapter
        │
        ▼
Controller
        │
        ▼
Actuator
        │
        ▼
State Feedback
        │
        └────────────────────┐
                             ▼
                  下一轮 Observation
```

整个流程形成了一个持续运行的闭环控制（Closed-loop Control）系统。

系统首先接收任务指令，通过传感器获取环境信息和机器人状态，由策略模型生成动作，再经过动作适配转换为机器人能够执行的控制命令，由控制器驱动执行机构完成运动。机器人运动后，传感器再次读取最新状态，并反馈给系统，作为下一轮策略推理的输入。

因此，机器人并不是一次性完成整个任务，而是在不断"感知—决策—执行—反馈"的循环过程中逐步完成任务目标。

## Task Instruction：任务目标

执行链路的起点是任务指令（Task Instruction）。

任务指令描述机器人需要完成什么，而不是告诉机器人如何运动。

任务可以来自多个来源，例如：

- 用户输入的自然语言
- 上层任务规划器
- 预定义技能（Skill）
- 调度系统
- 遥操作指令

例如：

```text
Pick up the red cup.
```

```text
Open the drawer.
```

```text
Move to the kitchen.
```

对于现代 Vision-Language-Action（VLA）模型而言，任务指令通常会作为模型输入的一部分，与视觉信息共同参与策略推理。

任务指令本身不包含任何机器人控制参数，而是定义了机器人需要完成的目标。

## Observation：机器人对环境的观测

机器人在执行任务之前，需要首先了解当前环境。

这一阶段产生的数据称为 Observation（观测）。

Observation 描述的是机器人当前能够感知到的外部世界，它主要面向环境理解和任务决策。

典型 Observation 包括：

- RGB 图像
- 深度图（Depth）
- 点云（Point Cloud）
- 多视角相机图像
- 激光雷达数据
- 当前任务描述
- 环境语义信息
- 历史观测数据

例如，在机械臂抓取任务中，Observation 可能包括：

```text
Camera Image
```

![camera](../assets/2-1-2_camera.png)

```text
Task:
Grab the red cup.
```

策略模型正是依据这些环境信息判断目标的位置、姿态以及障碍物分布，从而生成下一步动作。

Observation 更关注的是机器人"看到什么""感知到了什么"，而不是机器人自身当前的运动状态。

## Robot State：机器人自身状态

除了环境观测之外，机器人还需要了解自身当前所处的状态。

这部分信息通常称为 Robot State（机器人状态）。

Robot State 主要描述机器人本体的运动状态以及执行反馈，例如：

- Joint Position
- Joint Velocity
- Joint Torque
- Base Pose
- Base Velocity
- IMU 数据
- Gripper State
- Motor Status
- Battery State

Observation 与 Robot State 的主要区别在于两者关注的对象不同。

Observation 面向环境和任务，用于描述机器人所感知到的外部世界，例如图像、点云、目标位置和任务指令等；Robot State 则面向机器人本体，用于描述机器人自身当前的姿态、关节状态、运动速度以及执行反馈。

在现代具身智能系统中，这两类信息通常会共同作为策略模型的输入。一方面，机器人需要知道目标物体在哪里；另一方面，也需要知道自己的机械臂当前处于什么位置、夹爪是否已经闭合以及底盘是否仍在运动。只有同时结合环境信息和自身状态，策略模型才能生成合理且安全的控制动作。

## Policy：策略生成动作

策略（Policy）是机器人执行链路中的决策核心。

策略模型接收 Observation、Robot State 以及任务指令，根据当前环境和任务目标计算机器人下一步应该执行的动作。

策略可以采用多种不同实现方式，例如：

- Reinforcement Learning
- Diffusion Policy
- VLM/LLM + coding
- Vision-Language-Action（VLA）模型

无论采用哪一种算法，其输出通常都是一种抽象的动作表示（Action）。

例如：

```text
Δx = +0.04 m

Δy = -0.02 m

Δz = +0.03 m

Gripper = Close
```

或者：

```text
Joint Position

Joint1 = 0.52 rad

Joint2 = -0.31 rad

...

Joint6 = 1.43 rad
```

需要特别注意的是，这些动作仍属于策略层输出，并不能直接发送给机器人硬件执行。

## Adapter：动作适配与接口转换

策略输出通常采用统一的动作表示，而不同机器人支持的控制接口却各不相同，因此需要一个中间层完成动作适配（Adapter）。

Adapter 位于策略与控制器之间，负责将策略输出转换为机器人能够理解的控制命令。

这一过程中通常需要完成多个步骤。

首先，需要确定动作空间定义。例如，策略输出的是关节角度、关节速度还是末端位姿，不同机器人支持的控制方式可能完全不同，因此需要将动作映射到目标控制模式。

其次，需要完成单位转换。例如，策略输出采用国际单位制（米、弧度），而机器人控制接口可能采用毫米、角度或编码器计数值，因此需要进行统一换算。

随后，需要进行坐标转换。策略模型通常在世界坐标系或相机坐标系下生成动作，而机器人控制器一般要求基于机器人基坐标系或工具坐标系进行控制，因此需要完成坐标系之间的变换。

为了保证机器人运行安全，还需要对动作进行限幅处理，包括限制关节角度、运动速度、加速度以及力矩等参数，防止策略输出超过机器人允许范围。

最后，由于策略模型和控制器通常运行在不同频率下，还需要完成控制频率匹配。例如，策略可能以 10 Hz 输出动作，而机器人控制器需要以 500 Hz 的频率接收控制命令，因此 Adapter 通常需要进行插值、缓存或重复发送，使动作能够连续稳定地执行。

经过这些转换之后，策略动作才真正成为机器人控制器可以执行的标准控制指令。

## Controller：控制器执行命令

Controller（控制器）负责接收 Adapter 输出的控制命令，并按照固定控制周期驱动机器人执行动作。

控制器通常运行在实时系统中，直接与驱动器和执行机构通信，因此承担着机器人运动控制和安全管理的重要职责。

控制器的主要功能包括：

- 接收目标动作指令；
- 根据控制模式生成实时控制信号；
- 按照固定控制频率发送控制命令；
- 管理机器人运动过程；
- 判断动作是否执行完成；
- 监测异常情况并触发安全保护。

需要强调的是，控制器并不负责理解任务，也不会参与策略推理，它仅负责可靠地执行来自上层系统的控制命令。

## Actuator 与 Hardware Feedback：执行与反馈

控制器生成的控制信号最终会发送给执行机构（Actuator），由执行机构完成真实物理运动。

执行机构通常包括：

- 电机
- 驱动器
- 减速器
- 液压执行器
- 气动执行器

这些硬件负责将数字控制信号转换为机械运动，例如：

- 电机旋转；
- 机械臂关节运动；
- 底盘移动；
- 夹爪闭合；
- 灵巧手手指运动。

与此同时，机器人硬件会持续产生反馈信息（Hardware Feedback）。

这些反馈不仅用于更新 Robot State，也是控制器判断动作执行情况的重要依据。

典型反馈包括：

- 当前关节位置；
- 当前关节速度；
- 当前关节力矩；
- IMU 状态；
- 电机温度；
- 力传感器数据；
- 夹爪开合状态；
- 当前控制模式。

控制器根据这些反馈持续监测机器人运行状态，并向上层系统报告执行结果。例如，当机器人成功到达目标位置时，控制器会返回任务完成（Completed）；如果检测到通信异常、关节超限、碰撞或执行时间超过设定阈值，则会返回相应的故障（Fault）或超时（Timeout）信息。

这些反馈不仅保证机器人能够安全运行，同时也为下一轮策略决策提供最新状态，实现完整的闭环控制。

## 机械臂抓取示例

下面以"机械臂抓取桌面上的红色杯子"为例，说明整条执行链路中各模块传递的信息。

用户首先输入任务指令："抓取桌面上的红色杯子"。系统接收到任务后，相机采集当前桌面图像，深度相机获取目标物体距离信息，同时机器人读取当前机械臂关节角度、夹爪状态等 Robot State。这些信息共同组成策略模型的输入。

策略模型根据任务目标和环境观测，判断红色杯子的位置，并生成下一步动作，例如现代 VLA 模型里主干网络的作用。例如，策略输出"机械臂末端向前移动 5 cm，保持当前姿态，夹爪保持张开"。这一动作仍属于抽象动作表示，并不能直接驱动机器人。

随后，Adapter 将动作转换为机器人支持的控制格式，包括计算对应的关节目标位置、完成坐标系转换、统一单位、限制运动范围以及按照控制器要求的频率发送控制命令。

Controller 接收到目标关节指令后，按照固定控制周期驱动各关节电机，使机械臂逐渐靠近目标位置。当机械臂到达抓取姿态后，控制器继续执行夹爪闭合命令，完成对杯子的抓取。

整个过程中，关节编码器持续回传关节位置，夹爪反馈当前开合状态，力传感器监测接触力，控制器不断判断机器人是否已经到达目标位置、是否发生碰撞以及是否出现超时或故障。当动作执行完成后，最新的 Robot State 会重新参与下一轮 Observation，策略模型再根据新的环境状态决定后续动作，例如抬起杯子、移动到目标位置并完成放置。

通过这一示例可以看到，机器人真正执行一项任务并不是一次性的控制过程，而是一个持续进行"感知—决策—执行—反馈"的闭环系统，每一个模块都承担着不可替代的职责。

## 本章小结

机器人完成一项任务，需要经历从任务理解到动作执行的完整控制链路。系统首先根据任务指令和环境观测生成策略动作，再经过动作适配、控制执行和硬件反馈等多个环节，最终将抽象动作转换为真实机器人运动。

在整个过程中，Observation 主要描述机器人所感知到的环境和任务信息，Robot State 则反映机器人本体的实时状态和执行反馈，两者共同构成策略决策的重要输入。策略输出不能直接驱动机器人硬件，而必须经过动作空间定义、单位转换、坐标转换、安全限幅以及控制频率匹配等步骤，才能生成符合机器人控制接口要求的标准控制命令。控制器负责可靠执行这些命令，并持续接收硬件反馈，报告任务完成情况以及 Fault、Timeout 等异常状态，从而形成完整的闭环控制系统。

理解这一执行链路，有助于后续进一步学习机器人控制架构、数据采集、策略训练以及真实机器人部署等内容，也为理解具身智能系统的软件组织方式奠定了基础。
