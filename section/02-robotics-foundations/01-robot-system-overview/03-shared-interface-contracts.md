# 跨仿真、数据、策略与真机的接口契约

## 本章概述

在具身智能系统中，一个完整的机器人研发流程通常会经历多个阶段，包括机器人建模、仿真验证、数据采集、模型训练、策略评测以及最终的真机部署。虽然这些阶段分别对应不同的软件系统和运行环境，但它们处理的对象始终是同一台机器人。因此，机器人在不同阶段所使用的数据格式、控制接口和状态描述必须保持一致，否则即使每个模块本身都能够正常工作，整个系统仍然无法顺利衔接。

例如，一条在仿真环境中采集得到的数据，如果关节顺序与训练代码读取的顺序不同，那么训练出的策略将学习到错误的动作映射；一个在仿真中表现良好的策略，如果真实机器人使用了不同的坐标系定义或控制单位，也可能导致动作方向错误甚至引发安全事故。这类问题往往不是算法本身造成的，而是由于接口定义不一致导致的数据和控制语义发生偏差。

为了解决这一问题，现代机器人软件系统通常都会建立一套统一的**接口契约（Interface Contract）**。接口契约规定了机器人状态、动作、坐标系、单位以及数据组织方式等基础约定，使仿真平台、数据集、训练框架和真机控制系统能够围绕同一套接口进行开发和协作。

本章将介绍接口契约的基本概念，分析机器人系统中需要保持一致的核心字段，总结跨平台开发过程中常见的不一致问题，并说明接口契约对于实验复现、策略迁移以及基准评测的重要意义。最后，本章给出一份建议的最小接口检查表，为后续真机部署和系统评测章节奠定基础。

## 什么是接口契约

接口契约可以理解为机器人系统各个模块之间共同遵守的一套数据规范和通信约定。它并不是一种具体的软件框架，而是一组保证不同模块能够正确交换信息的统一规则。

对于同一台机器人而言，从仿真环境到真实机器人通常会经历如下几个阶段：

```text
机器人模型
      │
      ▼
仿真环境
      │
      ▼
数据采集
      │
      ▼
数据集
      │
      ▼
模型训练
      │
      ▼
策略部署
      │
      ▼
真实机器人
```

这些阶段虽然运行在不同的软件平台中，例如 Gazebo、Isaac Sim、MuJoCo、ROS、LeRobot、PyTorch 或机器人厂商 SDK，但它们描述的始终是同一个机器人。如果不同阶段对机器人采用了不同的命名方式、不同的坐标系定义或不同的控制语义，那么整个系统将无法保证数据能够正确流动。

因此，接口契约的核心思想可以概括为一句话：

**机器人在仿真、数据集、训练代码和真机控制中，应共享一致的命名、单位、顺序和语义。**

只有这样，才能真正避免不同系统之间频繁进行格式转换和人为适配。

## 接口契约需要统一哪些内容

接口契约不仅包括通信接口，还涉及机器人状态、动作以及各种元数据的统一定义。其中，以下几个字段通常需要在整个机器人研发流程中保持一致。

首先是**关节名称（Joint Name）**。每个关节都应具有唯一且固定的名称，例如 `shoulder_pan_joint`、`elbow_joint`、`wrist_roll_joint` 等。关节名称是机器人模型、控制器和数据集之间建立对应关系的基础，不同系统应避免出现同一关节使用多个名称或多个关节使用相同名称的情况。

其次是**关节顺序（Joint Order）**。虽然机器人拥有相同数量的关节，但不同软件中关节数组的排列顺序可能不同。如果训练数据按照一种顺序记录，而控制器按照另一种顺序读取，那么策略输出的每一个关节动作都会发送到错误的执行机构。因此，关节顺序必须在仿真、数据记录、训练代码和控制接口之间保持完全一致。

第三是**坐标系标识（Frame ID）**。机器人通常包含世界坐标系、机器人基坐标系、相机坐标系、工具坐标系等多个参考坐标系。接口契约需要明确每个状态量或动作量所属的坐标系，并统一各坐标系之间的方向定义和命名方式，避免由于坐标系理解不同而导致运动方向错误。

此外，还需要统一**时间戳（Timestamp）**。机器人中的传感器、控制器和数据记录模块通常工作在不同频率下，统一时间基准能够保证多源数据之间正确同步，为后续的数据对齐、训练和回放提供依据。

机器人控制过程中所使用的**单位（Unit）**同样需要统一。例如位置统一采用米（m），角度统一采用弧度（rad），速度统一采用米每秒（m/s）或弧度每秒（rad/s），力矩统一采用牛·米（N·m）。统一单位能够避免不同模块之间重复进行单位换算，同时减少由于单位混用造成的控制错误。

对于动作接口，还需要统一**控制模式（Control Mode）**。不同机器人支持的位置控制、速度控制、力矩控制或末端位姿控制具有完全不同的含义，因此策略输出和控制器输入必须明确采用同一种控制模式，否则即使动作数值完全一致，也可能产生截然不同的运动结果。

除此之外，机器人状态字段（State Field）、动作字段（Action Field）以及故障码（Error Code）等内容，也应保持统一的命名和语义。例如，关节位置始终使用 `joint_position` 表示，而不是在不同模块中分别使用 `q`、`angle`、`position` 等不同名称；机器人发生急停、通信超时或关节超限时，也应采用统一的错误码进行描述，方便不同模块识别和处理。

## 常见的接口不一致问题

在机器人研发过程中，接口定义的不一致是导致系统调试困难和实验无法复现的重要原因。相比算法错误，这类问题更加隐蔽，往往需要经过大量排查才能定位。

最常见的问题之一是**关节顺序错位**。例如，数据集中的第三个关节对应机器人肩关节，而控制器却将第三个关节解释为腕部关节，那么策略输出的动作虽然数值正确，却会驱动错误的执行机构，最终表现为机器人动作完全异常。

另一类常见问题是**角度和弧度混用**。深度学习模型通常采用弧度表示关节角度，而部分工业机器人接口仍然使用角度（Degree）。如果缺少单位转换，原本只有几十度的目标角度可能被误认为几十弧度，从而导致机器人关节快速撞向机械限位。

**坐标系方向不一致**也是机器人系统中经常出现的问题。例如，相机采用右手坐标系，而机器人控制器采用左手坐标系；或者仿真平台定义 Z 轴向上，而真实机器人定义 Y 轴向上。这类差异会导致目标位置和运动方向发生偏移，即使策略模型本身预测正确，也无法获得预期动作。

对于依赖多传感器融合的系统，还经常出现**时间戳漂移**的问题。相机、IMU、编码器和控制器如果没有统一时间基准，就可能导致同一时刻的数据来自不同时间点，从而影响状态估计和策略推理，甚至引起控制延迟。

此外，还需要注意**仿真限位与真机限位不同**的问题。仿真环境通常允许机器人运动到理论极限，而真实机器人为了保证安全，会设置更加保守的软件限位或硬件限位。如果接口契约没有统一这些约束，策略在仿真中能够顺利执行，但部署到真机后可能频繁触发限位保护，导致任务失败。

## 接口契约对系统复现的影响

建立统一的接口契约，不仅能够减少系统开发过程中的调试工作，更直接影响机器人实验的可复现性和不同平台之间的兼容能力。

首先，接口契约决定了一份数据能否被准确回放。只有数据记录时使用的关节顺序、时间戳、单位和坐标系与回放程序保持一致，机器人才能按照原始轨迹完成运动。否则，即使数据文件本身没有损坏，也无法正确重现采集过程。

其次，接口契约影响策略模型的跨平台部署能力。如果不同机器人平台遵循相同的状态定义和动作接口，那么策略模型无需修改即可部署到新的机器人平台，只需完成少量与机器人硬件相关的适配工作即可。这也是近年来越来越多机器人软件框架采用统一 Observation 和 Action 定义的重要原因。

此外，统一接口也是实现公平 Benchmark 的前提条件。多个机器人平台如果采用不同的数据字段、控制频率或状态定义，那么它们的实验结果将难以直接比较。只有在统一接口契约的基础上，才能保证不同算法面对的是相同的输入信息、相同的动作空间以及相同的评测标准，从而使 Benchmark 结果具有可比性和可信度。

因此，接口契约不仅是一套软件规范，更是连接仿真、数据、训练和真机部署的共同语言，是实现机器人系统可迁移、可复现和可扩展的重要基础。

## 建议的最小接口检查表

为了降低接口不一致带来的风险，在机器人系统开始数据采集、模型训练或真机部署之前，建议首先完成一份基础接口检查。对于大多数具身智能平台而言，以下内容应作为最低限度的检查项：

| 检查项 | 检查内容 |
|--------|---------|
| Joint Name | 是否所有模块使用完全一致的关节名称 |
| Joint Order | 是否所有关节数组顺序完全一致 |
| Frame ID | 是否统一世界坐标系、机器人坐标系和工具坐标系 |
| Timestamp | 是否采用统一时间基准，支持多传感器同步 |
| Unit | 是否统一长度、角度、速度、力矩等单位 |
| Control Mode | 是否明确位置控制、速度控制或力矩控制模式 |
| State Field | 是否统一机器人状态字段名称及含义 |
| Action Field | 是否统一动作字段定义及维度 |
| Error Code | 是否统一故障码、异常状态和超时定义 |

上述检查表主要用于建立机器人系统的基础接口一致性。在实际工程中，还需要进一步检查通信协议、消息格式、坐标变换树、控制频率、安全策略、实时性能以及设备同步等内容。这些更详细的接口验证方法将在后续真机部署、机器人通信以及系统评测章节中进一步介绍。

## 本章小结

机器人研发并不是孤立地完成仿真、训练或真机部署，而是一个贯穿机器人全生命周期的系统工程。为了保证不同阶段之间的数据能够顺利流转，同一台机器人必须在仿真环境、数据集、训练框架和真实控制系统之间共享一致的接口契约，包括统一的命名方式、字段定义、单位、坐标系、控制模式以及状态语义。

实践中，大量难以定位的问题都源于接口定义的不一致，例如关节顺序错误、单位混用、坐标系方向相反、时间戳不同步以及仿真与真机参数不一致等。这些问题虽然不会影响单个模块的正常运行，却会破坏整个机器人系统的数据一致性，最终导致策略无法部署、实验无法复现或评测结果缺乏可比性。

因此，在机器人系统设计初期建立统一的接口契约，并在整个研发流程中持续遵循这一规范，是实现数据可回放、策略可迁移、实验可复现以及平台可扩展的重要前提，也是现代具身智能软件架构中的核心基础设施之一。
