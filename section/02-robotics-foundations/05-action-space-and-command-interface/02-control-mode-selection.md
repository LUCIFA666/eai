# 控制模式选择

机器人策略在输出动作之后，并不会直接驱动电机运动，而是需要经过机器人控制器（Controller）进行解释和执行。控制器根据不同的控制模式（Control Mode），将策略输出转换为具体的电机控制命令。因此，即使策略输出完全相同，不同控制模式下机器人的实际行为也可能完全不同。

例如，一个策略输出关节增量：

```text
[+0.02, -0.01, +0.03, ...]
```

如果机器人运行在位置控制（Position Control）模式下，这组数据会被解释为新的关节目标位置；而如果运行在速度控制（Velocity Control）模式下，则可能被解释为目标关节速度；在阻抗控制（Impedance Control）模式下，又可能表示期望运动轨迹，由控制器结合环境接触力共同决定最终运动。

因此，动作空间（Action Space）定义了**策略输出什么**，而控制模式决定了**机器人如何理解和执行这些输出**。二者共同构成了具身智能系统中策略与机器人本体之间的执行接口。

需要强调的是，本节关注的是控制接口层（Interface Layer）的设计，而不是底层控制器的数学推导，不讨论具体控制律的稳定性分析，而重点介绍不同控制模式能够接收哪些命令、返回哪些反馈，以及它们适用于哪些机器人和任务。

## 常见控制模式

机器人控制系统通常支持多种控制模式，不同模式控制目标不同，对机器人硬件能力的要求也不同。目前机器人最常见的控制模式包括位置控制、速度控制、力矩控制、阻抗控制、导纳控制以及混合控制。

## Position Control（位置控制）

位置控制是工业机器人和大多数协作机器人最常见的控制模式，也是目前具身智能最广泛采用的执行接口。

在位置控制模式下，策略输出的是目标关节位置（Joint Position）或目标末端位姿（End-effector Pose），机器人底层控制器负责驱动电机不断逼近目标位置。

典型命令字段包括：

```text
joint_position_target
```

或

```text
ee_pose_target
```

机器人反馈给策略的信息通常包括：

```text
joint_position
joint_velocity
joint_effort
```

策略本身无需关心电机如何完成运动，只需要不断更新目标位置即可。

例如：

```text
Joint1 = 35°
Joint2 = 18°
```

机器人控制器会自动规划较平滑的运动轨迹，并利用内部的 PD 控制器逐渐逼近目标位置。

位置控制具有以下特点：

- 控制稳定，调试简单；
- 控制器成熟，工业应用广泛；
- 对策略学习难度较低；
- 安全性较高，便于加入速度和位置限幅。

因此，目前大量模仿学习（Imitation Learning）和视觉语言动作模型（VLA）最终都会将策略输出转换为位置控制命令。

其不足之处在于，机器人无法主动调节与环境之间的接触力。当机器人发生碰撞或接触障碍物时，控制器仍会持续尝试到达目标位置，容易产生较大的接触力，因此不适合需要柔顺交互的任务。

## Velocity Control（速度控制）

速度控制模式中，策略输出的是关节速度或末端速度，而不是目标位置。

常见命令字段包括：

```text
joint_velocity
```

或

```text
cartesian_velocity
```

机器人反馈通常包括：

```text
position
velocity
effort
```

控制器按照控制周期不断积分速度：

```text
Position += Velocity × Δt
```

因此策略需要持续输出新的速度命令，否则机器人会逐渐停止。

速度控制特别适用于：

- 连续轨迹跟踪；
- 移动机器人导航；
- 遥操作系统；
- 强化学习连续控制。

例如移动机器人通常输出：

```text
vx
vy
ω
```

分别表示：

- 前向速度；
- 横向速度；
- 角速度。

速度控制具有响应快、运动连续的优点，但如果速度命令异常或者控制周期不稳定，机器人可能持续运动甚至失控，因此通常需要配置严格的速度上限和通信超时保护。

## Torque Control（力矩控制）

力矩控制直接控制电机输出力矩，是机器人能够开放的最低层控制接口之一。

策略输出的是：

```text
joint_torque
```

单位通常为：

```text
Nm
```

机器人反馈一般包括：

```text
position
velocity
measured_torque
```

在这种模式下，策略实际上决定了机器人每个关节施加多大的驱动力，而不是希望运动到哪里。

例如：

```text
Joint1 = 2.5 Nm
Joint2 = -1.2 Nm
```

机器人会依据动力学产生对应运动。

力矩控制能够实现最高的控制精度，也是实现动态运动、全身平衡控制以及强化学习控制的重要基础。例如四足机器人、人形机器人以及高动态机械臂往往采用力矩控制完成跳跃、奔跑或复杂接触任务。

但与此同时，力矩控制也具有最高的风险。策略输出如果存在较大误差，机器人可能立即产生较大的驱动力，引发剧烈运动甚至损坏设备。因此，开放力矩接口的机器人通常需要具备完善的安全机制，包括力矩限幅、关节保护、碰撞检测和实时故障监测。

## Impedance Control（阻抗控制）

阻抗控制（Impedance Control）并不是直接控制位置或力，而是人为定义机器人在受到外界作用力时应表现出的“机械特性”。

可以将机器人想象成一个由弹簧和阻尼器组成的系统。当机器人偏离目标位置时，会产生类似弹簧恢复力；当机器人运动速度较快时，又会产生阻尼作用，使运动逐渐稳定下来。因此，机器人不会僵硬地追踪目标，而是能够在保持目标位置的同时允许一定程度的偏移。

典型命令字段包括：

```text
target_pose
stiffness
damping
force_limit
```

反馈信息通常包括：

```text
position
velocity
contact_force
joint_torque
```

阻抗控制广泛应用于：

- 插接装配；
- 打磨抛光；
- 开门；
- 人机协作；
- 柔顺抓取。

例如机器人执行插孔任务时，如果目标位置略有偏差，位置控制可能直接撞击孔壁，而阻抗控制允许机器人轻微退让，在接触过程中自动调整姿态，更容易完成插入动作。

因此，阻抗控制成为目前协作机器人和操作机器人中最重要的柔顺控制方式之一。

## Admittance Control（导纳控制）

导纳控制（Admittance Control）可以看作阻抗控制的“反向实现”。

阻抗控制通常接受位置目标，根据外力调整输出力；而导纳控制则首先测量机器人受到的外力，再根据测得的力计算机器人应该产生怎样的运动。

典型命令字段通常包括：

```text
desired_force
compliance_parameter
```

反馈字段包括：

```text
measured_force
position
velocity
```

导纳控制需要机器人配备力传感器，因此更多用于：

- 人机协作；
- 外力拖动示教；
- 医疗机器人；
- 康复机器人。

例如，人轻轻推动机器人手臂，机器人即可根据检测到的外力主动跟随运动，实现自然的拖动示教，而无需人工解除伺服。

对于不具备高性能力传感器的机器人，导纳控制通常难以实现。

## Hybrid Control（混合控制）

现实中的机器人任务往往同时需要位置控制和力控制，因此出现了混合控制（Hybrid Control）。

混合控制通常将不同自由度采用不同控制方式。

例如：

```text
X、Y方向控制位置

Z方向控制接触力

Yaw控制姿态
```

机器人执行打磨任务时：

- 平面内沿轨迹移动；
- 垂直方向保持恒定压力。

这种控制方式能够兼顾轨迹精度和接触稳定性，因此广泛应用于：

- 抛光；
- 装配；
- 焊接；
- 打磨；
- 医疗操作。

混合控制通常要求机器人具备较强的实时控制能力和高精度力反馈，因此更多出现在高端工业机器人和研究平台中。

## 相同策略输出在不同控制模式下的含义

动作空间定义了策略输出的数据格式，而控制模式决定了这些数据如何被机器人解释。因此，相同的策略输出，在不同控制模式下可能具有完全不同的物理意义。

例如策略输出：

```text
Δq = +0.02
```

在位置控制模式下，这一数值通常表示关节目标位置增加 0.02 rad，即控制器将当前位置作为参考，生成新的目标位置并驱动关节运动。

在速度控制模式下，同样的数值可能表示目标关节速度为 0.02 rad/s，机器人会按照该速度持续运动，直到收到新的速度指令或停止命令。

在阻抗控制模式下，策略输出的位姿变化则更多体现为新的期望平衡点，机器人是否真正到达这一位置，还会受到刚度、阻尼以及外界接触力的共同影响。

因此，在设计策略接口时，必须明确动作数据对应的控制模式。如果策略与控制器对同一数据采用不同解释方式，即使数据格式完全一致，也可能导致机器人行为异常甚至产生安全风险。

## 控制模式与机器人硬件能力的关系

并不是所有机器人都支持所有控制模式。控制模式的开放程度通常由机器人硬件能力、驱动器性能以及厂商的软件接口共同决定。

工业机器人为了保证系统稳定性和设备安全，大多数仅向用户开放位置控制接口。用户可以设定目标关节位置或末端位姿，而底层伺服控制、轨迹规划以及力矩控制均由机器人控制器内部完成，用户无法直接访问。

协作机器人通常在位置控制基础上进一步开放阻抗控制或导纳控制接口，使机器人能够完成柔顺装配、人机协作和拖动示教等任务。

移动机器人则更多开放速度控制接口，例如底盘速度、轮速控制等，而不会允许用户直接控制每个电机的力矩。

对于四足机器人、人形机器人以及科研平台，为了支持强化学习、全身控制和高动态运动，厂商通常会开放力矩控制接口，甚至允许用户直接访问电机驱动层。但与此同时，这类平台也需要更加完善的安全保护机制，对控制算法和使用者提出更高要求。

因此，在部署具身智能策略之前，需要首先确认机器人实际支持哪些控制模式，而不是默认所有策略都能够直接输出任意控制命令。

## 控制接口中的关键参数

除了动作命令本身之外，机器人控制接口通常还包含若干重要参数，它们决定了机器人运动的稳定性、柔顺性以及安全性。

### PD 参数

PD（Proportional-Derivative）参数是位置控制和阻抗控制中最常见的控制参数。

其中：

- **P（Proportional）** 决定机器人偏离目标位置时产生多大的纠正作用。比例增益越高，机器人越倾向于快速回到目标位置，但过高可能引起振荡。
- **D（Derivative）** 决定机器人对运动速度变化的抑制能力，相当于增加阻尼，使运动更加平稳，减少超调。

很多机器人虽然不允许用户直接修改底层控制律，但会开放 PD 参数的配置接口，以适应不同任务需求。

### Stiffness（刚度）

刚度描述机器人抵抗位置偏差的能力。

刚度越高，机器人越"硬"，会更努力地保持目标位置；刚度越低，机器人越容易受到外力影响而产生位移，因此柔顺性更好。

在阻抗控制中，刚度通常是最重要的调节参数之一。

### Damping（阻尼）

阻尼用于抑制机器人运动过程中的速度变化。

较大的阻尼可以减少震荡，使机器人停止更加平稳；阻尼过小则容易产生摆动甚至振荡。因此，在柔顺控制中通常需要结合刚度共同调节。

### Force Limit（力限制）

力限制（Force Limit）用于限制机器人能够施加的最大接触力或关节输出。

例如：

```text
Max Contact Force = 20 N
```

当机器人检测到接触力超过设定值时，可以主动减速、停止运动或进入保护状态，从而降低碰撞风险。

力限制在人机协作、柔顺抓取以及精密装配任务中具有重要作用，也是保障机器人安全运行的重要参数。

## 选择控制模式时必须检查的内容

在真实机器人部署过程中，仅选择合适的控制模式还远远不够，还需要确保控制接口满足系统实时性和安全性的要求。

首先，应确认控制频率是否满足策略要求。不同机器人支持的控制周期差异较大，位置控制可能工作在几十赫兹，而力矩控制通常需要几百赫兹甚至上千赫兹。如果策略更新频率低于控制器要求，机器人可能出现抖动、迟滞甚至进入故障状态。

其次，应检查所有动作命令是否进行了合理的限幅，包括位置、速度、加速度、力矩以及接触力等。任何未经限制的策略输出都有可能超出机器人硬件能力，引发危险运动。

急停（Emergency Stop）机制同样不可忽视。控制系统应能够在通信中断、策略异常或碰撞检测触发时立即停止机器人运动，并确保机器人进入安全状态。

此外，策略每次发送控制命令后，都应及时读取机器人的实际状态反馈，包括当前位置、速度、力矩、传感器信息以及控制器状态，而不能仅依赖理论目标值。通过持续的状态回读，可以及时发现跟踪误差、通信异常或执行失败等问题。

最后，需要建立完善的 Fault（故障）处理机制。当机器人进入过流、过热、碰撞、编码器异常或驱动器报警等故障状态时，策略应停止发送动作命令，并按照控制器规定的流程完成故障确认、恢复和重新初始化，而不是继续执行后续动作。对于真实机器人而言，完善的故障处理流程往往与控制算法本身同等重要。

## 本节小结

控制模式决定了机器人如何解释和执行策略输出，是连接动作空间与机器人执行机构的关键接口。位置控制、速度控制、力矩控制、阻抗控制、导纳控制以及混合控制分别适用于不同的机器人硬件和任务场景，其差异不仅体现在控制目标上，也体现在命令字段、反馈信息、安全性以及对硬件能力的要求上。

需要注意的是，相同的动作表示在不同控制模式下可能具有完全不同的含义，因此策略接口设计必须与机器人控制模式保持一致。同时，控制模式的选择受到机器人硬件开放接口的限制，并需要综合考虑控制频率、命令限幅、急停机制、状态回读以及故障处理等工程因素。对于具身智能系统而言，优秀的策略只有建立在可靠、安全且与硬件匹配的控制接口之上，才能稳定地部署到真实机器人平台。
