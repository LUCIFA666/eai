# 策略到控制器的接口适配

在前面的几节中，我们分别讨论了动作空间设计、控制模式选择、位姿到关节命令的转换以及轨迹命令与安全执行。这些概念共同定义了一个问题：策略模型的输出（Action）与机器人控制器能够接受的输入（Controller Command）之间存在显著的格式差异和语义鸿沟，需要经过系统的转换和校验才能安全对接。

策略到控制器的接口适配层（Adapter）正是为了解决这一对接问题而存在。Adapter 的职责不是在策略层面修改模型行为，而是在策略与控制器之间建立一个稳定的转换边界，将策略的"意图"转化为控制器能够理解和执行的"指令"，同时确保指令的合法性、安全性和时效性。

本节介绍 Adapter 需要完成的各项转换任务、运行约束处理、安全防护措施以及日志记录要求。本节不讨论具体 VLA 模型结构或训练方法，而是聚焦于部署时策略与机器人控制器之间的接口边界定义。

## Adapter 的核心职责

Adapter 的位置处于策略输出与控制器输入之间，承担着翻译器（Translator）和守门人（Gatekeeper）的双重角色。

作为翻译器，Adapter 必须将策略输出的数据格式转换为控制器接口所要求的格式。策略可能输出末端位姿增量，而控制器只接受关节位置命令；策略可能使用毫米作为单位，而控制器要求使用米；策略可能按照自己的关节编号输出动作，而控制器的关节顺序不同。这些格式差异如果不经处理直接传递，会导致机器人行为与预期完全不同。

作为守门人，Adapter 必须确保每一条发送给控制器的命令都是安全且合法的。策略由于训练数据偏差、环境变化或模型自身不确定性，可能输出超出机器人运动范围、违反安全约束甚至物理上不可执行的动作。Adapter 在命令到达控制器之前进行裁剪、限幅和校验，承担最后一道安全防线。

Adapter 的设计原则是不改变策略的语义——即不"纠正"策略的决策——但保证策略意图在执行层面是合法的。如果策略想做的事在当前条件下不可行，Adapter 应拒绝该命令或将其降级为安全的替代动作，而不是静默地修改策略的意图。

## 必须处理的数据转换

策略输出与控制器命令之间的差异涉及多个维度，Adapter 需要依次完成以下转换，确保每一步的输出都是下一步合法的输入。

**Token/Action 解码**是面向语言模型或 VLA 模型的特殊步骤。这些模型的原始输出通常是离散的 token 序列而不是连续的数值向量，因此 Adapter 首先需要将 token 解码为动作数值。例如，模型输出：

```text
<action>
  <pos>0.45, 0.12, 0.30</pos>
  <rot>0.0, 0.7071, 0.0, 0.7071</rot>
  <gripper>0.8</gripper>
</action>
```

Adapter 需要将这些结构化或半结构化的文本解析为数值向量，才能进行后续处理。对于直接输出连续向量的模仿学习策略，此步骤可以跳过。

**单位转换**确保策略输出与控制器接口使用相同的物理单位。常见的单位差异包括：

```text
策略输出角度单位: degree       →  控制器要求: rad
策略输出位置单位: mm           →  控制器要求: m
策略输出速度单位: cm/s         →  控制器要求: m/s
```

如果角度被误当作弧度处理，机器人旋转量可能相差约 57 倍。因此单位转换是 Adapter 中最基础但也最容易出错的环节，通常应在转换流水线的最前端完成。

**坐标系转换**解决策略输出与控制器命令处于不同参考坐标系的问题。例如：

```text
策略输出: Camera Frame 下的抓取位姿
控制器要求: Base Frame 下的目标位姿
```

Adapter 需要利用机器人的 TF 树（Transform Tree）查找 Camera Frame 到 Base Frame 的变换关系，并将策略输出的位姿从源坐标系变换到目标坐标系。这一步骤依赖准确的传感器外参标定——如果外参不准确，变换后的位姿将带系统性的空间偏差。

**Absolute/Relative 转换**处理策略输出绝对目标还是相对增量的差异。如果策略输出相对增量而控制器需要绝对目标：

```text
策略输出: Δx = +0.05  (相对增量)
         ↓  加上当前末端位置
控制器命令: x_target = x_current + 0.05  (绝对目标)
```

反之，如果策略输出绝对目标而控制器需要相对增量，则减去当前状态即可。当前状态来自机器人实时反馈，而不是策略的记忆或估计。

**关节顺序映射**解决策略训练数据与目标机器人之间关节编号不一致的问题。不同机器人的关节索引、命名和顺序可能完全不同：

```text
策略训练数据（机器人 A）:    [shoulder, elbow, wrist_1, wrist_2, wrist_3]
目标机器人（机器人 B）:      [base_joint, shoulder_joint, elbow_joint, wrist_pitch, wrist_roll]
```

Adapter 需要维护一个明确的关节映射表，将策略输出向量中的每个元素正确映射到目标机器人的对应关节上。关节顺序错误比单位错误更难排查——机器人可能会动，但动的关节不对，而位置反馈看起来"数值合理"。

**夹爪映射**处理末端执行器的控制差异。策略可能输出二值的开/关信号，而目标机器人的夹爪可能需要连续的位置控制；策略可能以 0～1 的比例表示开合程度，而目标夹爪使用 0～255 的 PWM 值或 0～1000 的编码器计数。夹爪映射通常还涉及逻辑信号的转换——例如策略输出的 1（关闭）可能对应目标夹爪的 0（最小开口），需要根据实际硬件约定进行适配。

## 运行约束的适配处理

除了数据转换之外，Adapter 还需要处理策略与控制器在运行时特性上的不匹配。两者的推理/控制频率、延迟容忍以及命令时效性可能完全不同。

**控制频率（Control Rate）与策略频率（Policy Rate）**往往不一致。典型的机器人控制频率为 50～1000 Hz，而策略模型（尤其是大型 VLA 模型）的推理频率可能只有 1～10 Hz。这意味着在策略的连续两次输出之间，控制器需要多个周期的控制命令。

Adapter 处理频率不匹配的常见策略包括：

- **零阶保持（Zero-Order Hold）**：在下一帧策略输出到达之前，重复发送上一帧的动作命令。简单但可能导致机器人行为滞后。

- **插值（Interpolation）**：在两个相邻策略动作之间进行线性或平滑插值，生成中间帧的控制命令。插值可以显著提高运动平滑性，但需要策略输出的语义支持（例如相对动作适合插值，绝对动作需要小心处理）。

- **动作块执行（Action Chunk Execution）**：策略一次输出多步动作（例如未来 10 步），Adapter 在每个控制周期依次弹出下一步，无需等待策略的新输出。ACT、Diffusion Policy 等方法普遍采用这一模式。

**动作时效（Action Horizon）**是指策略输出的动作在多长时间内仍然有效。如果策略更新频率较低，而机器人运动速度较快，上次策略输出的动作可能在下一帧到达之前就已不再适用。Adapter 需要为每个动作设置有效时间窗口，超出窗口仍未更新的动作应触发保守处理（如减速、保持或进入安全状态），而不是无限制地继续执行。

**延迟管理（Latency Management）**关注从策略产生输出到机器人实际执行之间的时间延迟。延迟来源包括：模型推理时间、网络传输时间、Adapter 处理时间以及控制器接收队列的排队时间。在高速运动或需要精确时序配合的任务中（例如动态抓取），延迟可能导致机器人错过任务窗口。Adapter 可以通过时间戳标记、前向预测或延迟补偿等机制在接口层面缓解延迟影响。

**命令超时（Command Timeout）**是控制器端的保护机制。如果控制器在一定时间内（例如 200 ms）没有收到新的有效命令，应自动进入安全状态——通常是减速到零或保持当前位置。Adapter 必须确保以高于超时阈值的频率持续发送命令，否则控制器将频繁触发超时保护，导致机器人不断停止。

**命令平滑（Command Smoothing）**用于滤除策略输出的高频噪声或突变。原始策略输出可能存在帧间跳变，直接发送给控制器会导致机器人抖动或振荡。Adapter 可以在输出端应用低通滤波、移动平均或速率限制，使实际发送的命令变化更加平缓。需要注意的是，平滑会引入额外的延迟，因此平滑强度需要在运动平顺性和响应速度之间权衡。

## 安全处理措施

Adapter 是策略与控制器之间的最后一道安全关口。即使策略输出了不合理的动作，Adapter 也必须确保发出的命令在物理上是安全的。

**动作裁剪（Action Clipping）**将策略输出的每个维度限制在预设的安全范围内。例如：

```text
关节增量最大步长: |Δq_i| ≤ 0.1 rad
末端位置增量最大步长: |Δx|, |Δy|, |Δz| ≤ 0.05 m
夹爪开合范围: [0.0, 1.0]
```

裁剪操作不修改策略的决策方向，只限制幅度。这样即使策略输出了一个极大的动作，机器人也只会按照安全上限运动，不会发生剧烈动作。

**工作空间钳制（Workspace Clamp）**确保末端目标位姿不会超出机器人的安全工作空间。如果策略输出的目标位置位于工作空间之外，Adapter 将其投影到工作空间边界上最近的合法点。工作空间通常以轴对齐包围盒或多边形边界的形式预定义在配置文件中。

**速度限制（Velocity Limit）**不仅约束轨迹的关节速度，也约束 Adapter 输出的命令所隐含的速度。对于输出位姿增量的策略，速度隐含在增量大小和控制周期的比值中。Adapter 应检查隐含速度是否超出硬件限制，必要时降低增量或增大步数。

**碰撞保护（Collision Protection）**在可行的情况下对 Adapter 输出的目标进行快速碰撞检测。虽然完整的碰撞检测通常由运动规划器完成，但 Adapter 可以基于简化的环境模型进行轻量级检查，至少应排除目标位姿导致的显式自碰撞。如果检测到碰撞风险，应拒绝该命令并通知策略或上层规划器。

**低速模式（Low-speed Mode）**是部署期间的核心安全策略。通过全局速度缩放因子（Velocity Scaling Factor）：

```text
0.1 ~ 0.25
```

将机器人实际运动速度限制在额定速度的 10%～25%。低速模式允许策略和开发者在真实机器人上安全地调试和验证行为，而不必担心策略异常输出造成严重后果。当系统经过充分验证后，可以逐步提高速度因子。

**失败回退（Failure Fallback）**定义当 Adapter 无法生成合法命令时的行为。例如，IK 求解失败、坐标系变换信息缺失或碰撞检测不通过时，Adapter 应进入预定义的降级状态而不是抛出异常或静默跳过。典型的回退策略包括：保持当前位置（Holding）、减速到零（Soft Stop）、返回预定义安全姿态（Home Position）。回退策略的选择取决于具体的任务场景和风险等级。

**急停信号（E-Stop Signal）**是最高优先级的安全机制。Adapter 必须持续监控急停信号的状态——无论来自物理按钮、软件指令还是碰撞检测——并在急停触发时立即停止发送运动命令，转为发送停止指令或进入静默模式。急停恢复后，Adapter 不应自动继续执行急停之前的动作序列，而应等待策略重新评估环境状态后发送新的指令。

## Adapter 需要记录的日志

机器人在真实环境中运行时，很多问题不是立刻暴露的——它们可能在运行几分钟、几小时甚至几天后才出现。当出现异常时，如果只有"机器人撞了"的结论而没有数据支撑，几乎无法排查原因。Adapter 作为策略与控制器之间的信息枢纽，是记录系统运行日志的关键节点。

**Raw Action（原始动作）**是策略模型的直接输出，记录了策略的原始意图。保留原始动作对于分析策略行为、评估模型质量以及排查训练数据偏差都具有重要价值。原始动作也是衡量后续转换步骤是否引入误差的基准。

**Converted Command（转换后命令）**是经过 Adapter 全部转换和处理后最终发送给控制器的命令。同时记录原始动作和转换后命令，可以在事后逐步骤追溯：如果机器人行为异常，是因为策略输出了错误的动作，还是因为转换过程中出现了错误。

**State Before/After（执行前后状态）**记录命令执行前后机器人的实际状态，包括关节位置、末端位姿、速度和力矩等。执行前后的状态差异反映了命令的实际执行效果，是判断命令是否生效、是否存在跟踪误差的直接依据。

**Timestamp（时间戳）**为每一条日志记录精确的时间信息。在没有时间戳的情况下，只能知道"发生了什么"而不知道"什么时候发生的"，无法进行时序分析和因果推断。时间戳应使用统一的时钟源（如系统单调时钟），避免因时钟同步问题导致的数据不一致。

**Frame ID（坐标系标识）**为所有涉及空间位置的记录标注所属坐标系。同样的 (0.45, 0.12, 0.30) 在 base_link、camera_link 和 map 坐标系下是完全不同的物理位置。记录 frame_id 可以在事后分析和坐标系变换时避免歧义。

**Error Code（错误码）**记录转换和执行过程中出现的任何异常。错误码应以结构化方式记录（而非简单的"失败"），至少包括：错误类型（编码）、错误描述、触发条件和时间。结构化的错误码便于自动化监控和报警系统进行统计分析。

一条完整的日志至少应包含：

```text
timestamp: 1723000456.789
frame_id: base_link
raw_action: [0.02, -0.01, 0.03, 0, 0.01, -0.02, 0]
converted_command: [0.02, -0.01, 0.03, 0, 0.005, -0.02, 0]  # 注意 Joint 5 被裁剪
state_before: [0.50, -1.20, 0.85, 0.30, 0.15, -0.40, 0.60]
state_after: [0.52, -1.21, 0.88, 0.30, 0.155, -0.42, 0.60]
error_code: 0  (no error)
```

通过完整的日志记录，可以在事后复现和分析机器人的完整行为链路，将"机器人为什么动错了"转化为可追溯的数据排查过程。

## 本节小结

策略到控制器的接口适配层（Adapter）是连接模型智能与机器人执行的关键中间件，承担着翻译器和守门人的双重角色。Adapter 需要完成从策略输出到控制器命令的全链路转换，包括 token/动作解码、单位转换、坐标系转换、绝对/相对转换、关节顺序映射以及夹爪映射。这些转换必须在保持策略语义的前提下确保命令格式的合法性。

在运行时维度上，Adapter 需要通过零阶保持、插值或动作块执行等方式解决策略频率与控制频率不匹配的问题，同时管理动作时效、延迟和命令超时，确保控制器始终收到合法且及时的命令。命令平滑在抑制策略输出噪声方面也发挥着重要作用。

安全方面，Adapter 作为最后一道防线，通过动作裁剪、工作空间钳制、速度限制、碰撞保护、低速模式、失败回退和急停监控等多层机制，确保任何发送给控制器的命令都不会超出机器人的物理安全边界。

最后，Adapter 需要对全链路数据进行结构化日志记录。原始动作、转换后命令、执行前后状态、时间戳、坐标系标识和错误码等信息，是将运行时异常转化为可排查的数据问题的关键基础。完整的日志链路使策略到执行的过程从"黑盒"变为"可追溯"，是确保机器人系统长期稳定运行的重要工程实践。
