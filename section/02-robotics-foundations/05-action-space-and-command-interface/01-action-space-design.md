# 动作空间设计

动作空间（Action Space）描述了机器人策略（Policy）每一步能够输出什么类型的控制指令，是连接智能决策与机器人执行系统之间最重要的接口之一。对于具身智能而言，无论策略来自模仿学习（Imitation Learning）、强化学习（Reinforcement Learning）还是视觉-语言-动作模型（Vision-Language-Action, VLA），最终都必须将模型输出转换为机器人能够理解并执行的控制命令。因此，动作空间本质上定义了策略与机器人之间的"语言"。

很多初学者容易将动作空间理解为"机器人有哪些动作"，实际上二者并不完全相同。机器人能够完成抓取、移动、开门、装配等复杂任务，但策略通常不会直接输出这些动作名称，而是输出更加底层的控制变量，例如关节角度增量、末端位姿变化量、底盘速度或者夹爪开闭状态。机器人控制系统再根据这些控制量驱动电机运动，最终完成具体任务。

因此，本节讨论的重点并不是哪一种动作空间更优秀，而是分析策略输出究竟应该以什么形式表示，才能稳定、高效地落到机器人真实可执行的控制接口上。

## 常见动作空间类型

不同机器人平台由于运动结构不同，其动作空间设计也有所区别。目前具身智能系统最常见的动作空间主要可以分为关节空间动作、任务空间动作、移动底盘动作、末端执行器动作以及高级语义动作几类。

### Joint Position Delta（关节位置增量）

这是目前使用最广泛的一类动作空间。策略每一步输出所有关节相对于当前状态需要变化的角度（或位移）。

对于一个具有 $n$ 个自由度的机械臂，当前关节状态为

$$q_t=[q_1,q_2,\cdots,q_n]$$

策略输出

$$\Delta q=[\Delta q_1,\Delta q_2,\cdots,\Delta q_n]$$

机器人执行后更新为

$$q_{t+1}=q_t+\Delta q$$

例如，一个 7 自由度机械臂一次策略输出可能为：

```text
[+0.02, -0.01, +0.03, 0, 0.01, -0.02, 0]
```

意味着每个关节仅移动很小的角度。

这种表示方式具有多个优点：

- 输出连续，容易学习；
- 对控制误差具有一定鲁棒性；
- 即使上一时刻存在少量误差，也不会无限累积；
- 易于直接接入机器人底层 Position Controller。

目前大量模仿学习数据集（如 LeRobot、ALOHA、ACT 等）都采用这一表示方式。

### Joint Velocity Delta（关节速度）

另一种方式不是输出目标位置，而是输出各关节速度：

$$\dot q=[\dot q_1,\dot q_2,\cdots,\dot q_n]$$

机器人按照控制周期积分：

$$q_{t+1}=q_t+\dot q \Delta t$$

这种方式更加符合传统运动控制器接口，也常见于强化学习环境，因为速度控制更加平滑，适合连续运动。

但速度积分容易产生累计误差，因此很多真实机器人仍然会在更底层增加位置闭环控制。

### End-effector Pose Delta（末端位姿增量）

另一大类动作空间直接描述机器人末端执行器（End Effector）的运动，而不是各关节。

策略输出通常包括：

- 三维平移

$$(\Delta x,\Delta y,\Delta z)$$

- 三维旋转

例如：

- Roll-Pitch-Yaw
- Rotation Matrix
- Quaternion
- Axis-angle

组合后形成

$$a=[\Delta x,\Delta y,\Delta z,\Delta r_x,\Delta r_y,\Delta r_z]$$

机器人随后通过逆运动学（Inverse Kinematics）求解对应关节角度。

这种表示最大的优点是：

动作直接对应任务目标。

例如：

抓杯子：

```text
向前5cm
下降3cm
夹紧
```

比直接控制七个关节更符合人类直觉。

因此大量视觉策略（Visual Servoing、Diffusion Policy 等）都采用末端位姿作为动作表示。

缺点在于：

- 依赖稳定的逆运动学；
- 奇异位姿处理较复杂；
- 不同机器人之间 IK 求解器不同。

### Base Velocity（移动底盘速度）

移动机器人通常需要控制底盘。

策略输出一般为：

$$(v_x,v_y,\omega)$$

分别表示：

- 前向速度
- 横向速度（全向底盘）
- 偏航角速度

例如：

```text
[0.3,0,-0.2]
```

表示：

机器人前进 0.3 m/s，同时顺时针旋转。

对于差速底盘，则通常只有

$$(v,\omega)$$

即可。

移动机器人策略很多采用这种动作接口。

### Gripper Open / Close（夹爪控制）

夹爪通常单独作为一个动作维度。

最简单的是：

```text
0
```

表示关闭。

```text
1
```

表示打开。

也可以输出连续值：

$$g\in[0,1]$$

表示夹爪张开程度。

例如：

```text
0.72
```

表示夹爪张开 72%。

对于灵巧手，则动作维度可能扩展为十几甚至几十个手指关节控制量，而不再是单一开闭信号。

### Language-conditioned High-level Action（语言条件高级动作）

近年来的大模型开始输出更加抽象的动作。

例如：

```text
Pick up cup
```

或者：

```text
Open drawer
```

甚至：

```text
Move bottle onto tray
```

这些动作本身并不能直接驱动机器人，而是需要任务规划器（Task Planner）进一步分解为多个低层控制动作，例如：

```text
移动到目标
↓
调整姿态
↓
下降
↓
夹紧
↓
抬起
↓
移动
↓
放置
```

因此，高层动作空间通常不会直接作用于机器人控制器，而是作为机器人行为规划的输入。

## Action Representation 的关键设计维度

动作空间不仅决定输出什么，还决定输出采用什么表示方式。不同表示方式会直接影响模型训练难度、控制稳定性以及机器人执行效果。

### Absolute 与 Relative

Absolute（绝对动作）表示策略直接输出目标状态。

例如：

```text
Joint 1 = 45°
Joint 2 = 18°
```

机器人每一步都尝试到达指定位置。

Relative（相对动作）则输出变化量：

```text
Joint1 +2°
Joint2 -1°
```

即：

$$q_{t+1}=q_t+\Delta q$$

目前 Relative Action 更加常见。

原因包括：

- 更容易泛化到不同初始状态；
- 控制更加平滑；
- 小误差不会立即导致失败；
- 数据分布更加稳定。

### Joint Space 与 Task Space

Joint Space 使用关节变量：

$$q$$

作为动作。

Task Space 使用末端位姿：

$$(x,y,z,R)$$

作为动作。

两者最大的区别在于：

Joint Space 更贴近机器人本体。

Task Space 更贴近任务目标。

一般来说：

- 控制器喜欢 Joint Space；
- 学习算法喜欢 Task Space；
- 工业机器人常结合两者共同使用。

### Continuous 与 Discrete

连续动作：

```text
0.23
-0.51
0.14
```

可以输出任意实数。

离散动作则类似：

```text
Move Left
Move Right
Open
Close
```

连续动作适合运动控制。

离散动作更适合高层决策。

因此目前具身智能底层控制几乎全部采用连续动作。

### Single-step 与 Chunked Action

传统策略每一步只输出当前控制量：

```text
t
↓
Action_t
```

近年来越来越多模型采用 Action Chunk。例如一次输出未来十步：

```text
Action1
Action2
Action3
...
Action10
```

机器人随后依次执行。

这样做具有几个优势：

首先，可以降低模型推理频率。例如控制频率为 50 Hz 时，不需要每 20 ms 推理一次，而可以每 200 ms 推理一次，显著减轻计算压力。

其次，相邻动作由模型统一生成，能够保证整体轨迹更加平滑，减少由于逐步预测带来的抖动。

此外，在网络通信存在延迟或机器人控制链路较长的场景中，动作块还能提高系统稳定性，避免因为偶发延迟导致控制中断。因此，ACT、Diffusion Policy 等方法普遍采用 Chunked Action，而许多传统控制策略仍然采用 Single-step Action。

## 不同机器人形态下的动作空间设计

机器人结构不同，其动作空间维度和设计重点也会发生明显变化。

### 固定机械臂

固定机械臂通常只有机械臂本体和夹爪。

动作空间一般包括：

```text
Joint Delta + Gripper
```

或者：

```text
EE Pose Delta + Gripper
```

这是目前最简单、最成熟的一类动作空间。

### 移动操作机器人

移动操作机器人增加了移动底盘，因此动作空间通常变为：

```text
Base Velocity + Arm + Gripper
```

例如：

```text
[vx,vy,w,Δq1...Δq7,gripper]
```

策略需要同时协调导航与操作，动作维度明显增加。

### 双臂机器人

双臂机器人需要同时控制左右两条机械臂。

动作可以表示为：

```text
Left Arm + Right Arm + Left Gripper + Right Gripper
```

两个机械臂既可以独立完成不同动作，也可以协同完成搬运、装配等双手任务。因此，策略除了需要输出各自的运动指令外，还必须学习两条机械臂之间的时序配合与空间约束，动作空间复杂度明显高于单臂系统。

### 人形机器人

人形机器人通常拥有：

- 腿部
- 腰部
- 双臂
- 头部
- 手部

动作维度往往达到几十甚至上百维。

例如：

```text
Base
Leg
Waist
Head
Left Arm
Right Arm
Hands
```

此时动作空间设计不仅要保证上肢完成操作任务，还需要兼顾下肢平衡和全身协调，因此策略往往采用分层控制，将高层决策与底层运动控制解耦。

### 灵巧手

灵巧手拥有多个手指，每个手指包含多个关节。

例如：

```text
Thumb
Index
Middle
Ring
Little
```

整个动作空间可能超过 20～30 个自由度。相比简单夹爪，其动作空间更加高维，控制更加精细，同时也要求数据采集具有更高精度，模型需要学习复杂的手指协调关系，因此训练难度和数据需求都会显著增加。

## 动作空间选择对系统性能的影响

动作空间设计并不仅仅影响模型输出形式，还会贯穿数据采集、模型训练以及机器人实际执行的整个流程。

在数据采集阶段，动作空间决定了需要记录哪些控制量。如果动作采用关节角度表示，那么采集系统需要准确记录每个关节的位置、速度或力矩；如果采用末端位姿，则需要保证机器人坐标系、相机坐标系和世界坐标系之间具有稳定且准确的标定关系。动作空间越复杂，数据同步和标定成本通常越高。

在模型训练阶段，动作表示直接决定学习目标的分布特性。相对动作通常变化范围较小、数据分布更加集中，因此模型更容易收敛；绝对动作则更容易受到初始姿态变化影响，需要模型学习更大的状态空间。任务空间动作具有较好的语义一致性，但依赖逆运动学求解；关节空间动作虽然语义较弱，却更加直接稳定。

在泛化能力方面，动作空间也会产生明显影响。以末端位姿增量作为输出时，不同品牌、不同尺寸的机械臂只要能够完成相同的末端运动，就可以共享同一种动作表示，因此更容易实现跨机器人迁移。而直接输出关节角度通常与机器人结构紧密绑定，不同自由度或不同连杆参数的机器人之间难以直接复用策略。

动作空间还会影响系统延迟。单步动作需要高频推理，对计算资源和通信链路要求较高；动作块（Action Chunk）能够降低推理频率，提高系统吞吐量，但机器人在执行动作块期间无法立即响应新的环境变化，因此需要在实时性与效率之间进行权衡。

安全性同样与动作空间密切相关。底层控制通常会对动作施加关节限位、速度限制、加速度限制以及碰撞检测等约束，避免策略输出异常控制命令导致机器人发生剧烈运动或碰撞。相对动作由于单步变化较小，更容易受到控制器约束，因此在真实机器人部署中通常具有更高的安全性。

## VLA、模仿学习与强化学习中的动作接口

虽然不同学习范式采用不同的数据来源和训练目标，但最终都必须输出机器人能够执行的动作接口，只是动作表示的侧重点有所不同。

模仿学习通常直接学习专家示范数据，因此动作表示一般与数据采集接口保持一致，最常见的是关节位置增量、末端位姿增量以及夹爪状态。这类动作能够直接监督学习，训练流程相对简单，也是当前大多数机器人数据集采用的形式。

强化学习则更加关注控制过程中的连续优化，因此动作通常直接对应机器人控制器的连续控制量，例如关节位置、关节速度、关节力矩或底盘速度等。由于策略需要频繁与环境交互，动作空间往往要求连续且可微，以便实现稳定的策略优化。

近年来的视觉-语言-动作模型（VLA）在输入端引入了图像和自然语言，但输出端通常仍然需要落到机器人底层接口。例如，模型可以理解"把杯子放到托盘上"这样的语言指令，但最终仍需要输出关节增量、末端位姿变化或动作块，由机器人控制系统逐步执行。因此，VLA 的创新主要体现在感知和决策能力，而不是改变机器人底层动作接口。

可以发现，无论采用哪一种学习框架，策略最终都需要输出可执行的控制命令。不同方法之间最大的区别在于模型如何学习这些动作，而不是机器人最终执行动作的形式。

## 本节小结

动作空间是具身智能策略与机器人控制系统之间最核心的接口，它定义了模型每一步能够输出什么样的控制命令，以及这些命令如何映射到机器人本体。常见动作空间包括关节位置或速度增量、末端位姿增量、移动底盘速度、夹爪控制以及语言条件下的高级动作，不同机器人形态会根据自身自由度和任务需求组合出不同的动作表示。

动作表示还涉及绝对与相对、关节空间与任务空间、连续与离散、单步与动作块等多个设计维度，它们会影响数据采集方式、模型训练难度、跨机器人泛化能力、系统实时性以及实际部署的安全性。需要强调的是，本节关注的是**策略输出如何映射到机器人可执行接口**，而不是比较不同学习算法或讨论哪一种动作空间最优。真正的动作空间设计需要结合机器人结构、控制器能力以及具体应用场景综合考虑，在表达能力、稳定性和执行效率之间取得平衡。
