# 轨迹命令与安全执行

策略输出的动作（Action）通常描述的是"希望机器人做什么"——例如移动到某个末端位姿、施加某个关节增量或维持某个速度。然而，从"希望的目标"到机器人安全地完成运动，中间还需要一个关键步骤：将目标点转换为带有时间信息、速度规划和约束检查的轨迹命令（Trajectory Command），再由控制器逐步执行。

一个只有终点、没有中间过程的动作指令，在实际机器人上是无法直接执行的。机器人不能瞬间从当前位置跳跃到目标位置，而需要沿一条平滑的轨迹、在合理的速度和加速度范围内逐渐逼近目标。如果没有明确的时间信息，控制器无法确定每一步应该运动到哪里；如果没有约束检查和保护机制，异常的运动指令可能导致机器人剧烈运动甚至发生碰撞。

本节介绍轨迹命令的构成要素、路径/轨迹/控制命令三者之间的区别、安全执行需要检查的约束条件、执行过程中涉及的状态反馈，以及低速、限幅、急停等安全机制在接口层的体现方式。本节不展开轨迹优化和时间参数化算法，这些内容将在第 4 章结合具体工具进行介绍。

## 轨迹命令的基本组成

一个完整的轨迹命令（Trajectory Command）远不止一个目标位置，而是由一系列带有明确时间信息的路径点（Waypoint）组成。每个路径点描述了机器人在某一时刻应当达到的状态。

典型的轨迹命令通常包含以下字段：

```text
waypoints:
  - time_from_start: 0.0       # 从轨迹开始计算的时刻 (s)
    positions: [0.0, 0.5, 1.2] # 各关节目标位置 (rad 或 m)
    velocities: [0.0, 0.0, 0.0] # 各关节目标速度 (rad/s 或 m/s)
    accelerations: [0.0, 0.0, 0.0] # 各关节目标加速度
    effort: [0.0, 0.0, 0.0]    # 各关节目标力矩 (Nm)，可选

  - time_from_start: 0.5
    positions: [0.1, 0.6, 1.1]
    velocities: [0.2, 0.2, -0.2]
    accelerations: [0.4, 0.4, -0.4]
    effort: [0.5, 0.3, -0.2]

  - time_from_start: 1.0
    positions: [0.3, 0.8, 1.0]
    velocities: [0.0, 0.0, 0.0]
    accelerations: [0.0, 0.0, 0.0]
    effort: [0.0, 0.0, 0.0]
```

每个 waypoint 包含的核心字段及其意义为：

- **time_from_start**：从轨迹开始执行算起的时刻。它定义了时间轴，将"希望到达哪里"与"什么时候到达"绑定在一起，使控制器能够按时间推进执行。
- **positions**：目标关节位置向量，是轨迹最基本的空间描述。对于机械臂通常是各关节角度，对于移动底盘则是轮子位置或底盘位姿。
- **velocities**：目标关节速度向量。在位置控制模式下，速度信息用于前馈补偿，使控制器能够提前产生相应驱动力，减小跟踪误差；在速度控制模式下，则是直接的控制目标。
- **accelerations**：目标关节加速度向量。加速度信息对高速运动尤为重要，它可以用于前馈力矩计算，减少控制器滞后，提高高速运动下的跟踪精度。
- **effort**：目标关节力矩（或力），在力矩控制模式下作为直接控制目标，其他模式下则作为前馈参考或可选字段。

轨迹命令中 waypoint 的密度（时间间隔）直接影响运动质量。过疏的 waypoint 意味着控制器需要在两个路径点之间自行插值，如果机器人内置插值器不够好，可能导致运动不平滑；过密的 waypoint 则增加通信负担，可能超出控制总线的带宽限制。实际工程中，waypoint 的时间间隔通常在毫秒到几十毫秒量级。

## Path、Trajectory 与 Controller Command 的区别

在机器人系统中，路径（Path）、轨迹（Trajectory）和控制器命令（Controller Command）虽然紧密相关，但属于不同层次的抽象，其区别直接影响系统设计和调试。

**路径（Path）**仅描述机器人应该沿怎样的几何路线运动，不包含任何时间信息。路径可以表示为一系列空间点（末端三维位置、关节角度序列等），它只回答"经过哪里"，不回答"什么时候到达"和"以多快的速度运动"。例如，从 A 点到 B 点的一条直线、一段圆弧或一组关节角度的插值序列，都属于路径。路径无法直接交给控制器执行，因为控制器需要知道每一步的目标状态，而缺少时间信息的路径无法确定任意时刻的期望状态。

**轨迹（Trajectory）**在路径的基础上赋予了时间维度。轨迹不仅定义几何路线，还定义了每个时刻机器人应该处于什么状态——位置、速度甚至加速度。简而言之，轨迹回答了"在 $t_1$ 时刻到达 $q_1$，在 $t_2$ 时刻到达 $q_2$"这样的问题。时间信息的加入使轨迹具备了可执行性：控制器可以在每个控制周期中根据当前时间查询轨迹上对应的目标状态，从而实现连续运动。轨迹的时间参数化通常还需满足速度、加速度甚至加加速度的连续性和限幅要求。

**控制器命令（Controller Command）**是轨迹经过底层控制系统处理后，以控制周期频率发出的最终执行指令。它需要满足机器人硬件接口的具体格式要求，包括数据维度、单位、控制频率以及通信协议。控制器命令不再描述"整段运动"，而只关心当前控制周期的具体指令——例如"当前时刻，关节 1 的目标位置为 0.52 rad，目标速度为 0.1 rad/s"。控制器命令也可以不来自预先生成的轨迹，而是由策略直接实时输出（例如强化学习的 step-by-step 推理）。

三者的关系可以概括为：

```text
Path
  │  添加时间信息、速度规划、约束检查
  ▼
Trajectory
  │  按控制周期采样、转换为硬件接口格式
  ▼
Controller Command
```

在策略部署中，如果策略只输出末端位姿目标，则通常需要经过 IK 求解生成关节目标，再进行轨迹规划（Time Parameterization）生成带时间的 waypoint 序列，最后以控制频率下发控制器命令。如果策略本身已经输出完整的关节轨迹，则只需经过约束检查和格式转换即可交由控制器执行。无论哪种情况，轨迹命令与底层控制命令之间存在明确的层次关系，理解这种关系有助于在调试时快速定位问题是出在轨迹规划层还是控制器执行层。

## 安全执行必须检查的约束

轨迹命令在被控制器接受之前，必须经过一系列约束检查。这些检查的目的是保证机器人不会因为超出物理能力或安全边界的运动指令而发生危险。以下约束应在轨迹生成阶段或控制器接收命令阶段进行检查。

**关节限位（Joint Limit）**是最基本的约束。每个关节都有最低和最高角度（或位移）限制：

```text
q_min ≤ q(t) ≤ q_max, ∀t
```

如果轨迹中的任意 waypoint 的关节位置超出了该关节的允许范围，该轨迹不能被执行。关节限位通常在 IK 求解和轨迹规划阶段就已纳入考虑，但在控制器端仍需进行二次校验，以防止模型参数不一致或计算错误导致的越限。

**速度限制（Velocity Limit）**确保关节速度不超过驱动器或机械结构的允许上限：

$$|\dot{q}(t)| \leq v_{max}, \quad \forall t$$

即使轨迹的位置序列合法，如果时间参数化过于激进——即路径点之间的时间间隔过短——也可能导致关节速度超出限制。这在策略直接输出动作或以高加速度执行快速运动时尤其值得关注。

**加速度限制（Acceleration Limit）**约束关节加速度的大小：

$$|\ddot{q}(t)| \leq a_{max}, \quad \forall t$$

过大的加速度不仅会对电机和传动机构产生冲击载荷，还可能导致轨迹跟踪误差显著增大。对于协作机器人，加速度限制也是保障操作人员安全的重要措施。

**加加速度限制（Jerk Limit）**约束加速度的变化率：

$$\left|\overset{...}{q}(t)\right| \leq j_{max}, \quad \forall t$$

加加速度反映了运动过程中力的变化率。过大的加加速度会导致机器人产生高频振动、噪声增加，并对机械结构产生额外的疲劳损伤。在高精度装配或需要平稳运动的场景中，加加速度的限制尤为重要。

**工作空间限制（Workspace Limit）**约束末端执行器的空间活动范围。即使各关节均未超限，末端位姿也可能超出预定义的允许工作区域。工作空间限制通常以包围盒或多边形边界的形式定义，在末端位姿命令和轨迹生成阶段进行检查。

**碰撞安全余量（Collision Margin）**是指在机器人与障碍物（包括环境物体和机器人自身连杆）之间预留的最小安全距离。碰撞检测通常在轨迹规划或轨迹执行前进行，如果路径上任意点与障碍物的距离小于安全余量，该轨迹应被拒绝或修改。

在实际实现中，以上约束检查通常以流水线形式执行：轨迹生成器首先根据目标位姿和时间参数化生成候选轨迹；约束检查器对每个 waypoint 逐项验证；只有全部检查通过的轨迹才会被下发至控制器执行。任何一个约束不满足，都应触发拒绝、裁剪或重新规划的流程，而不是静默忽略。

## 执行过程中的状态反馈

轨迹命令发送至控制器后，并不会立即被执行完成。控制器会追踪整个执行过程，并通过一组状态字段将执行进度和结果反馈给上层（策略或任务规划器）。理解这些反馈字段的含义，对于编写健壮的机器人控制程序至关重要。

典型的轨迹执行反馈包括以下状态：

```text
accepted    — 轨迹已被接收，排队等待执行
active      — 轨迹正在执行中
done        — 轨迹执行成功完成（到达终点且满足精度要求）
preempted   — 轨迹执行被更高优先级的新轨迹中断
aborted     — 轨迹执行因异常而中止（碰撞、关节超限、通信中断等）
timeout     — 轨迹执行未在指定时间内完成
tracking_error — 实际关节位置与目标位置之间的实时偏差
```

各状态的含义和触发条件为：

- **accepted**：控制器确认收到了轨迹命令并接受执行。此时轨迹可能尚未开始运动（例如正在排队等待前序动作完成），但控制器已认可命令的合法性。如果轨迹因约束检查失败而被拒绝，通常不会返回 accepted，而是直接返回错误码。

- **active**：轨迹正在被驱动执行，机器人处于运动状态。在 active 期间，控制器在每个控制周期中根据时间推进 waypoint 索引，并驱动关节跟踪目标位置。

- **done**：轨迹的所有 waypoint 均已执行完毕，且末端位置误差（或关节位置误差）在预设容差范围内。done 是正常执行结束的标志，策略可以据此触发下一步动作。

- **preempted**：当前轨迹被新的更高优先级的轨迹命令中断。例如，策略检测到危险情况而发送急停轨迹，它可以抢占（preempt）当前正在执行的运动，使机器人优先响应紧急指令。被抢占的轨迹不会继续执行。

- **aborted**：轨迹因异常情况中止。常见原因包括：关节位置超过硬限位、驱动器检测到过流或过温、碰撞传感器触发、控制器与策略之间通信丢失等。aborted 通常意味着机器人已进入保护状态，策略需要在排查原因后才能重新发送命令。

- **timeout**：轨迹在预设的超时时间内未能完成。例如，设置了 5 秒的完成时限，但 5 秒后机器人仍未到达目标位置——可能因为速度设置过低、关节被卡住或目标位姿不可达。timeout 是判断执行异常的重要信号。

- **tracking_error**：不同于上述离散状态，tracking_error 是一个持续的数值指标，表示当前位置与轨迹目标之间的偏差。策略可以实时读取这一数值，如果发现跟踪误差突然增大或持续不收敛，可以主动触发停止或重新规划。

对于策略开发者而言，不应假设每条轨迹命令都一定能成功完成。正确的做法是在每次发送轨迹命令后，持续监控反馈状态，并根据不同的反馈结果做出相应的处理——done 后继续下一步、aborted 后进入安全状态、timeout 后排查原因并降级处理。

## 安全机制在接口层的体现

除了约束检查和状态反馈，机器人控制接口还需要内置一系列安全机制，以确保在异常情况下机器人能够安全地减速、停止或恢复。这些安全机制虽然主要由底层控制器实现，但策略接口也必须遵循相应约定。

**低速执行模式（Low-speed Mode）**是部署初期的标准做法。在首次将策略部署到真实机器人时，应将运动速度限制为正常速度的 10%～25%。低速模式不是简单地缩小目标位置，而是限制轨迹的速度上限。这样做可以显著降低意外运动的风险——即使策略输出了不合理的动作，机器人在低速下也有更充足的时间被外部急停或人工干预。低速模式通常通过控制器接口中的 velocity scaling 参数实现，策略无需修改输出内容。

**动作裁剪（Action Clipping）**是指将策略输出的动作限制在预设的安全范围内。例如，无论策略输出多大的关节增量，接口层都会将其裁剪到每次的最大允许增量：

```text
clipped_action = clamp(raw_action, -max_delta, +max_delta)
```

类似地，末端位姿的变化量也应在空间位置上设置上限。动作裁剪是防御策略输出异常的"最后一道防线"，它不修改策略本身的输出逻辑，而是在控制接口层施加硬约束。

**急停（Emergency Stop）**是机器人最重要的一类安全机制。急停通常分为两个层级：软件急停（Soft E-Stop）通过发送零速度或零力矩命令使机器人快速减速并停止，通常不切断电机电源；硬件急停（Hard E-Stop）则由物理急停按钮触发，直接切断电机动力，使机器人立即制动。从接口角度看，急停信号应具有最高优先级，可以抢占任何正在执行的轨迹或控制命令。策略应具备检测急停状态并优雅退出的能力，而不是在急停恢复后继续发送过期的控制命令。

**保护区（Safety Zone / Restricted Zone）**是指在机器人工作空间中预定义的一组禁止进入或限制进入的区域。当轨迹的末端位置或各连杆位置进入保护区时，控制器应减速、停止或重新规划路径。保护区通常结合安全光栅、激光扫描仪或虚拟围栏等技术实现，在接口层表现为 workspace limit 约束的扩展。

**恢复动作（Recovery Action）**是指在异常发生后，让机器人从当前状态安全回到正常工作状态的预设动作序列。例如，碰撞触发后，机器人可以先沿接触方向的反向微动退出接触，再回到预定义的安全姿态（home position），最后等待新的控制指令。恢复动作不应依赖策略的实时决策——因为在异常发生时，策略可能已经处于不确定状态——而应由控制器或接口层的安全逻辑独立完成。

这些安全机制在接口层的统一原则是：安全约束的优先级高于一切策略输出。无论策略认为机器人应该如何运动，控制器都不应执行违反安全约束的命令。因此，接口层的设计本质上是在策略的"智能"与控制器的"保守"之间建立清晰的责任边界。

## 本节小结

轨迹命令是连接策略目标与机器人实际运动之间的桥梁。它由一系列携带时间信息的路径点（waypoint）组成，每个 waypoint 包含了目标位置、速度、加速度和力矩等信息，使控制器能够在每个控制周期中准确知道"当前时刻机器人应该处于什么状态"。路径只描述几何路线，轨迹在路径之上加入时间维度，而控制器命令则是以控制频率发出的最终硬件指令——三者处于不同的抽象层级。

安全执行不仅仅依赖策略输出的正确性，更需要接口层对轨迹进行全面的约束检查，包括关节限位、速度限制、加速度限制、加加速度限制、工作空间限制以及碰撞安全余量。在轨迹执行过程中，控制器通过 accepted、active、done、preempted、aborted、timeout 和 tracking_error 等状态字段持续反馈执行进度，策略需要根据这些反馈做出相应的后续决策。此外，低速执行模式、动作裁剪、急停、保护区和恢复动作等安全机制在接口层形成了多层防护，确保即使策略出现异常输出，机器人也能安全地减速、停止或恢复。
