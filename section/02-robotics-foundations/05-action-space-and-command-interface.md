# 动作空间与命令接口（Action Space and Command Interface）

机器人学习模型最终输出的是**动作（Action）**，而机器人硬件真正能够执行的是**控制命令（Command）**。两者虽然紧密相关，但并不等价。动作空间决定了策略模型输出什么样的数据，而命令接口决定了控制器和机器人硬件能够接受什么格式、什么频率以及什么约束条件下的控制指令。

在现代机器人系统中，无论是模仿学习（Imitation Learning）、强化学习（Reinforcement Learning），还是视觉语言动作模型（Vision-Language-Action，VLA），策略输出通常都不能直接发送给机器人执行，而需要经过一系列标准化转换，包括单位转换、坐标变换、关节映射、安全约束检查以及控制频率匹配等步骤，最终才能生成符合机器人控制接口要求的命令。

因此，理解动作空间与命令接口之间的关系，是理解机器人学习系统如何真正驱动机器人执行任务的重要基础。本节主要介绍动作的语义、命令接口的定义以及动作从策略输出到硬件执行之间的必要转换过程，而具体的控制算法（如 MPC、WBC、MoveIt、cuRobo 等）将在第 4 章进行介绍。

## 动作空间与命令接口的区别

动作空间（Action Space）描述的是**策略模型输出什么**，而命令接口（Command Interface）描述的是**机器人控制器能够接收什么**。

对于学习算法而言，动作空间通常是一个固定维度的向量。例如，一个七自由度机械臂的策略可以直接输出七个关节目标角度，也可以输出末端执行器的位姿变化，甚至输出底盘速度和夹爪开合指令。这些输出仅表示策略希望机器人完成的动作，其数据形式主要服务于模型训练和推理。

命令接口则属于机器人控制系统的一部分，它定义了机器人控制器所支持的控制类型、数据格式、更新时间以及安全约束。例如，同样表示机械臂运动，某些控制器只能接收关节位置命令，而另一些控制器则支持末端位姿目标、速度控制或完整轨迹命令。命令接口通常与机器人驱动程序、实时控制器以及硬件平台直接相关。

因此，动作空间强调的是**策略表达能力**，而命令接口强调的是**控制执行能力**。策略输出只有经过适当转换，才能成为机器人能够实际执行的控制命令。

## 从策略输出到机器人执行的必要转换

策略模型输出的动作通常不能直接发送至机器人执行，而需要经过一系列数据转换和安全处理，以保证动作能够被正确解释，并满足机器人控制系统的要求。

### 单位转换（Unit Conversion）

不同机器人系统采用的单位可能并不完全一致。例如，策略模型可能输出角度单位为 degree，而机器人控制器要求使用 rad；末端位置可能以毫米（mm）表示，而控制接口采用米（m）。

因此，在发送控制命令之前，应统一完成单位转换，确保动作数据与控制接口采用一致的物理单位。统一的单位体系不仅有助于不同机器人平台之间的数据共享，也能够避免由于单位错误导致的控制异常。

### 坐标转换（Coordinate Transformation）

机器人学习模型输出的位置或姿态通常位于某一参考坐标系，而机器人控制器可能要求使用另一坐标系。

例如：

* Vision 模型输出 Camera Frame 下的抓取位姿；
* 控制器需要 Base Frame 下的目标位姿；
* 移动机器人需要 Map Frame 下的导航目标。

因此，在动作执行之前，需要利用机器人坐标变换关系（TF）完成坐标转换，保证控制命令始终位于控制器所要求的参考坐标系中。

### 关节顺序映射（Joint Order Mapping）

不同机器人平台对于关节编号和数组顺序的定义可能不同。

例如，策略训练数据采用：

```text
[shoulder, elbow, wrist]
```

而机器人控制器实际要求：

```text
[elbow, shoulder, wrist]
```

如果不进行关节映射，即使所有关节角度数值完全正确，机器人也会执行错误动作。因此，在策略输出与控制接口之间，必须建立统一的关节名称与数组索引映射关系，而不能仅依赖数组位置。

### 动作裁剪（Action Clipping）

学习模型输出通常没有严格保证物理可行性，因此需要根据机器人运动范围进行裁剪。

例如：

* 关节角度不得超过机械极限；
* 夹爪开口不得超过最大宽度；
* 底盘速度不得超过安全速度；
* 末端位姿不得超出工作空间。

动作裁剪能够防止模型输出超出机器人能力范围的控制命令，也是机器人安全控制的重要组成部分。

### 频率匹配（Rate Matching）

策略模型与机器人控制器通常具有不同的运行频率。

例如：

* VLA 推理频率：10 Hz；
* 模仿学习策略：30 Hz；
* 控制器更新频率：250 Hz；
* 电机驱动频率：1000 Hz。

因此，需要进行频率匹配，例如：

* 保持（Hold Last Command）；
* 插值（Interpolation）；
* 重采样（Resampling）。

频率匹配能够保证机器人始终以稳定的控制周期运行，而不会因为策略更新较慢导致运动不连续。

### 限幅与安全检查（Limits and Safety Checks）

在命令真正发送给机器人之前，还需要进行最后一级安全检查。

典型检查内容包括：

* 速度限制；
* 加速度限制；
* 力矩限制；
* 工作空间限制；
* 自碰撞检查；
* 奇异位姿检查；
* 急停状态检查；
* 故障状态检查。

这些安全约束通常由机器人控制系统负责执行，其目的并不是修改策略，而是在策略输出存在异常时保护机器人和周围环境的安全。

## 常见的命令类型

不同机器人控制器支持不同类型的命令接口，但大多数机器人系统可以归纳为以下几类控制命令。

### Joint Target（关节目标）

Joint Target 是最常见的机器人控制方式。

命令直接给出每个关节的目标值，例如：

```text
joint_target:
    position[]
```

也可以扩展为：

```text
position
velocity
torque
```

不同控制模式下，仅部分字段会生效。

Joint Target 的优点是控制器实现简单、实时性高，也是工业机器人和大多数学习算法最常采用的动作表示。

### End-Effector Pose Target（末端位姿目标）

末端位姿控制直接指定机械臂末端执行器的目标位置和姿态。

例如：

```text
pose_target:
    position
    orientation
```

控制器随后通过逆运动学、轨迹规划等模块，将目标位姿转换为关节运动。

这种接口更加符合抓取、装配和操作任务的需求，也方便策略直接学习任务空间动作，而无需关注机器人具体关节结构。

### Base Velocity（底盘速度命令）

对于移动机器人，策略通常不会直接控制轮子，而是输出机器人整体速度。

例如：

```text
base_velocity:
    linear_x
    linear_y
    angular_z
```

差速底盘通常仅支持：

* linear_x；
* angular_z。

而全向移动平台则支持完整二维速度控制。

底盘控制器进一步将速度命令转换为各个车轮的实际转速。

### Gripper Command（夹爪命令）

夹爪通常具有独立控制接口。

例如：

```text
gripper:
    width
```

或者：

```text
position
force
mode
```

不同夹爪控制器支持的命令有所不同，但通常包括：

* 开口宽度；
* 目标位置；
* 目标夹持力；
* 开启/关闭命令。

### Trajectory Command（轨迹命令）

对于复杂运动，机器人控制器还可以接收完整轨迹。

例如：

```text
trajectory:
    waypoints[]
```

每个轨迹点通常包括：

* 时间；
* 关节位置；
* 速度；
* 加速度。

轨迹命令适用于连续运动、复杂装配以及需要满足时间约束的任务，能够保证机器人按照指定轨迹平滑执行动作。

## 控制算法与命令接口的边界

需要注意的是，**命令接口并不等同于控制算法**。

本章讨论的是**机器人能够接收哪些类型的命令、这些命令具有哪些语义，以及在发送之前需要满足哪些数据格式和安全约束**。

至于机器人如何根据这些命令生成具体的控制输入，则属于控制算法的职责。例如：

* **MPC（Model Predictive Control）**根据系统模型预测未来状态并优化控制输入；
* **WBC（Whole-Body Control）**协调多关节机器人全身运动；
* **MoveIt**负责运动规划、逆运动学求解和轨迹生成；
* **cuRobo**利用 GPU 加速完成高性能运动规划与轨迹优化。

这些算法虽然都会产生或处理控制命令，但它们属于控制与规划层，其具体原理和实现将在第 4 章进行介绍。本章仅关注命令本身的表示方式及执行约束，为后续章节建立统一的接口定义。

## 最小 Command Schema

为了保证不同机器人平台、不同学习算法以及不同控制系统之间具有良好的兼容性，建议所有机器人数据集和控制接口至少采用统一的 Command Schema。该 Schema 能够作为后续 VLA、模仿学习、强化学习等章节统一引用的动作表示规范。

```yaml
command:
  timestamp:             # 命令生成时间
  frame_id:              # 命令参考坐标系（如 base_link、world）
  command_type:          # joint_target / ee_pose / base_velocity / gripper / trajectory
  control_mode:          # position / velocity / torque / impedance

  joint_target:
    names: []            # 关节名称
    position: []         # rad 或 m
    velocity: []         # 可选
    effort: []           # 可选

  ee_pose_target:
    position: [x, y, z]
    orientation: [x, y, z, w]

  base_velocity:
    linear: [vx, vy]
    angular: wz

  gripper:
    position:
    width:
    force:
    mode:

  trajectory:
    waypoints: []

  source:                # teleoperation / policy / planner / replay
  calibration_version:   # 使用的标定版本
  safety_checked: true   # 是否完成安全检查
```

上述 Command Schema 并不依赖具体机器人型号，而是抽象出了机器人控制命令的核心组成部分。它能够覆盖机械臂、移动机器人、人形机器人等常见平台的控制需求，并为后续章节介绍视觉语言动作模型、模仿学习和强化学习中的动作表示提供统一的数据接口。
