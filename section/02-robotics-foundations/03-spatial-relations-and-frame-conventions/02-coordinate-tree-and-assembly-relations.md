# 坐标树与装配关系

## 本章概述

机器人不仅由机械结构组成，还由大量具有空间关系的部件共同构成，例如机器人底座、机械臂各级连杆、末端工具、相机、激光雷达、IMU 以及定位系统等。这些部件都有各自独立的坐标系，并且彼此之间存在固定或动态的空间关系。为了让机器人能够正确理解自身结构，并实现感知、规划、控制等模块之间的数据共享，机器人系统通常采用**坐标树（Frame Tree）**来统一描述所有坐标系之间的装配关系。

坐标树可以看作是机器人空间结构的"骨架"。它记录了每一个坐标系属于哪个父节点、如何与父节点连接，以及任意两个坐标系之间如何进行坐标变换。通过坐标树，机器人能够将相机检测到的目标位置转换到机械臂坐标系，将导航目标转换到底盘控制坐标系，也能够在数据记录和回放过程中保持空间信息的一致性。

需要强调的是，坐标树不仅是机器人学中的一个数学概念，更是机器人软件系统中的基础接口规范。每一个坐标系名称、父子关系、坐标变换以及更新时间都会作为接口数据存在于机器人模型、通信消息、数据集以及控制系统中，直接影响机器人各模块之间的协同工作。

本章将介绍坐标树的基本作用，说明 Parent Frame、Child Frame、Static Transform、Dynamic Transform、Transform Chain 和 TF Tree 等概念，分析机器人中各种坐标变换的来源，并介绍机器人系统中常见坐标系的命名方式及职责。同时，本章还将总结坐标树配置错误可能带来的典型问题。本章重点关注机器人模型中的装配关系和空间组织方式，不涉及 TF 软件接口、API 使用方法或调试命令，这些内容将在软件接口与运行调试章节进一步介绍。

## 坐标树的作用

机器人系统中的每一个部件都拥有自己的局部坐标系，例如底盘、机械臂、夹爪、相机以及激光雷达都有独立的 Frame。如果这些坐标系彼此孤立，机器人便无法知道它们之间的位置关系，也无法完成跨模块的数据转换。

坐标树（Frame Tree）的作用，就是将机器人所有坐标系按照装配关系组织成一个层级结构，使每一个坐标系都能够找到自己的父节点，并最终连接到整个机器人系统的根节点。这样，机器人不仅能够描述每个部件的位置，还能够计算任意两个坐标系之间的空间变换（Transform）。

例如，当视觉算法检测到目标物体位于相机坐标系下时，机器人可以沿着坐标树依次完成：

```text
camera_frame
        ↓
tool_0
        ↓
wrist_link
        ↓
base_link
```

最终将目标位置转换到机器人基座坐标系，从而用于运动规划和抓取控制。同样，对于移动机器人，也可以将机器人当前位姿从 base_link 一直转换到 map 坐标系，用于导航和定位。

因此，坐标树不仅描述机器人各部件之间的装配关系，更承担着整个机器人系统空间信息统一管理的职责。只要坐标树完整且一致，机器人就能够查询任意两个 Frame 之间的 Transform，实现感知、规划、控制和数据记录之间的无缝衔接。

## 坐标树中的基本概念

机器人坐标树由多个坐标系和它们之间的变换关系组成，其中几个基础概念贯穿机器人模型、通信接口以及控制系统。

### Parent Frame 与 Child Frame

每一个坐标系都会通过一条变换关系连接到另一个坐标系，因此坐标树中的每一个节点都具有明确的父子关系。

其中：

- **Parent Frame（父坐标系）** 表示参考坐标系；
- **Child Frame（子坐标系）** 表示相对于父坐标系建立的新坐标系。

例如：

```text
base_link
      │
camera_link
```

表示 camera_link 安装在 base_link 上，camera_link 的位置和姿态相对于 base_link 进行描述。

这种父子关系构成了整个机器人坐标树的层级结构。

### Static Transform

Static Transform（静态变换）表示两个坐标系之间始终保持不变的空间关系。

例如：

- 相机安装在机器人头部；
- 激光雷达固定在底盘前方；
- IMU 固定安装在机身内部；
- 工具安装在法兰盘末端。

这些装配关系通常不会随着机器人运动发生变化，因此只需要配置一次即可长期使用。

Static Transform 主要描述机器人装配完成后的固定几何关系。

### Dynamic Transform

Dynamic Transform（动态变换）表示会随着机器人运动不断更新的坐标关系。

例如：

- 机械臂各关节运动；
- 移动机器人底盘运动；
- 人形机器人全身姿态变化。

这些变换需要根据机器人实时状态持续更新，因此通常由机器人状态反馈实时计算得到。

机器人控制、运动规划以及状态可视化都会持续依赖这些动态坐标关系。

### Transform Chain

机器人系统中，两个坐标系之间往往没有直接建立变换关系，而是需要经过多个中间节点逐级计算。

例如：

```text
map
 │
odom
 │
base_link
 │
arm_base
 │
tool0
 │
camera_link
```

如果需要计算 map 到 camera_link 的空间关系，就需要依次沿着上述路径完成多个坐标变换。

这一连续的变换路径称为 **Transform Chain（变换链）**。

Transform Chain 的存在，使机器人无需为每一对坐标系单独建立变换关系，只需维护相邻节点之间的关系即可。

### TF Tree

整个机器人所有 Frame 与 Transform 共同组成 **TF Tree（坐标树）**。

TF Tree 本质上就是机器人空间关系的完整描述，它记录了：

- 所有坐标系名称；
- 父子连接关系；
- 每条变换的来源；
- 每条变换是否动态更新；
- 每个坐标系如何连接到机器人整体结构。

机器人系统中的所有空间计算，最终都建立在 TF Tree 的基础之上。

## 坐标变换的来源

机器人坐标树中的各种 Transform 并不是全部来自同一个地方，而是由机器人模型、状态反馈、标定系统和定位系统共同提供。

### 来自机器人模型

机器人模型（如 URDF、MJCF、USD）主要提供机器人自身结构中的固定装配关系。

例如：

- base_link 到 shoulder_link；
- shoulder_link 到 elbow_link；
- wrist_link 到 tool_0；
- flange 到 gripper。

这些关系由机器人机械结构决定，一般不会在运行过程中发生变化。

### 来自 Joint State

机器人关节运动会不断改变各 Link 之间的相对姿态。

因此：

- shoulder_joint
- elbow_joint
- wrist_joint

等动态变换通常由 Joint State 实时更新。

机器人根据当前关节角度计算每一级 Link 的实际位置，从而更新整条机械臂的坐标关系。

### 来自标定结果

机器人上的各种传感器通常需要经过外参标定。

例如：

- camera_link
- lidar_link
- imu_link

与机器人本体之间的位置关系通常来自标定结果。

如果重新安装相机、更换工具或调整传感器位置，就需要重新更新对应外参。

### 来自定位系统

对于移动机器人而言，还有一些坐标变换来自定位系统。

例如：

```text
map
    │
odom
```

通常由 SLAM 或定位算法提供。

而：

```text
odom
    │
base_link
```

则通常来自机器人里程计、轮速计或状态估计系统。

因此，一个完整的坐标树往往融合了机器人模型、关节状态、外参标定以及定位算法等多个模块共同提供的数据。

## 常见 Frame 的命名及职责

机器人开发过程中，不同平台虽然命名略有差异，但许多坐标系已经形成较为统一的工程习惯。

### base_link

base_link 通常表示机器人本体的基础坐标系。

对于固定机械臂，它一般位于机器人底座；对于移动机器人，则通常位于底盘中心。

base_link 是机器人运动链的重要起点，也是许多运动规划和控制算法采用的参考坐标系。

### link

link 通常表示机器人运动链中的各级连杆坐标系，例如：

```text
shoulder_link

upper_arm_link

forearm_link

wrist_link
```

这些 Frame 会随着关节运动不断更新，共同组成机器人机械结构。

### tool_0

tool_0 一般表示机器人法兰盘或默认工具坐标系。

许多工业机器人都会提供 tool_0，作为安装夹爪、吸盘、焊枪等末端工具的标准接口。

如果安装新的工具，还可能进一步建立新的 Tool Frame。

运动规划和末端控制通常以 tool_0 或 Tool Frame 为目标。

### camera_link

camera_link 表示相机本体坐标系。

它通常位于相机安装中心，用于描述相机整体在机器人中的安装位置。

camera_link 本身并不一定符合视觉算法的成像坐标约定，因此很多系统还会进一步定义 camera_optical_frame。

### camera_optical_frame

camera_optical_frame 表示符合相机成像模型的光学坐标系。

视觉算法输出的图像坐标、深度数据、点云等通常采用该坐标系。

因此：

- camera_link 更偏向机器人装配关系；
- camera_optical_frame 更偏向视觉算法接口。

两者之间通常存在一个固定的静态变换。

## 坐标树配置错误的影响

坐标树中的每一个 Transform 都参与机器人空间关系计算，因此任何一个节点配置错误，都可能影响整个机器人系统。

首先，**感知结果位置错误**是最常见的问题。如果相机外参配置错误，即使目标检测结果完全正确，机器人计算出的目标位置仍然会偏离真实位置，导致抓取失败。

其次，**规划目标不可达**。如果 Tool Frame 与机器人末端实际位置不一致，运动规划器会认为目标位姿存在，但机器人实际上无法到达对应位置，从而导致规划失败或运动轨迹异常。

第三，**数据回放无法对齐**。数据集中的位姿通常记录在特定 Frame 下，如果回放时使用了不同版本的坐标树，机器人模型与历史数据之间将产生空间偏差，使同一段数据无法正确复现。

此外，还存在一种较为隐蔽的问题：**相机外参数值看似正确，但方向配置错误**。例如，相机安装位置完全正确，但光轴方向发生了 180° 翻转，视觉算法输出的位置虽然数值正常，却始终位于机器人背后或朝向错误方向。这类问题往往不会立即报错，却会导致抓取、定位和导航等任务持续失败，因此在机器人调试过程中需要特别注意坐标轴方向和 Frame 定义是否一致。

## 本章建议掌握的内容

本章不要求读者掌握 TF 软件接口或具体 API，而是重点理解机器人如何利用坐标树组织各部件之间的空间关系。

读者应能够理解坐标树为什么能够统一机器人模型、传感器和环境之间的空间表达，认识 Parent Frame、Child Frame、Static Transform、Dynamic Transform、Transform Chain 和 TF Tree 等基本概念；能够区分机器人模型、Joint State、外参标定和定位系统分别负责哪些坐标变换，并理解它们共同构成完整机器人空间关系的方式。

同时，应熟悉 base_link、各级 link、tool0、camera_link、camera_optical_frame 等常见坐标系的职责，理解它们在机器人模型、视觉感知和运动规划中的作用。最后，应能够识别坐标树配置错误可能带来的典型问题，包括感知目标位置偏移、规划失败、数据回放不一致以及外参方向错误等，为后续机器人软件开发、系统调试和真机部署建立正确的空间组织观念。

## 本章小结

坐标树是机器人系统组织空间关系的核心结构，它通过父子坐标系和坐标变换将机器人本体、末端工具、传感器以及定位系统连接为统一的空间表达体系，使机器人能够查询任意两个坐标系之间的 Transform，实现感知、规划、控制和数据记录之间的一致协同。

机器人中的静态变换主要来源于模型装配关系和外参标定，动态变换则主要来源于关节状态和定位系统。base_link、各级 link、tool0、camera_link、camera_optical_frame 等常见 Frame 分别承担机器人本体、运动链、工具接口和视觉感知等不同职责，共同组成完整的 TF Tree。

在工程实践中，坐标树配置错误往往会导致感知目标位置错误、运动规划失败、数据回放无法复现以及外参方向异常等问题。因此，在机器人系统开发过程中，应始终将坐标树视为机器人软件架构的重要组成部分，确保模型、传感器、控制器和算法模块共享一致且正确的空间关系，为后续感知、规划、控制和真机部署提供可靠的坐标基础。
