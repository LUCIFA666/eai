# 定位坐标约定

## 本章概述

对于固定机械臂而言，机器人通常只需要关注机械臂本体及其末端执行器之间的空间关系；而对于移动机器人、移动操作机器人以及人形机器人，机器人自身的位置会随着运动不断发生变化，因此除了机器人内部的坐标系之外，还需要建立描述机器人在环境中位置的定位坐标体系。

为了统一机器人定位、导航、运动规划和多传感器融合等模块之间的数据接口，机器人系统通常采用 **map、odom 和 base_link** 等定位相关坐标系来描述机器人在不同层次上的空间关系。这些坐标系虽然都能够表示机器人的位置，但它们承担的职责完全不同：有的用于表示机器人在全局地图中的位置，有的用于描述机器人连续运动过程中的局部位姿，有的则作为机器人本体所有部件的参考基准。只有明确这些坐标系的职责边界，机器人系统才能保证定位、导航、控制以及数据记录之间保持一致的空间语义。

需要强调的是，定位坐标不仅仅是机器人学中的数学概念，更是机器人软件接口的重要组成部分。定位模块输出的位姿、速度、置信度以及时间信息，都必须明确所属坐标系，并与机器人模型、传感器数据和控制模块保持统一。不同平台虽然具体实现方式有所不同，但大多数机器人系统都遵循类似的坐标约定，其中 **ROS REP-105** 已成为机器人领域广泛采用的参考规范。本章将以这一约定作为背景，重点介绍课程中如何理解和使用这些坐标系，而不是介绍具体的软件实现。

本章将介绍 map、odom 和 base_link 三类定位坐标系的职责，分析 map→odom 与 odom→base_link 两类变换的分工，讨论不同机器人形态下 Base Frame 的设置方式，并说明定位接口中常见的数据字段及其语义。同时，本章还将明确与后续空间定位与建图章节的边界。本章重点关注定位坐标系的接口约定和工程语义，不涉及扩展卡尔曼滤波（EKF）、视觉惯性里程计（VIO）、激光惯性里程计（LIO）、位姿图优化（Pose Graph）或 SLAM 等定位算法，这些内容将在第 3 章中详细介绍。

## 定位坐标系的职责

机器人在运动过程中，需要同时满足两个目标：一方面能够连续、平滑地描述自身运动，另一方面能够始终知道自己在整个环境中的真实位置。由于这两个目标对定位系统提出了不同要求，因此机器人通常将定位信息划分为多个坐标层次，并分别由不同坐标系承担不同职责。

### map 坐标系

map 表示机器人所在环境的全局地图坐标系。

它用于描述机器人相对于整个工作环境的位置，例如机器人位于工厂地图中的哪个区域、仓库中的哪个货架附近，或者家庭环境中的哪个房间。

map 坐标系强调的是**全局一致性**。当机器人经过长时间运动后，即使累计误差不断增加，定位系统也会通过地图匹配、回环检测或其他全局定位方法对机器人位置进行修正，使机器人重新回到地图中的正确位置。因此，map 坐标系允许发生全局调整，但始终保持与环境地图的一致性。

对于导航、任务调度、多机器人协同以及长期运行系统而言，map 通常是最高层级的参考坐标系。

### odom 坐标系

odom 表示机器人连续运动过程中的局部参考坐标系。

它通常由轮速计、关节编码器、IMU 或局部里程计系统持续更新，用于描述机器人从启动开始的连续运动轨迹。

与 map 不同，odom 更强调**局部连续性**。机器人在短时间内的位置变化应当平滑、连续，不允许突然跳变，否则运动控制、轨迹跟踪和状态估计都会受到影响。

由于 odom 主要依赖局部运动估计，因此随着机器人运行时间增加，误差会逐渐积累。这种误差通常不会立即修正，而是通过 map 与 odom 之间的关系进行整体调整。

因此，odom 更适合作为机器人实时控制和局部规划的参考坐标，而不是长期全局定位结果。

### base_link 坐标系

base_link 表示机器人本体坐标系，是机器人所有运动链和传感器安装关系的基础参考坐标。

机器人上的机械臂、相机、IMU、激光雷达以及其他部件，通常都直接或间接连接到 base_link。

机器人控制器输出的关节状态、工具位姿以及机器人本体速度，也大多相对于 base_link 进行定义。

因此，base_link 可以理解为机器人自身的"身体坐标系"，它并不描述机器人位于环境中的哪个位置，而是描述机器人内部各部件之间的空间关系。

## map→odom 与 odom→base_link 的分工

在机器人定位系统中，map、odom 和 base_link 并不是彼此独立存在，而是通过连续的坐标变换连接起来。

通常情况下，机器人会维护如下空间关系：

```text
map
 │
odom
 │
base_link
```

其中，**map→odom** 和 **odom→base_link** 分别承担不同职责。

### map→odom

map→odom 用于建立局部运动轨迹与全局地图之间的对应关系。

定位系统会根据地图匹配、回环检测或全局定位结果，不断调整 map 与 odom 的相对位置，使机器人始终保持在地图中的正确位置。由于其目的是修正累计误差，因此 map→odom 可以发生离散变化或整体修正。例如，当机器人重新识别到环境中的已知地标后，定位系统可能一次性修正机器人在地图中的位置，从而使 map 坐标重新与真实环境保持一致。

因此，map→odom 更强调全局一致性，而不是运动连续性。

### odom→base_link

odom→base_link 描述机器人相对于局部参考坐标系的实时运动。它通常由机器人底盘编码器、惯性测量单元、状态估计器或局部里程计持续更新，直接反映机器人当前的运动状态。

与 map→odom 不同，odom→base_link 要求具有良好的短时连续性。即使机器人长期运行会产生一定累计误差，其输出也不应突然发生跳变，否则会导致运动控制器、轨迹规划器以及状态反馈系统产生异常。因此，机器人通常允许 odom 随时间逐渐漂移，再通过 map→odom 的修正保持整体定位准确，而不是直接修改 odom→base_link 本身。

这种职责划分兼顾了实时控制对连续性的要求和全局定位对准确性的要求，是目前移动机器人系统中最常见的定位接口设计方式。

## 不同机器人形态中的 Base Frame

虽然不同机器人平台都采用 Base Frame 作为本体参考坐标，但由于机器人结构不同，其具体定义也存在差异。

对于**移动机器人**而言，base_link 通常建立在底盘中心附近，作为底盘运动、导航控制和传感器安装的统一参考坐标。机器人所有运动均围绕该坐标系进行描述。

对于**移动操作机器人**而言，base_link 除了承担底盘参考坐标的职责外，还作为机械臂运动链的起点。机械臂基座、工具坐标系以及各类传感器都通过 base_link 与移动底盘建立联系，因此它既是导航系统的参考点，也是操作系统的空间基准。

对于**人形机器人**而言，Base Frame 的设置更加灵活。由于机器人具有双腿、躯干和上肢等多个运动链，Base Frame 通常建立在骨盆、腰部或机器人质心附近，用于统一描述全身姿态、平衡控制和运动规划。不同平台可能采用不同命名方式，但其作用仍然是作为机器人本体空间关系的统一参考。

因此，无论机器人形态如何变化，Base Frame 始终承担机器人内部空间关系组织的核心职责，只是在不同机器人平台中，其具体位置和定义会根据结构特点有所调整。

## 定位接口中的关键字段

定位模块不仅需要输出机器人的位置，还需要提供足够的信息，使其他模块能够正确理解定位结果的来源、可信程度以及所属坐标系。因此，一个完整的定位接口通常包含以下关键字段。

### Pose

Pose 表示机器人当前位姿，包括位置和姿态，是导航、路径规划和地图更新最核心的数据。

### Twist

Twist 表示机器人当前运动状态，通常包括线速度和角速度。

控制器、轨迹跟踪器以及运动预测模块都会依赖 Twist 信息完成实时控制。

### Covariance / Confidence

定位系统通常还需要输出定位结果的不确定性。

有些系统采用协方差矩阵（Covariance）描述定位误差范围，有些系统则直接输出置信度（Confidence）。

这些信息能够帮助上层算法判断定位结果是否可靠，并决定是否需要重新定位或降低运动速度。

### Source

Source 用于说明定位结果来自哪个模块或传感器。

例如：

- GNSS
- Wheel Odometry
- Visual Odometry
- LiDAR Localization
- SLAM

记录 Source 有助于系统分析定位来源，也便于数据记录和实验复现。

### Tracking Status

Tracking Status 表示当前定位状态。

例如：

- Tracking
- Initializing
- Relocalizing
- Lost

导航系统通常根据 Tracking Status 判断机器人是否具备继续执行任务的条件。

### Timestamp

Timestamp 表示定位结果产生的时间。

由于定位信息需要与传感器数据、机器人状态和控制命令进行同步，因此时间戳是定位接口中不可缺少的重要字段。

### frame_id

frame_id 用于说明定位结果所属的参考坐标系。

例如：

```text
map odom base_link
```

同样的 Pose，如果属于不同 Frame，其物理意义完全不同。因此，任何定位输出都必须明确记录 frame_id，保证各模块能够按照统一的坐标语义进行数据处理。

## 本章与空间定位算法章节的边界

本章主要介绍机器人定位坐标系的组织方式及接口语义，帮助读者理解定位数据在机器人系统中的表达形式。

重点关注的问题包括：

- map、odom、base_link 各自承担什么职责；
- 定位坐标系之间如何建立空间关系；
- 定位输出需要包含哪些接口字段；
- 不同机器人平台如何定义 Base Frame。

而后面的章节将进一步介绍定位数据如何获得，包括：

- 扩展卡尔曼滤波（EKF）；
- 位姿图优化（Pose Graph）；
- 视觉惯性里程计（VIO）；
- 激光惯性里程计（LIO）；
- 同时定位与建图（SLAM）；
- 地图构建与全局定位。

因此，本章回答的是"定位坐标如何组织和使用"，而后续章节回答的是"定位坐标如何通过算法计算得到"。

## 本章建议掌握的内容

本章不要求读者掌握具体定位算法，而是重点理解机器人定位坐标系的职责划分及接口语义。

读者应能够理解 map、odom 和 base_link 分别承担全局地图一致性、局部连续运动和机器人本体参考的职责，认识 map→odom 与 odom→base_link 两类坐标变换的分工，理解为什么 odom 需要保持短时连续，而 map 可以进行全局修正。

同时，应了解移动机器人、移动操作机器人和人形机器人在 Base Frame 定义上的差异，掌握定位接口中 Pose、Twist、Covariance（或 Confidence）、Source、Tracking Status、Timestamp 和 frame_id 等关键字段的含义，能够明确这些字段如何支撑导航、规划、控制和数据记录之间的数据共享，为后续学习空间定位、建图算法和机器人导航系统奠定统一的接口基础。

## 本章小结

定位坐标约定是机器人空间接口体系的重要组成部分，通过 map、odom 和 base_link 三类坐标系分别承担全局地图一致性、局部连续运动以及机器人本体参考等不同职责，使机器人能够同时满足实时控制和长期定位的需求。map→odom 与 odom→base_link 的职责分离，使定位系统既能够保持局部运动的连续性，又能够利用全局定位结果修正累计误差，这也是当前移动机器人系统广泛采用的定位坐标组织方式。

不同机器人形态虽然 Base Frame 的具体位置有所区别，但都承担着机器人本体空间关系的统一参考作用。定位接口除了输出位姿外，还应完整记录速度、定位置信度、数据来源、跟踪状态、时间戳以及所属坐标系等信息，以保证导航、规划、控制和数据记录之间具有一致的空间语义。

本章以 **ROS REP-105** 的坐标约定作为背景，重点介绍课程中如何理解和使用这些定位相关坐标系，而不涉及具体定位算法。建立统一、规范的定位坐标约定，是实现机器人感知、导航、移动操作以及真机部署的重要基础，也为后续空间定位与建图章节的学习提供了统一的接口框架。
