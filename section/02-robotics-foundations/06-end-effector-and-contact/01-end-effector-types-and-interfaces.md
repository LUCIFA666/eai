# 末端工具类型与接口

机器人与环境之间的物理交互，最终都要通过末端执行器（End Effector）来完成。无论是抓取一个杯子、吸附一个包装盒、推动一个滑块，还是操作一个门把手，策略输出的动作指令都必须转化为末端执行器的具体控制命令，并通过末端的传感反馈来判断任务是否成功。

不同类型的末端工具在控制接口、状态反馈和执行能力上差异极大。二指平行夹爪只能输出开/合命令和读取宽度反馈，而灵巧手则需要控制十几个甚至二十几个手指关节，每个关节都有独立的位置和力传感器。如果策略设计时不考虑末端工具的接口差异，很可能出现"模型输出灵巧手动作但机器人只有二指夹爪"或者"策略只输出夹爪开合但机器人需要控制吸附力"的接口不匹配问题。

本节介绍机器人系统中常见的末端工具类型，分别说明它们的可控命令、状态反馈以及在模型文件中的表达方式，最后讨论末端工具选择对动作空间设计和数据记录的影响。本节不展开灵巧手学习算法和抓取生成方法，而是聚焦于末端工具在接口层面的能力和边界。

## Parallel Gripper（二指平行夹爪）

二指平行夹爪是目前具身智能领域使用最广泛的末端执行器。两个手指沿平行方向对称运动，通过改变手指间距来抓取或释放物体。

**可控命令**通常包括：

```text
command:
  mode: "position" | "force" | "velocity"
  target_width: 0.05           # 目标开合宽度 (m)，0 表示完全闭合
  target_force: 15.0           # 目标夹持力 (N)，力控模式下使用
  target_speed: 0.02           # 开合速度 (m/s)
```

最简单的接口只接收一个 0～1 的归一化值表示开合程度：

```text
gripper_command: 0.8           # 0 = 完全闭合, 1 = 完全张开
```

许多模仿学习数据集（如 ALOHA、LeRobot）和 VLA 模型都采用这种简化的归一化接口，将夹爪控制作为一个或两个标量维度附加在动作向量末尾。

**状态反馈**通常包括：

```text
feedback:
  position: 0.048              # 当前手指间距 (m)
  velocity: 0.01               # 当前开合速度 (m/s)
  effort: 12.3                 # 当前夹持力 (N)
  is_moving: true              # 是否正在运动
  is_grabbed: false            # 是否检测到物体（部分夹爪支持）
  fault: none                  # 故障状态
```

二指夹爪的优势在于接口简单、控制稳定、成本低廉，非常适合标准化的抓取-放置任务。其局限在于无法适应复杂形状的物体，抓取策略主要依赖物体几何和夹爪位姿，缺乏手指级别的灵活调整能力。

## Suction Cup（吸盘）

吸盘通过真空吸附方式拾取物体，广泛应用于物流分拣、仓储搬运和包装行业。与夹爪不同，吸盘不需要从两侧包夹物体，只需要接触物体的一个平整表面即可完成拾取。

**可控命令**：

```text
command:
  vacuum_on: true              # 开启/关闭真空
  target_pressure: -60.0       # 目标气压 (kPa)，负值表示真空度
  blow_off: false              # 是否反向吹气释放
```

**状态反馈**：

```text
feedback:
  pressure: -58.2              # 当前气压 (kPa)
  vacuum_established: true     # 是否已建立有效真空
  object_detected: true        # 是否检测到物体被吸附
  leak_rate: 1.5               # 泄漏速率 (kPa/s)
  fault: none
```

吸盘的关键接口特性在于：其"抓取"状态不能通过机械位置判断，而必须依赖气压传感器的反馈。因此，策略不能仅凭"已发送吸附指令"就认为物体已牢固拾取，而必须读取 vacuum_established 和 object_detected 等反馈信号进行确认。此外，吸盘对物体表面平整度和材质有较高要求——多孔、粗糙或柔性表面可能导致真空泄漏，使吸附力不足。

## Multi-finger Hand（多指手）

多指手通常具有 2～4 个手指，每个手指包含 1～3 个独立关节，能够完成比二指夹爪更复杂的抓取姿态。多指手在工业上常用于特定形状工件（如圆柱体、环形件）的抓取，在服务机器人中则用于抓取日常物品。

**可控命令**：

多指手的控制接口通常为每个手指关节提供独立的控制通道：

```text
command:
  finger_joints:               # 所有手指关节的目标位置
    finger_1: [0.5, 0.3]       # 手指 1 的两个关节 (rad)
    finger_2: [0.5, 0.3]       # 手指 2
    finger_3: [0.5, 0.3]       # 手指 3
  target_force:                # 可选，力控模式下的目标力
    finger_1: [5.0, 3.0]       # (N)
    ...
```

**状态反馈**：

```text
feedback:
  joints:
    finger_1: {position: [0.48, 0.29], velocity: [...], effort: [...]}
    finger_2: ...
  contact:                     # 各手指的接触状态
    finger_1: {contact: true, force: 5.2}
    finger_2: {contact: true, force: 4.8}
    finger_3: {contact: false, force: 0.0}
  fault: none
```

相比二指夹爪，多指手的接口维度显著增加，策略需要同时考虑更多控制变量，数据采集和训练难度也相应提高。许多系统为了简化接口，会将预定义的抓取模式（如包络抓取、三指捏取）作为离散命令下发，由底层控制器自动生成手指关节轨迹，而不是让策略直接输出每个手指关节的位置。

## Dexterous Hand（灵巧手）

灵巧手是多指手的进一步演进，通常具有 5 个手指和 15～25 个自由度，接近人手的运动能力。灵巧手的控制接口高度复杂，不仅包含大量关节位置和力命令，还可能涉及触觉阵列、温度传感器和肌腱张力等反馈信息。

**可控命令**通常以完整的关节向量表示：

```text
command:
  positions: [q1, q2, ..., qN]      # N = 16~24 (各关节目标位置)
  efforts: [τ1, τ2, ..., τN]        # 各关节目标力矩（力控模式）
  grasp_preset: "power_grasp"       # 可选，预定义抓取模式
```

**状态反馈**更为丰富：

```text
feedback:
  positions: [q1, q2, ..., qN]      # 当前关节位置
  velocities: [v1, v2, ..., vN]     # 当前关节速度
  efforts: [τ1, τ2, ..., τN]        # 当前关节力矩
  tactile:                           # 触觉阵列数据（如 15×15 的压力矩阵）
    thumb: [[0, 0.1, 0.2, ...], ...]
    index: [...]
  contact:                           # 各指节的接触状态
    thumb_distal: {contact: true, force: 1.2}
    ...
  fault: none
```

灵巧手在具身智能领域的应用尚处于早期阶段，目前主要面临几方面挑战：控制维度高导致策略学习困难，数据采集需要高精度动捕或遥操作系统，仿真到真实的迁移差距较大（触觉和软体接触难以精确建模）。对于大多数实际部署场景而言，灵巧手的接口能力远超当前策略的利用水平，因此通常需要通过接口封装和抽象简化来降低策略的学习难度。

## Tool Changer（工具快换装置）

工具快换装置（Tool Changer）允许机器人在运行过程中自动切换不同的末端执行器。例如，同一台机械臂可以先使用吸盘拾取工件，再切换到二指夹爪完成装配，最后换用打磨工具进行表面处理。

**可控命令**：

```text
command:
  tool_attach: true            # 安装当前工具（锁定）
  tool_detach: true            # 释放当前工具（解锁）
  tool_id: "gripper_2f_01"    # 目标工具标识
  tool_present: true           # 读取当前是否有工具安装
```

**状态反馈**：

```text
feedback:
  tool_id: "gripper_2f_01"    # 当前安装的工具 ID
  locked: true                 # 是否已锁定
  tool_standby: [              # 工具架上各工具的状态
    {id: "gripper_2f_01", present: false},
    {id: "suction_cup_01", present: true},
    {id: "sander_01", present: true}
  ]
  fault: none
```

工具快换装置的接口要点在于：切换工具时，控制器需要知道当前装载的是哪一种末端执行器，从而激活对应的命令和反馈字段。如果策略不知道当前装载的是吸盘还是夹爪，就可能在发送夹爪闭合命令时期望吸盘产生真空——这在接口层面是致命的语义错误。因此，工具切换后应及时更新末端执行器的接口定义和状态字段映射。

## Custom Tool（定制工具）

在焊接、涂胶、切割、测量等工业场景中，机器人末端常常安装的是专门设计的定制工具而不是通用夹爪。这些工具可能包含加热元件、激光器、喷头、探针等非标执行组件。

定制工具的接口没有统一标准，但通常遵循以下原则：

- 提供与工具功能对应的专用命令字段（如 `weld_on`、`glue_flow_rate`、`laser_power`）；
- 继承机械臂末端位姿的通用状态字段（位置、速度）；
- 添加工具特有的传感反馈（温度、流量、功率、探针位移等）；
- 与工具控制器（PLC 或微控制器）通过数字 IO、现场总线或串口通信。

定制工具的接口设计需要在专用性和可复用性之间权衡。过于通用的接口可能导致策略不了解工具的实际能力，过于专用的接口则难以跨平台迁移。

## 末端工具在模型文件中的表达

在机器人模型文件（URDF、MJCF 等）中，末端工具作为机器人运动学链的最后一个连杆（或一组连杆）进行定义。模型文件中与末端工具相关的关键信息包括：

- **Tool Frame（工具坐标系）**：定义在末端工具的参考点上，通常位于夹爪中心、吸盘接触面中心或工具尖端。Tool Frame 是所有末端位姿命令的默认参考坐标系，其位置和朝向直接影响抓取和操作精度。
- **Mimic Joint（从动关节）**：对于二指平行夹爪，通常使用 mimic joint 机制——一个关节主动运动，另一个关节镜像跟随，以简化控制接口。
- **Collision Geometry（碰撞几何）**：末端工具的简化碰撞模型（通常为包围盒或凸包），用于自碰撞检测和环境碰撞检测。过于简化的碰撞模型可能导致夹爪在仿真中穿透物体，过于精细的模型则增加碰撞检测的计算开销。
- **Contact Surface（接触面）**：定义末端工具上与物体发生接触的表面属性，包括摩擦系数、接触刚度、阻尼等参数。这些参数直接影响仿真中抓取行为的真实度。
- **Payload（负载能力）**：末端工具的自重（mass）和惯量（inertia），以及允许的最大负载。负载数据用于轨迹规划中的力矩和加速度限制计算。

## 末端工具选择对动作空间和数据记录的影响

末端工具的类型决定了策略需要输出的动作维度和数据记录的字段集合。如果将不同末端工具的动作字段统一为同一组维度，会带来严重的接口设计问题。

例如，二指夹爪的动作空间可能只需一个标量（开合程度），而灵巧手则需要 16～24 维的关节向量。如果强行将所有末端工具的动作字段统一为一个固定维度向量，那么对于二指夹爪而言，大部分维度将被浪费或填充零值；而对于灵巧手，有限维度又可能不足以表达完整的控制意图。

同样，数据记录也必须根据末端工具类型调整：

- 二指夹爪的数据集需要记录夹爪宽度和夹持力；
- 吸盘的数据集需要记录真空压力和泄漏速率；
- 灵巧手的数据集需要记录每个手指关节的位置、速度和力矩，以及触觉阵列数据。

因此，在机器人系统设计中，动作空间定义和数据记录格式应与末端工具类型解耦——工具类型决定哪些字段有效、哪些字段被忽略，而不是将所有字段强行塞入统一的模板。使用工具配置文件或动态接口描述（如 ROS 的 URDF + SRDF 或自定义的 tool config YAML）来声明当前末端工具的接口字段，是一种工程上更可维护的做法。

## 本节小结

末端执行器是机器人与物理世界交互的最终界面，不同类型末端工具在控制命令、状态反馈和接口复杂度上差异巨大。二指平行夹爪接口最简单，适合大多数抓取-放置任务；吸盘依赖气压反馈而非机械位置，适合平面物体拾取；多指手和灵巧手提供更高的灵活性，但接口维度暴增，对策略学习和数据采集提出更高要求；工具快换装置引入了工具身份的运行时切换；定制工具则需要针对具体功能设计专用接口。

模型文件中的 Tool Frame、Mimic Joint、碰撞几何、接触面以及负载等属性共同定义了末端工具的物理特性，是接口能够正确工作的基础。末端工具的类型直接决定了动作空间的维度设计和数据记录的字段集合——二指夹爪和灵巧手不应共用相同的动作字段模板。在工程实践中，应根据实际装载的末端工具动态配置命令接口和反馈通道，而不是将所有可能字段硬编码为固定维度的统一接口。
