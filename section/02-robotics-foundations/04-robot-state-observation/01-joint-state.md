# 关节状态

## 本章概述

机器人能够完成运动控制、轨迹规划、状态估计以及策略推理，前提是系统能够持续获取机器人本体的实时状态。其中，**关节状态（Joint State）**是描述机器人自身运动情况最基础、最重要的数据接口之一。无论是机械臂、移动操作机器人、人形机器人，还是四足机器人，其运动最终都由各个关节的状态共同决定，因此 Joint State 也是机器人系统中更新频率最高、使用范围最广的数据类型之一。

在机器人软件中，Joint State 并不仅仅表示"当前关节角度"，它通常包含关节名称、位置、速度、受力情况以及时间信息等多个字段，用于完整描述机器人在某一时刻的运动状态。运动控制器依赖 Joint State 构建反馈闭环，策略模型将其作为本体感知（Proprioception）的重要输入，仿真平台利用它驱动机器人模型运动，数据集则通过持续记录 Joint State 实现机器人动作的完整复现。

需要特别强调的是，Joint State 是一种严格依赖接口约定的数据结构。关节名称、关节顺序、单位、时间戳以及控制模式等信息必须保持一致，否则即使数值本身完全正确，也可能导致机器人动作错误、数据回放失败甚至控制系统异常。其中，**关节顺序错误往往比少量数值噪声更加危险**，因为它会使多个关节的数据发生整体错位，从而直接改变机器人运动语义。

本章将介绍 Joint State 的基本组成，说明关节名称、位置、速度、力矩等字段的含义，分析不同类型关节在状态表示上的区别，并介绍机器人系统中常见的扩展状态字段。同时，本章还将说明 Joint State 在策略训练、轨迹跟踪、数据记录、仿真回放和系统诊断中的作用，并总结机器人开发过程中最容易出现的接口问题。本章重点关注 Joint State 的接口定义和工程使用方式，不涉及具体控制算法或状态估计方法。

## Joint State 的基本组成

Joint State 用于描述机器人所有关节在某一时刻的运动状态。通常情况下，机器人会周期性地发布一组关节状态数据，上层模块根据这些数据了解机器人当前姿态和运动情况。

一个最基本的 Joint State 一般包含以下几个核心字段：

- name
- position
- velocity
- effort
- timestamp

这些字段共同描述了机器人每一个关节在特定时刻的运动信息。

### name

name 用于记录每一个关节的名称。

例如：

```text
shoulder_joint
elbow_joint
wrist_joint
gripper_joint
```

关节名称用于唯一标识机器人模型中的每一个关节，也是机器人模型、控制器、数据集和策略模型之间建立对应关系的重要依据。

### position

position 表示关节当前位置。

对于旋转关节，它表示当前关节角度；对于直线关节，则表示当前移动距离。

机器人运动学计算、轨迹规划以及状态反馈都会大量使用 Position 数据。

### velocity

velocity 表示关节当前运动速度。

控制器通常利用 Velocity 判断机器人是否按照期望速度运行，也可以用于预测机器人未来运动状态。

### effort

effort 表示机器人关节当前受到的驱动力或输出力矩。

不同机器人平台对于 Effort 的定义可能略有不同，有些表示电机输出力矩，有些表示估计驱动力，也有部分系统直接提供控制器内部计算值，因此实际使用时需要结合机器人平台进行理解。

### timestamp

timestamp 表示当前 Joint State 的采集时间。

机器人系统中的 Joint State 往往需要与：

- 相机图像；
- IMU 数据；
- 力传感器；
- 控制命令；

进行时间同步，因此时间戳是机器人状态接口不可缺少的重要组成部分。

## Joint Name 与 Joint Order 的一致性

机器人中的 Joint State 本质上是一组数组，而数组本身并不能表达每一个数值对应哪个关节，因此必须依靠 Joint Name 和 Joint Order 保持一致。

Joint Name 定义了每一个数组元素代表哪个关节。

例如：

```text
name

[shoulder_joint elbow_joint wrist_joint]
```

对应：

```text
position

[0.3 0.6 1.2]
```

表示：

```text
shoulder_joint → 0.3

elbow_joint → -0.6

wrist_joint → 1.2
```

与此同时，**Joint Order（关节顺序）**必须在机器人模型、控制器、状态反馈、动作命令、数据集以及策略模型之间保持完全一致。

例如，机器人模型规定：

```text
[joint1 joint2 joint3]
```

如果控制器却按照：

```text
[joint2 joint1 joint3]
```

解析数组，那么机器人虽然收到完全正确的数值，却会控制错误的关节，造成严重运动错误。

相比于少量测量噪声，这种整体错位通常更加危险，因为机器人无法通过滤波或控制算法自动修正接口语义错误。因此，在机器人开发过程中，应始终将 Joint Name 和 Joint Order 作为接口契约的重要组成部分，确保所有模块采用统一的关节排列方式。

## Position、Velocity 与 Effort 的含义及单位

不同类型关节虽然都采用 Position、Velocity 和 Effort 三类状态字段，但具体物理含义和单位有所不同。

### Revolute Joint

Revolute Joint（旋转关节）用于描述绕固定轴旋转的关节，是机械臂、人形机器人和四足机器人最常见的关节类型。

对于 Revolute Joint：

Position 表示关节角度，通常采用**弧度（rad）**作为单位；
Velocity 表示角速度，单位通常为 **rad/s**；
Effort 表示输出力矩，单位通常为 **N·m**。

这些数据共同反映关节当前的旋转状态和驱动能力。

### Prismatic Joint

Prismatic Joint（移动关节）用于描述沿某一方向做直线运动的关节，例如滑台、升降机构或伸缩机构。

对于 Prismatic Joint：

Position 表示线性位移，通常采用**米（m）**作为单位；
Velocity 表示线速度，单位通常为 **m/s**；
Effort 表示线性驱动力，单位通常为 **N**。

虽然接口字段名称保持一致，但由于运动形式不同，其物理意义与旋转关节存在明显区别。因此，在机器人系统中，应根据关节类型正确解释各字段的单位和含义，避免角度与位移、力矩与推力之间发生混淆。

## 常见扩展状态字段

除了 Position、Velocity 和 Effort 外，机器人系统通常还会提供更多用于监控和诊断的状态字段。

### Joint Limit

Joint Limit 用于描述关节允许运动的范围。

控制器可以根据 Joint Limit 判断机器人是否接近机械极限，从而提前进行限位保护。

### Temperature

Temperature 表示电机或驱动器当前温度。

长时间高负载运行时，Temperature 可以反映机器人是否存在过热风险，是设备健康监测的重要指标。

### Current

Current 表示电机实际工作电流。

电流大小通常能够反映机器人当前负载情况，也可用于故障分析和执行器状态监测。

### Torque Estimate

部分机器人无法直接测量真实力矩，因此会提供 Torque Estimate（估计力矩）。

它通常由电机电流、动力学模型或控制器内部算法计算得到，可用于近似分析机器人受力情况，但其精度通常低于真实力矩传感器。

### Control Mode

Control Mode 表示当前关节采用的控制方式，例如：

- Position Control
- Velocity Control
- Torque Control
- Impedance Control

不同控制模式决定了机器人如何解释动作命令，也是策略部署和控制接口的重要上下文信息。

### Fault Flag

Fault Flag 用于表示关节当前是否存在异常。

例如：

- 过温；
- 过流；
- 通信故障；
- 编码器异常；
- 驱动器保护。

控制系统通常根据 Fault Flag 判断机器人是否允许继续执行运动任务。

## Joint State 的应用场景

作为机器人最基础的状态接口，Joint State 几乎参与了机器人系统的所有核心模块。

在**具身智能策略**中，Joint State 是机器人本体感知（Proprioception）的主要来源。策略模型通过关节角度、速度和受力情况感知自身姿态，并结合视觉、触觉等信息生成动作输出。

在**轨迹跟踪控制**中，控制器持续比较期望关节状态与实际 Joint State，通过反馈闭环修正控制误差，使机器人能够准确跟踪规划轨迹。

在**机器人数据集记录**中，Joint State 是每一帧机器人状态的重要组成部分。无论是示教数据、遥操作数据还是真机采集数据，都会同步记录 Joint State，以支持后续模型训练和实验复现。

在**仿真回放**过程中，机器人模型通常依据历史 Joint State 重建机器人运动过程，实现动作复现和算法验证。

此外，在**异常诊断与设备维护**中，Joint State 中的温度、电流、故障标志等扩展字段能够帮助工程人员快速定位机器人异常状态，评估机器人运行健康程度，并为设备维护提供依据。

## 常见问题与工程实践

Joint State 是机器人系统中最基础的数据接口，同时也是最容易出现接口错误的模块之一。

首先，**缺少 Joint Name** 是常见问题。如果状态数组中没有明确的关节名称，不同模块便无法确认每一个数据对应哪个关节，导致数据无法正确解析。

其次，**状态更新频率不稳定**。Joint State 通常需要以固定频率持续发布，如果更新周期波动较大，控制器和策略模型可能无法正确同步状态，影响控制稳定性。

第三，**Effort 数据可信度不足**。许多机器人平台输出的 Effort 并非真实测量值，而是控制器估计值或电流近似值。因此，在进行力控或动力学分析时，应确认 Effort 的具体来源，而不能默认其代表真实关节力矩。

第四，**仿真关节数量与真机关节数量不一致**。例如，仿真模型可能包含额外的虚拟关节，而真机控制器仅输出实际驱动关节。如果接口没有正确对齐，数据回放和策略迁移将出现维度不一致的问题。

最后，**Gripper Mimic Joint 处理错误**。部分机器人夹爪采用 Mimic Joint 表示多个指爪之间的联动关系。如果数据记录或控制接口错误地将 Mimic Joint 当作独立驱动关节处理，就可能导致状态重复、动作维度错误或控制逻辑异常。因此，在构建机器人模型和数据接口时，应明确区分真实驱动关节与 Mimic Joint，并保持一致的接口语义。

读者应能够理解 Joint State 的基本组成，掌握 name、position、velocity、effort 和 timestamp 等核心字段的作用；能够区分 Revolute Joint 和 Prismatic Joint 在 Position、Velocity 和 Effort 含义及单位上的差异，理解 Joint Name 与 Joint Order 在机器人模型、控制器、数据集和策略模型之间保持一致的重要性。

同时，应了解 Temperature、Current、Torque Estimate、Control Mode 和 Fault Flag 等扩展状态字段的用途，认识 Joint State 在策略本体感知、轨迹跟踪、数据记录、仿真回放和异常诊断等不同场景中的作用，并能够识别关节名称缺失、关节顺序错误、更新频率不稳定、Effort 不可信以及 Mimic Joint 处理不当等常见接口问题，为后续机器人控制、数据采集和具身智能策略开发建立可靠的状态接口基础。

## 本章小结

Joint State 是机器人系统描述本体实时运动状态的核心接口，通过 name、position、velocity、effort 和 timestamp 等基本字段持续反映机器人各关节的运动情况，为控制器、策略模型、仿真平台和数据记录系统提供统一的状态输入。对于不同类型关节，Position、Velocity 和 Effort 的物理含义及单位有所不同，因此应结合关节类型正确解释状态数据。

在工程实践中，Joint Name 与 Joint Order 的一致性比单纯提高数值精度更加重要，任何关节顺序错位都可能导致机器人动作语义发生根本性错误。同时，Temperature、Current、Torque Estimate、Control Mode 和 Fault Flag 等扩展字段能够进一步支持设备监测、异常诊断和系统维护。由于 Joint State 广泛应用于本体感知、轨迹反馈、数据集构建和仿真回放，因此建立统一、稳定且语义一致的关节状态接口，是实现机器人控制、算法训练和跨平台部署的重要基础。
