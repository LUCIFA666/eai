# 末端工具状态（End-Effector State）

机器人能够完成抓取、装配、搬运、按压等操作，不仅依赖于机械臂关节运动是否到达目标位置，还取决于**末端执行器（End-Effector）是否真正完成了与环境的交互**。因此，在机器人状态表示中，除了关节状态（Joint State）和底盘状态（Base State）之外，还需要记录**末端工具状态（End-Effector State）**。

末端工具状态用于描述夹爪、吸盘、电动工具、焊枪、螺丝刀等末端执行器当前的工作状态，包括开合程度、运动速度、施加力、接触情况、动作执行状态以及故障信息等。这些信息能够反映控制指令是否真正执行成功，也是判断机器人是否完成任务的重要依据。

在机器人数据采集、遥操作示教、模仿学习以及自动化生产过程中，End-Effector State 通常作为 Observation 的组成部分，与 Joint State、Base State 共同构成机器人的完整状态描述。

## End-Effector State 的基本字段

不同类型的末端执行器具有不同的状态信息，但大多数机器人系统都会记录以下几类基本字段。

### Gripper Width（夹爪开口宽度）

夹爪开口宽度表示两指夹爪当前的实际张开距离，是最常见的末端状态之一。

例如：

```text
gripper_width = 0.062 m
```

单位通常为：

```text
m
```

该字段能够直接反映夹爪是否已经张开或闭合，以及闭合后是否由于物体存在而停留在某一宽度。

对于平行夹爪来说，Gripper Width 通常比单独记录左右手指位置更直观，也是许多抓取数据集（如 LeRobot、ALOHA 等）中的标准字段。

### Gripper Position（夹爪位置）

部分夹爪控制器不会直接输出开口宽度，而是记录驱动电机的位置，例如：

```text
gripper_position
```

其单位可能为：

* m（滑块位移）
* rad（电机角度）
* encoder ticks（编码器计数）

Gripper Position 更多用于底层控制，而数据集通常会进一步转换为实际开口宽度，以便不同硬件之间保持统一表示。

### Gripper Velocity（夹爪速度）

夹爪速度表示夹爪开合的运动速度。

例如：

```text
gripper_velocity
```

单位通常为：

```text
m/s
```

或：

```text
rad/s
```

夹爪速度能够帮助判断：

* 是否正在执行开合动作；
* 是否发生运动停滞；
* 是否已经到达目标位置。

### Gripper Force（夹持力）

夹持力表示夹爪施加在物体上的作用力。

例如：

```text
gripper_force
```

单位通常为：

```text
N
```

夹持力过小可能导致物体滑落，而夹持力过大则可能损坏目标物体。因此，在抓取易碎物品或进行精细装配时，该字段尤为重要。

部分夹爪通过电流估计夹持力，部分高端夹爪则内置力传感器，可直接输出更准确的测量值。具有输出接触力功能的夹爪可以进行力控，从而得到更精准的控制结果，便于抓取柔软物体或者易碎物体。

### Vacuum Pressure（真空压力）

对于吸盘式末端执行器，不再关注夹爪开口，而是记录真空系统状态。

例如：

```text
vacuum_pressure
```

单位通常为：

```text
kPa
```

或：

```text
Pa
```

真空压力能够反映：

* 是否已经形成吸附；
* 是否发生漏气；
* 吸附是否稳定。

工业吸盘机器人通常依据真空压力判断物体是否已经成功抓取。

### Tool Mode（工具模式）

Tool Mode 描述末端工具当前所处的工作模式。

例如：

```text
tool_mode
```

可能包括：

```text
IDLE, OPEN, CLOSE, VACUUM_ON, VACUUM_OFF, SCREWING, CUTTING, WELDING
```

不同工具具有不同模式，但统一记录 Tool Mode 可以帮助控制系统快速了解当前工具状态，并便于数据回放和任务分析。

## 接触相关状态

末端执行器是否真正与环境发生交互，仅依靠位置信息通常无法判断，因此许多机器人系统会进一步记录接触状态。

### Contact Detected（检测到接触）

Contact Detected 表示末端工具已经与目标物体或环境发生接触。

例如：

```text
contact_detected = true
```

该状态通常来源于：

* 力传感器；
* 电流检测；
* 触觉传感器；
* 真空压力变化；
* 接触开关。

接触状态可用于判断机器人是否已经触碰目标，而不仅仅是运动到了目标位置。

### Object Held（已抓住物体）

Object Held 表示机器人已经成功保持目标物体。

例如：

```text
object_held = true
```

该状态通常综合以下信息判断：

* 夹爪宽度变化；
* 夹持力达到要求；
* 真空压力稳定；
* 电流特征符合抓取状态。

相比 Contact Detected，Object Held 更强调**目标已经被稳定持有**。

### Slip Detected（检测到滑移）

Slip Detected 表示抓取物体发生滑移。

例如：

```text
slip_detected = true
```

其来源可能包括：

* 力传感器变化；
* 触觉阵列；
* 高频振动检测；
* 电流异常变化。

滑移检测能够帮助控制器及时增加夹持力或重新调整抓取策略。

### Force Threshold Reached（达到力阈值）

Force Threshold Reached 表示末端施加的力已经达到预设阈值。

例如：

```text
force_threshold_reached = true
```

该状态常用于：

* 按压按钮；
* 插入装配；
* 打磨加工；
* 力控操作。

达到设定阈值后，控制器通常会停止继续施力，以避免损坏设备或工件。

## 动作执行状态

除了工具自身状态，机器人通常还需要记录当前动作执行过程，以便控制系统和上层任务管理器了解命令执行情况。

### Command Accepted（命令已接收）

表示控制器已经成功接收到控制指令。

例如：

```text
command_accepted = true
```

该状态仅表示命令已经进入执行流程，并不意味着动作已经完成。

### Moving（执行中）

表示末端执行器正在运动。

例如：

```text
moving = true
```

机器人通常依据当前位置与目标位置之间的误差判断是否仍处于运动状态。

### Done（执行完成）

表示控制命令已经执行结束。

例如：

```text
done = true
```

完成状态通常意味着：

* 到达目标位置；
* 达到目标力；
* 达到目标真空压力；
* 完成指定动作。

### Timeout（执行超时）

Timeout 表示在规定时间内未完成动作。

例如：

```text
timeout = true
```

可能原因包括：

* 机械阻塞；
* 目标不存在；
* 控制器异常；
* 通信中断。

超时状态通常需要重新规划动作或进入异常处理流程。

### Stalled（运动停滞）

Stalled 表示执行器无法继续运动。

例如：

```text
stalled = true
```

可能原因包括：

* 被异物卡住；
* 电机过载；
* 行程达到机械极限；
* 控制器保护。

Stalled 与 Timeout 不同，它强调的是**运动能力受阻**，相比于 Timeout 是更需要注意的报错。

### Fault（故障）

Fault 表示末端执行器发生硬件或软件故障。

例如：

```text
fault = true
```

可能包括：

* 电机异常；
* 编码器故障；
* 通信错误；
* 驱动器报警。

一旦进入 Fault 状态，机器人通常需要人工干预或重新初始化。

### Emergency Stop（急停）

Emergency Stop 表示机器人进入急停状态。

例如：

```text
emergency_stop = true
```

急停状态下，所有运动命令都会立即终止，是机器人安全系统的重要组成部分。数据集记录该字段有助于区分正常任务结束与因安全原因中断的情况。

## End-Effector State 与 Joint State 的区别

Joint State 与 End-Effector State 都属于机器人状态的重要组成部分，但两者关注的对象并不相同。

Joint State 描述的是机器人本体各个关节的运动状态，包括关节角度、速度、力矩等信息，其重点在于反映机器人自身是否按照控制指令完成了运动。

End-Effector State 则关注机器人与外部环境之间的实际交互情况，例如夹爪是否夹紧、吸盘是否吸附成功、工具是否达到目标力、是否已经完成动作等。即使关节状态已经达到目标位置，也并不意味着任务已经成功。例如，机械臂已经运动到抓取位置，但夹爪未能夹住物体，或者吸盘因漏气未能形成稳定吸附，此时关节状态虽然正常，末端工具状态却表明任务失败。

因此，在机器人控制、数据采集和模仿学习中，通常需要同时记录 Joint State 和 End-Effector State，才能完整描述机器人从运动到交互的全过程。也有部分机器人在控制的时候会把关节状态和夹爪状态合在一起，统一进行位置控制或者力控制。

## 不同任务应记录的末端状态

不同操作任务关注的末端状态存在明显差异，应根据任务特点选择合适的状态字段进行记录。

对于**抓取（Grasping）**任务，建议记录夹爪开口宽度、夹爪位置、夹持力、接触状态、是否成功持有物体以及动作执行状态。这些信息能够完整反映抓取动作是否成功以及抓取过程是否稳定。

对于**吸附（Suction）**任务，应重点记录真空压力、吸附状态、是否检测到物体、是否发生漏气以及工具工作模式。真空压力通常是判断吸附成功与否的核心指标。

对于**按压（Pressing）**任务，应记录末端施加的力、是否达到目标力阈值、接触检测状态以及动作完成状态，以确保按钮、开关或触控操作达到预期效果。

对于**插入（Insertion）**任务，除了记录接触状态和动作执行状态外，还应重点记录夹持力、滑移检测、力阈值达到情况以及是否发生运动停滞。这些状态能够帮助分析插入力控制是否稳定，并为后续的数据回放、误差分析和策略学习提供依据。

需要注意的是，本节仅介绍末端工具状态的表示与记录方式，而**抓取点生成、目标可供性分析以及触觉感知算法**等内容属于机器人感知与操作规划范畴，将在第 3 章中进一步介绍。
