# 传感器状态（Sensor State）

机器人系统中的观测数据主要来源于各种传感器，包括相机、深度相机、IMU、力/力矩传感器、触觉传感器以及关节编码器等。这些传感器共同构成了机器人对自身状态和外部环境的感知能力。然而，对于机器人控制、数据采集和机器学习而言，仅记录传感器输出的数据本身是不够的，更重要的是记录**传感器状态（Sensor State）**，以判断当前观测数据是否可信、是否能够正确解释，以及未来是否能够被准确复现。

例如，一张 RGB 图像即使内容完整，如果曝光参数发生变化、外参版本错误或时间戳与机械臂状态不同步，下游算法仍可能产生较大误差。同样，一组 IMU 数据即使连续输出，如果存在较大的零偏漂移或已经进入饱和状态，其测量结果也难以直接用于状态估计。因此，在机器人数据集和在线系统中，除了保存原始传感器数据之外，还应记录描述传感器配置、运行状态和数据质量的相关信息。

本节主要介绍各类传感器应记录的状态字段，以及这些字段如何帮助判断观测数据是否可靠，而不涉及具体的感知算法实现。

## 传感器状态的基本字段

无论是哪一种传感器，每一路观测数据都应至少记录能够描述其来源、时间、配置和运行状态的基础信息。这些字段不仅有助于在线控制，也保证了数据集能够在未来被正确解析和复现。

### Frame ID（参考坐标系）

每个传感器的数据都应明确其所属坐标系。

例如：

```text
frame_id = camera_front
```

或者：

```text
frame_id = imu_link
```

Frame ID 用于说明当前数据是在**哪个坐标系下测量得到的**，也是机器人坐标变换（TF）系统的重要组成部分。

例如：

* 相机图像对应 camera_optical_frame；
* 深度图对应 depth_camera_frame；
* IMU 对应 imu_link；
* 力传感器对应 wrist_ft_sensor。

如果 Frame ID 记录错误，即使数据本身正确，也可能导致机器人在坐标变换过程中产生位置偏差，影响感知、控制和数据回放。

### Timestamp（时间戳）

时间戳记录数据采集的准确时刻。

例如：

```text
timestamp = 1723456789.123456
```

高精度时间戳是实现多传感器同步的基础，可用于：

* 图像与关节状态对齐；
* IMU 与相机同步；
* 力传感器与控制命令对应；
* 数据回放与离线分析。

如果不同传感器之间时间不同步，即使每一路数据都正确，也无法准确反映机器人在同一时刻的真实状态。

### Rate（采样频率）

Rate 表示传感器的数据更新频率。

例如：

```text
rate = 30 Hz
```

不同传感器通常具有不同的采样速率，例如：

* RGB 相机：30 Hz；
* 深度相机：30 Hz；
* IMU：200～1000 Hz；
* 力/力矩传感器：500～2000 Hz；
* 编码器：1 kHz 以上。

记录采样频率有助于判断数据是否存在掉帧、断流或频率异常，也便于后续进行时间插值和数据同步。

### Resolution 或 Dimension（分辨率或数据维度）

不同类型传感器需要记录不同的尺寸信息。

对于图像类传感器，应记录：

```text
resolution:
    width
    height
```

例如：

```text
1280 × 720
```

对于非图像传感器，则通常记录数据维度，例如：

* IMU：6 维（加速度 + 角速度）；
* 力传感器：6 维（Force + Torque）；
* 触觉阵列：16×16 或 32×32；
* 编码器：对应关节数量。

这些信息决定了数据的解析方式，也是模型输入格式的重要组成部分。

### Calibration Version（标定版本）

Calibration Version 用于记录当前传感器所使用的标定参数版本。

例如：

```text
calibration_version = camera_calib_v3
```

机器人系统中的相机内参、外参、IMU 安装位姿等参数可能会随着重新标定而发生变化，因此数据集应明确记录所使用的标定版本。

否则，相同的数据可能因采用不同标定参数而得到完全不同的结果，影响实验的可重复性。

### Health Status（健康状态）

Health Status 用于描述传感器当前是否正常工作。

例如：

```text
health_status = OK
```

也可能包括：

```text
OK
WARNING
ERROR
OFFLINE
```

健康状态通常由驱动程序或设备诊断模块提供，可用于快速判断当前数据是否可靠，以及是否需要启用备用传感器或停止相关任务。

## 常见传感器的状态信息

不同类型的传感器除了基础字段外，还需要记录能够影响测量质量和数据解释的特定状态信息。

### 相机与深度相机

相机是机器人最重要的环境感知设备之一。除了图像本身，还需要保存与成像模型相关的重要参数。

首先是**相机内参（Intrinsics）**，包括焦距、主点位置等参数，用于建立图像像素与三维空间之间的几何关系。视觉定位、三维重建、目标检测和抓取定位等算法都依赖于正确的内参。

其次是**镜头畸变参数（Distortion）**。镜头通常存在径向畸变和切向畸变，如果未记录或使用错误的畸变参数，图像边缘可能产生明显几何误差，从而影响位姿估计和空间测量。

**外参（Extrinsics）**描述传感器相对于机器人本体或其他传感器的位置和姿态关系，是多传感器融合的重要依据。例如，相机与机械臂之间的手眼标定结果决定了视觉检测到的目标能否准确转换到机器人坐标系中。

对于图像采集，还应记录**曝光参数（Exposure）**。曝光时间、增益等设置会直接影响图像亮度、动态范围以及运动模糊程度。在不同曝光条件下，即使场景不变，视觉算法的表现也可能发生明显变化，因此曝光信息对于实验复现具有重要意义。

对于深度相机，还需要记录**Depth Scale（深度尺度）**。深度图中的原始数值通常需要乘以对应的尺度系数才能转换为真实距离。如果不同设备或不同 SDK 使用了不同的深度尺度，而数据集中未记录该参数，下游算法将无法正确恢复三维空间信息。

### IMU（惯性测量单元）

IMU 提供机器人角速度和线加速度信息，是姿态估计和运动状态推断的重要来源。

IMU 应记录**Bias（零偏）**，包括陀螺仪和加速度计的静态偏置。随着时间变化，零偏可能发生漂移，如果未进行补偿，将导致姿态估计误差不断累积。

同时应记录**Measurement Range（量程）**，例如：

* ±16 g；
* ±2000 °/s。

当真实运动超过量程时，IMU 将进入**Saturation（饱和）**状态，输出数据不再反映真实运动，因此系统需要记录是否发生饱和。

此外，还应记录传感器的**Noise（噪声）**特性，包括随机噪声和噪声密度等。这些参数有助于评估测量质量，并为后续状态估计提供参考。

最后，应记录 IMU 的**Mount Frame（安装坐标系）**。不同机器人可能将 IMU 安装在底盘、躯干或其他位置，安装方向的不同会直接影响加速度和角速度的解释，因此必须明确其安装参考系。

### 力/力矩传感器（Force/Torque Sensor）

力/力矩传感器通常安装在机械臂腕部，用于测量机器人与环境之间的交互力。

除了六维力数据本身，还应记录：

* Bias（零点偏置）；
* Measurement Range（测量量程）；
* Saturation（是否超量程）；
* Noise（噪声水平）；
* Mount Frame（安装坐标系）。

例如，当机器人执行装配、插入或打磨任务时，如果传感器已经达到测量上限，那么即使输出值保持不变，也不能说明真实作用力没有继续增加。因此，记录饱和状态对于正确解释数据十分重要。

### 触觉传感器

触觉传感器主要用于检测机器人与物体之间的局部接触信息。

根据不同类型，可记录：

* 传感单元数量；
* 压力范围；
* 是否检测到接触；
* 饱和状态；
* 更新频率；
* 标定版本。

这些信息能够帮助判断当前触觉数据是否能够真实反映接触情况，并保证不同版本传感器之间的数据具有可比性。

### 编码器（Encoder）

编码器主要用于测量关节位置或电机转角，是 Joint State 的主要来源。

对于编码器，应记录：

* 分辨率（Resolution）；
* 编码器类型（绝对式或增量式）；
* 零点偏移（Zero Offset）；
* 标定版本；
* 健康状态。

如果编码器零点发生变化而数据集未记录对应信息，则同一组关节角度可能对应不同的真实姿态，影响机器人运动复现和离线分析。

## 常见的数据质量问题

传感器状态不仅用于描述设备配置，还能够帮助识别数据采集过程中可能出现的质量问题，从而判断当前观测是否值得信任。

### 丢帧（Frame Drop）

由于硬件性能不足、通信拥塞或设备异常，部分数据帧可能未能成功记录，导致时间序列出现间断。丢帧会降低数据连续性，并影响视频、深度信息及控制指令之间的同步关系。

### 数据乱序（Out-of-Order）

在网络通信或多线程采集过程中，不同时间的数据可能以错误顺序写入数据集。若不依据时间戳重新排序，将导致轨迹分析和模型训练出现时间逻辑错误。

### 延迟（Latency）

数据从采集到被系统接收之间通常存在一定延迟。延迟过大会使机器人控制基于过时的信息进行决策，在高速运动或实时控制任务中尤其需要关注。

### 时间不同步（Time Desynchronization）

不同传感器若使用不同时间基准，或者时钟漂移未得到校正，就可能导致图像、IMU、关节状态等数据无法对应到同一真实时刻。这类问题会直接影响数据融合、状态估计和离线回放，因此时间同步是保证数据质量的重要前提。

### 外参版本错误（Extrinsics Version Mismatch）

如果数据采集过程中重新进行了手眼标定、相机安装位置调整或机器人结构发生变化，而数据仍使用旧版本外参，则各传感器之间的空间关系将不再正确。这种问题通常不会体现在原始数据中，却会导致三维重建、目标定位和机器人控制产生系统性误差，因此应始终记录并核对外参版本。

### 传感器断流（Sensor Stream Loss）

由于通信故障、设备掉线或驱动异常，传感器可能停止输出数据，形成连续的空缺时间段。断流不仅影响当前任务执行，也会破坏数据集的完整性，因此需要结合健康状态、采样频率和时间戳等信息进行检测和标记。

## 传感器状态在机器人系统中的作用

传感器状态的作用不仅在于描述设备本身，更重要的是帮助系统判断**当前观测数据是否可信、是否能够被正确解释以及未来是否能够被准确复现**。

在在线机器人系统中，传感器状态能够帮助控制器及时发现设备异常，避免利用失效或低质量的数据进行决策，提高系统运行的安全性和稳定性。

在机器人数据采集和数据集构建过程中，传感器状态能够完整记录每一路观测数据的来源、配置和运行情况，使研究人员能够准确理解数据的采集条件，并在后续实验中使用相同的标定参数和设备配置进行复现。

对于机器人学习而言，传感器状态还能作为数据质量评估的重要依据。在训练前，可以利用健康状态、标定版本、同步情况和质量标记等信息筛除异常样本，避免低质量观测对模型训练产生负面影响，从而提高数据集的可靠性和算法的泛化能力。
