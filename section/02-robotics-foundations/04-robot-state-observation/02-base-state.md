# 底盘状态（Base State）

机器人除了关节状态（Joint State）之外，还需要描述**机器人整体在空间中的运动状态**，这一部分通常称为 **Base State（底盘状态或基座状态）**。对于移动机器人、人形机器人以及浮动基座机器人而言，Base State 是整个机器人状态表示的重要组成部分，它决定了机器人当前位于哪里、朝向哪里、运动速度如何，以及这些状态的可信程度。

对于固定机械臂而言，由于机器人底座通常固定在世界坐标系中，因此 Base State 往往是一个恒定值，甚至可以完全省略。而对于移动机器人、自主导航平台、人形机器人、四足机器人以及无人机等系统，Base State 则需要持续更新，并与关节状态共同构成机器人完整的状态（Robot State）。

在机器人数据采集、运动控制、导航定位、策略学习以及数据集构建过程中，Base State 通常都会作为 Observation 的重要组成部分进行记录。

## Base State 的基本字段

Base State 本质上描述的是**机器人基座（Base Link）相对于某一参考坐标系的位置、姿态及运动状态**。不同机器人平台的数据格式有所区别，但大多数系统都会包含以下几个基本字段。

### pose（位姿）

Pose 描述机器人基座当前所在的位置（Position）以及朝向（Orientation）。

位置通常表示为三维坐标：

```text
position = (x, y, z)
```

其中：

* x：世界坐标系中的 X 坐标（m）
* y：世界坐标系中的 Y 坐标（m）
* z：世界坐标系中的 Z 坐标（m）

姿态用于描述机器人朝向，一般有两种表示方式。

第一种是欧拉角：

```text
roll
pitch
yaw
```

单位通常为 rad。

第二种是四元数：

```text
(x, y, z, w)
```

现代机器人系统（ROS、Isaac、MuJoCo、Gazebo 等）大多采用四元数表示姿态，因为其不存在万向锁问题，且便于进行姿态插值与连续旋转计算。

因此，一个典型的 Pose 可以表示为：

```text
pose:
    position:
        x
        y
        z
    orientation:
        x
        y
        z
        w
```

Pose 通常表示：

Base Link 相对于某个参考坐标系（如 map、odom 或 world）的位姿。

### twist（速度）

Twist 描述机器人整体运动速度，由**线速度（Linear Velocity）**和**角速度（Angular Velocity）**组成。

通常表示为：

```text
twist:
    linear:
        vx
        vy
        vz
    angular:
        wx
        wy
        wz
```

其中：

线速度：

```text
(vx, vy, vz)
```

单位：

```text
m/s
```

表示机器人沿三个坐标轴的平移速度。

角速度：

```text
(wx, wy, wz)
```

单位：

```text
rad/s
```

表示机器人绕三个坐标轴旋转的速度。

在很多数据集中，即使存在 `twist` 字段，也会单独保留线速度和角速度字段，以方便后续的数据读取和神经网络输入。

### linear velocity

有些系统直接记录：

```text
linear_velocity
```

例如：

```text
linear_velocity:
    x
    y
    z
```

它实际上就是 Twist 中 linear 的独立表示。

对于移动机器人来说，最重要的是：

```text
vx
vy
```

对于无人机、人形机器人，则通常需要完整三维速度。

### angular velocity

角速度通常表示为：

```text
angular_velocity:
    x
    y
    z
```

单位：

```text
rad/s
```

移动机器人最常使用：

```text
yaw rate
```

即：

```text
wz
```

因为地面机器人主要绕 Z 轴旋转。

而四足、人形、无人机则通常需要完整三轴角速度。

### timestamp（时间戳）

Base State 必须具有时间信息。

例如：

```text
timestamp = 1723456789.123456
```

或者：

```text
sec
nanosec
```

时间戳用于：

* 与 Joint State 对齐
* 与相机图像同步
* 与 IMU 同步
* 与 Action 对齐
* 数据回放
* 多传感器融合

如果缺少准确的时间戳，Base State 将无法与其他观测数据进行可靠对应，影响控制、训练和离线分析的正确性。

### frame_id（参考坐标系）

Base State 必须明确说明其所属坐标系。

例如：

```text
frame_id = world
```

或者：

```text
frame_id = map
```

常见参考坐标系包括：

| frame_id  | 含义                      |
| --------- | ----------------------- |
| world     | 世界坐标系，通常作为仿真或实验的全局参考坐标系 |
| map       | 全局地图坐标系，定位系统输出通常位于该坐标系  |
| odom      | 里程计坐标系，连续但可能存在长期漂移      |
| base_link | 机器人自身基座坐标系              |

记录 `frame_id` 的目的，是明确状态所属的参考系，避免不同来源的数据被错误混用。例如，相同的 `(x, y)` 数值在 `map` 与 `odom` 坐标系下可能代表完全不同的位置，因此数据集必须保存对应的参考坐标系信息。

## 不同机器人 Base State 的差异

不同类型机器人，由于结构和运动方式不同，其 Base State 的内容也存在明显差异。

### 固定基座机械臂

固定机械臂的 Base Link 通常安装在工作台、地面或机械平台上，其底座不会发生运动，因此 Base State 通常保持不变。多数控制系统不会持续发布 Base State，而是将其视为已知常量，仅记录关节状态即可。

### 移动底盘机器人

移动机器人（如轮式机器人、AMR、AGV）需要持续记录二维或三维位姿及速度。Base State 是导航、路径规划、避障以及移动操作（Mobile Manipulation）的核心状态，通常包含位姿、线速度、角速度等信息。

### 浮动基座机器人

四足机器人、无人机等属于浮动基座系统，其基座并不固定，六自由度位姿和速度都会不断变化。因此 Base State 不仅需要完整的三维位置和姿态，还需要记录三轴线速度和角速度，以准确反映机器人在空间中的运动状态。

### 人形机器人

人形机器人同样采用浮动基座建模，但由于具有大量关节，其 Base State 需要与全身关节状态联合使用，才能完整描述机器人姿态和平衡状态。行走、跑步、上下楼梯以及双臂协同操作等任务，都高度依赖 Base State 的准确性。

## Base State 的来源

Base State 并非只能由单一传感器直接测得，而是可以来自多个传感器或状态估计算法。不同来源具有不同的精度、稳定性和适用场景。

常见来源包括：

**Wheel Odometry（轮式里程计）**：根据编码器推算机器人位姿和速度，连续性好，但长期运行容易产生累计误差。
**IMU（惯性测量单元）**：提供角速度、线加速度及姿态信息，更新频率高，但需要配合其他信息抑制漂移。
**Visual Odometry（视觉里程计）**：利用相机估计机器人运动，可在无编码器条件下工作，但对环境纹理和光照较为敏感。
**Motion Capture（动作捕捉）**：通过外部光学系统获取高精度位姿，常用于实验室标定、算法评测和高质量数据采集。
**Simulation Ground Truth（仿真真值）**：仿真环境可直接输出机器人真实状态，不受传感器噪声和漂移影响，常作为训练标签或性能评估基准。
**State Estimator Output（状态估计器输出）**：许多机器人会融合轮速计、IMU、视觉等多源信息，由状态估计器统一输出 Base State。实际部署中，常见的 EKF、VIO、SLAM 等算法都可以作为这一输出的来源，但在本节中无需展开其具体实现过程。

## 状态质量字段

除了位姿和速度本身，一个可靠的数据集通常还会记录 Base State 的质量信息，以便算法判断当前状态是否可信。

### covariance / confidence

状态估计通常伴随不确定性，可使用协方差矩阵（Covariance）或置信度（Confidence）描述估计质量。协方差越小，说明估计结果越稳定；置信度越高，则表示系统对当前状态越有信心。

### tracking status

Tracking Status 用于表示定位或跟踪系统当前的工作状态，例如：

```text
TRACKING
LOST
INITIALIZING
RELOCALIZING
```

当系统进入 LOST 状态时，Base State 可能不再可靠，此时控制器或数据处理流程通常需要采取保护措施。

### source

Source 用于记录当前 Base State 的来源，例如：

```text
wheel_odometry
imu
visual_odometry
motion_capture
simulation
state_estimator
```

这一字段能够帮助后续分析不同数据来源的特点，并支持同一数据集内多种状态来源的统一管理。

### reset flag

Reset Flag 表示定位系统是否发生重置，例如重新初始化、地图切换或仿真环境重启等事件。该字段可用于标记轨迹的不连续点，提醒后续处理避免将重置前后的状态误认为连续轨迹。

### drift warning

Drift Warning 用于提示系统检测到明显漂移风险，例如里程计累计误差过大、视觉定位质量下降或状态估计可信度持续降低等情况。虽然该字段通常不直接参与控制，但对于离线分析、数据清洗和训练样本筛选具有重要价值。

## Base State 在机器人系统中的作用

Base State 不仅描述机器人整体运动状态，也是机器人各类功能模块之间共享的重要信息。

对于移动操作任务，机械臂末端的实际位姿需要结合机器人底盘位姿共同计算，因此 Base State 会直接影响抓取、搬运和操作精度。

在导航系统中，定位、路径规划、轨迹跟踪以及避障等模块都依赖 Base State 判断机器人当前位置及运动趋势，没有可靠的 Base State，导航任务将无法正常进行。

在数据采集与回放过程中，Base State 与 Joint State、传感器数据及控制指令共同构成完整的时间同步轨迹。只有准确记录 Base State，才能在离线环境中真实复现机器人运动过程，保证数据集的可重现性。

在强化学习中，Base State 通常作为策略网络的重要输入之一。强化学习、模仿学习以及视觉语言动作模型都会结合 Base State 与关节状态、图像观测等信息，共同形成 Observation，使策略能够同时感知机器人自身运动状态和外部环境，从而生成更加稳定、准确的控制动作。
