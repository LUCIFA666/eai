# 空间关系与坐标约定

## 本章概述

机器人在执行任务时，需要同时处理来自机器人本体、传感器、环境以及任务规划等多个来源的信息。这些信息虽然描述的是同一个物理世界，但往往分别来自不同的坐标系。例如，相机识别出的目标物体位于相机坐标系中，机械臂末端位姿定义在工具坐标系中，移动机器人定位结果通常位于地图坐标系中，而机器人自身的关节运动又依赖于机器人基座坐标系。如果这些信息不能被统一到一致的空间关系中，机器人便无法正确理解环境，更无法完成感知、规划与控制之间的数据传递。

因此，机器人系统必须建立一套统一的空间表达方式，使机器人模型、传感器数据、感知结果、规划目标以及控制命令都能够在同一个坐标约定下进行描述和转换。这种统一不仅是数学上的坐标变换，更是机器人软件接口设计的重要组成部分。坐标系名称、父子关系、时间戳以及变换关系都会作为接口字段贯穿机器人模型、消息通信、数据记录以及算法模块之间。

本章将介绍机器人系统中常见的空间关系与坐标约定，包括位姿、旋转、坐标树、外参、工具坐标系、相机坐标系以及定位坐标系等基本概念，重点说明 frame_id、timestamp、parent frame、child frame、静态变换和动态变换在工程系统中的作用。同时，本章还将明确与后续视觉感知章节的边界，并总结机器人开发过程中最容易出现的坐标系统错误。本章重点关注机器人系统中的坐标组织方式和接口规范，不涉及视觉标定、三维重建或 SLAM 等算法实现，这些内容将在后续章节中进一步介绍。

## 空间关系在机器人系统中的作用

机器人软件中的几乎所有数据都具有空间属性。例如，机械臂末端的位置需要相对于机器人底座进行描述，摄像头检测到的目标位置需要转换到机器人坐标系中，导航系统输出的位置需要对应到地图坐标系，而控制器最终执行的动作又需要转换到具体关节坐标。

如果这些数据分别采用不同的坐标约定，机器人将无法判断它们描述的是不是同一个物体，也无法完成后续的路径规划和运动控制。因此，机器人系统需要建立统一的空间关系，使所有模块能够共享一致的空间表达方式。

统一的坐标约定主要承担以下几个作用：

- 为机器人模型中的各个部件建立固定的空间关系；
- 为相机、激光雷达、IMU 等传感器提供统一的安装位置描述；
- 为感知算法输出的目标位置提供统一参考坐标；
- 为运动规划和控制模块提供一致的目标位姿；
- 保证数据记录、数据回放以及真机部署时空间信息保持一致。

可以认为，坐标系统构成了机器人软件系统中的"公共语言"，不同模块虽然关注的任务不同，但都必须遵循相同的空间约定才能实现协同工作。

## 位姿与旋转

机器人系统中最基本的空间描述对象是**位姿（Pose）**。

位姿不仅描述物体位于哪里，还描述物体朝向哪里，因此通常由**位置（Position）**和**姿态（Orientation）**共同组成。

其中，位置表示物体在三维空间中的坐标，而姿态表示物体相对于参考坐标系的旋转方向。

在机器人开发过程中，一个完整的位姿通常包含以下信息：

- 三维位置（x、y、z）
- 三维姿态（Rotation）
- 所属坐标系（Frame）
- 时间戳（Timestamp）

姿态可以采用多种方式进行表示，例如旋转矩阵、欧拉角、四元数或轴角表示。不同软件平台可能采用不同的数据格式，但它们本质上都用于表达刚体在空间中的旋转关系。

本章并不讨论各种旋转表示之间的数学推导，而重点强调：无论采用何种表示方式，都必须明确它属于哪个坐标系，以及相对于哪个参考坐标系定义。

## 坐标树与空间层级关系

机器人通常由多个刚体组成，每个部件都拥有自己的局部坐标系。因此，机器人系统并不是只有一个坐标系，而是由大量坐标系按照层级关系组成一棵坐标树（Frame Tree）。

例如，一个移动操作机器人可能具有如下空间关系：

```text
map
 │
odom
 │
base_link
 ├── camera_link
 ├── imu_link
 └── arm_base
      │
   shoulder_link
      │
    elbow_link
      │
    wrist_link
      │
     tool0
```

坐标树中的每一个节点表示一个坐标系，而边表示两个坐标系之间的空间变换关系。

这种层级结构能够保证机器人任意两个部件之间都能够计算空间关系。例如，可以根据坐标树计算相机相对于机器人底盘的位置，也可以计算机械臂末端相对于地图的位置。

因此，机器人模型中的 Link、Joint 与机器人软件中的坐标树实际上具有密切对应关系。

## 外参与各类常用坐标系

除了机器人自身的运动链之外，机器人还需要描述各种传感器、工具以及环境之间的空间关系。

### 外参（Extrinsic）

外参用于描述两个坐标系之间固定的空间关系。

例如：

- 相机安装在机器人头部；
- 激光雷达安装在底盘前方；
- IMU 固定在机身中心。

这些安装关系通常不会随着机器人运动而改变，因此可以通过外参进行统一描述。

外参通常由标定过程获得，并在机器人系统中长期使用。

### 工具坐标系（Tool Frame）

工具坐标系通常建立在机器人末端执行器上。

对于机械臂而言，它通常位于：

- 夹爪中心；
- 吸盘中心；
- 焊枪末端；
- 螺丝刀尖端。

运动规划和抓取任务中的目标位姿，大多数都是相对于工具坐标系进行定义。

不同工具对应不同 Tool Frame，因此更换末端工具后通常需要重新配置工具坐标。

### 相机坐标系（Camera Frame）

相机坐标系用于描述视觉观测结果。

目标检测、三维重建、深度估计等算法输出的位置，通常首先位于 Camera Frame 中。

机器人需要结合外参，将 Camera Frame 下的目标位置转换到机器人坐标系或世界坐标系中，才能进一步完成抓取和运动规划。

### 定位坐标系（Localization Frame）

移动机器人通常还包含定位相关坐标系，例如：

- map
- odom
- base_link

其中：

- **map** 表示全局地图坐标；
- **odom** 表示机器人连续运动产生的局部参考坐标；
- **base_link** 表示机器人本体坐标。

导航系统通常通过这些坐标系共同描述机器人在环境中的运动状态。

## 坐标接口中的关键字段

在机器人软件中，空间关系不仅仅体现为几何变换，更会以接口字段的形式出现在各种消息、数据集和控制模块中。

### frame_id

frame_id 用于说明一条数据属于哪个坐标系。

例如：

```text
frame_id: camera_color_frame
```

表示该数据是在相机坐标系下描述的。

没有 frame_id，算法无法判断空间数据的参考系，也无法进行正确转换。

### timestamp

timestamp 表示数据产生的时间。

机器人系统中的不同传感器具有不同采样频率，因此必须利用时间戳完成空间信息同步。

例如：

- 图像
- IMU
- 机器人关节状态

只有时间一致，才能保证坐标变换对应同一时刻。

因此，timestamp 不仅属于时间同步信息，也是空间接口的重要组成部分。

### Parent Frame 与 Child Frame

机器人中的每一个空间变换，都需要明确：

- Parent Frame
- Child Frame

例如：

```text
base_link
      │
camera_link
```

表示 camera_link 是 base_link 的子坐标系。

Parent 与 Child 的方向不能随意交换，否则整个坐标树都会发生错误。

### Static Transform 与 Dynamic Transform

机器人系统中的坐标变换可分为静态变换和动态变换。

**Static Transform（静态变换）** 表示固定不变的空间关系，例如：

- 相机安装位置；
- IMU 安装位置；
- 激光雷达安装位置；
- 工具安装位置。

这些关系通常在机器人启动后保持不变。

**Dynamic Transform（动态变换）** 则表示随着机器人运动不断更新的空间关系，例如：

- 机器人底盘运动；
- 机械臂关节运动；
- 人形机器人全身姿态。

控制系统和感知系统需要持续更新这些变换，以保证空间信息始终保持一致。

因此，Static Transform 和 Dynamic Transform 不仅是坐标变换的分类，更直接决定机器人接口如何组织和更新空间数据。

## 本章与视觉感知章节的边界

空间关系与坐标约定贯穿整个机器人系统，但本章主要关注机器人软件中的坐标组织方式和接口规范，而不涉及具体算法实现。

本章重点讨论：

- 坐标系如何建立；
- 各类坐标系之间如何组织；
- 外参如何描述安装关系；
- 坐标树如何统一机器人模型；
- 接口字段如何表达空间关系。

而第 3 章将进一步介绍视觉感知相关内容，包括：

- 相机标定；

- 三维点云坐标恢复；
- 深度估计；
- 三维目标检测；

也就是说，本章回答的是"坐标关系如何组织"，而后续章节回答的是"这些空间关系如何通过感知算法获得"。

## 常见坐标系统错误

机器人开发过程中，坐标系统配置错误往往比算法错误更加常见，而且通常难以排查。以下几类问题尤其需要重点关注。

首先是**左右手坐标系混用**。不同软件平台可能采用不同的坐标系约定，如果在模型转换、数据接口或仿真平台之间没有统一，机器人运动方向可能完全相反，导致控制结果与预期不一致。

其次是**base、tool 与 camera 坐标系混淆**。例如，将目标物体在相机坐标系中的位置误认为是机器人基座坐标系的位置，或者将工具坐标系误用为末端法兰坐标系，都会导致抓取位置计算错误，即使视觉检测结果本身没有问题，也无法完成正确操作。

第三类常见问题是**外参版本不一致**。机器人重新安装相机、更换工具或调整传感器位置后，如果软件仍然使用旧版本外参，视觉结果与机器人模型之间就会产生固定偏差，表现为目标位置始终存在系统性误差。这类问题在长期维护和多版本部署中尤为常见，因此需要建立明确的外参版本管理机制。

最后是**map、odom 与 base_link 的语义混用**。在移动机器人系统中，三者分别代表全局地图、局部里程计和机器人本体坐标。如果算法错误地将它们视为同一坐标系，导航、定位和路径规划都会受到影响，甚至导致机器人运动轨迹持续偏移。因此，在设计接口和记录数据时，应始终明确各坐标系的语义，而不是仅仅关注它们之间的数学变换。

## 本章建议掌握的内容

本章不要求读者掌握三维旋转推导或坐标变换算法，而是重点理解机器人系统中空间关系的组织方式以及接口规范。

读者应能够理解机器人为什么需要统一坐标约定，认识位姿、旋转、坐标树、外参、工具坐标系、相机坐标系以及定位坐标系在机器人系统中的作用；能够识别 frame_id、timestamp、parent frame、child frame、Static Transform 和 Dynamic Transform 等关键接口字段，并理解它们不仅具有几何意义，更承担着系统间数据交互的重要职责。

同时，应明确本章与后续视觉感知章节的分工，知道坐标约定解决的是空间组织和接口一致性问题，而视觉标定、三维感知和地图构建则负责获取这些空间关系。最后，还应能够识别左右手系混乱、坐标系语义混用、外参版本错误以及坐标树配置错误等常见工程问题，为后续机器人感知、规划、控制以及数据采集打下统一的空间表达基础。

## 本章小结

机器人系统中的空间关系不仅用于描述机器人各部件之间的位置关系，更是连接机器人模型、传感器、环境感知、运动规划和控制执行的重要基础。通过统一的坐标约定，机器人能够将来自不同模块的数据组织到同一空间参考下，实现环境理解、目标定位和动作执行之间的一致性。

位姿、旋转、坐标树、外参、工具坐标系、相机坐标系以及定位坐标系共同构成了机器人空间表达体系，而 frame_id、timestamp、parent frame、child frame、Static Transform 和 Dynamic Transform 等接口字段则保证了这些空间关系能够在模型、通信接口和数据集中保持一致。工程实践中，左右手坐标系混用、base/tool/camera 坐标混淆、外参版本错误以及 map、odom、base_link 语义混用等问题，都是导致机器人控制失败和数据复现困难的常见原因。

因此，在机器人系统开发过程中，应始终将空间关系视为一项基础接口规范，而不仅仅是数学上的坐标变换。建立统一、准确且一致的坐标约定，是实现机器人感知、规划、控制以及仿真与真机协同工作的前提。
