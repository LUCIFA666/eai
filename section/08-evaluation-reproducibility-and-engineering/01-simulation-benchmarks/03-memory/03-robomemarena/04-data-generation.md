# 数据生成管线

RoboMemArena 的演示不是靠人遥操作逐条采的，而是一条三阶段自动管线：VLM 把任务分解成子任务，抓取模型自主执行并按后条件重试，最后用多条件规则抽取关键帧。下面的公式与阈值符号来自论文方法一节，接口细节来自本地评测参考实现。

## 阶段一：VLM 任务分解

给定任务的自然语言目标，一个 VLM 把它分解成有序的子任务序列，每个子任务落到一个受限的原语集合上：Move、Place、Pour、Open、Close。VLM 被要求输出严格 JSON，便于下游直接解析成可执行的子任务。这一步产出的有序序列就是任务的真值 `primitive_order`，既驱动后续自动执行，也作为语言子任务标注保留下来。把动作限制在少数原语上，是为了让分解结果稳定、可执行、可核验。

同一套受限原语在评测时也复用于在线规划。评测参考实现里的 VLM 规划器读入历史关键帧与最近的双相机视觉窗口，输出严格 JSON，只含两个字段：当前该执行的原语，以及最近窗口内哪些帧是关键帧。

```text
# SYSTEM_PROMPT_MEMORY_DEMO（评测参考实现）
- Output strict JSON only, with no extra text.
- The JSON must contain exactly two fields: current_primitive and keyframe_positions.
- keyframe_positions are 1-indexed positions within the recent 5-frame window.
```

`current_primitive` 对应正在执行或该执行的原语，`keyframe_positions` 用 1 起的下标标出最近 5 帧窗口里的关键帧位置（窗口内没有关键帧时为空列表）。生成期与评测期共用同一套原语和同一种 JSON 契约，保证分解和在线推断的语义一致。

## 阶段二：AnyGrasp 自主执行与后条件重试

每个子任务交给一个基于 AnyGrasp 的自主执行器：由抓取模型提议抓取位姿，配合运动规划完成 Move / Place / Pour / Open / Close。关键在于每个子任务都带一个后条件，例如物体是否已在目标容器内、抽屉是否已打开或关上。执行器按 `primitive_order` 逐个子任务推进，每完成一个就检查它的后条件：满足才进入下一个子任务，不满足就重试当前子任务；重试若干次仍失败则丢弃整条轨迹。因为只有全部子任务的后条件依次满足的轨迹才被保留，库里的演示都是完整成功的示范，且每个子任务的边界都有明确、可机器判定的完成判据——这也正是评测阶段各任务分阶段成功检查的来源。

## 阶段三：多条件关键帧抽取

一条轨迹上千步，不能把每帧都当记忆条目。RoboMemArena 从两类信号里抽关键帧，取并集：

```text
K = K_phys ∪ K_kin
```

- 物理事件 `K_phys`：夹爪开合状态发生变化的帧。抓起、放下这类改变接触关系的时刻，往往正是承载记忆的时刻（放进去了什么、放到了哪）。
- 运动学拐点 `K_kin`：末端运动出现拐点的帧，用两个条件之一判定——末端速度出现局部极小（速度低于阈值 ε，对应到达、停顿、切换目标），或相邻两段速度方向变化明显（速度向量夹角的余弦低于阈值 cosθ，对应转向）。

其中速度极小阈值 ε 与方向变化阈值 cosθ 论文只给符号、未给具体数值。两类关键帧取并集，既覆盖接触事件、也覆盖运动切换，得到每条轨迹上稀疏但信息密集的关键帧标注。

这套抽取规则和评测期在线判定关键帧是一致的：VLM 规划器输出的 `keyframe_positions` 就是在线判定的关键帧，被累积进历史关键帧记忆。评测参考实现默认关键帧记忆不设容量上限（环境变量 `K_MAX=0` 表示无限历史关键帧），因此长时程里早期的关键证据不会被挤掉。
