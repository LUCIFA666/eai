# 概览与定位

RoboHiMan 是一套面向长时程操作、专为组合泛化设计的分层评测范式，配套 benchmark 名为 HiMan-Bench。任务分原子与组合两层，搭在 RLBench / CoppeliaSim 上，再借 Colosseum 的扰动 API 系统性叠加外观、几何、光照、视角上的变化。它用高层规划器加低层策略的分层架构评测模型，把长时程任务笼统的成功率拆开，看模型能否把学过的原子技能在扰动下组合成一条长任务。

## 要填的缺口

长时程操作的模型往往只在整段任务上报一个成功率。这个数字把几种不同的失败混在一起，说不清问题出在哪：是没学会某个原子技能，是学会了单步技能却不会按语言指令把它们排成正确顺序，还是外观、几何、视角一变模型就难以应对。三种失败对应的改进方向完全不同，混在一个数字里就都看不见。RoboHiMan 把它们拆开分别评。

它评的核心问题是：一个只用原子技能数据训练的模型，能不能在环境扰动下泛化到由这些技能组合而成的长时程任务。掌握单步技能，不等于会把这些技能调度、拼接、串成一条长指令去执行，后者才是长时程操作真正难的地方。

## 分层架构与非分层对照

RoboHiMan 把一次执行拆成高低两层。高层规划器读入语言指令 $l$ 和视觉观测 $o$，输出当前阶段该做的子任务描述 $s$；低层策略再把子任务 $s$ 翻译成一段机器人动作 $\{a_{1:T}\}$。观测 $o$ 既可以是多视角 RGB 这类 2D 信号，也可以是点云这类 3D 表示，取决于低层策略的输入约定。

作为对照，还有一个非分层基线：去掉规划器，低层策略直接把 $(l, o)$ 映射成整段动作 $\{a_{1:T}\}$。分层与非分层跑同一批任务、用同一个低层策略，两者的成功率差就量化了规划器对长时程组合任务的贡献。这条对照是整个评测范式的支点，三种评测设置都建在它上面。

## 组合泛化在这里的具体所指

组合泛化不是泛指。原子任务各自是两阶段的短交互，组合任务把多个原子技能链成多阶段的长任务，其中一部分还要求跨域迁移，例如从抽屉操作切换到橱柜操作。模型即便逐个原子技能都会，也仍要正确调度和拼接它们，才能完成一条把草莓果冻从抽屉取出再放进橱柜这样的长指令。顺序错、衔接断、跨域时目标认错，任意一处失手，整条长任务就失败。这正是组合泛化要考的能力。

## 与相邻基准的区别

HiMan-Bench 沿用 RLBench 的任务设计范式，用 PyRep API 搭在 CoppeliaSim 上，在 DeCoBench 的 10 原子加 12 组合任务基础上，借 Colosseum 的扰动 API 把任务集扩展开。和几个常被拿来对比的基准放在一起，差别集中在三点：

| 基准 | 强制多阶段技能组合 | 系统性环境扰动 | 规划-执行分层归因 |
|---|---|---|---|
| RLBench / LIBERO | 否 | 否 | 否 |
| Colosseum | 否 | 是 | 否 |
| DeCoBench | 是 | 否 | 否 |
| RoboHiMan（HiMan-Bench） | 是 | 是 | 是 |

RLBench、LIBERO 是单技能任务，不要求把技能组合成长任务；DeCoBench 有组合但不加扰动；Colosseum 系统性地加扰动，但任务本身不是多阶段组合。三者各覆盖一个维度，都没有把长任务的失败拆到规划端还是执行端。RoboHiMan 把组合、扰动、分层归因三者放进同一套任务，才能同时回答技能会不会组合、组合稳不稳、失败卡在哪。

## 规模

HiMan-Bench 把任务组织成四类：

- 原子（A）：10 个任务。
- 带扰动的原子（AP）：104 个任务。
- 组合（C）：12 个任务。
- 带扰动的组合（CP）：132 个任务。

AP 与 CP 是 A、C 在 12 个扰动因子下实例化出来的变体。连同扰动变体，整个分布覆盖 114 个原子任务与 144 个组合任务。训练侧另有一套从难到易、逐级为超集的四级数据 L1–L4，越靠前的级别给的组合信息越少，越考模型自己把原子技能拼起来的能力。
