# 4.5 评测指标与结果分析

## 目标

ALFRED 和 DialFRED 的评测不仅关注 agent 是否最终完成任务，也关注它是否完成了中间子目标、动作路径是否高效、是否发生了交互错误，以及在对话设置下是否能有效利用提问信息。

本节主要介绍 ALFRED / DialFRED 中常见的评测指标和结果阅读方式。

## 任务成功率

任务成功率衡量 agent 是否完成整条任务。

例如任务是：

```text
Rinse off a mug and place it in the coffee maker.
```

只有当 agent 成功完成清洗、移动和放置，并满足最终状态条件时，任务才算成功。

在 ALFRED 中，任务成功率是很严格的指标。因为长程任务中的任意关键步骤失败，都可能导致最终任务失败。

例如：

```text
找到杯子，但没有清洗
-> 失败

清洗杯子，但放错位置
-> 失败

放到咖啡机附近，但物体不是目标杯子
-> 失败
```

因此，任务成功率能反映完整任务执行能力，但不能单独说明模型失败在哪一步。

## 子目标成功率

子目标成功率用于衡量 agent 完成了多少中间阶段。

例如 Clean & Place 任务可以拆成：

```text
找到物体
-> 拿起物体
-> 找到水槽
-> 清洗物体
-> 找到目标容器
-> 放置物体
```

即使最终任务失败，模型也可能完成了前几个子目标。

子目标成功率的意义在于，它可以区分：

```text
完全不会做
和
能完成部分步骤，但无法完成整条任务
```

如果一个模型任务成功率低，但子目标成功率相对较高，说明它具备一定局部能力，但长程衔接或最终状态判断不稳定。

## 路径长度加权指标

ALFRED 中也会关注路径长度。一个 agent 即使完成任务，如果走了很多无效路线，也说明策略效率不高。

路径长度加权指标主要衡量：

```text
是否成功完成任务
完成任务所需动作是否过多
路径是否比专家轨迹长很多
```

例如：

```text
模型 A：
50 步完成任务

模型 B：
200 步完成任务

二者都成功，但模型 A 更高效
```

这类指标可以防止 agent 通过随机探索获得成功，同时鼓励更接近专家轨迹的执行方式。

## 动作失败类型

ALFRED 的失败经常可以通过动作类型分析。

常见失败包括：

| 失败类型                   | 表现                |
| ---------------------- | ----------------- |
| Navigation Error       | 走不到正确位置或迷路        |
| Object Detection Error | 没有识别目标物体或识别错实例    |
| Interaction Error      | 拿取、打开、放置等动作失败     |
| State Change Error     | 清洗、加热、冷却等状态变化没有完成 |
| Planning Error         | 子目标顺序错误或遗漏步骤      |
| Stop Error             | 没有在任务完成后正确停止      |
| Memory Error           | 忘记目标物体位置或已完成步骤    |

这些错误往往会叠加出现。例如，目标检测错误会导致拿错物体，拿错物体又会导致最终放置失败。

因此，分析 ALFRED 结果时，不能只看最终成功率，还要结合轨迹、动作日志和子目标完成情况。

## Seen 与 Unseen

ALFRED 的结果通常会区分 seen 和 unseen 场景。

```text
Seen：
测试场景和训练场景更接近

Unseen：
测试环境在训练中没有出现
```

Unseen 结果更能体现泛化能力。

如果模型在 seen 上表现明显好于 unseen，说明它可能依赖训练场景中的固定布局、物体位置或视觉模式，而没有学到稳定的任务执行策略。

对于具身智能来说，unseen 表现很重要。真实家庭环境通常不会和训练环境完全一样，agent 必须能适应新的房间布局和物体分布。

## DialFRED 的评测关注点

DialFRED 在 ALFRED 的基础上加入对话，因此结果分析需要多看几个方面。

### 提问是否有帮助

如果加入问答后任务成功率提高，说明 agent 能够利用额外信息改善任务执行。

例如：

```text
没有提问时找不到目标物体
提问后知道目标在 sink 附近
任务成功率提高
```

### 问题是否合理

Agent 不能随意提问。一个好的 questioner 应该在信息不足时提出 task-relevant question。

例如：

```text
目标不可见时问位置
多个相似物体时问外观
局部方向不确定时问方向
```

如果 agent 在已经知道答案时仍然提问，或者问与任务无关的问题，就说明 questioner 效率不高。

### 回答是否被正确利用

即使用户回答了问题，agent 也不一定能正确使用。

例如：

```text
用户回答：
The mug is on the counter near the sink.

agent 仍然在卧室搜索
```

这说明 performer 没有把对话信息和视觉导航结合起来。

## 对话成本

在真实人机交互中，提问不是免费的。频繁提问会增加用户负担。

因此，DialFRED 结果可以从两个角度看：

```text
任务成功率是否提升
提问次数是否合理
```

理想的 agent 不是问得越多越好，而是在关键时刻问出有价值的问题。

可以理解为：

```text
少问但问对
比
频繁提问但信息利用低
更有价值
```

## 与前面几个 benchmark 的结果阅读差异

ALFRED / DialFRED 的结果阅读方式和前面几个 benchmark 有一定差异。

| Benchmark           | 结果阅读重点                                                         |
| ------------------- | -------------------------------------------------------------- |
| OmniNavBench        | 多种导航能力在组合任务中的连续执行和跨形态泛化                                        |
| Habitat Challenge   | ObjectNav、ImageNav、Rearrangement 中的 success、SPL 和 challenge 排名 |
| AI2-THOR / RoboTHOR | 室内交互、ObjectNav、sim-to-real 和动作执行结果                             |
| ALFRED / DialFRED   | 语言指令是否能被转化为长程动作序列，以及对话信息是否能改善任务完成                              |

ALFRED 的失败往往来自长程链条中的某个环节，例如找错物体、拿错物体、交互失败、状态变化失败或忘记目标。DialFRED 则进一步要求分析提问质量和回答利用方式。

因此，阅读 ALFRED / DialFRED 结果时，不应该只看最终任务成功率，而要结合子目标、动作失败类型、seen / unseen 差距和对话交互过程综合分析。

## 结果分析方式

阅读 ALFRED / DialFRED 结果时，可以按下面顺序分析：

```text
先看完整任务成功率
-> 再看子目标成功率
-> 分析 seen / unseen 差距
-> 查看失败动作类型
-> 对 DialFRED 额外分析提问质量和回答利用
```

如果模型任务成功率低但子目标成功率高，说明问题可能在长程衔接和最终状态判断。

如果 seen 与 unseen 差距大，说明模型泛化能力不足。

如果交互错误多，说明模型可能已经到达目标附近，但物体定位、动作执行或状态判断有问题。

如果 DialFRED 中提问后效果提升，说明对话信息确实帮助了任务完成；如果提问很多但效果不明显，则说明 agent 没有真正学会利用回答。

## 本节小结

ALFRED 的评测重点在于完整家庭任务是否完成，以及 agent 在长程导航和物体交互中是否保持稳定。DialFRED 进一步引入对话能力，使评测不仅关注任务执行，还关注 agent 是否能在不确定时主动提问，并有效利用回答。

从结果分析角度看，ALFRED / DialFRED 的价值不只是比较分数，而是帮助研究者定位语言理解、视觉 grounding、导航、交互、记忆和对话信息利用中的具体短板。
