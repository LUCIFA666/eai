# 1.1 概览与评测协议

## 目标

OmniNavBench 是一个面向通用具身导航的 benchmark，主要用于评估 embodied agent 在复杂环境中完成多类型导航任务的能力。与只关注单一目标的导航任务不同，OmniNavBench 更强调多种导航能力的组合、连续执行以及不同机器人形态下的泛化表现。

本节主要介绍 OmniNavBench 的基本定位、任务组织方式和评测思路，为后续理解具体任务类型、环境配置、专家轨迹和评测指标建立整体框架。

## OmniNavBench 的基本定位

具身导航是 embodied AI 中非常基础的一类任务。它要求 agent 在环境中根据观测和指令做出移动决策，从当前位置逐步到达目标区域、目标物体或目标对象附近。

传统导航任务通常只关注某一种能力，例如：

```text
走到指定坐标
根据语言指令导航
寻找目标物体
跟随移动的人
回答环境相关问题
```

这些任务分别对应 PointNav、VLN、ObjectNav、Human Following、EQA 等不同方向。单独评测这些任务可以帮助研究者分析某一类导航能力，但真实场景中的机器人通常不会只面对一种固定任务。

OmniNavBench 的核心思想是将多种导航能力放到统一框架中评测。它关注的不是 agent 是否只会完成某一个单独任务，而是 agent 是否能够在连续任务中理解指令、切换目标、适应不同场景，并完成多阶段导航过程。

可以简单概括为：

```text
单一导航任务：
固定目标
-> 单一能力
-> 独立评测

OmniNavBench：
组合指令
-> 多种能力
-> 连续执行
-> 统一评测
```

因此，OmniNavBench 更适合用来观察 agent 的通用导航能力，而不是只测试某一项孤立技能。

## 通用导航评测的动机

在真实应用中，导航任务往往不是一步完成的。一个机器人可能需要先理解语言指令，再搜索目标物体，随后跟随某个人，最后根据观察结果回答问题。

例如，一个连续任务可以包含：

```text
先移动到客厅
-> 找到桌子附近的目标物体
-> 跟随前方的人
-> 保持合理距离
-> 回答关于当前场景的问题
```

这种任务要求 agent 同时具备多种能力：

```text
语言理解
空间导航
目标识别
路径规划
动态跟随
场景观察
任务切换
```

如果只在单项任务上评测，就可能出现一种情况：模型在某个单独任务上表现不错，但在多阶段任务中无法稳定完成完整流程。

例如：

```text
能够找到物体，但不能理解长指令
能够跟随人，但无法保持合适距离
能够到达目标点，但不能回答环境问题
能够完成单个子任务，但连续执行时容易中断
```

OmniNavBench 的价值就在于，它把这些能力放在同一个连续 episode 中考察，使评测更接近真实 embodied navigation 的复杂性。

## Benchmark 的基本组成

OmniNavBench 可以拆成几个基本组成部分：

```text
Composite Instruction
-> Navigation Sub-tasks
-> Environment
-> Robot Embodiment
-> Sensor Observation
-> Expert Trajectory
-> Policy Execution
-> Evaluation Metrics
```

各部分含义如下：

| 组成 | 含义 |
| --- | --- |
| Composite Instruction | 组合式任务指令，由多个导航子任务组成 |
| Navigation Sub-tasks | 具体导航任务，例如目标到达、物体查找、跟随、问答等 |
| Environment | 任务发生的室内或复杂三维场景 |
| Robot Embodiment | 执行任务的机器人形态，例如轮式、四足或类人机器人 |
| Sensor Observation | agent 可获得的观测输入，例如 RGB-D、LiDAR 或全景视觉 |
| Expert Trajectory | 专家完成任务时产生的参考轨迹 |
| Policy Execution | policy 根据当前观测和任务目标输出动作 |
| Evaluation Metrics | 衡量任务完成度、路径效率、交互质量和问答表现等结果 |

可以理解为：

```text
指令定义任务目标
环境提供任务空间
机器人形态决定运动约束
传感器决定可观测信息
轨迹提供参考行为
指标用于评估最终表现
```

## 组合式导航指令

OmniNavBench 的关键特点之一是 composite instruction，即组合式导航指令。

普通导航任务通常只有一个目标，例如：

```text
走到沙发旁边
```

组合式指令则可能包含多个连续目标，例如：

```text
先走到客厅
再找到桌子旁边的垃圾桶
然后跟随前方的人
最后回到起点附近
```

这类指令更接近真实机器人任务，因为现实中的导航往往不是单个动作，而是多个子目标的连续组合。

组合式导航指令的难点不只在于每个子任务本身，还在于子任务之间的衔接。Agent 需要判断当前阶段是否完成，并决定什么时候切换到下一个目标。

例如：

```text
是否已经到达目标区域？
是否已经找到目标物体？
是否应该继续跟随目标对象？
是否可以进入问答阶段？
是否已经满足任务终止条件？
```

这使得 OmniNavBench 不仅考察导航能力，也考察指令理解、阶段判断和长程执行能力。

## Episode 的执行流程

在 OmniNavBench 中，一次 episode 表示 agent 执行一条组合式指令的完整过程。

一个 episode 通常可以理解为：

```text
初始化环境
-> 加载机器人
-> 给出组合式指令
-> agent 接收观测
-> policy 输出动作
-> agent 在环境中移动
-> 逐步完成多个子任务
-> 达到终止条件
-> 统计评测结果
```

导航任务是典型的闭环任务。Agent 每一步动作都会改变自己的位置，也会改变下一步看到的环境。

可以写成：

```text
observation
-> policy
-> action
-> new observation
-> next action
```

如果 agent 在前期阶段走错方向，后续子任务也会受到影响。例如，agent 如果没有正确进入目标房间，就可能无法找到目标物体，也无法完成后续跟随或问答任务。

因此，组合式导航对长程稳定性要求更高。它不仅要求 agent 当前一步动作合理，还要求整个执行过程能够持续保持目标一致性。

## 跨机器人形态评测

OmniNavBench 还关注不同机器人形态下的导航表现。不同机器人在运动方式、视角高度、可通过区域和动作约束上都有差异。

例如：

```text
轮式机器人移动稳定，但对台阶和复杂地形更敏感
四足机器人可以适应更多地形，但运动控制方式不同
类人机器人具有不同视角和动作空间
```

同一条导航指令，在不同机器人平台上可能会产生不同难度。一个方法如果只在单一机器人上表现良好，并不一定说明它具备通用导航能力。

因此，跨形态评测关注的是：

```text
同一种导航策略换到不同机器人后是否仍然有效
```

这对于 embodied AI 很重要，因为真实应用中的机器人平台并不统一。一个更通用的导航方法应该尽量减少对固定机器人形态的依赖。

## 专家轨迹与导航行为

导航数据中经常会使用 expert trajectory 作为参考。专家轨迹既可以用于 imitation learning，也可以用于分析 agent 的路径选择和行为模式。

在一些导航任务中，专家轨迹可以由最短路径算法生成，即从起点到目标点的几何最短路线。但真实导航行为并不总是等价于最短路径。

人在复杂环境中移动时，可能会：

```text
先观察周围环境
绕开障碍物或拥挤区域
为了确认目标调整视角
保持与他人的合理距离
在不确定时短暂停顿
```

因此，专家轨迹不仅表示“从哪里走到哪里”，也包含观察、判断、避让和交互等行为特征。对于通用具身导航来说，这类轨迹能提供比单纯最短路径更丰富的学习信号。

## 评测协议的整体思路

在简单导航任务中，评测可能只关注 agent 是否到达目标位置。但在组合式导航中，只看最终成功与否并不够。

例如，一个 episode 包含四个子任务：

```text
子任务 1：完成
子任务 2：完成
子任务 3：失败
子任务 4：未开始
```

这种情况下，agent 没有完成整条指令，但已经完成了一部分任务。如果只看最终成功率，就会忽略中间过程中的能力表现。

因此，OmniNavBench 的结果通常需要从多个角度理解：

```text
任务是否最终完成
完成了多少子目标
路径是否高效
是否保持合理交互距离
是否正确回答环境问题
不同机器人形态下是否稳定
```

可以先用两个直观概念理解：

```text
Success：整条任务是否完成
Progress：中间子任务完成了多少
```

不同结果可以这样分析：

| 结果现象 | 可能说明 |
| --- | --- |
| success 高，progress 高 | agent 能稳定完成完整组合任务 |
| success 低，progress 高 | agent 能完成部分子任务，但长程衔接不稳定 |
| success 低，progress 低 | agent 在基础导航、目标识别或指令理解上存在明显问题 |
| 某类子任务表现较差 | agent 可能不擅长该类导航能力 |
| 换机器人后性能明显下降 | 方法可能依赖特定机器人形态 |

这种多角度分析方式比单一成功率更适合组合式导航 benchmark。

## 常见实验设置

阅读 OmniNavBench 相关实验时，可以从三个层面理解。

### 单一形态评测

单一形态评测是在固定机器人形态上测试 policy，例如只使用轮式机器人。这种设置变量较少，适合分析方法在固定平台上的基本能力。

它主要回答：

```text
方法在固定机器人平台上能否完成组合导航任务？
```

### 跨形态评测

跨形态评测是在多种机器人形态上测试同一类方法，例如轮式、四足和类人机器人。

它主要回答：

```text
方法是否依赖某一种机器人身体？
换一种机器人后性能是否明显下降？
```

### 跨场景评测

跨场景评测是在不同环境中训练和测试，观察 agent 是否能泛化到新场景。

它主要回答：

```text
agent 是否真正学会了导航能力，
还是只记住了训练环境中的路线和布局？
```

对于具身导航来说，跨场景泛化非常关键。真实机器人部署时，遇到的环境往往不会和训练环境完全一样。


## 本节小结

OmniNavBench 是一个面向通用具身导航的 benchmark。它将多种导航子任务组织到同一个连续 episode 中，并通过不同环境、不同机器人形态和多维评测指标，观察 embodied agent 是否具备稳定的通用导航能力。
