# 1.4 专家轨迹与示范数据

## 目标

OmniNavBench 不只是提供任务定义和评测环境，也提供了与组合式导航任务对应的专家轨迹数据。专家轨迹记录了人类操作者在仿真环境中完成任务时的移动过程、视觉观测和关键状态信息，可以作为 imitation learning、行为分析和评测参考的重要数据来源。

本节主要介绍 OmniNavBench 中专家轨迹的采集方式、数据组成、质量控制以及它在导航学习中的作用。

## 专家轨迹的数据定位

在具身导航中，轨迹表示 agent 从初始位置到任务完成过程中的连续状态变化。对于一个组合式导航任务来说，轨迹不仅记录“走过了哪些位置”，还记录任务执行过程中每个阶段的行为变化。

一条专家轨迹通常对应一次完整 episode：

```text
初始位置
-> 接收组合式指令
-> 执行第一个导航子任务
-> 切换到下一个子任务
-> 持续观察和移动
-> 完成整条任务或达到终止状态
```

这种轨迹数据可以帮助我们理解：

```text
专家如何根据语言指令选择路径
专家如何寻找目标物体或目标区域
专家如何在动态人类附近调整移动方式
专家如何在多个子任务之间切换
专家如何通过观察收集问答所需信息
```

因此，OmniNavBench 中的专家轨迹不是简单的路径点集合，而是组合式导航任务中的行为记录。

## 人类遥操作采集流程

OmniNavBench 使用人类遥操作方式采集专家轨迹。也就是说，专家并不是通过最短路径算法自动生成，而是由人工操作者控制机器人，在仿真环境中完成给定任务。

整体流程可以理解为：

```text
选择场景
-> 初始化机器人位置
-> 构造组合式任务指令
-> 人类操作者遥操作机器人完成任务
-> 系统记录观测、位姿和轨迹信息
-> 专家审核轨迹是否有效
-> 汇总为最终数据集
```

这种采集方式更接近真实导航行为。人类操作者在完成任务时，通常不会只追求几何最短路径，而是会根据环境情况进行观察、判断和调整。

例如，在不确定目标位置时，操作者可能会先转头观察；在有人经过时，操作者可能会提前避让；在寻找目标物体时，操作者可能会移动到更合适的视角再确认目标。

这些行为虽然不一定让路径最短，但更符合自然导航过程。

## 轨迹数据的基本组成

一条专家轨迹通常可以拆成多个时间步。每个时间步都记录 agent 在当前时刻的观测和状态。

可以抽象为：

```text
trajectory = [
  step_0,
  step_1,
  step_2,
  ...
  step_T
]
```

每个 step 可能包含：

| 数据内容 | 含义 |
| --- | --- |
| RGB 观测 | 当前第一人称视觉画面 |
| Depth 观测 | 当前视角下的深度信息 |
| 机器人位姿 | 机器人在环境中的位置和朝向 |
| Waypoint | 高层路径点或阶段性移动目标 |
| 当前子任务状态 | 当前正在执行哪个导航子任务 |
| 任务指令 | 与该 episode 对应的语言描述 |
| 目标信息 | 目标区域、目标物体、目标人或问答目标 |
| 时间步信息 | 当前 step 在整条轨迹中的位置 |

可以把它理解成：

```text
视觉观测告诉 agent 看到了什么
机器人位姿告诉 agent 自己在哪里
waypoint 描述专家接下来往哪里移动
任务指令说明当前 episode 要完成什么
```

这些信息共同构成了可用于训练和分析的 demonstration 数据。

视频展示了一段 OmniNavBench expert trajectory 中的 RGB 观测序列。可以看到，轨迹数据不是单个静态画面，而是 agent 在三维环境中连续移动、观察和执行任务的过程。这类视频能够直观体现专家轨迹中第一人称视觉观测随时间变化的特点，也有助于理解 demonstration 如何作为导航策略学习和行为分析的数据来源。


## 指令、子任务与轨迹的对应关系

OmniNavBench 的轨迹和组合式指令是一一对应的。每条轨迹不是孤立存在的，而是服务于某条具体任务指令。

例如，一条组合式指令可以写成：

```text
Go to the living room.
Find the trash can near the table.
Follow the person walking toward the sofa.
Answer whether there is a lamp beside the sofa.
```

对应轨迹可以分成多个阶段：

| 阶段 | 子任务 | 轨迹中的表现 |
| --- | --- | --- |
| 1 | VLN | 从初始位置移动到 living room |
| 2 | ObjectNav | 在 living room 中搜索 trash can |
| 3 | Human Following | 跟随目标人移动到 sofa 附近 |
| 4 | EQA | 移动到可观察位置并回答问题 |

这种对应关系使轨迹不仅能表示运动过程，也能表示任务执行过程。

对于组合式导航来说，这一点很重要。因为 agent 需要知道自己当前处于哪个任务阶段，以及当前动作是为哪个子目标服务的。

## Waypoint 表示

OmniNavBench 中的专家轨迹使用 waypoint 序列作为重要表示。Waypoint 可以理解为专家轨迹中的关键路径点，用于描述机器人在高层导航中的移动路线。

和直接记录低层控制指令相比，waypoint 更关注导航决策本身。

可以简单理解为：

```text
低层动作：
每一时刻的速度、转角、关节控制等

Waypoint：
专家希望机器人到达的关键空间位置
```

使用 waypoint 表示有几个好处：

| 表示方式 | 特点 |
| --- | --- |
| 低层动作 | 更贴近具体机器人控制，但容易受到机器人动力学、摩擦和控制误差影响 |
| Waypoint | 更抽象，强调空间路径和任务阶段，适合跨机器人形态使用 |

在跨机器人形态评测中，waypoint 表示尤其重要。因为轮式机器人、四足机器人和类人机器人的底层控制方式不同，如果直接学习某一种机器人的低层动作，可能很难迁移到另一种机器人。

Waypoint 把轨迹表示提升到更高层，使不同机器人可以根据自己的控制方式去跟踪相同或相近的导航目标。

## 人类轨迹与最短路径轨迹的差异

很多导航任务可以通过最短路径算法生成参考轨迹。最短路径轨迹通常追求从起点到终点的几何距离最短。

这类轨迹适合构造基础导航任务，但它存在一个问题：它不一定符合真实人类在环境中移动时的行为习惯。

例如，最短路径算法可能直接给出：

```text
当前位置
-> 几何最短路线
-> 目标点
```

而人类操作者可能会表现出更复杂的行为：

```text
先观察目标是否可见
绕开人的活动区域
经过门口时调整视角
靠近目标前减速确认
在不确定时短暂停顿
为了回答问题主动寻找更好视角
```

这些行为体现了真实导航中的感知、判断和交互过程。

因此，人类专家轨迹的价值不只在于提供“正确路线”，还在于提供更自然的执行方式。对于具身导航来说，这类数据可以帮助模型学习到更接近真实使用场景的策略。

## 示范数据与 imitation learning

专家轨迹可以直接用于 imitation learning。Imitation learning 的基本思想是让 policy 学习专家在相似状态下会采取什么行动。

可以写成：

```text
输入：
当前 observation
当前任务指令
历史状态或当前子任务

输出：
专家下一步 waypoint 或动作
```

训练样本可以从轨迹中整理出来：

```text
(obs_0, instruction) -> waypoint_0
(obs_1, instruction) -> waypoint_1
(obs_2, instruction) -> waypoint_2
...
```

如果模型使用历史信息，还可以把输入扩展成：

```text
历史观测序列
当前观测
组合式指令
当前子任务状态
-> 下一步导航目标
```

这种形式适合训练视觉语言导航模型、通用导航策略或高层规划模块。

在组合式任务中，imitation learning 不只是模仿移动方向，还需要学习：

```text
如何根据语言选择目标
如何识别任务阶段
如何在子任务之间切换
如何处理动态目标
如何保持社交距离
如何为问答收集视觉信息
```

因此，专家轨迹为模型提供的是完整任务流程中的监督信号。

## 示范数据与评测分析

专家轨迹除了用于训练，也可以用于评测分析。

在分析一个 policy 的表现时，可以将模型轨迹与专家轨迹进行对比：

```text
模型是否选择了相似路线
模型是否在关键位置观察环境
模型是否遗漏了某个子目标
模型是否过早切换任务阶段
模型是否在动态人类附近保持合理距离
模型是否比专家轨迹绕了更多路
```

这种对比可以帮助判断失败原因。

例如：

| 现象 | 可能原因 |
| --- | --- |
| 模型路径明显偏离专家轨迹 | 可能没有正确理解指令或空间结构 |
| 模型在目标附近来回移动 | 可能目标识别或停止判断不稳定 |
| 模型完成前半段但后半段失败 | 可能长期状态保持或子任务切换存在问题 |
| 模型靠近行人过近 | 可能缺少社交导航约束 |
| 模型没有移动到合适视角就回答问题 | 可能 EQA 阶段的信息收集不足 |

这种分析方式比只看最终成功率更细致，尤其适合组合式导航任务。

## 轨迹质量控制

由于专家轨迹会用于训练和评测参考，数据质量非常重要。OmniNavBench 的轨迹采集并不是简单记录一次人工操作，而是包含审核和修正过程。

一条轨迹通常需要满足：

```text
任务目标被正确执行
关键地标或目标物体被清楚观察到
子任务顺序与指令一致
动态人类相关约束被满足
轨迹没有明显无效移动或异常行为
视觉观测和位姿记录完整
```

如果轨迹没有清楚经过指定地标、没有正确找到目标物体，或者没有满足任务中的社交约束，就需要重新检查或修正。

这种质量控制可以减少无效示范对模型训练的干扰。

对于 imitation learning 来说，数据质量往往比单纯数据数量更关键。低质量轨迹可能会让模型学习到错误行为，例如错误路径、错误停止位置或不合理的避让方式。

## 数据规模与覆盖范围

OmniNavBench 的示范数据覆盖多种环境、任务类型和机器人形态。它不是只为单一导航任务采集轨迹，而是围绕组合式导航 episode 构建数据。

从数据组织角度看，可以把每条样本理解为：

```text
一个场景
+ 一个机器人形态
+ 一条组合式指令
+ 一条专家轨迹
+ 一组同步观测和位姿记录
```

这种组织方式使数据能够同时支持多个研究问题：

```text
不同任务组合对模型有什么影响
不同场景会不会造成性能下降
不同机器人形态是否影响轨迹执行
不同语言表达是否影响导航稳定性
专家轨迹能否提升长程任务表现
```

由于轨迹覆盖了不同场景和任务组合，它更适合分析通用导航能力，而不是只训练某个特定任务的策略。

## 语言指令的扩展

OmniNavBench 中的轨迹与语言指令绑定。为了评估 agent 对语言表达变化的鲁棒性，同一个任务目标可以对应不同语言风格的指令。

常见形式包括：

```text
原始指令
简洁指令
详细指令
第一人称指令
```

例如：

```text
原始指令：
Go to the kitchen and find the trash can.

简洁指令：
Find the trash can in the kitchen.

详细指令：
Move through the hallway, enter the kitchen area, and look for the trash can near the counter.

第一人称指令：
I need to go to the kitchen and find the trash can.
```

这些指令在语义上指向同一个任务，但语言形式不同。

这种设计可以测试模型是否真正理解任务含义，而不是只适应固定模板。如果模型只记住某种表达方式，在面对更自然或更复杂的用户指令时就容易失败。

## 轨迹数据的使用方式

根据研究目标不同，专家轨迹可以有多种使用方式。

### 作为监督学习数据

最直接的方式是将专家轨迹整理成 observation-action 或 observation-waypoint 对，用于训练 policy。

```text
observation + instruction
-> expert waypoint
```

这种方式适合行为克隆和视觉语言导航策略训练。

### 作为高层规划参考

轨迹中的 waypoint 可以用于学习高层路径规划，而不是直接学习低层动作。

```text
当前状态
-> 预测下一个高层目标点
-> 底层控制器负责执行
```

这种方式更适合跨机器人形态，因为不同机器人可以使用不同控制器跟踪同一类 waypoint。

### 作为评测对照

专家轨迹也可以作为分析模型输出的参考。通过比较模型轨迹和专家轨迹，可以观察模型是否偏离合理路线、是否错过关键观察点、是否在动态人类附近产生不合适行为。

### 作为错误分析依据

当模型失败时，可以回看专家轨迹，判断正确行为应该是什么。

例如：

```text
专家在进入房间前先转向观察
模型直接穿过房间导致错过目标

专家在行人靠近时减速避让
模型继续前进导致社交距离过近

专家在回答问题前移动到更好视角
模型没有收集足够信息就回答
```

这种对比能帮助研究者定位模型能力短板。

## 组合式轨迹带来的学习难点

OmniNavBench 的轨迹不是单阶段轨迹，而是多子任务组合轨迹。这会给学习带来更高难度。

### 子任务边界不总是显式可见

在连续执行过程中，模型需要判断当前动作属于哪个子任务。子任务之间的边界并不总是像数据表格那样清楚。

例如，从“进入客厅”切换到“寻找垃圾桶”时，模型需要知道自己已经完成第一个目标，并开始执行下一个目标。

### 轨迹误差会累积

在长程轨迹中，早期偏差会影响后续观测。如果模型一开始走错房间，后续看到的环境就和专家轨迹完全不同。

这会导致：

```text
当前位置偏移
-> 目标不可见
-> 子任务切换失败
-> 后续轨迹继续偏离
```

### 不同任务需要不同策略

VLN、ObjectNav、Human Following 和 EQA 对行为的要求不同。模型不能只学习一种固定移动模式，而要根据当前任务阶段调整策略。

例如：

```text
VLN 阶段更依赖语言地标
ObjectNav 阶段更依赖物体搜索
Human Following 阶段更依赖动态目标跟踪
EQA 阶段更依赖主动观察
```

### 跨形态执行会改变轨迹表现

同一条高层路线在不同机器人上执行时，视觉观测、运动轨迹和局部控制都可能不同。模型需要适应这种 embodiment 差异，而不是只记住某一种机器人上的轨迹模式。

## 与单任务数据集的区别

单任务导航数据集通常围绕一种任务构建，例如只做 VLN 或只做 ObjectNav。轨迹目标相对单一，数据结构也更集中。

OmniNavBench 的示范数据更强调组合性：

| 数据形式 | 主要特点 |
| --- | --- |
| 单任务轨迹 | 目标类型单一，任务边界清楚，评测相对集中 |
| 组合式轨迹 | 多目标连续出现，任务边界需要判断，失败原因更复杂 |

这意味着 OmniNavBench 的轨迹更适合研究通用导航，但也更难训练。

模型不仅要从轨迹中学习“往哪里走”，还要学习：

```text
当前任务阶段是什么
下一个子目标是什么
什么时候应该切换目标
哪些观测信息对当前阶段有用
如何在动态环境中保持合理行为
```

这也是组合式专家轨迹比普通路径数据更有研究价值的原因。

## 本节内容回顾

OmniNavBench 的专家轨迹通过人类遥操作采集，记录了组合式导航任务中的观测、位姿和 waypoint 序列。它们不仅可以作为 imitation learning 的监督数据，也可以用于评测分析、路径对照和失败原因定位。

理解专家轨迹时，需要重点关注三个方面：

```text
轨迹不是孤立路径，而是和组合式指令绑定
轨迹不是单纯最短路径，而是包含观察、避让和任务切换行为
轨迹不是只服务于训练，也服务于结果解释和错误分析
```
