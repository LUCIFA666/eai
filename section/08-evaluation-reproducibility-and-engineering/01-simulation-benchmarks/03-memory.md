# 记忆

大多数操作 benchmark 默认当前一帧观测就足以决定下一步动作，任务是马尔可夫的。记忆类 benchmark 针对相反的情形：环境部分可观测，相同的当前观测可能来自不同的历史、因而对应不同的正确动作，策略必须把此前的观测与动作保留下来，并在后续步骤用上。

## 记忆负载的来源

这类任务的记忆负载来自几种反复出现的设置：

- 遮挡与物体永久性：目标物在前几步可见，之后被容器或其他物体挡住，动作仍要指向它当前的位置或身份。
- 计数与时序：某个动作要执行指定次数，或要在计到第 N 次时触发，中间各步的场景难以区分。
- 顺序依赖：后一步用哪个容器、走哪条路径，取决于此前某一步的结果。
- 空间记忆与容量：要同时记住多个物体的位置、颜色或形状，并在干扰物出现后仍能回忆。

判断一个任务是否真正依赖记忆，看的是能否只凭当前观测推出正确动作；部分 benchmark 用历史依赖子任务的比例把这一点量化出来。
