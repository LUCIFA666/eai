# 数据格式与保存

机器人策略训练的效果在很大程度上取决于数据质量，而数据质量不仅受到采集数量的影响，更受到数据组织方式和存储规范的影响。在真实机器人系统中，一条示教轨迹（episode）通常包含多模态观测、机器人状态、动作指令以及任务相关信息，这些内容需要在采集过程中保持严格的时间对齐和统一的数据结构，从而保证后续训练、回放以及跨平台迁移能够稳定进行。因此，在真机采集阶段，应当优先关注 episode 内部字段的组织方式、数据落盘格式的选择以及数据集封口过程中的一致性管理。

## Episode 数据结构与时间对齐

从数据组织的角度来看，一条 episode 可以理解为机器人完成一次完整任务过程中产生的时间序列数据集合。无论采用何种存储格式，其核心字段通常保持一致，至少包含视觉观测、机器人状态、动作信息以及任务描述等内容。

其中，`observation.images` 用于保存机器人在各个时刻获取到的图像信息。图像来源可以包括第一视角相机、固定视角相机、深度相机以及腕部相机等多个传感器，每个时间步可能对应多路同步图像数据。由于视觉信息通常占据数据体积的大部分，因此实际系统中一般不会直接将原始图像逐帧存储，而是采用视频编码方式进行压缩，以减少存储开销。

`observation.state` 表示机器人当前时刻的状态向量，它反映机器人自身的物理状态和环境反馈。状态信息通常包括关节位置、关节速度、夹爪开合状态、末端执行器位姿以及力传感器读数等。对于移动机器人或双臂系统，还可能包含底盘位姿、惯性测量单元数据以及多机械臂协同状态。状态向量通常采用固定维度的数值数组表示，以便后续直接输入神经网络。

`action` 表示机器人在当前时刻执行的控制指令，它是监督学习和模仿学习中最核心的标签信息。动作可以采用关节空间位置增量、速度指令、力矩指令或者末端笛卡尔空间位姿变化来描述。为了保证策略训练时输入输出之间具有明确对应关系，动作数据应当与观测数据保持严格同步。

除了观测和动作之外，每个时间步还需要记录对应的 `timestamp`。时间戳是实现多模态同步的基础，它既可以使用系统时间，也可以使用统一的单调时钟。对于多相机、多传感器系统，仅依靠数组索引进行对应往往是不可靠的，因此实际采集过程中通常以时间戳作为唯一同步依据，并在后处理阶段完成插值和重采样。

在 episode 级别，还需要保存任务相关信息。`task` 字段用于描述当前轨迹对应的任务目标，例如“抓取红色积木并放置到指定区域”或“打开抽屉”。任务描述既可以是离散编号，也可以是自然语言文本，为后续条件策略学习提供任务上下文。

为了区分成功示教和失败示教，还需要记录 `success` 字段。该字段通常采用布尔值表示，用于标识当前 episode 是否完成目标任务。成功标记能够帮助后续数据筛选、成功率统计以及奖励建模，对于行为克隆和强化学习均具有重要意义。

此外，还需要通过 `metadata` 保存额外信息，例如采集日期、操作者编号、机器人型号、相机参数、控制频率、环境配置以及软件版本等。这些元数据虽然不直接参与训练，但对于实验复现、问题定位以及数据集维护具有重要价值。

在上述字段之外，更重要的是保证各个模态之间的时间对齐关系。理想情况下，每一个动作都应对应唯一的观测状态，即形成：

```text
(observationt, actiont) → observationt+1
```

这种一一对应关系是策略学习的基础。如果不同传感器存在频率差异，例如相机以 30 Hz 工作，而机器人控制频率达到 100 Hz，则需要通过插值、最近邻匹配或者重采样机制构建统一时间轴，使得所有数据能够在同一时间基准下进行组织。只有保证观测、状态和动作之间的严格同步，才能避免训练过程中出现时序错位，从而提高策略学习的稳定性。

## 常用数据落盘格式及其取舍

数据在现场以何种文件格式写入磁盘，直接影响到采集系统的稳定性、磁盘 I/O 负载以及后续的数据读取效率。目前在具身智能开源社区中，主要活跃着 LeRobotDataset（Parquet+MP4）、HDF5 以及 RLDS 三种数据格式，它们在现场落盘时各有优劣。

LeRobotDataset 采用的是“结构化表格与独立视频流”相解耦的设计思路。它的文本信息、时间戳、机器人本体状态和动作指令被存储在具备极高检索和压缩效率的 Parquet 表格文件中，而高带宽的图像数据则被实时编码并存储为独立的 MP4 视频文件。这种格式最大的优势在于对人类开发者极其友好，现场采集人员无需编写任何复杂的解析脚本，直接双击 MP4 视频即可肉眼检查采集质量。得益于 H.264 或 H.265 硬件加速编码，其占用的磁盘空间和实时写入带宽在三种格式中是最小的。

HDF5是机器人与强化学习领域的传统行业标准。它将多维数组（如图像的 uint8 矩阵、状态的 float 数组）统一打包进一个单一的二进制文件中。HDF5的核心优势在于支持原生的随机读写和分块存储，现场采集系统可以直接将原始图像或JPEG压缩流以矩阵形式直接放进磁盘，几乎不消耗额外的编解码计算资源，且能够完美保证时间步的绝对精确。但是HDF5文件的问题是内存占用太大，一般一个episode有3Gb以上。因此如π0，Diffusion Policy等模型均有数据预处理的脚本，例如π0会将HDF5的数据进行内存压缩和语言模态的绑定；DP会将HDF5转化为更轻量化的zarr格式进行存储。但是现场采集的过程中，HDF5格式依然是研究中最推荐的格式。

RLDS（Robot Learning Dataset Standard）则是基于谷歌 TFRecord 或 Protocol Buffers 构建的生态体系，专为大规模分布式训练和流式数据加载而设计。在海量数据集群中，RLDS 的读取吞吐量和兼容性无可比拟。但在真机采集的第一现场，RLDS 的使用体验并不理想。其严格的 Schema 限制使得现场如果想要临时增加一个传感器字段变得极其繁琐，且纯二进制流的形式让现场的可视化排查和局部 Debug 变得非常困难。

基于上述特性，现场落盘的通用取舍策略是：如果现场采集主机的算力充裕、磁盘带宽有限，且非常注重数据的直观预览与快速排查，应优先选择类似 LeRobotDataset 的视频分离方案；如果追求极低的采集系统开销、绝对精准的时间步步进，并且有稳定的电源保障，则选择 HDF5 格式，但最好准备数据转换脚本，处理后进行传输；而在真机现场通常不推荐直接将 RLDS 作为第一落盘格式，它更适合作为后期数据进入训练集群时的最终转换目标。

## 数据集封口与版本管理

真机采集结束后，并不意味着数据可以直接用于训练。在正式发布数据集之前，还需要完成数据集封口过程，以保证整个数据集具有一致性和可复现性。

首先需要对所有 episode 进行统一检查，包括时间序列长度是否一致、是否存在缺失帧、图像文件是否损坏以及动作和状态维度是否匹配等。异常 episode 通常需要进行剔除或者重新采集，从而保证数据质量。

随后需要统计整个数据集的归一化参数。由于不同维度的数据量纲差异较大，例如关节角度、位置坐标和力传感器数据具有不同范围，因此通常需要计算：

```text
mean、std、min、max
```

等统计量，并将其保存为独立文件。训练阶段可以直接利用这些统计信息完成标准化处理，从而提高模型收敛速度和稳定性。由于归一化参数与数据集内容严格对应，因此应将其视为数据集的一部分进行统一管理。

在完成统计之后，需要生成数据集版本信息和唯一哈希值。版本号用于记录数据集迭代过程，而哈希值则能够保证数据内容的一致性。当后续增加新的 episode、修改标注或者重新计算归一化参数时，都应重新生成版本号和哈希值，以确保训练结果能够准确追溯到对应的数据版本。

最终，经过检查、统计和版本封装后的数据集将形成一个稳定的数据快照。此时数据集内容不再随意修改，而是作为一个完整的训练输入被提交到模型训练流水线中。这样的数据集封口机制能够有效避免不同实验之间的数据漂移，提高实验结果的可复现性，并为后续的大规模数据管理和持续迭代提供可靠基础。

需要说明的是，本节主要关注真机采集现场的数据组织与落盘原则。关于 Parquet、HDF5、RLDS 等格式的内部结构、转换工具以及不同框架之间的数据适配方法，将在第 6 章中进一步展开介绍。
