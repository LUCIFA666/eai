VLA 基础：从视觉语言到动作

VLA 是什么、动作怎么表示、怎么生成、怎么适配不同机器人

前面的章节讲了 Behavior Cloning（模仿学习）和 Diffusion Policy（扩散策略）。它们解决的问题是：给一堆演示数据，训练一个"看图出动作"的模型。但它们有一个共同的局限——只认识训练时见过的任务。你让它拿杯子它会，但你说"把杯子递给我"，它不理解。

VLA（Vision-Language-Action model）的核心想法很简单：把大语言模型（LLM）的"理解能力"借过来，让模型不仅看图，还听懂自然语言指令，最后输出机器人动作。

1. VLA 的基本架构

一个 VLA 模型通常由三部分组成：看、想、动。

VLA 模型的三段式架构：视觉编码 + 语言理解 + 动作输出

为什么要用大语言模型做 backbone？
因为 LLM 已经在海量互联网数据上学到了"世界知识"——它知道杯子是用来装水的、盘子在桌上、"递给我"意味着移向人的方向。这些常识对机器人执行自然语言指令至关重要。VLA 不是从零训练一个巨大模型，而是在已有的 VLM（如 PaliGemma、Qwen-VL）上加装一个"动作输出"模块，再用机器人数据微调。

2. 动作表示：机器人能听懂的"语言"

VLA 输出的"动作"到底是什么？不同系统的答案不一样。理解这些差异非常重要——选错了动作表示，模型训练得再好也控制不了机器人。

三种动作表示方式——不同项目对"动作"的定义不同

一条真实的动作数据长什么样？

Action Chunk 示例（ACT 模型输出，H = 4 步预览）
chunk[0] [0.002, -0.001, -0.003, 0.01, 0.00, -0.02, 0.8] ← 当前步：微微右移、稍微下降，夹爪开
chunk[1] [0.003, -0.002, -0.005, 0.01, 0.00, -0.03, 0.6] ← 继续靠近，夹爪开始收拢
chunk[2] [0.001, -0.001, -0.002, 0.00, 0.00, -0.01, 0.1] ← 到达位置，夹爪几乎合拢
chunk[3] [0.000, 0.000, 0.010, 0.00, 0.00, 0.00, 0.0] ← 抬起物体，夹爪完全闭合
action_space delta_end_effector_pose ← 每一步是相对位移（增量），不是绝对坐标
frequency 10 Hz ← 每秒执行 10 步，4 步 = 0.4 秒的预测
normalized true (range: [-1, 1]) ← 训练时归一化，执行时必须反归一化回真实值
归一化——最容易忽略的 bug
训练时，动作值通常被归一化到 [-1, 1] 或 [0, 1]。部署时如果忘了反归一化，模型输出 0.3 本来代表"移动 3 厘米"，却被当成"移动 0.3 弧度"——机器人会抽搐或者不动。反归一化的 mean/std 或 min/max 必须和训练时完全一致。

3. 动作 Token 化：让语言模型"说出"动作

大语言模型只会输出离散的 token（单词编号）。但机器人动作是连续的浮点数（比如"向右移 0.003 米"）。怎么让 LLM 输出连续动作？

最直接的办法：把连续动作变成离散 token。

均匀量化（Uniform Binning）：把连续浮点数映射到离散的 bin 编号

均匀量化 (Uniform Binning)

最简单的方法。把 [-max, +max] 分成 N 个等宽的格子，每个值取最近的格子编号。RT-2 和 OpenVLA 都用这种方式。

缺点：大部分动作集中在中间小范围，但 bin 均匀分布，浪费了两端的精度。

FAST Tokenizer

先对训练数据做聚类，让频繁出现的动作范围分到更多 bin，稀少的范围分到更少 bin。就像 Huffman 编码——常用的东西用更短的码。

优点：精度更高，token 序列更短，推理更快。

量化误差有多大影响？
用 256 bin 量化 [-0.05, +0.05] 的范围，每个 bin 宽度 ≈ 0.0004 m = 0.4 mm。对多数抓取任务（精度要求 ~5mm），这个误差可以忽略。但如果量化范围设错了（比如动作实际范围是 [-0.5, +0.5] 但你只用了 [-0.05, +0.05]），超出范围的动作会被截断到边界，机器人会表现得"犹豫不决"——这是非常常见的 bug。

4. 两种动作生成方式：自回归 vs 扩散

有了动作的"表示"方式，下一个问题是：模型怎么生成这些动作？目前主流有两条路线。

方式 A：自回归 (Autoregressive)

像写作文一样，一个 token 一个 token 地写。先输出 Δx 的 token，再输出 Δy 的 token……这就是 RT-2 和 OpenVLA 的做法。

自回归输出：一次生成一个动作维度的 token

方式 B：扩散 (Diffusion)

不一个个生成 token，而是一次性把整个动作块从"噪声"里"雕刻"出来。就像雕塑家从一块大理石中逐步凿出形状。

扩散输出：从纯噪声开始，经过 K 步去噪得到完整动作块

对比自回归 (AR)扩散 (Diffusion)
输出方式逐个 token 依次生成整个动作块同时从噪声中生成
动作连续性token 之间独立，可能不太平滑整体去噪，动作天然平滑
推理速度token 多时慢（串行）去噪步数多时慢（但可并行优化）
多模态动作需要特殊处理天然支持（同一输入可能有多种合理动作）
代表模型RT-2, OpenVLAπ₀, Diffusion Policy, OpenPI
和 LLM 的兼容性原生兼容（LLM 就是 AR）需要在 LLM 输出后接一个扩散头

5. 一个 VLA 的完整 Token 序列

让我们把前面的概念串起来，看看一次推理中模型实际处理的 token 序列长什么样：

OpenVLA 风格的 token 序列：

<bos> img_1 img_2 img_3 … ×256 把 红色 杯子 放到 盘子 上 <act> 127 124 119 130 128 125 204 <eos>
蓝色 = 视觉 token 绿色 = 语言 token 红色 = 动作 token 紫色 = 特殊标记

从 LLM 的角度看，动作 token 和文字 token 没有本质区别——都是"下一个最可能的词"。只不过动作 token 的"词表"是 256 个 bin 编号，而不是中文汉字。

6. 3D VLA：让模型"看到"空间

标准 VLA 输入的是 2D 图像。但机器人操作本质上是 3D 问题——抓取需要知道深度，避障需要理解空间。3D VLA 通过引入点云、深度或体素表示来补充空间信息。

3D VLA 在 2D 视觉基础上引入点云/深度作为额外输入

7. 跨机器人训练：一个模型多个身体

不同机器人的"身体"差异很大：有的是 6 个关节，有的是 7 个；有的夹爪开合，有的灵巧手；有的 20Hz 控制，有的 50Hz。能不能训练一个 VLA 模型，让它同时适配多种机器人？

这就是 Multi-Embodiment 训练。核心挑战和解决思路：

多机器人训练：不同的身体，共享的"大脑"

为什么要做跨机器人？
一个机器人的演示数据往往只有几百到几千条。但如果能把 10 种机器人的数据混在一起训练（总计可能几十万条），模型就能学到更通用的"操作知识"——比如"拿东西要先对准再合拢"这个规律不依赖于具体是哪个机器人。这就是 Octo、RT-X、OpenVLA 等项目追求的目标。

一句话总结
VLA = VLM（视觉语言模型）+ Action Head（动作输出）。核心问题只有三个：怎么表示动作（连续 vs token）、怎么生成动作（自回归 vs 扩散）、怎么适配不同机器人（统一空间 + 归一化）。剩下的都是工程选择。
