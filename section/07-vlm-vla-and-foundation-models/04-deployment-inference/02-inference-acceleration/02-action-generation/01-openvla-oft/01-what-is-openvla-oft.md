# OpenVLA-OFT 是什么

OpenVLA-OFT 的全称是 Optimized Fine-Tuning，是在 OpenVLA 主干上换一套微调配方得到的变体，主干和预训练权重都沿用 OpenVLA，只在微调阶段改动作生成段的解码路径和动作头，目标是同时拿到更高的推理速度和更高的任务成功率。它要解决的是 OpenVLA 的一个具体短板：动作生成太慢，达不到高频控制需要的频率。

## OpenVLA 的动作生成慢在哪

OpenVLA 把一步动作表示成一串离散 token：七维动作（末端位置、姿态、夹爪开合）逐维量化进 256 个分箱，得到 7 个动作 token，再像语言模型生成文本一样自回归地解出来。自回归解码是串行的，第二个 token 要等第一个解完才能算，于是解一步动作要让主干 Transformer 走 7 次前向。主干是 7B 参数的大模型，单次前向本身开销就不小，乘以 7 之后，动作生成这一段的吞吐被压到 3–5 Hz。

高频控制通常需要 25–50 Hz，双臂等灵巧任务还要更高。3–5 Hz 落不进这个频率给的时间预算，自回归逐 token 这条路径满足不了实时控制。瓶颈不在视觉编码，也不在主干单次前向的开销，而在于动作生成段要逐个 token 串行解码，总开销随动作 token 的个数线性增长。

## OFT 的三项改动

OFT 的微调配方由三项改动组成：

- 并行解码：去掉 token 间的串行依赖，让一步动作的所有维度在一次前向里同时解出，把 7 次串行前向压成 1 次。这是提速的主力。
- 连续动作表示：不再把动作量化成离散 token，直接回归连续动作值，省掉逐维分箱带来的离散化误差。
- L1 回归目标：用一个轻量 MLP 动作头把主干输出映射成连续动作，以 L1 损失训练，替代原来逐 token 的交叉熵。

后两项主要提精度，几乎不增加推理开销，因为多出来的 MLP 动作头相对 7B 主干的计算量可以忽略。并行解码还顺带打开了 action chunking：一次前向不止解当前一步，而是连着解出未来 K 步的整段动作，机器人按这段动作连续执行 K 个控制步，才需要再推理一次。chunk 越长，单次推理摊到每一步的成本越低，动作生成的有效吞吐随 K 成倍上升。

## 动作生成吞吐与成功率

并行解码把七维动作原来的 7 次串行前向替换成 1 次前向，叠加 K=8 的 action chunking 后，动作生成吞吐进到百 Hz 量级；连续动作配 L1 回归几乎不改变这个吞吐。

下表列出各配置的动作生成吞吐与相对提速。数字为论文报告值，在 NVIDIA A100 上测得：每次查询输入一张 224×224 图像和一条 LIBERO 指令，吞吐为 100 次查询的平均值。

| 配置 | 吞吐 (Hz) | 相对原始 OpenVLA |
| --- | --- | --- |
| OpenVLA（自回归） | 4.2 | 1× |
| + 并行解码 | 15.9 | ≈4× |
| + 并行解码 + K=8 chunking | 108.8 | ≈26× |
| + 连续动作 + L1 | 109.7 | ≈26× |

提速没有以成功率为代价。完整 OFT 配方（并行解码 + action chunking + 连续动作 + L1，再加腕部相机和本体状态输入）在 LIBERO 四个任务套件上达到 97.1% 平均成功率，相对原始 OpenVLA 的 76.5% 是一次明显提升；只用单张第三人称图像的连续 L1 变体平均成功率为 95.3%。以上成功率为论文报告值。

## 本页小结

- OpenVLA 的动作生成受限于自回归逐 token 解码，七维动作要 7 次串行前向，吞吐落在 3–5 Hz，进不了高频控制。
- OpenVLA-OFT 是同一 OpenVLA 主干上的微调配方，由并行解码、连续动作表示和 L1 回归三项改动组成，提速靠并行解码与 action chunking，精度靠连续动作与 L1。
- 论文报告并行解码约 4×、叠加 K=8 chunking 约 26×，LIBERO 四套件平均成功率从 76.5% 提到 97.1%。
