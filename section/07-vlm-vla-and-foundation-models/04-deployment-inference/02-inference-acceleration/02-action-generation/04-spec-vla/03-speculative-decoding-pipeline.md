# 投机解码流水线

一次投机解码是 draft 草拟与验证核验交替的循环：draft 模型草拟一批候选动作 token，验证模型一次前向并行核验，接受正确前缀后进入下一轮。

## 本节目标

理解投机解码这条循环怎么运行：draft 如何组织候选、验证如何并行核验、接受长度这个效率指标，以及严格接受为什么在 VLA 的动作 token 上提速有限。

## draft 树草拟

draft 模型草拟时不是只出一条候选序列。每一步它给出概率最高的若干个动作 token（Top-K），把这些候选按自回归的展开方式组织成一棵草稿树：每个节点是一个候选 token，从根到叶的每条路径对应一串可能的动作序列。树的深度决定草拟多少步，每层的分支来自该步的 Top-K。

用树而非单条序列，是为了在一次验证里覆盖多条候选路径。单条序列一旦某步草拟错，后面全部作废；草稿树同时保留多条路径，验证时更有机会命中一条较长的正确前缀，接受长度的期望因此更高。Spec-VLA 沿用 Eagle-2 的动态草稿树，按候选的概率动态决定树的形状，而非固定结构。

## tree-attention 并行验证

验证模型要在一次前向里核验整棵草稿树的所有路径，靠的是 tree-attention。它按树的父子关系构造注意力掩码：每个候选 token 只能注意到从根到它自己这条路径上的祖先节点，不同分支互不可见。这样一次前向就能并行算出每条路径上各位置的验证输出，而不必为每条路径单独跑一次。

得到验证输出后，从根沿每条路径逐个比对：接受与验证模型预测一致的 token，直到第一个分歧处停下。被接受的最长前缀就是本轮的收获，分歧处的 token 由验证模型的输出替换，作为下一轮 draft 的新起点。如果某条路径整条被接受，验证模型再额外多出一个 token，本轮就多确认一步。

## 接受长度这个指标

一次前向确认的 token 数称为接受长度，它是投机解码效率的核心指标。自回归每次前向只出一个 token，接受长度恒为 1；投机解码里，接受长度越大，等量的动作 token 需要的验证前向次数越少，提速越明显。draft 草拟得越接近验证模型的输出，被接受的前缀越长，接受长度越高。评估 draft 质量、比较严格接受与松弛接受，用的都是这个指标。

## 严格接受为什么在 VLA 失效

标准投机解码采用严格接受：draft token 只有与验证模型的预测序号完全相等才接受，否则在该位置回退。这保证最终输出与验证模型单独解码逐 token 一致，是无损的。

问题在于动作 token 上的严格相等太难满足。draft 模型要在多模态条件下预测机器人动作，比自然语言里草拟下一个词更难，逐 token 命中率低。论文报告约一半样本里，draft 连第一个动作 token 都没能与验证模型对上（接受长度为 0 的样本占五成上下）。接受长度长期贴近 0 到 1，投机解码退化得接近逐 token 自回归，提速只有 1.08× 到 1.15×。

症结不在 draft 不够好，而在贪心 argmax 下严格相等的门槛过高：两个相邻 bin 对应的动作在连续空间里几乎没有差别，却因为序号不同被严格接受判为不匹配而丢弃。把这条判定放宽到容许相近的 bin，才能避免丢弃这些近义动作。

## 本页小结

- draft 模型每步给出 Top-K 候选，组织成动态草稿树，一次验证覆盖多条路径，接受长度的期望比单条序列更高。
- 验证模型用 tree-attention 一次前向并行核验整棵树，按路径逐个接受一致前缀，分歧处由验证输出替换；整条路径被接受时再多确认一个 token。
- 接受长度是投机解码的效率指标，自回归恒为 1，接受长度越大提速越明显。
- 严格接受要求逐 token 序号相等，draft 在动作 token 上命中率低，约半数样本接受长度为 0，提速只有 1.08–1.15×；相邻 bin 动作几乎无差却被判为不匹配，是松弛接受要修的问题。
