# EfficientVLA 是什么

EfficientVLA 是一个训练无关的结构化推理加速框架，作用在 CogACT 这类带 diffusion 动作头的 VLA 上。它把三条互补的策略组合起来：按层间冗余剪除语言模块中作用小的层，用 task-aware 的方式把视觉 token 从 256 个筛到几十个，再在扩散动作头里缓存并复用相邻去噪步的中间特征。三条策略都不改权重、不重新训练，作为一层推理优化叠加在已有 CogACT 上。

## 本节目标

理解 EfficientVLA 在 token 剪枝路线里的定位、它与单点方法的差别、免训练叠加的前提，以及三处冗余为什么要一起压缩、整体能带来多大加速。

## 在 token 剪枝路线里的定位

token 剪枝的思路是在进入注意力之前丢弃对当前动作贡献小的 token，成比例地降低这一段计算量。同路线的 FastV 只在单帧之内按注意力打分剪视觉 token；前一节的 VLA-Cache 走的是复用而非剪枝，跨帧缓存静态视觉 token 的 KV。两者都只作用在视觉 token 这一处。

EfficientVLA 的不同在于覆盖面。它把视觉 token 剪枝、语言模块层剪枝、扩散动作头特征缓存放进同一个框架，视觉 token 选择只是其中负责空间冗余的一环。剪枝判据也更保守：不是单纯按注意力取 top-k，而是在任务相关性之外额外保留一部分多样性 token，避免只留下彼此相似的高分 token 而丢掉其余区域的视觉信息。

## 三处冗余，为什么要一起压缩

CogACT 的单步延迟主要由两块构成：语言模块 memory-bound，扩散动作头 compute-bound。视觉 token 剪枝只在算力受限区有效，一旦语言模块进入显存受限区，继续减少视觉 token 几乎不再缩短延迟。这正是 VLA-Cache 在 CogACT 上只达到 1.38× 的原因：它压缩的是视觉 token 这一处，语言模块的显存开销没有动。

EfficientVLA 对三处冗余各用一条策略：

- 语言模块层间冗余：相邻层的隐藏态高度相似，深层尤其明显，说明不少层对表示的改动很小，可以剪除。
- 视觉 token 冗余：一部分 token 与当前任务关系弱，另一部分因图像相似而信息重复，两类都可裁掉。
- 去噪步时序冗余：扩散动作头相邻去噪步的注意力与 MLP 中间特征变化很小，重算基本得到相同结果。

三处分处算力受限区与显存受限区，只优化一处，另一处会立即成为新瓶颈。三处一起压缩，才能同时降低算力和显存开销，把加速推到单点方法达不到的量级。

## 免训练与基座 CogACT

EfficientVLA 的三条策略都在推理期生效，不需要额外训练。层重要度、视觉 token 的任务相关分都来自一次前向里的隐藏态和注意力，缓存调度是固定间隔，没有需要学习的参数。这让它可以直接叠加在训练好的 CogACT 权重上。

基座 CogACT 由三部分组成：DINOv2 加 SigLIP 的视觉编码器输出 256 个视觉 token，Llama2-7B 语言模块做多模态融合与推理，DiT 扩散动作头经多步去噪回归 7-DoF 动作。三条策略分别落在语言模块的层、进入语言模块的视觉 token，以及扩散动作头的去噪步上。

## 加速的整体量级

在 SIMPLER 的 Visual Matching 设置下，EfficientVLA 与基线及单点方法的对照如下（Google Robot 四个任务的平均成功率，FLOPs 以占基线的百分比计，论文报告）：

| 方法 | 免训练 | 平均成功率 | FLOPs | 加速 |
| --- | --- | --- | --- | --- |
| CogACT（基线） | - | 74.8% | 100% | 1.00× |
| FastV | 是 | 74.1% | 42.0% | 1.21× |
| VLA-Cache | 是 | 74.4% | 80.1% | 1.38× |
| EfficientVLA（保留 22 层，56 token） | 是 | 74.2% | 28.9% | 1.93× |

同样免训练，EfficientVLA 把 FLOPs 降到基线的 28.9%、加速 1.93×，而成功率与基线只差 0.6 个百分点。FastV 虽然把 FLOPs 降到 42%，但只优化视觉 token，语言模块的显存开销未动，加速止步 1.21×；VLA-Cache 同样受显存受限区限制，FLOPs 只降到 80.1%。差距来自覆盖面：单点方法难以压缩的那部分开销，正是结构化框架同时处理的部分。

## 本页小结

- EfficientVLA 是训练无关的结构化加速框架，在 CogACT 上把层剪枝、视觉 token 剪枝、扩散特征缓存组合成一套推理优化。
- 与只作用于视觉 token 的 FastV、VLA-Cache 不同，它同时覆盖语言模块层深和扩散去噪步两处，视觉 token 选择只是其中一环。
- 语言模块 memory-bound、扩散动作头 compute-bound，三处冗余分处两个受限区，只优化一处会让另一处成为新瓶颈，因此需要一起压缩。
- SIMPLER 上保留 22 层、56 个视觉 token 时，FLOPs 降到基线的 28.9%、加速 1.93×，平均成功率仅降 0.6 个百分点（论文报告）。
