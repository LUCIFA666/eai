# token / KV 优化

单步延迟中，视觉编码与注意力计算这一段的开销随视觉 token 数量增长。VLA 在连续控制中逐帧推理，相邻时刻的图像高度重叠，动作序列里又有大量过渡性步骤，于是同一份视觉信息被反复编码，同一批 token 的注意力被反复计算。这一组方法针对的就是这种冗余，沿两条互补路线压缩它：复用没变的，丢弃不重要的。复用指把上一时刻已经算过、当前帧基本没变的部分缓存下来直接复用；剪枝指在进入注意力之前丢弃对当前动作贡献小的 token。两条路线背后共享一个底层机制，即 KV cache 与时序复用，下面分三节展开。

## token cache

token cache 的出发点是时间连续性：以机械臂操作为例，相邻两帧之间真正发生变化的区域往往很小，背景和远离操作点的物体几乎不动。这些静态区域对应的视觉 token，上一帧已经在各层计算出 key-value 表示，当前帧重算一遍只会得到几乎相同的结果。把这些表示缓存下来跨帧复用，就能跳过对应的编码与注意力计算。

VLA-Cache 在 OpenVLA 这类自回归骨干上实现了这条路线，且免训练。它先比较相邻帧，找出变化最小的视觉 token，复用这些 token 已缓存的 key-value；对任务相关、会随环境变化的 token 则选择性重算，避免因丢失关键视觉信息而损害动作精度。复用比例不是全局固定的：各 decoder 层的注意力集中程度不同，VLA-Cache 按每层的注意力分布动态调整复用比例，把算力优先用在需要重算的 token 上。

token cache 的收益取决于场景的静态程度：静态区域越多，可复用的 token 越多。它免训练、可叠加在已有模型上，主要的取舍在于重算判定——判定太宽松会让过期缓存影响动作输出的准确性，太保守则复用率难以提升。

## token pruning

token pruning 不复用旧结果，而是直接减少要参与计算的 token。视觉输入里有大量 token 对当前这一步动作贡献很小，把它们在进入语言骨干或注意力之前丢弃，就能成比例地降低这一段的计算量。难点在于判据：哪些 token 可以丢弃而不影响动作，需要一个能区分重要与冗余的打分方式。

EfficientVLA 把 token 剪枝纳入一个更完整的免训练框架，针对 CogACT 这类带 diffusion 动作头的 VLA 同时压缩三处冗余：按层间冗余剪除语言模块中作用不大的层；用 task-aware 的方式筛选出一组兼顾任务相关性与信息覆盖的紧凑视觉 token，其余丢弃；在迭代式 diffusion 动作头里缓存并复用关键中间特征，消除去噪步骤之间的重复计算。视觉 token 选择是其中负责空间冗余的一环。

SP-VLA 把 token 剪枝和模型调度联合起来。剪枝部分按两类信号给 token 打分：spatial 信息来自 Canny 算子（一种边缘检测算子）提取的边缘，semantic 重要性由模型自身的注意力分布给出，两者结合排序后再剪枝。剪枝比例与当前动作速度正相关：高速过渡阶段动作粗放，可以提高剪枝比例；低速精细操作时关闭剪枝，避免丢弃支撑精确操作的视觉细节。

剪枝的主要风险是过度剪枝：随机剪枝或只依赖单一信号都会导致精度下降。EfficientVLA 用覆盖性约束保持信息多样性，SP-VLA 用速度自适应的比例和低速关闭剪枝来守住精度下限，本质上都是让剪枝强度随对精度的容忍度调整。

## KV cache 与时序复用

KV cache 是注意力计算的标准优化：自回归解码时，每生成一个新 token 都要对之前所有 token 做注意力，而历史 token 的 key-value 在后续步骤里不再改变，缓存下来就不必逐步重算。它消去的是单次解码内部、序列方向上的重复计算。

时序复用把这个思路从一次解码内部扩展到推理之间。VLA 逐帧输出动作，相邻帧的视觉输入大量重叠，于是静态视觉 token 的 key-value 不仅在一次解码内可复用，还能跨控制步复用，这正是 token cache 所做的。同样的逻辑也适用于 diffusion 动作头：去噪是一个多步迭代过程，相邻去噪步的某些中间特征变化很小，缓存复用即可省去重复计算，EfficientVLA 的特征缓存就属于这一类。

时序复用没有单独的代表项目，它是前面缓存类方法共同的底层基础。它的核心风险是缓存过期：跨帧或跨步复用的前提是被复用的部分确实变化很小，一旦场景发生变化、复用的表示已经过时，继续沿用就会让动作偏离真实观测。因此这类方法都要配套一组约束，包括变化检测、对环境敏感 token 的选择性重算、随注意力或速度调整的复用比例，用来界定哪些可以复用、复用到什么程度。

## 机制对比

复用（token cache）和剪枝（token pruning）是压缩这段开销的两条并列路线，KV cache 与时序复用则是它们共同的底层机制，本身不是与前两者并列的第三个方法项目。下表前两行按路线对照，末行单列这层底层机制：

| 机制 | 如何压缩这段开销 | 训练或前提依赖 | 主要风险 |
| --- | --- | --- | --- |
| token cache（复用） | 跨帧复用静态视觉 token 已算出的 KV，跳过重复编码 | 免训练，可叠加 | 重算判定过宽时，过期缓存影响动作精度 |
| token pruning（剪枝） | 进入注意力前丢弃对当前动作贡献小的 token | 免训练，依赖一套重要性判据 | 剪枝过度或判据不准时精度下降 |
| KV cache 与时序复用（底层机制） | 复用序列方向与控制步、去噪步之间不变的中间结果 | 前两条路线共享的实现基础，无单独项目 | 场景变化使缓存过期，复用越界则动作偏离观测 |

复用与剪枝针对的是同一段开销的两个方向，可以叠加：先剪除不重要的 token，再对剩下的静态 token 复用缓存。两条路线都免训练，主要差别在于依赖什么判据来界定复用或丢弃的边界。选哪一类，取决于场景的静态程度有多高、动作序列里过渡性步骤占多少，以及对动作精度的容忍空间还有多大。
