# 推理加速

VLA 读入观测图像和任务指令，输出机器人要执行的动作。它不是算一次就结束，而是嵌在一个不断重复的控制回路里：机器人采集观测，模型推理出动作，机器人执行，再采集下一帧观测。控制频率决定了每一轮留给推理的时间，频率越高，每一步能用的时间越短，10–50 Hz 大致对应 20–100 ms 的单步预算。推理加速要做的，就是让一次推理稳定地在这段预算内算完。

这和通用大模型的推理加速不同。在线服务追求吞吐量，关心单位时间能处理多少请求；这里追求的是单步延迟，关心一次推理能不能按时算完。量化、剪枝、少步采样、松弛投机解码这些方法大多以动作质量换延迟，衡量标准是把精度损失控制在可接受范围内、同时落入延迟预算，而非追求精度零损失。一个推理很快却无法稳定完成任务的策略没有意义。

action chunking 是贯穿本章的前提：模型一次推理输出未来一小段连续动作，机器人依据这段动作连续执行若干步，不必每个控制步都重新推理。它把推理频率和控制频率解耦，降低了对单步延迟的敏感度，但每一次推理本身仍要落入预算。chunking 的队列与时序细节属于运行时处理的范畴，本节不展开。

## 延迟来自哪里

一次推理从读入观测到给出动作，时间花在几个串联的阶段上：

- 视觉编码：把图像切成 token，经视觉 backbone 做一次前向。输入分辨率越高、图像越多，这一段越重。
- LLM/VLM 前向：主干 Transformer 在视觉 token 和文本 token 上做注意力与前馈计算。参数量大、上下文长，这一段通常是延迟的主体。
- 动作生成：把主干的输出变成具体动作，开销取决于动作的生成方式。自回归要逐个 token 串行解码，flow 或 diffusion 要迭代采样很多轮，而并行动作头一次前向就能生成一整段动作。
- 反归一化与后处理：把归一化的动作还原成真实量纲，再做裁剪和平滑，开销通常很小。
- 服务通信与运行时队列：policy server 的网络往返、观测与动作队列、控制频率匹配，这部分属于运行时。

这几段里，LLM/VLM 前向和动作生成占了主要部分，视觉 token 的数量又直接影响前向的注意力规模。本章前面三组加速技术正好分别落在这几处：动作生成加速针对的是动作生成那一段，模型压缩针对的是主干前向的参数量和精度，token / KV 优化针对的是视觉 token 和注意力上的重复计算。最后一节再用 Video Prediction Policy（VPP）作为一个架构级案例，说明如何把原本很重的未来视频预测改写成更适合闭环控制的未来表征抽取。

## 技术速览

### 动作生成加速

动作生成常常是推理中最慢的一段：自回归要一个 token 接一个 token 地解码，diffusion 类方法要反复迭代采样。这组方法从不同角度压缩这段成本。

OpenVLA-OFT 用并行动作解码，把逐 token 的串行生成换成一次前向输出整段动作。PD-VLA 同样走并行解码，但不改网络结构，而是把自回归解码重写成一个可以并行迭代求解的方程组。Consistency Policy 针对 diffusion 的多步采样，把它压缩到少数几步甚至一步。FAST 把连续动作离散成更少的 token，复用语言模型成熟的解码路径、减少要生成的 token 数量，π0-FAST 就是用上 FAST token 的自回归模型。Spec-VLA 则用投机解码，让一个小模型先快速草拟动作 token，再由大模型一次性验证。

### 模型压缩

如果瓶颈在主干本身太大，就换一个开销更低的模型。这组方法用更少的参数、更低的数值精度或更轻的结构，换取速度和端侧可行性。SmolVLA 和 TinyVLA 从设计上就采用更小的骨干。BitVLA 走量化路线，主干采用三值权重（取值 -1、0、1，等效约 1.58-bit），显存和计算量大幅下降。知识蒸馏是一条通用思路，用大模型指导一个小 student 模型学到相近的行为，本身没有对应到某个单独的方法项目，在本章作为机制介绍。

### token / KV 优化

连续控制中前后两帧的画面变化往往很小，把每一帧的全部 token 都重新编码会产生重复开销。这组方法利用这种时间冗余减少计算。VLA-Cache 在 token 层面缓存前一帧的结果，对帧间几乎不变的 token 复用缓存的 KV，跳过重复计算。EfficientVLA 和 SP-VLA 做 token 剪枝，在推理时丢弃冗余的 token。KV cache 与时序复用作为机制，在多个方法里以不同形式出现。

### Video Prediction Policy

VPP 不是传统意义上和前面三组并列的一类通用加速技巧，而是一个很适合放在部署推理视角下理解的案例：如果直接在闭环里完整生成未来视频，扩散视频模型通常太慢；VPP 的关键做法是只取视频模型内部的 predictive representation，再把它交给动作策略使用。它展示的是一种架构级减算思路，即把“完整未来生成”改写成“未来表征抽取”，从而把视频基础模型真正带进控制回路。
