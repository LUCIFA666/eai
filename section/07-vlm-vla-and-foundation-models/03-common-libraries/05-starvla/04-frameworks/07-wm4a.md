# WM4A

目标：理解 StarVLA 官方 WM4A 路线如何把 pretrained video-generation world models 用作 action prediction 的 backbone。

WM4A，即 **WM4A: World Model for Action**，或者叫 **World Action Model**，使用 pretrained video-generation DiT models，例如 Cosmos-Predict2 和 Wan2.2，作为 action prediction 的 backbone。

这一路线的出发点是：视频生成模型在预训练时学习了物体运动、时序变化和物理交互的表征，这些表征可能比纯 VLM 视觉表征更贴近动作预测。

读 WM4A 前要先分清一件事：OFT、FAST、PI、GR00T 主要是在讨论“动作头怎么预测动作”；WM4A 主要是在讨论“backbone 从哪里提表征”。因此 WM4A 可以和 OFT、PI、GR00T 组合使用，它的重点是替换 backbone。

例如：

```text
QwenGR00T:
  Qwen-VL backbone + GR00T action head

WanGR00T:
  Wan world-model backbone + GR00T action head

CosmoPredict2PI:
  Cosmos world-model backbone + PI action head
```

代码路径：

```text
starVLA/model/framework/WM4A/
starVLA/model/modules/world_model/
starVLA/model/modules/action_model/
```

## VLM4A 与 WM4A 的差别

```text
VLM4A:
  image + instruction
    -> VLM encoder
    -> language-aligned hidden states
    -> action head

WM4A:
  image/video + instruction
    -> video-generation world model
    -> physics/dynamics-aligned hidden states
    -> action head
```

VLM4A 更强调视觉语言对齐，WM4A 更强调时空动态表征。两者最终都接 action head，因此可以复用训练和部署基础设施。

可以先用下面的方式理解：

| 路线 | 它更擅长什么 | 可能短板 |
|---|---|---|
| VLM4A | 把图像和语言指令对齐，理解“要做什么” | 对物理运动和未来变化的建模不一定充分 |
| WM4A | 从视频/世界模型中提取动态表征，理解“物体可能怎么动” | 模型更重，依赖更多，训练和部署成本更高 |

## 支持的 backbone

官方 WM4A 文档提到两个主要 backbone：

| Backbone | 参数量 | 说明 |
|---|---|---|
| Cosmos-Predict2-2B | 约 2B | NVIDIA Cosmos 系列视频预测模型 |
| Wan2.2-T2V | 约 5B | Wan 视频生成模型 |

对应 framework 文件包括：

```text
CosmoPredict2OFT.py
CosmoPredict2GR00T.py
CosmoPredict2PI.py
WanOFT.py
WanGR00T.py
WanPI.py
```

命名方式和 VLM4A 类似：backbone 名 + action head 类型。

## action head 组合

WM4A 也可以接三类动作头：

| 变体 | 动作头 | 特点 |
|---|---|---|
| `CosmoPredict2OFT` / `WanOFT` | MLP 回归 | 快，适合最小 baseline |
| `CosmoPredict2GR00T` / `WanGR00T` | 单层 flow matching | 动作分布建模更强 |
| `CosmoPredict2PI` / `WanPI` | layer-wise flow matching | 使用更多中间层表征，开销更高 |

这和 VLM4A 的设计保持一致。换 backbone 不要求重写 trainer。

这也是 StarVLA “乐高式”设计最直观的例子：同一个动作头可以接在不同 backbone 后面。动作头仍然负责输出 `action_loss` 和 `normalized_actions`，trainer 和 server 不需要知道前面是 Qwen-VL、Cosmos 还是 Wan。

## 特征提取方式

WM4A framework 通常会：

1. 用文本编码器处理 instruction。
2. 用 VAE 或视频模型预处理图像/视频为 latent。
3. 运行视频 DiT backbone。
4. 从 DiT 中间层或最后层取 hidden states。
5. reshape 成 token 序列。
6. 交给 action head。

官方文档中特别提到一个实现技巧：在特征提取时使用接近 clean 的 timestep，让 DiT 表征更适合动作预测，同时避免完整执行视频去噪生成。

这句话可以理解为：WM4A 借用视频生成模型内部的表征，用 world model 在预测世界变化时形成的 hidden states 做动作预测条件，最终视频帧本身通常不是控制接口。

## 和 VLM4A 变体的区别

| 对比对象 | WM4A 的区别 |
|---|---|
| QwenOFT | QwenOFT 用 VLM hidden state + MLP；WM4A-OFT 用 world-model hidden state + MLP |
| QwenPI | QwenPI 用 Qwen-VL 多层表征；WM4A-PI 用 world model 中间层表征 |
| QwenGR00T | QwenGR00T 用 Qwen-VL 最后一层表征；WM4A-GR00T 用 world model 表征接 GR00T 风格动作头 |
| QwenFast | FAST 强依赖 VLM action token 生成；WM4A 通常不是 token 生成路线 |

所以不要把 WM4A 记成“第五种动作头”。更准确的记法是：VLM4A 和 WM4A 是 backbone 路线；OFT、PI、GR00T 是动作头路线；FAST 是比较特殊的 VLM token 生成路线。

## 为什么仍然能共用 trainer

无论内部是 Qwen-VL 还是 Cosmos DiT，framework 对外还是：

```python
def forward(self, examples):
    return {"action_loss": action_loss}

def predict_action(self, examples):
    return {"normalized_actions": actions_np}
```

这就是 StarVLA “乐高式”设计的关键。trainer 不知道 backbone 是 VLM 还是 world model；deployment 也不需要知道 hidden states 来自哪里。

## 使用方式

训练时只需要切换：

```bash
--framework.name CosmoPredict2OFT
```

或：

```bash
--framework.name WanGR00T
```

并确保对应 world model 权重路径在配置中可用。官方文档示例：

```bash
huggingface-cli download nvidia/Cosmos-Predict2-2B-Video2World \
  --local-dir <MODEL_ROOT>/nvidia/Cosmos-Predict2-2B-Video2World
```

具体配置字段随 WM4A framework 文件而定，实际运行前应先用单文件验证：

```bash
python starVLA/model/framework/WM4A/CosmoPredict2GR00T.py
```

## 小结

- WM4A 用视频生成/预测 world model 的表征做动作预测。
- 它和 VLM4A 共用 action head 思路、trainer 和 deployment。
- 主要 backbone 包括 Cosmos-Predict2 和 Wan2.2。
- 使用时切换 `framework.name`，并准备对应 world model 权重。

## 动手练习

1. 运行 `find starVLA/model/framework/WM4A -maxdepth 1 -type f -name '*.py' | sort`，列出 WM4A framework 文件。
2. 运行 `rg -n "def forward|def predict_action|normalized_actions|FRAMEWORK_REGISTRY.register" starVLA/model/framework/WM4A/CosmoPredict2OFT.py starVLA/model/framework/VLM4A/QwenOFT.py`，找出它们对外接口相同的位置。
3. 运行 `rg -n "build_framework|model.forward|predict_action" starVLA/training deployment/model_server`，说明 WM4A 复用训练和部署入口的代码依据。
