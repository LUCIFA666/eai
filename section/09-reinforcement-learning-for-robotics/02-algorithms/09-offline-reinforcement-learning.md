# 离线强化学习（Offline RL）

Offline RL 的核心吸引力很直接：机器人不需要一边在线乱试一边学，而是先吃现成数据集，再从历史轨迹里学出更好的策略。对真实机器人来说，这很重要，因为在线探索昂贵、慢，而且可能不安全。你可以把它理解成“先看很多历史操作录像和状态动作日志，再决定下一版控制策略”，但它又不只是模仿，因为它还想利用奖励信号做策略改进。

## 学习目标

学完本页后，你应该能回答下面几件事：

- 什么是 offline RL，它和 behavior cloning、online RL 的数据来源与更新方式有什么不同。
- 为什么机器人场景里常常优先考虑 offline RL，而不是直接让真机在线探索。
- 什么叫分布外动作（out-of-distribution, OOD action）风险，为什么 Q 函数在离线设定里容易“瞎乐观”。
- 如何从数据覆盖、成功率、动作质量、观测质量和奖励质量五个角度评估一个机器人离线数据集。

## 初学者心智模型

先建立一个三分法：

- behavior cloning（BC）像“照着老师做”。数据集里怎么做，策略就学着怎么做，不主动利用未来回报去改进。
- offline RL 像“只允许看历史录像，但可以根据奖励重新打分”。策略不能去环境里新增交互，只能在旧数据里学，同时试图比示教更好。
- online RL 像“边开车边练”。策略会实时与环境交互，不断收集新样本，再用这些新样本更新自己。

对机器人来说，offline RL 最适合的典型场景是：

- 你已经有一批遥操作、脚本策略或旧版本策略产生的数据。
- 真机采样成本高，或者错误探索会碰撞、掉落、卡死。
- 你希望先在离线阶段把策略学到“至少能用”，再决定要不要做少量在线微调。

一个好记的直觉是：BC 主要问“老师当时做了什么”；offline RL 还会多问一句“老师当时那样做，长期回报真的高吗”。

## Offline RL 为什么难

offline RL 最难的地方，不是“没有数据”，而是“只有固定数据”。

在 online RL 里，如果当前策略想试一个新动作，就可以真的去环境里试，拿到真实反馈；但在 offline RL 里，训练时只能反复重放旧数据。于是会出现一个经典问题：

- Q 函数可能给某些从未在数据里出现过的动作打出很高分。
- 策略根据这个错误高分，越来越偏向这些数据集外动作。
- 但这些动作没有真实数据支撑，一旦部署就可能失效，甚至在机器人上表现得很危险。

这就是 OOD 动作风险。对初学者来说，可以把它理解成：模型在“没见过的动作区域”里开始脑补。

机器人里这个问题尤其明显，因为动作空间通常是连续的，比如末端位姿增量、关节速度、夹爪开合量。连续空间一大，数据覆盖就更稀疏，策略更容易走到数据没覆盖的区域。

## 与 BC 和 Online RL 的区别

### 和 Behavior Cloning 的区别

BC 只需要最小化“我预测的动作”和“数据里的动作”之间的误差，所以训练目标简单、稳定、容易收敛。但它也有明显限制：

- 如果数据集里存在次优动作，BC 会一并学进去。
- 如果任务需要长时序 credit assignment，BC 很难主动纠偏。
- 如果部署时状态稍微偏离训练分布，BC 容易累积误差。

offline RL 的额外目标，是借助 reward / return / value 去区分“虽然都出现在数据里，但哪些动作更值得保留”。所以它理论上可以超过示教者，或者至少在混合质量数据上学到更优的决策边界。

### 和 Online RL 的区别

online RL 的优势是可以持续采新数据，能靠探索弥补覆盖不足；代价是采样慢、真机危险、训练不稳定。offline RL 则把风险前置到“数据收集阶段”，训练阶段更像大规模监督学习加价值估计，但它受数据上限约束非常强：

- 数据没覆盖到的状态，策略很难学会。
- 数据里的奖励写错了，算法不会自己纠正。
- 数据动作质量差，策略的上限通常也会被拉低。

所以 offline RL 的一句大白话总结是：它不怕训练久，怕数据烂。

## 核心工作流

把机器人 offline RL 项目拆成下面 6 步最容易落地：

1. 明确任务边界：观测是什么、动作是什么、成功条件是什么、奖励是不是可信。
2. 审核数据来源：遥操作、脚本策略、旧 checkpoint、自主探索日志，各自噪声和偏差不同。
3. 检查数据覆盖：是否覆盖起始状态、关键中间状态、失败恢复状态和成功结束状态。
4. 先做 BC baseline：确认数据至少能把策略学到“复现示教水平”。
5. 再做 offline RL：在 BC 或已有策略基础上，引入 value/Q 学习做策略改进。
6. 用独立评测验证：看 success rate、失败类型、安全性，而不是只看训练损失。

对于初学者，顺序不要跳。没有 BC baseline 时，offline RL 学坏了你也不知道是算法问题还是数据本身就不可学。

## 机器人数据集该怎么看

看离线数据集，不要只看“条数够不够”，而要看下面五类质量：

### 1. 覆盖质量

- 初始状态是否多样。
- 目标位置、姿态、物体类别是否有变化。
- 失败状态是否存在，而不是只有成功演示。
- 恢复轨迹是否存在，例如抓偏后如何重试。

如果数据只覆盖“理想起点 + 理想轨迹”，策略一旦偏离就很容易崩。

### 2. 动作质量

- 动作是不是人类遥操作产生，是否有抖动。
- 动作有没有被后处理，比如平滑、裁剪、限幅。
- 不同来源的动作语义是否一致，例如一部分是关节空间，一部分是笛卡尔增量。

动作口径不一致，是机器人离线数据最常见的隐性坑之一。

### 3. 观测质量

- 传感器时间戳是否对齐。
- 图像、状态、力觉是否同步。
- 是否存在缺帧、NaN、单位错误、归一化不一致。

offline RL 训练阶段不会帮你发现传感器接线问题，但会把这些脏数据学进策略。

### 4. 奖励质量

- 奖励是不是事后自动标的，标注规则是否稳定。
- success/failure 定义是否一致。
- 是否把不该泄漏给策略的信息写进了奖励。

奖励质量差时，offline RL 可能比 BC 更糟，因为它会放大奖励中的偏差。

### 5. 策略来源质量

- 数据来自专家、半熟练操作者，还是随机策略。
- 多个策略混合时，是否记录了策略 ID 或阶段信息。
- 是否有明显的分布漂移，例如早期数据很差、后期数据很好。

混合质量数据不是不能用，但你得知道它是混合的。

## 常见方法直觉

本页不展开推导，但你需要有几个方向感：

- 保守型方法：限制策略不要偏离数据分布太远，宁可保守一点，也别去追 OOD 高分动作。
- 价值约束型方法：在 Q 学习时惩罚数据外动作，降低错误乐观。
- BC + RL 混合型方法：先学模仿，再逐步加入价值优化，让训练更稳。

如果你只是刚入门机器人 RL，一个实用原则是：先把 offline RL 当作”在 BC 旁边加一个很谨慎的策略改进模块”，而不是幻想它会从差数据里自动炼金。

## 代码示意：Offline RL 与 BC 的区别

下面用伪代码展示 BC 和 offline RL 在训练循环上的核心差异：

```python
# ========== Behavior Cloning ==========
# 只最小化”策略输出”和”数据集动作”之间的差异
for batch in offline_dataset:
    obs, action_demo = batch[“obs”], batch[“action”]
    action_pred = policy(obs)
    # 直接模仿——不关心 reward 和 return
    loss = mse_loss(action_pred, action_demo)
    loss.backward()
    optimizer.step()

# ========== Offline RL (CQL 风格示意) ==========
# 不但学动作，还要通过 Q 函数评估”哪些动作长期更值钱”
for batch in offline_dataset:
    obs, action, reward, next_obs, done = batch.values()

    # 1. 更新 Critic：学习每个 (s, a) 的长期价值
    with torch.no_grad():
        next_action = policy(next_obs)
        target_q = reward + gamma * (1 - done) * target_critic(next_obs, next_action)  # γ 折扣
    q_pred = critic(obs, action)
    critic_loss = mse_loss(q_pred, target_q)

    # 2. CQL 核心：惩罚 Q 函数对”数据外动作”过度乐观
    #    随机采一批动作，如果 Q(s, a_random) 比 Q(s, a_data) 高，就施加惩罚
    random_actions = torch.rand_like(action) * 2 - 1  # 均匀随机动作
    q_random = critic(obs, random_actions)
    cql_penalty = (q_random.mean() - q_pred.mean())  # 压低 OOD 动作的 Q 值

    total_critic_loss = critic_loss + alpha_cql * cql_penalty  # α_cql 控制保守程度
    total_critic_loss.backward()

    # 3. 更新 Actor：偏向 Q 函数认为更好的动作
    actor_action = policy(obs)
    actor_loss = -critic(obs, actor_action).mean()  # 最大化 Q
    actor_loss.backward()
```

关键区别一目了然：

- BC 只管”像不像”（模仿损失）。
- Offline RL 多了”值不值”（Q 函数）和”信不信”（CQL 惩罚防 OOD）。

## 常见坑

- 把 offline RL 当作“更高级的 BC”，却没有检查奖励是否可信。
- 数据里只有成功演示，没有失败和恢复过程，导致策略不会纠偏。
- 训练集表现很好，但部署时策略频繁输出数据集没见过的大动作。
- 混合了多个控制频率、动作尺度或相机视角的数据，却当成同一分布直接训练。
- 只看离线指标，不做独立 rollout 评测，误把 value 提升当成真实成功率提升。
- 以为数据越多越好，却没发现大量低质量轨迹在稀释少量高质量示教。
