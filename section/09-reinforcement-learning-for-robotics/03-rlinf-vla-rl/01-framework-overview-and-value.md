
# 1. 框架总览与核心价值：为什么我们需要新一代 RL 基建？

## 1.1 RLinf 究竟是什么？

RLinf 是一个专为基础模型（Foundation Models）强化学习后训练（Post-training）设计的开源分布式框架。

它的命名“inf”包含了双重含义：一方面代表基础设施（Infrastructure），意味着它像 PyTorch 或 Ray 一样，旨在成为支撑下一代大模型训练的底层系统；另一方面代表无限（Infinite），寓意通过分布式架构打破单机算力瓶颈，支持模型在开放环境中的持续探索与能力泛化。

该框架由清华大学、卡内基梅隆大学与南加州大学联合开发，其核心架构理念已在 arXiv 论文《RLinf：Flexible and Efficient Large Scale Reinforcement Learning through Macro-to-Micro Flow Transformation》（arXiv：2509.15965）中详细阐述。在近期的版本更新中，RLinf 将具身智能与逻辑推理任务的底层逻辑进行了统一，原生支持了 π₀、π₀.₅、OpenVLA 等前沿大模型，并集成了 IsaacLab、ManiSkill3 等高吞吐量的物理仿真环境。

## 1.2 为什么传统的 RL 框架在“大模型时代”会遇到瓶颈？

过去几年，Stable Baselines3 等传统框架极大地降低了强化学习的门槛。但在面对参数量达百亿级别的视觉语言动作模型（VLA）时，传统架构面临着明显的局限性。

首先是显存限制。传统框架通常在单一进程内完成数据收集和模型更新。但以 7B 模型为例，仅加载半精度权重就需要 14GB 显存，若在 PPO 训练中保存优化器状态和运行梯度，单卡显存需求会迅速突破 60GB，导致普通 24GB 显卡直接内存溢出。

其次是吞吐量不平衡。物理仿真高度依赖 CPU 进行刚体解算，而大模型推理和反向传播则依赖 GPU。传统的同步阻塞式训练会让 GPU 在等待物理碰撞结算时处于闲置状态，造成算力浪费。此外，以往的框架通常将模型与算法深度耦合，导致不同研究方向的代码难以复用。

为了解决这些痛点，RLinf 采用了计算解耦的设计思路。它将环境交互、无梯度推理和梯度更新模块彻底拆分，并通过分布式通信框架部署在最合适的硬件上。这种混合执行模式（Hybrid Mode）有效避免了算力等待，使整体数据吞吐量提升了超过 100%。

## 1.3 核心性能指标：从 SFT 到 RL 的提升

在实际的基准测试中，RLinf 展现了明显的性能提升。

在具身智能领域，OpenVLA 模型在 ManiSkill3 的放置物体任务中，原本依赖监督微调（SFT）的成功率仅为 53.91%，经过 RLinf 的 PPO 后训练后，成功率提升至 96.09%，并在未见过的分布外（OOD）任务上保持了 81.93% 的泛化水平。此外，OpenVLA-OFT 在 LIBERO 框架的五个复杂任务组中达到了 98.11% 的平均成功率，最新的 π₀.₅ 模型也通过 Flow-Noise 算法优化斩获了 98.3% 的成绩。

在智能体推理增强方面，RLinf-math-1.5B 模型在 AIME 2024、AIME 2025 和 GPQA 等逻辑综合测试中取得 40.84 的平均分，超过了业界主流的轻量级方案；而其 7B 版本则达到了 56.23 的综合分数，处于同级别开源模型的领先位置。

## 1.4 实战提示：硬件底线与算力配置

在动手部署前，我们需要对硬件资源有清晰的评估。由于 RLinf 采用了计算解耦设计，单张显卡通常无法独立完成 VLA 级别的强化学习训练。

运行该框架的物理硬件最低门槛是两张具备 24GB 显存的独立显卡（如 RTX 3090/4090）。在双卡设定下，第一张卡作为采样节点（Rollout Worker），加载模型的只读推理副本，专门负责高速前向传播并与物理引擎交互以收集数据；第二张卡（Actor / Learner Worker）则独占剩余显存，加载带有完整梯度图和优化器状态的训练模型，负责执行 PPO 的数学计算和反向传播。

在条件允许的情况下，建议使用 4 卡或 8 卡的 A6000 或 A100 集群，并结合全分片数据并行（FSDP）技术来切分训练节点。这不仅能大幅降低单卡显存压力，还能显著提升训练的迭代速度。
