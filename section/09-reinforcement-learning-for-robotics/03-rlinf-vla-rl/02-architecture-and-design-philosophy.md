# 2. 架构与设计理念：重塑大模型强化的底层基础设施

要真正理解 RLinf，我们需要跳出单纯的算法视角，将其看作一个精密的分布式系统。面对参数量庞大的具身大模型（VLA）和复杂的物理仿真引擎，RLinf 在架构层面进行了深度的重构。

## 2.1 解耦的分层架构设计

传统的强化学习框架通常将环境交互、模型推理和网络训练集中在一个 Python 进程中。RLinf 改变了这一现状，采用三层架构明确划分了不同组件的物理边界与功能责任。

首先是数据采集层，作为系统的“感官”，它负责与复杂的外部世界交互并采集多模态数据。这一层不仅支持 MetaWorld、Behavior 等传统 CPU 模拟器，还对 IsaacLab、ManiSkill3 等基于光线追踪的 GPU 加速模拟器进行了吞吐量优化。同时，其高度抽象的接口设计允许开发者通过 ROS 或 ZeroMQ 等协议无缝接入 UR5、Franka 等真实机械臂，而无需修改上层训练代码。

其次是推理与采样层。对于 π₀.₅、OpenVLA 等具身大模型而言，生成动作本质上是极耗算力的自回归生成或连续预测过程。RLinf 将此层独立，专门用于部署策略模型的推理副本，并深度集成 SGLang、vLLM、Hugging Face TGI 等主流推理引擎，利用 KV-Cache 和 PagedAttention 等底层技术，大幅压缩了数据采集阶段的动作响应延迟。

最后是训练与优化层，即系统的核心中枢。它加载包含完整计算图和 Adam 优化器状态的模型副本。面对 7B 以上的庞大模型，单卡显存往往难以承受，该层支持根据配置自动调用 FSDP（全分片数据并行）或 Megatron-LM 集群进行分布式训练。此外，这里封装了 PPO、GRPO、SAC 等算法的数学实现，专门负责接收数据、计算优势函数、反向传播并更新梯度。这种分层设计也带来了良好的生态兼容性，研究人员可以专注优化算法公式，而底层框架原生兼容 PyTorch 和 Hugging Face 生态，并内置了 TensorBoard 和 Wandb 以精准追踪各项训练指标。

## 2.2 核心创新：宏观到微观的流转设计 (Macro-to-Micro Flow Transformation)

RLinf 的另一项核心设计是“宏观到微观的流转设计”。在传统的单机强化学习中，数据流转通常是串行且阻塞的，即依次执行环境步进、动作计算、奖励获取和梯度更新。然而在大规模集群中，这种串行方式会导致严重的算力闲置。RLinf 的设计初衷便是将宏观的强化学习逻辑，无损编译为底层硬件上的高效并行流水线。

在宏观视角下，研究者只需通过配置文件定义高级的抽象数据流，例如智能体如何获取观测、生成动作、聚合奖励以及使用轨迹数据更新模型。整个流程依然维持着标准马尔可夫决策过程（MDP）的形式。

当这些配置落地到具体硬件时，RLinf 的调度器会将其转化为微观的混合执行模式（Hybrid Mode）。在具身智能任务中，这通常表现为三端协同调度：Actor 进程专职驱动物理引擎并持续输出图像；Rollout 进程接收图像并利用推理引擎快速生成动作指令；Learner 进程则独占大显存，接收前两者的历史轨迹并执行繁重的 PPO 梯度计算。

这种设计的优势在于通过异步调度隐藏了系统延迟。当 Learner 进程满载运行反向传播时，Actor 和 Rollout 进程并未闲置。底层通信网络会以非阻塞的方式将 Learner 更新后的模型权重同步给 Rollout，随后 Actor 和 Rollout 立刻开始下一轮的交互以收集新数据。通过让数据采集和梯度计算并行运转，RLinf 消除了算力空窗期，使 GPU 集群的利用率最大化，从而显著提升了整体训练吞吐量。
