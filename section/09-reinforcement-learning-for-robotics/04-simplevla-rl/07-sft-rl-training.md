# 10.4.6 SFT 冷启动与 RL 训练

> 前面几节把代码模块拆开讲了，这一节把整个训练流程串起来——从 SFT 冷启动开始，到 RL 训练收敛，再到评估和 checkpoint 管理。知道了完整流程，跑实验的时候心里才有数。

## 10.4.6.1 SFT 冷启动阶段

### 为什么必须有 SFT？

直接说结论：**从零开始的 RL 训练在 VLA 任务上基本不可行**。

原因很简单：7B 参数的模型，随机初始化的话，输出的动作完全是乱的——机器人要么乱晃，要么直接撞墙，根本碰不到物体。二元奖励下，全都是失败，全失败就没有梯度信号（动态采样也救不了，因为重试多少次都是全失败），训练直接卡死。

SFT 的作用就是给模型一个"合理的初始策略"——不用特别好，但至少能偶尔成功几次。只要成功率不是 0%，RL 就能开始工作。

### 最少需要多少演示数据？

这个问题挺关键的——如果需要很多演示，那 SFT 的成本就高了。

SimpleVLA-RL 的论文里做了实验，结论是：**每个任务最少 1 个演示就能启动 RL**。当然，演示越多，SFT 基线越高，RL 收敛越快。但即使只有 1 个演示，RL 也能从 ~5% 的成功率慢慢爬上去。

这个结论很重要——意味着你不用花大量时间收集演示数据，几条就够了。剩下的交给 RL 自己去探索。

### SFT 训练流程

SFT 阶段跟普通的语言模型微调差不多，就是把动作 token 当成文本 token 来预测。

**基础模型**：openvla-7b-oft，已经在大规模机器人数据上预训练过了。

**损失函数**：交叉熵损失，跟语言模型一样——给定图像和历史动作，预测下一个动作 token。

```python
# 伪代码
logits = model(input_ids=input_tokens, labels=labels)
loss = F.cross_entropy(logits.view(-1, vocab_size), labels.view(-1))
```

**学习率**：2e-5，比 RL 阶段大一些。SFT 阶段有明确的监督信号，可以用更大的学习率。

**训练步数**：一般几千到一万步就够了。SFT 不需要训太久——目标不是让模型完美，而是让模型"会做这个任务"。

**数据增强**：可以做一些图像增强（随机裁剪、颜色抖动），也可以用不同的语言指令描述同一个任务，增加数据多样性。

### SFT 基线大概什么水平

训练完 SFT 之后，先评估一下基线成功率，心里有个数。

不同任务的基线不一样：

| 任务 | SFT 基线成功率 | 说明 |
|------|---------------|------|
| LIBERO Spatial | ~20-25% | 简单任务，SFT 就能有不错的表现 |
| LIBERO Object | ~15-20% | 稍难一些 |
| LIBERO Objective | ~10-15% | 更复杂 |
| RoboTwin | ~10-20% | 取决于具体任务 |

大概就是 10-25% 这个区间。任务越简单，SFT 基线越高。

### 常见的失败模式

SFT 模型经常犯哪些错？了解这个有助于理解 RL 到底在优化什么：

**1. 定位不准**：抓手到了物体旁边，但差了一点点，抓不起来。这是最常见的失败模式。

**2. 姿态不对**：位置到了，但抓手的角度不对，抓的时候滑掉了。

**3. 用力过猛或不够**：夹爪闭合的时机不对，要么没夹住，要么把物体碰飞了。

**4. 过早结束**：模型以为任务完成了，提前停止动作，但实际上还没到位。

**5. 完全跑偏**：往错误的方向移动，根本没靠近目标物体。这种在 SFT 基线低的时候比较多。

RL 训练的过程，本质上就是在减少这些失败模式的发生概率。定位不准的，慢慢调准；姿态不对的，慢慢调对；完全跑偏的，慢慢被淘汰掉。

## 10.4.6.2 RL 训练阶段

### 从 SFT Checkpoint 启动

SFT 训完之后，拿到一个 checkpoint，就可以启动 RL 训练了。

启动命令大概长这样：

```bash
torchrun --nproc_per_node=8 -m verl.trainer.main_ppo \
    --config ./align.json \
    --sft_ckpt_path ./checkpoints/sft_final \
    --batch_size 64 \
    --samples_per_query 8 \
    --learning_rate 5e-6 \
    --temperature 1.6 \
    --max_steps 100000 \
    --save_freq 5000 \
    --val_freq 1000 \
    --benchmark libero \
    --task_name libero_spatial
```

跟前面讲的一样，核心参数就那几个。

### 训练曲线长什么样

不同任务的训练曲线不太一样，但大致趋势是类似的。

**LIBERO Spatial（简单任务）**：

- **0-50 步**：成功率快速上升，从 20% 左右涨到 60-70%。这个阶段进步最快，因为 SFT 模型离"会做"只差一点点，RL 很快就能补上。
- **50-200 步**：继续提升，但速度变慢，从 70% 涨到 90% 左右。
- **200-500 步**：缓慢收敛，从 90% 涨到 95%+，甚至 99%+。
- **500 步以后**：基本平稳，偶尔波动。

**RoboTwin（复杂任务）**：

- 整体趋势类似，但周期更长，可能需要几千步甚至上万步才能收敛。
- 噪声更大，成功率波动更明显——因为任务更复杂，成功与否的偶然性更大。
- 最终成功率也低一些，可能在 70-90% 之间，取决于任务难度。

为什么前期快后期慢？因为"容易的"成功先被学到了——比如物体正好在正前方、角度正好合适的情况，模型很快就能掌握。"难的"情况——比如物体在侧面、有遮挡、需要精细调整的，学得慢一些。

### 训练不稳定怎么办？

RL 训练偶尔会崩——成功率突然掉下来，或者 KL 突然飙升。遇到这种情况别慌，几个常见原因：

**1. 学习率太高**：策略更新太猛，一下子跑偏了。试试把学习率降到 2e-6 或者 1e-6。

**2. 温度太高**：探索太激进，好的策略被坏的动作淹没了。试试降到 1.2 或者 1.0。

**3. batch_size 太小**：样本太少，梯度噪声大。能加就加，加不了就多积累几步梯度。

**4. 运气不好**：刚好连续几个 batch 都是难任务，模型没学到东西。这种情况多等几步可能自己就恢复了。

一般来说，调低学习率是最稳妥的解决办法——虽然慢一点，但不容易崩。

### Checkpoint 管理

训练过程中会定期保存 checkpoint，几个要点：

**保存间隔**：默认每 5000 步存一次。如果训练总步数是 10 万步，就是 20 个 checkpoint。

**存什么**：
- 模型权重（~14GB）
- 优化器状态（~28GB）
- 学习率调度器状态
- 当前步数和训练状态

加起来一个 checkpoint 大概 40-50GB。20 个就是将近 1TB，存储空间得够。

**最佳 checkpoint 怎么选**：不是最后一个就最好。有时候训练后期会过拟合或者轻微掉点。一般做法是：
1. 每隔 val_freq 步在验证集上评估一次
2. 记录验证成功率最高的那个 checkpoint
3. 训练结束后用最佳 checkpoint 来做最终评测

**要不要存优化器状态**：如果确定不会再继续训练了，可以只存模型权重，省很多空间。但建议至少存一个带优化器状态的，万一后面要接着训呢。

### 评估模式：val_only

训练跑完了，或者中间想看看效果，就用评估模式跑一下。

评估模式跟训练模式的区别：
- 不更新参数，只跑 rollout
- 用贪婪采样（温度 0），不是高温采样
- 跑更多的回合数，结果更准
- 输出详细的统计信息

启动命令大概长这样：

```bash
torchrun --nproc_per_node=8 -m verl.trainer.main_ppo \
    --config ./align.json \
    --sft_ckpt_path ./checkpoints/best_checkpoint \
    --val_only \
    --val_batch_size 100 \
    --benchmark libero \
    --task_name libero_spatial
```

`--val_only` 表示只做评估，不训练。`--val_batch_size` 是评估的时候跑多少个回合。

### 评测要跑多少回合

评测的时候，回合数越多，结果越准，但也越费时间。

**快速验证**：每个任务 10-20 回合。大概看看趋势，不用太准。训练过程中的验证一般就用这个量级。

**正式评测**：每个任务 50 回合，10 个任务就是 500 回合。这是 LIBERO 论文里的标准评测设置，结果比较可靠。

**严格评测**：每个任务 100 回合以上。用来发论文或者做最终报告，结果最稳。

为什么需要这么多回合？因为二元奖励的方差大——同样的模型，跑 10 回合可能成功率 60%，再跑 10 回合可能就是 80%。回合数多了，结果才稳定。

### 评测输出什么

评估完了会输出这些信息：

- **总体成功率**：所有任务所有回合的平均成功率
- **各任务成功率**：每个任务单独的成功率
- **成功轨迹示例**：挑几条成功的轨迹存下来，可以看视频或者图像
- **失败轨迹示例**：挑几条失败的，方便分析问题
- **每回合步数**：平均用了多少步完成任务，步数越少说明策略越高效

失败轨迹分析挺有用的——看看模型都是怎么失败的，才能针对性地调优。

## 小结

SFT 冷启动 + RL 训练，整个流程走下来：

1. **SFT 阶段**：用少量演示数据把模型训到"偶尔能成功"的水平（10-25% 成功率），给 RL 一个合理的起点
2. **RL 阶段**：从 SFT checkpoint 开始，用 GRPO + 动态采样 + 二元奖励训练，成功率逐步提升，简单任务能到 95%+
3. **Checkpoint 管理**：定期保存，选验证集最好的那个，注意存储空间
4. **评估**：val_only 模式，贪婪采样，多跑几个回合保证结果可靠

整个流程的核心思想就是"先学会走路，再学着跑"——SFT 教基础，RL 做精调。
