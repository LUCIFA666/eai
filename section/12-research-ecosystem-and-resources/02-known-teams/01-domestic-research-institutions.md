# 国内研究机构

目标：从国内高校、科研机构、公司、开源项目和数据平台入口中判断其研究方向、代表产出和课程可用证据等级。

国内生态的特点是学术研究、开源基础设施、机器人本体、真实数据和产业部署连接很紧。阅读时先按“高校与科研机构团队”和“公司团队”分组，再把论文、代码、数据、机器人本体、SDK 和 benchmark 放在同一条证据链里看。

## 三、统一证据链

```text
机构主页 -> 项目页 -> 论文/技术报告 -> 代码/数据/SDK -> 运行说明 -> 评测协议
```

如果只能找到新闻或视频，适合写入“生态观察”；如果有论文但没有代码，适合“导读”；如果有代码、数据、环境和评测脚本，才适合进入“实战”。

## 四、课程使用边界

| 资料类型 | 可以支持什么 | 不能替代什么 |
|---|---|---|
| 论文和技术报告 | 方法、任务、实验设置和主要结论 | 不能替代可运行代码 |
| GitHub 仓库 | 代码结构、环境依赖、issue、release | 不能证明论文所有结果都容易复现 |
| 数据平台 | 数据格式、传感器配置、采集协议、许可边界 | 不能替代真实任务的完整评测 |
| SDK / 开发文档 | 二次开发接口、ROS 支持、仿真或控制入口 | 不能证明硬件在你的场景中稳定可用 |
| 公司/实验室新闻 | 了解方向、合作生态和产品形态 | 不能当作 benchmark 结论 |
| 视频和演示 | 看任务形态、机器人形态、交互方式 | 不能替代任务协议、失败案例和日志 |
